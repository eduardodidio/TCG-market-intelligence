# Task F04-T02 — Concurrent Card Processing with Resume

**Feature:** F04
**Wave:** 1
**Type:** backend
**Depends on:** F04-T01
**Maps to AC:** AC2, AC3, AC5, AC7
**Status:** done

## User Story

As a data collector operator, I want backfill to process multiple cards
concurrently and skip already-collected cards, so that a full-catalog
run completes in under 1 hour instead of 3+ hours and can resume after
interruption.

## Objective

Add configurable concurrency via `asyncio.Semaphore` and resume capability
(skip cards already in DB) to `run_backfill` in `src/collectors/backfill.py`.

## Dev Notes

- File: `src/collectors/backfill.py` (265 lines)
- Current problem (AH-01): cards are processed sequentially in a `for` loop
  (line 55). At 1s delay per request and 2 requests per card (details +
  history), 10k cards = ~5.5 hours.
- The MYP provider is already async (`async def _fetch`), so concurrency
  is straightforward with `asyncio.Semaphore`.
- **Concurrency approach:**
  - Add `concurrency: int = 3` parameter to `run_backfill`
  - Create `asyncio.Semaphore(concurrency)` before the loop
  - Use `asyncio.gather` with semaphore-wrapped `_process_card` calls
  - The semaphore limits in-flight HTTP requests (each card = 2 requests)
  - Default 3 = 6 concurrent requests, conservative for Cloudflare
- **Resume approach:**
  - Before processing, query the DB for cards that already have observations:
    `repo.get_cards_with_observations(source)` — already exists (line 203)
  - Build a set of `external_id`s that have been collected
  - Skip any discovered card whose `external_id` is already in the set
  - Log skipped cards at debug level
  - Add `--no-resume` CLI flag to force re-processing all cards
- **Progress reporting:**
  - Add a simple counter: `processed/total` logged every N cards
  - Use `structlog` consistent with existing logging pattern
- **CLI changes** in `src/cli/main.py`:
  - Add `--concurrency` option to `backfill` command (default 3)
  - Add `--no-resume` flag to `backfill` command
- `run_update` and `run_retry_failed` remain sequential (smaller card sets,
  lower priority for concurrency)
- Error handling: if one card fails in a concurrent batch, the others must
  not be affected. `asyncio.gather(return_exceptions=True)` or
  try/except inside the semaphore wrapper.
- Convention: all parameters are keyword-only after `db_url`.

## Implementation Details

### backfill.py changes

```python
async def run_backfill(
    db_url: str = "sqlite:///tcg_market.db",
    set_filter: str | None = None,
    limit: int | None = None,
    dry_run: bool = False,
    delay: float = 1.0,
    history_days: int = 1095,
    concurrency: int = 3,
    resume: bool = True,
) -> CollectionSummary:
```

Key implementation points:
1. After discovering cards, if `resume` and not `dry_run`:
   ```python
   collected_ids = {eid for eid, _ in repo.get_cards_with_observations(provider.source_name)}
   discovered = [c for c in discovered if c.external_id not in collected_ids]
   log.info("resume_filtered", skipped=skipped_count, remaining=len(discovered))
   ```
2. Replace sequential loop with semaphore + gather:
   ```python
   sem = asyncio.Semaphore(concurrency)
   async def process_with_sem(card, index):
       async with sem:
           # existing _process_card logic with try/except
   tasks = [process_with_sem(card, i) for i, card in enumerate(discovered, 1)]
   await asyncio.gather(*tasks)
   ```
3. Use `asyncio.Lock` for thread-safe summary updates (summary.cards_processed += 1)
