## User Story

As a developer, I want integration tests covering the full collector
pipeline (backfill, update, retry-failed), so that I can confidently
refactor and extend the collector without regressions.

## Objective

Create integration tests that exercise `run_backfill`, `run_update`, and
`run_retry_failed` end-to-end with mocked HTTP responses and a real
in-memory SQLite database.

## Dev Notes

- New directory: `tests/integration/` (create `__init__.py`)
- New file: `tests/integration/test_collector_pipeline.py`
- These are NOT unit tests — they exercise the full stack:
  `CLI args -> backfill.py -> provider.py -> parser.py -> repository.py -> SQLite`
- Mock only the HTTP layer (`curl_cffi` responses), everything else is real.
- Use `sqlite:///:memory:` for the database (fast, no cleanup needed).
- Fixture approach: create realistic HTML fixtures that the parsers can
  actually parse. Reuse existing test data from `tests/unit/test_parsers.py`
  if applicable.
- The provider uses `AsyncSession.get()` from curl_cffi. Mock this at the
  provider level by patching `MypCardsProvider._fetch` to return
  pre-built HTML strings.
- Existing parser test fixtures in `tests/unit/test_parsers.py` contain
  sample HTML — extract shared fixtures to `tests/conftest.py` or
  `tests/fixtures/` if helpful.
- Convention: pytest-asyncio with `asyncio_mode = "auto"` (from pyproject.toml)
- Keep test execution fast (< 5 seconds total for the integration suite).
