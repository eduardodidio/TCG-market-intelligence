# F06-T05: Collection admin endpoints (backfill + update)

**Wave:** 1
**Status:** planned
**Estimate:** M

## User Story

As an admin, I want to trigger backfill and update collection jobs through the API so that I can manage data collection without SSH-ing into the server to run CLI commands.

## Dev Notes

- Create `src/api/routers/collect.py` with an `APIRouter(prefix="/collect", tags=["collection"])`.

### `POST /collect/backfill`

- Request body: `BackfillRequest` schema (`set: str`, `limit: int | None`, `history_days: int = 1095`).
- Since there is no job queue, use `asyncio.create_task()` to run the backfill in the background.
- Generate a UUID as `job_id`, store it in an in-memory dict (`_active_jobs: dict[str, str]`) with status.
- Return immediately with `JobStatus(job_id=..., status="started", message="Backfill started for set {set}")`.
- The background task calls the existing `run_backfill()` from `src/collectors/backfill.py` with the provided params.
- On completion/failure, update the in-memory job status.
- Note: This is a simple MVP approach. A proper job queue is future work.

### `POST /collect/update`

- Request body: `UpdateRequest` schema (`set: str | None`).
- Same background task pattern as backfill.
- Calls existing `run_update()` from `src/collectors/backfill.py`.
- Return `JobStatus` immediately.

### Job tracking (simple MVP)

- Create `src/api/jobs.py` with:
  - `JobTracker` class: `start(job_type, params) -> job_id`, `complete(job_id, summary)`, `fail(job_id, error)`, `get_status(job_id) -> JobStatus | None`
  - In-memory `dict` storage — jobs are lost on server restart. This is acceptable for MVP.
- The `JobTracker` is injected via FastAPI dependency, as a singleton.

### Files to create/modify:
- Create: `src/api/routers/collect.py`, `src/api/jobs.py`
- Reference (do not modify): `src/collectors/backfill.py` — call `run_backfill()` and `run_update()` directly

## Acceptance Criteria

- [ ] `POST /collect/backfill` with valid body returns 200 with `job_id` and `status: "started"`
- [ ] `POST /collect/backfill` without `set` field returns 422 validation error
- [ ] `POST /collect/update` returns 200 with job status
- [ ] Background tasks are spawned (verified by checking `asyncio.Task` creation in tests)
- [ ] `JobTracker` correctly transitions states: started -> completed/failed
- [ ] All responses use the standard envelope
