# F06-T02: Pydantic schemas and response envelope

**Wave:** 0
**Status:** planned
**Estimate:** M

## User Story

As a developer, I want a standard JSON response envelope and Pydantic schemas for all API resources so that every endpoint returns consistently structured responses.

## Dev Notes

- Create `src/api/schemas/envelope.py`:
  - `ErrorDetail(BaseModel)`: `code: str`, `message: str`, `field: str | None = None`
  - `Meta(BaseModel)`: `cursor: str | None = None`, `total: int | None = None`, `request_id: str`
  - `ApiResponse(BaseModel, Generic[T])`: `data: T | None = None`, `meta: Meta`, `errors: list[ErrorDetail] = []`
  - Helper functions: `success_response(data, meta)`, `error_response(errors, status_code)`, `paginated_response(data, cursor, total)`

- Create `src/api/schemas/cards.py`:
  - `CardSummary(BaseModel)`: `id: int`, `game: str`, `name_en: str`, `name_pt: str | None`, `set_code: str | None`, `collector_number: str | None`, `latest_price: Decimal | None` — used in list responses
  - `CardDetail(BaseModel)`: extends CardSummary with `source_cards: list[SourceCardSchema]`, `created_at: datetime`, `updated_at: datetime`
  - `SourceCardSchema(BaseModel)`: `source: str`, `external_id: str`, `sku: str | None`, `url: str`
  - `PriceObservation(BaseModel)`: `observed_at: date`, `median_price: Decimal | None`, `tcg_price: Decimal | None`, `last_sold_price: Decimal | None`, `quantity_available: int | None`, `currency: str`
  - `CardListParams(BaseModel)`: query params for `GET /cards` — `game`, `set`, `name`, `cursor`, `limit` with defaults and validation (limit max 200)
  - `HistoryParams(BaseModel)`: query params for `GET /cards/{id}/history` — `period` with enum validation

- Create `src/api/schemas/sets.py`:
  - `SetSummary(BaseModel)`: `set_code: str`, `game: str`, `card_count: int`

- Create `src/api/schemas/market.py`:
  - `MoverEntry(BaseModel)`: `card_id: int`, `name_en: str`, `set_code: str | None`, `price_start: Decimal`, `price_end: Decimal`, `change_pct: Decimal`
  - `MoversResponse(BaseModel)`: `gainers: list[MoverEntry]`, `losers: list[MoverEntry]`
  - `MarketStats(BaseModel)`: `total_cards: int`, `total_observations: int`, `avg_price: Decimal | None`, `date_range_start: date | None`, `date_range_end: date | None`

- Create `src/api/schemas/collect.py`:
  - `BackfillRequest(BaseModel)`: `set: str`, `limit: int | None = None`, `history_days: int = 1095`
  - `UpdateRequest(BaseModel)`: `set: str | None = None`
  - `JobStatus(BaseModel)`: `job_id: str`, `status: str`, `message: str`

- Use Pydantic v2 patterns: `model_config = ConfigDict(from_attributes=True)` for ORM compatibility.
- All Decimal fields should use `Decimal` type with appropriate serialization (not float).

## Acceptance Criteria

- [ ] All schema files created under `src/api/schemas/`
- [ ] `ApiResponse` generic envelope works with any data type
- [ ] `CardListParams` validates `limit` range (1-200, default 50)
- [ ] `HistoryParams` validates `period` against allowed values (`30d`, `90d`, `180d`, `1y`, `3y`)
- [ ] All schemas have `from_attributes=True` where they map to ORM models
- [ ] `request_id` is auto-generated as UUID in `Meta`
- [ ] Existing tests still pass
