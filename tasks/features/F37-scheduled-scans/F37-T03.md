# F37-T03: Repository CRUD for scheduled_scans

- **Wave:** 1
- **Type:** backend
- **Depends on:** T01
- **Status:** planned

## Objective

Add repository methods for CRUD operations on the `scheduled_scans` table,
following the existing patterns in `src/database/repository.py`.

## Implementation Details

### File: `src/database/repository.py`

Add the following methods to the `Repository` class:

```python
def create_scheduled_scan(
    self, name: str, cron_expression: str, scan_type: str,
    filters_json: str = "{}", description: str | None = None,
    max_retries: int = 3,
) -> int:
    """Insert a new scheduled scan and return its ID."""

def get_scheduled_scan(self, schedule_id: int) -> dict | None:
    """Get a single scheduled scan by ID."""

def list_scheduled_scans(
    self, status: str | None = None, limit: int = 50, offset: int = 0
) -> list[dict]:
    """List scheduled scans with optional status filter."""

def update_scheduled_scan(self, schedule_id: int, **kwargs) -> None:
    """Update fields on a scheduled scan row."""

def delete_scheduled_scan(self, schedule_id: int) -> bool:
    """Delete a scheduled scan. Returns True if deleted."""

def get_active_schedules(self) -> list[dict]:
    """Get all schedules with status='active'. Used by scheduler on startup."""
```

### Pattern reference

Follow the same pattern as `create_scan_run`, `get_scan_run`, `list_scan_runs`,
`update_scan_run` -- use raw `Session.execute` with `text()` or use the ORM
model, whichever is consistent with existing code.

- [ ] `list_scheduled_scans` supports status filter and pagination
- [ ] `update_scheduled_scan` updates only provided kwargs
