## Implementation Details

### File: `docs/diagrams/F37-architecture.mmd`

Mermaid flowchart showing:

- FastAPI lifespan starts `ScanScheduler`
- `ScanScheduler` loads active schedules from `scheduled_scans` table
- APScheduler fires CronTrigger at scheduled times
- Trigger callback calls `run_scan()` (reuses F13 scan orchestrator)
- `run_scan()` writes to `scan_runs` table
- Scheduler updates `scheduled_scans` metadata (last_run_id, error_count)
- API router reads/writes `scheduled_scans` for CRUD
- CLI commands read/write `scheduled_scans` directly

### File: `docs/diagrams/F37-journey.mmd`

BPMN-style user journey:

1. User opens Schedules page
2. User clicks "New Schedule"
3. User fills form (name, cron, filters)
4. System validates cron + creates schedule
5. APScheduler registers job
6. (time passes) APScheduler triggers scan
7. Scan runs, results stored in scan_runs
8. User views schedule history (last run, errors)
9. Alt: schedule fails N times -> auto-paused
10. User investigates errors, fixes, resumes
