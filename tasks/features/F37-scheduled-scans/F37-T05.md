# F37-T05: API Schemas + Router for Schedules

- **Wave:** 3
- **Type:** backend
- **Depends on:** T04
- **Status:** planned

## Objective

Create Pydantic schemas and FastAPI router for schedule management endpoints
under `/api/v1/schedules`.

## Implementation Details

### File: `src/api/schemas/schedules.py`

```python
class ScheduleCreateRequest(BaseModel):
    name: str
    cron_expression: str
    scan_type: str = "collection"
    filters_json: str = "{}"
    description: str | None = None
    max_retries: int = 3

class ScheduleUpdateRequest(BaseModel):
    name: str | None = None
    cron_expression: str | None = None
    scan_type: str | None = None
    filters_json: str | None = None
    description: str | None = None
    status: str | None = None  # active | paused
    max_retries: int | None = None

class ScheduleResponse(BaseModel):
    id: int
    name: str
    description: str | None
    cron_expression: str
    scan_type: str
    filters_json: str
    status: str
    last_run_id: int | None
    last_run_at: str | None
    next_run_at: str | None
    error_count: int
    max_retries: int
    created_at: str
    updated_at: str

class ScheduleListResponse(BaseModel):
    schedules: list[ScheduleResponse]
    total: int

class ScheduleTriggerResponse(BaseModel):
    schedule_id: int
    scan_id: int
    status: str
```

### File: `src/api/routers/schedules.py`

Endpoints (all require auth):

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/schedules` | Create a new schedule |
| `GET` | `/schedules` | List schedules (optional `?status=` filter) |
| `GET` | `/schedules/{id}` | Get schedule details |
| `PATCH` | `/schedules/{id}` | Update schedule (cron, filters, status) |
| `DELETE` | `/schedules/{id}` | Delete schedule |
| `POST` | `/schedules/{id}/trigger` | Manually trigger schedule now |

### Key behaviors

- **Create**: Validate cron expression via `croniter.is_valid()`. Reject sub-hour.
  Insert into DB. Call `scheduler.add_schedule(id)` to register with APScheduler.
- **Update**: If cron_expression changed, remove+re-add APScheduler job. If status
  changed to `paused`, call `scheduler.pause_schedule()`. If `active`, call
  `scheduler.resume_schedule()`.
- **Delete**: Call `scheduler.remove_schedule()`, then delete from DB.
- **Trigger**: Call `scheduler.trigger_now()`, return scan_id.

### Scheduler access

The router needs access to the `ScanScheduler` instance. Use FastAPI dependency
injection: store the scheduler on `app.state.scheduler` (set in T07 lifespan),
retrieve via `request.app.state.scheduler` in the router.

## Acceptance Criteria

- [ ] `POST /schedules` creates schedule, validates cron, returns ScheduleResponse
- [ ] `GET /schedules` returns paginated list with total count
- [ ] `GET /schedules/{id}` returns single schedule or 404
- [ ] `PATCH /schedules/{id}` updates fields, re-syncs APScheduler job if needed
- [ ] `DELETE /schedules/{id}` removes schedule and APScheduler job
- [ ] `POST /schedules/{id}/trigger` triggers immediate scan, returns scan_id
- [ ] All endpoints require authentication
- [ ] Invalid cron expressions return 422
- [ ] All existing tests pass
