# F115-T02: Frontend Default Sort by Price + URL Persistence

**Status:** planned
**Wave:** 1 (depends on T01 — backend must accept price sort)

## User Story

As a user, I want my collection to load sorted by value (highest first) and
this preference to survive page refresh via URL parameters.

## Root Cause Analysis

**Current state in MyCollection.tsx:276-277:**
```typescript
const [sortBy, setSortBy] = useState(searchParams.get("sort") ?? "price");
const [sortDir, setSortDir] = useState<"asc"|"desc">((searchParams.get("dir") as "asc"|"desc") ?? "desc");
```

Default is already "price desc" BUT:
1. Price sort is **never sent to backend** (lines 550-554 skip it)
2. Price sort is **not persisted in URL** (lines 536-539 exclude it)
3. Client-side sort only works on current page, not across pagination

## Dev Notes

## Acceptance Criteria

1. Collection loads sorted by price (highest first) on first visit
2. URL shows `?sort=price&dir=desc` (or omits for default)
3. Changing sort persists in URL — refresh preserves sort state
4. Pagination respects sort (page 2 has lower prices than page 1)
5. All sort options (name, set, number, added, price) work end-to-end

- Frontend test: refresh with ?sort=price&dir=asc — renders ascending
