# F08-T01: Fix UTF-8 double-encoding in parser/provider and migrate DB data

**Wave:** 0
**Status:** done
**Estimate:** L

## User Story

As a user browsing the dashboard, I want card names with accented characters
(e.g., "Contramagica", "Relampago Helice") to display correctly instead of
garbled text, so that I can read and search for cards in Portuguese.

## Dev Notes

### Root Cause Investigation

The `_fetch` method in `src/providers/myp/provider.py` (line 110) returns
`resp.text`. In `curl_cffi`, the `.text` property decodes the response body
using the charset from the `Content-Type` header. If MYP's server returns
`Content-Type: text/html` without a charset parameter (or with `charset=iso-8859-1`),
curl_cffi may decode the UTF-8 bytes using latin-1, producing mojibake.

**Diagnosis approach:**
1. Fetch a card page with curl_cffi and inspect `resp.headers['Content-Type']`
   and `resp.encoding` vs the actual HTML `<meta charset>` tag.
2. Compare `resp.text` vs `resp.content.decode('utf-8')` for a card with
   accented characters.

### Fix in Provider

In `src/providers/myp/provider.py`, method `_fetch` (around line 110):

```python
# BEFORE:
return resp.text

# AFTER — force UTF-8 decoding:
return resp.content.decode("utf-8")
```

This is safe because MYP Cards is a Brazilian site that serves UTF-8 HTML
(the `<meta charset="utf-8">` tag is in the HTML, but the HTTP header may
not include it).

**Alternative** (less invasive): Set `resp.encoding = "utf-8"` before
accessing `.text`. Choose whichever is cleaner after diagnosis.

### Files to Change

- `src/providers/myp/provider.py` -- `_fetch()` method, force UTF-8 decode
- `src/parsers/myp.py` -- no changes expected (it receives a `str`, encoding
  is already resolved by the provider)

### DB Migration Script

Create a one-time migration script to fix existing corrupted data:

- File: `scripts/fix_encoding.py`
- Logic:
  1. Read all `source_cards` rows where `name_pt` or `name_en` contains
     mojibake patterns (bytes C3 80-C3 BF when re-encoded to latin-1 produce
     valid UTF-8).
  2. For each affected row: `fixed = name.encode('latin-1').decode('utf-8')`
  3. Update the row in the database.
  4. Also fix the `cards` table `name_en` and `name_pt` columns.
  5. Print a summary of how many rows were fixed.
- Make it idempotent: if re-encoding raises `UnicodeDecodeError` or
  `UnicodeEncodeError`, the name is already correct -- skip it.
