# F103-T03 — Catalog seeder (batch upsert cards + source_cards)

**Status:** planned
**Wave:** 0
**Depends on:** T01, T02

## User Story

Como operador do sistema, quero rodar um seeder que insira todas as cartas
do bulk data do Scryfall no banco local (cards + source_cards para Liga),
para ter o catálogo completo disponível offline.

## Acceptance Criteria

- [ ] `src/catalog/seeder.py` com `seed_catalog(db_url, bulk_path, batch_size=500) -> SeedResult`
- [ ] `SeedResult` dataclass: cards_inserted, cards_updated, cards_skipped,
  source_cards_created, errors, elapsed_seconds
- [ ] Batch upsert: INSERT OR IGNORE por unique constraint (game, set_code, collector_number)
- [ ] Para cada card inserido/existente, cria `source_cards` entry:
  - source = "liga"
  - external_id = `liga_catalog_{set_code}_{collector_number}`
  - url = LigaMagic search URL construída do card name
  - card_id = FK para cards.id
- [ ] Progress logging a cada 1000 cards (structlog)
- [ ] Idempotente — rodar 2x não duplica dados
- [ ] Transacional por batch (commit a cada 500 rows, não por card individual)

## Dev Notes

- Usar `repo.session.execute(insert(...).on_conflict_do_nothing(...))` para
  batch insert eficiente, ou adaptar o padrão de `batch_upsert_price_observations`
- O seeder recebe o path do JSON já baixado (T02 cuida do download)
- Construir Liga URL: `https://www.ligamagic.com.br/?view=cards/card&card={quote_plus(name_en)}&show=1`
  — reusar `_build_card_url` de `src/providers/liga/provider.py`
- Para cards com mesmo nome mas sets diferentes, cada printing gera uma
  `source_cards` entry diferente (external_id tem set_code + collector_number)
- SQLite: usar `INSERT OR IGNORE` ao invés de `ON CONFLICT DO NOTHING`
  (SQLAlchemy compila para o dialeto correto)
