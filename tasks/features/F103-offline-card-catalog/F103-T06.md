# F103-T06 — Catalog REST API endpoints

**Status:** planned
**Wave:** 2
**Depends on:** T01, T03

## User Story

Como frontend, quero endpoints REST para listar, buscar e filtrar cartas
do catálogo completo, com preços Liga quando disponíveis, para que a
página de catálogo funcione.

## Acceptance Criteria

- [ ] `GET /catalog/cards` — lista paginada (limit/offset, default 50)
  - Filtros query params: `set_code`, `rarity`, `color` (contém), `name` (LIKE),
    `has_price` (bool), `min_price`, `max_price`
  - Ordenação: `name`, `set_code`, `price` (asc/desc)
  - Response inclui: card fields + latest Liga price (nullable) + image_uri
- [ ] `GET /catalog/cards/{card_id}` — detalhes de uma carta + preço Liga
- [ ] `GET /catalog/sets` — lista de sets disponíveis no catálogo
  - Response: `[{set_code, card_count, priced_count}]`
  - Ordenado por set_code
- [ ] `GET /catalog/stats` — estatísticas gerais
  - total_cards, total_sets, cards_with_price, cards_without_price, last_seed_at
- [ ] Endpoints são públicos (sem auth) — catálogo é reference data
- [ ] Performance: query com JOIN em price_observations deve usar o index existente

## Dev Notes

- Criar `src/api/routers/catalog.py` com router `catalog_router`
- Registrar no `src/api/app.py`
- Service layer: `src/services/catalog.py` com `CatalogService`
- Para preço Liga, fazer LEFT JOIN com latest price_observation:
  ```sql
  SELECT c.*, po.median_price, po.observed_at
  FROM cards c
  LEFT JOIN source_cards sc ON sc.card_id = c.id AND sc.source = 'liga'
  LEFT JOIN (
    SELECT external_id, median_price, observed_at,
           ROW_NUMBER() OVER (PARTITION BY external_id ORDER BY observed_at DESC) rn
    FROM price_observations WHERE source = 'liga'
  ) po ON po.external_id = sc.external_id AND po.rn = 1
  WHERE c.game = 'magic'
  ```
- Paginação: usar LIMIT/OFFSET (catálogo estático, não precisa cursor)
- Considerar cache em memória para `/catalog/sets` e `/catalog/stats` (5min TTL)
