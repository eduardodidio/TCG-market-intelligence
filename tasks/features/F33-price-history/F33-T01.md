# F33-T01 — Backend: Extend Periods + Aggregation Logic

**Wave:** 1 (parallel with T02)
**Estimated effort:** small-medium

## Objective

Add 24h and 7d periods to the existing history API, and create a pure
aggregation module that groups daily observations into weekly resolution
for longer periods.

## Files to Modify

- `src/api/routers/cards.py` — extend `PERIOD_MAP`
- `src/api/schemas/cards.py` — extend `HistoryPeriod` literal type

## Files to Create

- `src/analytics/aggregation.py` — pure aggregation functions

## Detailed Steps

### 1. Extend PERIOD_MAP

In `src/api/routers/cards.py`, add entries to `PERIOD_MAP`:

```python
PERIOD_MAP = {
    "24h": 1,
    "7d": 7,
    "30d": 30,
    "90d": 90,
    "180d": 180,
    "1y": 365,
}
```

Remove the "3y" period (1095 days) — it is excessive for daily collection
data that has been running for weeks/months. Replace with the new shorter
periods.

### 2. Update HistoryPeriod type

In `src/api/schemas/cards.py`, update:

```python
HistoryPeriod = Literal["24h", "7d", "30d", "90d", "180d", "1y"]
```

### 3. Create aggregation module

Create `src/analytics/aggregation.py` with:

```python
def determine_resolution(period: str) -> str:
    """Return 'daily' for periods <= 90d, 'weekly' for longer."""

def aggregate_weekly(
    observations: list[PriceObservation],
) -> list[PriceObservation]:
    """Group observations by ISO week.

    For each week, produce one data point:
    - observed_at: last date in the group
    - median_price: average of non-None median_price values
    - tcg_price: average of non-None tcg_price values
    - last_sold_price: average of non-None last_sold_price values
    - quantity_available: last non-None value in the group
    - currency: from first observation
    """

def aggregate_series(
    observations: list[PriceObservation],
    period: str,
) -> tuple[list[PriceObservation], str]:
    """Apply aggregation based on period.

    Returns (aggregated_observations, resolution_string).
    """
```

Key design decisions:
- Use `date.isocalendar()` for ISO week grouping
- Input and output use the same `PriceObservation` Pydantic model from
  `src/api/schemas/cards.py`
- The function is pure — no database access, no side effects
- Weekly average uses only non-None values (skip None in average calc)

### 4. Wire aggregation into cards history endpoint

In `src/api/routers/cards.py`, after building the observation list in
`get_history()`, apply aggregation:

```python
from src.analytics.aggregation import aggregate_series

data, resolution = aggregate_series(data, period)
```

This replaces the raw data list with the aggregated version for 180d+
periods.

## Acceptance Criteria

- `GET /cards/{id}/history?period=24h` returns observations from last 24h
- `GET /cards/{id}/history?period=7d` returns observations from last 7d
- `GET /cards/{id}/history?period=180d` returns weekly-aggregated data
- `GET /cards/{id}/history?period=1y` returns weekly-aggregated data
- `GET /cards/{id}/history?period=30d` returns daily data (no aggregation)
- "3y" period returns 422 (removed from valid periods)
- `aggregate_weekly` correctly averages prices within ISO weeks
- All functions in `aggregation.py` are pure (no imports from database)
