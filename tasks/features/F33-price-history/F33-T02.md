# F33-T02 — Backend: Collection History Endpoint + Price Change Summary

**Wave:** 1 (parallel with T01)
**Estimated effort:** small-medium

## Objective

Add a dedicated history endpoint for collection entries (with auth) and
a price change summary schema that accompanies history responses.

## Files to Modify

- `src/api/routers/collection.py` — add history endpoint
- `src/api/schemas/cards.py` — add `PriceChangeSummary` schema
- `src/api/schemas/collection.py` — add `CollectionHistoryResponse` schema

## Detailed Steps

### 1. Add PriceChangeSummary schema

In `src/api/schemas/cards.py`, add:

```python
class PriceChangeSummary(BaseModel):
    period: str
    price_start: float | None = None
    price_end: float | None = None
    absolute_change: float | None = None
    percent_change: float | None = None
    data_points: int = 0
    resolution: str = "daily"
```

### 2. Add CollectionHistoryResponse schema

In `src/api/schemas/collection.py`, add:

```python
from src.api.schemas.cards import PriceChangeSummary, PriceObservation

class CollectionHistoryResponse(BaseModel):
    observations: list[PriceObservation] = []
    summary: PriceChangeSummary | None = None
```

### 3. Add helper: compute_price_change_summary

Create a pure function (can live in `src/analytics/aggregation.py` or
inline in the router) that computes the summary from a list of
observations:

```python
def compute_price_change_summary(
    observations: list[PriceObservation],
    period: str,
    resolution: str,
) -> PriceChangeSummary:
    """Compute start/end price and change metrics.

    - price_start: median_price of first observation
    - price_end: median_price of last observation
    - absolute_change: price_end - price_start
    - percent_change: ((price_end - price_start) / price_start) * 100
    """
```

### 4. Add collection history endpoint

In `src/api/routers/collection.py`, add:

```python
@router.get(
    "/{entry_id}/history",
    response_model=ApiResponse[CollectionHistoryResponse],
)
def get_collection_history(
    entry_id: int,
    period: str = Query(default="30d"),
    currency: str = Query(default="BRL", pattern="^(BRL|USD|PILA)$"),
    repo: Repository = Depends(get_db),
    converter: CurrencyConverter = Depends(get_currency_converter_dep),
    user_id: str = Depends(require_auth_or_api_key),
):
```

Logic:
1. Validate `period` against `PERIOD_MAP` (import from cards router or
   duplicate the constant).
2. Look up collection entry, verify ownership (`user_id` match).
3. If `card_id` is None, return empty response.
4. Get source cards for `card_id`.
5. Call `repo.get_price_series()` for each source card with `days` param.
6. Convert prices via `CurrencyConverter`.
7. Apply aggregation via `aggregate_series()` from T01.
8. Compute `PriceChangeSummary`.
9. Return `CollectionHistoryResponse`.

### 5. Also add summary to cards history endpoint

Update `get_history()` in `src/api/routers/cards.py` to also return
the summary. This requires changing the response model from
`list[PriceObservation]` to a new wrapper. Options:

- Option A: Change response to `CollectionHistoryResponse` (reuse schema).
- Option B: Keep returning `list[PriceObservation]` for backward
  compatibility; add summary as a separate endpoint.

**Recommended: Option A** — change the cards history response to also use
the `{observations, summary}` shape. Update the response model. This is
a breaking change for the frontend, but T03 will update the frontend in
Wave 2 to match.

## Acceptance Criteria

- `GET /collection/{id}/history?period=30d` returns observations + summary
- Endpoint requires authentication (JWT or API key)
- Endpoint returns 404 if entry does not belong to the authenticated user
- Endpoint returns empty observations if card_id is None (unlinked)
- `PriceChangeSummary` correctly calculates absolute and percent change
- `GET /cards/{id}/history` also returns the new response shape
- Period validation rejects invalid period strings with 422

## Notes

- This endpoint depends on T01's aggregation module. If T01 is not yet
  merged, the aggregation call can be stubbed (pass-through) and wired
  later. The two tasks are independent enough for parallel development.
- The PERIOD_MAP constant should be extracted to a shared location (e.g.,
  `src/api/schemas/cards.py` or a constants module) to avoid duplication
  between cards.py and collection.py routers.
