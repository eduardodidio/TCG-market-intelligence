# F33-T03 — Frontend: Updated PriceChart + Price Change Summary

**Wave:** 2 (parallel with T04, after T01+T02)
**Estimated effort:** medium

## Objective

Update the PriceChart component to support 6 period options (24h, 7d, 30d,
90d, 180d, 1y), consume the new response shape (`{observations, summary}`),
and display the price change summary.

## Files to Modify

- `frontend/src/components/PriceChart.tsx` — main changes
- `frontend/src/api/cards.ts` — update response handling
- `frontend/src/types/api.ts` — add new types

## Detailed Steps

### 1. Add TypeScript types

In `frontend/src/types/api.ts`, add:

```typescript
export interface PriceChangeSummary {
  period: string;
  price_start: number | null;
  price_end: number | null;
  absolute_change: number | null;
  percent_change: number | null;
  data_points: number;
  resolution: string;
}

export interface PriceHistoryResponse {
  observations: PriceObservation[];
  summary: PriceChangeSummary | null;
}
```

### 2. Update fetchCardHistory

In `frontend/src/api/cards.ts`, change the return type of
`fetchCardHistory` from `ApiResponse<PriceObservation[]>` to
`ApiResponse<PriceHistoryResponse>`.

### 3. Update PriceChart component

#### Period buttons

Replace the current `PERIODS` array:

```typescript
const PERIODS = [
  { label: "24h", value: "24h" },
  { label: "7d", value: "7d" },
  { label: "30d", value: "30d" },
  { label: "90d", value: "90d" },
  { label: "180d", value: "180d" },
  { label: "1y", value: "1y" },
] as const;
```

Default period: "30d" (unchanged).

#### Data consumption

Update the `useApi` call to consume `PriceHistoryResponse` instead of
`PriceObservation[]`. Extract `observations` and `summary` from the
response.

#### Price change summary display

Add a summary bar between the period buttons and the chart:

```
  [Start: R$ 12.50]  [End: R$ 15.00]  [+R$ 2.50 (+20.0%)]  [Weekly]
```

Design:
- Show below the period selector, above the chart
- `absolute_change` and `percent_change`: green text if positive, red if
  negative, slate if zero/null
- Show resolution indicator ("Daily" or "Weekly") as a subtle badge
- If summary is null or prices are null, show "No data for period"

#### Sparse data handling

- 24h period may return 0-1 points. Show "No price data for this period"
  message if 0 points.
- 7d period may have very few points. Keep existing sparse-data notice
  (threshold < 7 points).

### 4. Handle backward compatibility

During the transition, the response might be either the old format
(`PriceObservation[]`) or the new format (`PriceHistoryResponse`). Add
a type guard:

```typescript
function isHistoryResponse(data: unknown): data is PriceHistoryResponse {
  return data != null && typeof data === "object" && "observations" in data;
}
```

If the response is the old array format, wrap it:
`{ observations: data, summary: null }`.

## Acceptance Criteria

- Period selector shows 6 buttons: 24h, 7d, 30d, 90d, 180d, 1y
- "3y" button is removed
- Selecting a period fetches data and updates chart
- Price change summary displays above the chart with color coding
- Resolution badge shows "Daily" or "Weekly"
- 24h with no data shows appropriate empty message
- Zoom, Brush, and sparse-data features still work
- No visual regressions on existing chart functionality
