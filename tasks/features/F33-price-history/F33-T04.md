# F33-T04 — Frontend: Collection Detail Integration + i18n

**Wave:** 2 (parallel with T03, after T01+T02)
**Estimated effort:** small

## Objective

Update CollectionCardDetail to use the new collection history endpoint,
and add all i18n keys for the new price history UI.

## Files to Modify

- `frontend/src/pages/CollectionCardDetail.tsx` — switch to collection
  history endpoint
- `frontend/src/api/collection.ts` — add `fetchCollectionHistory`
- `frontend/src/i18n/locales/en.json` — add English keys
- `frontend/src/i18n/locales/pt-BR.json` — add Portuguese keys

## Detailed Steps

### 1. Add collection history API function

In `frontend/src/api/collection.ts`, add:

```typescript
export function fetchCollectionHistory(
  entryId: number,
  period?: string,
  currency?: string,
): Promise<ApiResponse<PriceHistoryResponse>> {
  const params: Record<string, string> = {};
  if (period) params.period = period;
  if (currency) params.currency = currency;
  return apiGet<PriceHistoryResponse>(
    `/api/v1/collection/${entryId}/history`,
    params,
  );
}
```

### 2. Update CollectionCardDetail

Currently, `CollectionCardDetail.tsx` renders `<PriceChart>` and passes
`cardId` and `currency`. The `PriceChart` internally calls the cards
history endpoint (`/cards/{cardId}/history`).

Change: pass a custom fetcher to `PriceChart` that calls the collection
history endpoint instead. Options:

- **Option A**: Make `PriceChart` accept an optional `fetchFn` prop that
  overrides the default `fetchCardHistory`. CollectionCardDetail passes
  `fetchCollectionHistory(entryId, period, currency)`.
- **Option B**: Add an `entryId` prop to `PriceChart` alongside `cardId`,
  and choose the endpoint internally.

**Recommended: Option A** — keeps PriceChart generic and reusable.

Add to `PriceChart` props:

```typescript
interface PriceChartProps {
  cardId: number;
  currency?: string;
  fetchHistory?: (period: string, currency: string) => Promise<ApiResponse<PriceHistoryResponse>>;
}
```

If `fetchHistory` is provided, use it instead of `fetchCardHistory`.
CollectionCardDetail passes:

```typescript
<PriceChart
  cardId={entry.card_id!}
  currency={currency}
  fetchHistory={(period, curr) =>
    fetchCollectionHistory(entryId, period, curr)
  }
/>
```

### 4. Remove unused price_history from CollectionCardDetail

The `CollectionCardDetail` schema currently includes `price_history` as a
flat list in the main response. Since the new history endpoint is separate,
this field can be left empty (it already defaults to `[]`) or deprecated.
Do NOT remove it from the schema to avoid breaking the API contract. Just
stop populating it in the backend (`_build_collection_detail` in
`collection.py` can skip the price series fetch). This reduces the payload
size of the detail endpoint.
