## Dev Notes

Create three files:

### 1. PRD: `docs/prd/F180-reality-fracture-catalog.md`

Minimal PRD covering:

- **Feature ID:** F180
- **Status:** planned
- **Date:** 2026-09-28
- **Problem:** Reality Fracture (FRA) releases 2026-10-02. Users want to
  browse FRA cards on the Cards page and see Liga prices before/at launch.
  The existing catalog infrastructure handles this automatically once
  Scryfall publishes bulk data, but we need an operational script and a
  re-seed.
- **Goal:** Seed FRA + FRC + TFRA + TFRC into the catalog via Scryfall
  bulk data, scan FRA/FRC prices via Liga, provide a one-click bat script.
- **Scope IN:** Re-run catalog seed, create bat script, scan FRA + FRC
  via Liga, update README.
- **Scope OUT:** No schema changes, no new API endpoints, no frontend
  changes (existing Cards page handles new sets automatically via set
  filter).
- **Success metrics:** FRA cards appear in `/cards` set filter; bat runs
  end-to-end without errors.

### 2. Architecture diagram: `docs/diagrams/F180-architecture.mmd`

Simple Mermaid flowchart showing:

```
Scryfall Bulk API --> catalog seed --> cards table (FRA/FRC/TFRA/TFRC)
Liga Magic --> catalog scan --set fra --> source_cards + price_snapshots
bats/catalog-seed-fra.bat --> orchestrates seed + scan
```

### 3. Journey diagram: `docs/diagrams/F180-journey.mmd`

BPMN-style user journey:

```
User runs catalog-seed-fra.bat
  --> catalog seed downloads Scryfall bulk (includes FRA)
  --> catalog scan --set fra fetches Liga prices
  --> catalog scan --set frc fetches Liga prices
  --> User opens /cards, selects FRA in set filter
  --> FRA cards displayed with prices
```
