# F46-T01: Backend canonize endpoint error handling

**Status: planned**

## User Story

As a user, when I canonize a card and the MYP product page is unavailable
(404, timeout, etc.), the endpoint should still return success because the
card was linked. I should see a warning that price data could not be fetched,
not a 500 error.

## Dev Notes

### File: `src/api/routers/collection.py`

**Current code (lines 529-572):**
```python
try:
    ce = row_to_collection_entry(entry)
    if ce.name_en:
        # ... search, match, get_card_details, fetch_current_price ...
finally:
    await provider.close()
```

The `try/finally` has no `except`. Any exception from `get_card_details()`
(line 545), `search_card()` (line 532), or `fetch_current_price()` (line 553)
propagates as HTTP 500.

**Required change:**

Add an `except Exception` clause between `try` and `finally` (around line 571)
that:

1. Catches any exception from the MYP interaction block.
2. Logs a warning with `log.warning("canonize_myp_fetch_failed", ...)` including
   the entry_id, card_id, and exception message.
3. Sets a local `warning` variable (e.g. `myp_warning: str | None = None`
   initialized before the try block).
4. Does NOT re-raise -- execution continues to the success return.

**Response change (line 575):**

The endpoint currently returns `_build_collection_detail(...)`. The response
schema is `ApiResponse[CollectionCardDetail]`. The `ApiResponse` wrapper
already has an optional `warnings` field (or `errors` list). Two options:

- **Option A (preferred):** Add the warning as a non-fatal error in the
  `ApiResponse.errors` list with a distinct code (e.g. `"myp_fetch_failed"`)
  so the frontend can distinguish it from a hard error. Check how `ApiResponse`
  is structured in `src/api/schemas/` and use whatever mechanism exists for
  non-fatal warnings.
- **Option B (simpler):** If `ApiResponse` does not support warnings natively,
  just return the normal success response. The frontend fix in T02 will
  re-fetch anyway, so the user will see the correct state. Log the warning
  server-side only.

Check `src/api/schemas/` for the `ApiResponse` definition before deciding.

### Lines to modify

- `src/api/routers/collection.py` line ~571: Add `except Exception as exc:`
  block before `finally`.
- `src/api/routers/collection.py` line ~575: Optionally include warning in
  response.
