# F46-T02: Frontend re-fetch after canonize + button state

**Status: planned**

## User Story

As a user, after I click "Vincular" (canonize), even if the MYP price fetch
partially fails, I should see the correct button state: the canonize button
disappears and the refresh button appears. I should see a warning message
(not a hard error) if price data could not be fetched.

## Dev Notes

### File: `frontend/src/pages/CollectionCardDetail.tsx`

**Current code (lines 81-102) -- `handleCanonize`:**

```typescript
const handleCanonize = useCallback(async () => {
  if (canonizing || !entry || entry.card_id != null) return;
  setCanonizing(true);
  setRefreshMsg(null);
  try {
    const res = await canonizeCard(entryId, ...);
    if (res.data) {
      setEntry(res.data);                          // line 90
      setRefreshMsg({ type: "success", text: ... });
    } else {
      const msg = res.errors?.[0]?.message || ...;
      setRefreshMsg({ type: "error", text: msg }); // line 94
    }
  } catch {
    setRefreshMsg({ type: "error", text: ... });   // line 97
  } finally {
    setCanonizing(false);
    ...
  }
}, [...]);
```

**Problem:** On HTTP 500 (catch branch, line 96-98), the code shows an error
message but does NOT re-fetch the entry. The entry state still has
`card_id == null` even though the backend already linked it. The canonize
button stays visible; the refresh button does not appear.

**Required changes:**

1. **Add `refetch()` call in the `catch` block (after line 97):**
   After showing the error message, call `refetch()` to reload the entry from
   the server. This will pick up the updated `card_id` and correctly toggle
   button visibility.

2. **Also add `refetch()` in the `else` branch (after line 94):**
   When the backend returns a response with errors (but HTTP 200 -- the new
   behavior from T01), the `res.data` may still be populated. But as a safety
   net, if `res.data` is null and there are errors, still call `refetch()`.

3. **Differentiate warning from error (optional, depends on T01 approach):**
   If T01 returns success with a warning, the `res.data` branch (line 89) will
   fire and `setEntry(res.data)` will work correctly. Check if
   `res.errors` has entries with a non-fatal code and show an amber warning
   instead of a red error. Something like:
   ```typescript
   if (res.data) {
     setEntry(res.data);
     if (res.errors?.length) {
       // Partial success -- card linked but MYP fetch failed
       setRefreshMsg({ type: "warning", text: t("collection.canonizePartial") });
     } else {
       setRefreshMsg({ type: "success", text: t("collection.canonizeSuccess") });
     }
   }
   ```
   This requires adding `"warning"` to the `refreshMsg.type` union and using
   `text-amber-400` for warning styling (line 295).
