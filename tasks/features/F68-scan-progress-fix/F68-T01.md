# F68-T01: Debug and fix scan progress bar real-time updates

**Status:** done
**Wave:** 0
**Parallel with:** F63-T01, F64-T01, F70-T01

## User Story

As a collector refreshing my entire collection's prices, I want to see a live
progress bar showing which cards have been scanned and how many remain, so I
know the system is working and can estimate completion time.

## Root Cause Analysis

Two bugs identified:

### Bug 1 (Major): Polling fallback shows no progress

The scan orchestrator (`src/collectors/scan.py`) only persisted `cards_processed`
to the database at the end of the scan (final `repo.update_scan_run()` call).
When SSE fails (common in production due to proxies, CORS edge cases, or
EventSource limitations) and the frontend falls back to polling
`GET /scans/{id}`, it always saw `cards_processed=0` until the scan finished.

**Fix:** Added `_persist_progress()` helper that writes current counters to the
database after each card is processed. Called in all code paths (success,
no-price, and all error handlers).

### Bug 2 (Minor): Progress never reaches 100% with failures

Failed cards incremented `cards_failed` but NOT `cards_processed`. Since the
progress bar shows `processed/total`, it could never reach 100% if any cards
failed during the scan.

**Fix:** All error handlers (NotFoundError, RateLimitError exhausted, generic
Exception) now also increment `cards_processed`, so `cards_processed` always
equals `cards_total` at completion.
