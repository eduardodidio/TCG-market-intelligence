# F86-T01: db-reset Service Function + CLI Command + Tests

**Status:** done
**Wave:** 0

## User Story

As an operator, I want a single CLI command that wipes all price data and
removes non-collection cards so I can start fresh with a clean scan, without
losing my collection, users, decks, or credits.

## Dev Notes

### 1. New function in `src/database/cleanup.py`

Add a `reset_database` function alongside the existing `cleanup_non_collection_data`.

```python
@dataclass
class ResetResult:
    """Counts of rows deleted (or that would be deleted in dry-run)."""
    prices_deleted: int = 0
    scan_runs_deleted: int = 0
    portfolio_snapshots_deleted: int = 0
    collection_errors_deleted: int = 0
    cards_deleted: int = 0
    source_cards_deleted: int = 0
    legalities_deleted: int = 0
    legality_history_deleted: int = 0
    cards_kept: int = 0
    dry_run: bool = False
    backup_path: str | None = None
```

**Logic (in order):**

1. **Safety check** -- refuse if `user_collection` is empty (same pattern as
   `cleanup_non_collection_data`).
2. **Identify collection card_ids** -- `SELECT DISTINCT card_id FROM
   user_collection WHERE card_id IS NOT NULL`. These cards survive.
3. **Count phase** (always runs, both dry-run and real):
   - `COUNT(*)` on `price_observations`
   - `COUNT(*)` on `scan_runs`
   - `COUNT(*)` on `portfolio_snapshots`
   - `COUNT(*)` on `collection_errors`
   - Cards to delete: all `cards.id` NOT IN collection_card_ids
   - Source cards to delete: `card_id IS NULL` OR `card_id` in
     cards-to-delete set
   - Legalities to delete: `card_id` in cards-to-delete set
   - Legality history to delete: `card_id` in cards-to-delete set
   - Cards kept: `len(collection_card_ids)`
4. **If dry-run** -- return ResetResult with counts, no mutations.
5. **Backup** -- call `backup_database(extract_db_path(db_url))` unless
   `skip_backup=True`.
6. **Delete phase** (single transaction):
   a. `DELETE FROM price_observations` (full truncate, no WHERE)
   b. `DELETE FROM scan_runs`
   c. `DELETE FROM portfolio_snapshots`
   d. `DELETE FROM collection_errors`
   e. `DELETE FROM legality_history WHERE card_id IN (:ids_to_delete)`
   f. `DELETE FROM card_legalities WHERE card_id IN (:ids_to_delete)`
   g. `DELETE FROM source_cards WHERE card_id IS NULL OR card_id IN (:ids_to_delete)`
   h. `DELETE FROM cards WHERE id IN (:ids_to_delete)`
   i. Commit
7. **VACUUM** -- outside transaction, reclaim space.
8. Return ResetResult with actual counts.

**Important:** The delete order matters. Delete observations/legalities/source_cards
before cards to avoid any future FK constraint issues if FK enforcement is
enabled.

### 2. New CLI command in `src/cli/main.py`

```python
@cli.command("db-reset")
@click.option("--db", default=None, help="Database URL")
@click.option("--confirm", is_flag=True, help="Required to actually delete")
@click.option("--skip-backup", is_flag=True, help="Skip pre-delete backup")
def db_reset(db, confirm, skip_backup):
    """Reset prices + remove non-collection cards. Preserves collection, users, decks."""
```

**Behavior:**

- Without `--confirm`: runs dry-run, prints table of counts, prints
  "Pass --confirm to execute."
- With `--confirm`: runs real deletion, prints counts + backup path.
- Uses `get_db_url()` for default (existing pattern from `reset-prices`).

**Output format:**

```
  DATABASE RESET PREVIEW (dry-run)

  Will delete:
    Price observations:     12,345
    Scan runs:                  42
    Portfolio snapshots:        30
    Collection errors:          15
    Cards (non-collection):    800
    Source cards:               850
    Card legalities:           800
    Legality history:          120

  Will keep:
    Collection entries:        349
    Cards (in collection):     280

  Pass --confirm to execute.
```

### 3. Tests

Add `tests/database/test_cleanup_reset.py`:

1. **test_reset_dry_run_counts** -- seed DB with cards (some in collection,
   some not), prices, scan_runs, portfolio_snapshots, legalities. Call
   `reset_database(dry_run=True)`. Assert all counts match expected. Assert
   no rows were actually deleted.

2. **test_reset_deletes_correct_data** -- same seed. Call
   `reset_database(dry_run=False, skip_backup=True)`. Assert:
   - `price_observations` table is empty
   - `scan_runs` table is empty
   - `portfolio_snapshots` table is empty
   - `collection_errors` table is empty
   - Only collection-linked cards remain in `cards`
   - Only source_cards for surviving cards remain
   - `user_collection` untouched (same count)
   - `users` untouched
   - `decks` + `deck_cards` untouched
   - `credit_balances` untouched
   - `exchange_rates` untouched

3. **test_reset_refuses_empty_collection** -- empty `user_collection`,
   assert `ValueError` raised.

4. **test_reset_creates_backup** -- call with `skip_backup=False`, assert
   `result.backup_path` is not None and file exists.

5. **test_reset_vacuum_runs** -- verify VACUUM executes (can mock or just
   confirm no error on a real SQLite file).

Add CLI test in `tests/cli/test_db_reset.py`:

6. **test_db_reset_dry_run** -- invoke CLI without `--confirm`, assert
   exit code 0, assert "dry-run" or "PREVIEW" in output.

7. **test_db_reset_confirm** -- invoke CLI with `--confirm`, assert
   exit code 0, assert "Deleted" in output.
