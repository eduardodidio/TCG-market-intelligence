# F186-T01 — Fix ticker layout and update tests

## Wave: 0
## Type: fix
## Depends on: none
## Status: planned

## User Story

As a user viewing the Dashboard, I want the movers ticker at the top to
scroll continuously so I can see all price gainers and losers without
manual interaction.

## Objective

Add `w-max` (Tailwind utility for `width: max-content`) to the inner
animated div in `MoversTicker.tsx` so the `translateX(-50%)` keyframe
animation produces visible scrolling movement. Update the test file to
verify the fix.

## Dev Notes

**Root cause (confirmed by code review):**

In `MoversTicker.tsx` line 86, the inner div has:
```
className="animate-ticker inline-flex whitespace-nowrap motion-reduce:animate-none motion-reduce:overflow-x-auto"
```

The parent div (line 79) has `overflow-hidden`. Without an explicit width,
the `inline-flex` container's computed width is constrained by the parent.
Since `translateX(-50%)` is relative to the element's own width, a
parent-constrained width means the translation does not scroll new content
into view.

**Fix:** Add `w-max` to the inner div's className. This is a standard
Tailwind utility (`width: max-content`) available in all Tailwind versions
used by this project. No Tailwind config changes needed.

**Why this works:** With `w-max`, the inner div's width becomes the full
intrinsic width of all 2N children (items are duplicated for seamless
loop). `translateX(-50%)` then shifts by exactly N items' worth of width,
creating the classic infinite-scroll marquee effect. The parent's
`overflow-hidden` clips the overflow so only one set of items is visible
at a time.

## Implementation Details

### File: `frontend/src/components/MoversTicker.tsx`

**Line 86** — Change the inner div's className from:
```tsx
className="animate-ticker inline-flex whitespace-nowrap motion-reduce:animate-none motion-reduce:overflow-x-auto"
```
to:
```tsx
className="animate-ticker inline-flex w-max whitespace-nowrap motion-reduce:animate-none motion-reduce:overflow-x-auto"
```

That is the only production code change.

### File: `frontend/src/components/__tests__/MoversTicker.test.tsx`

Add a new test case that verifies `w-max` is present on the inner animated
div. This test should be placed alongside the existing "has correct CSS
classes for hover pause" test (line 191):

```tsx
it("has w-max class for proper scroll animation width", async () => {
  mockFetchCollectionMovers.mockResolvedValue({
    data: {
      gainers: [sampleGainers[0]],
      losers: [sampleLosers[0]],
      period_days: 7,
    },
    errors: [],
  });

  render(<MoversTicker />);

  await waitFor(() =>
    expect(screen.getByTestId("movers-ticker")).toBeInTheDocument(),
  );

  const ticker = screen.getByTestId("movers-ticker");
  const innerDiv = ticker.firstElementChild as HTMLElement;
  expect(innerDiv.className).toContain("w-max");
});
```

class are correct as-is. The problem was purely in the component's layout
classes, not the animation definition.
