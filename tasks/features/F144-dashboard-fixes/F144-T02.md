# F144-T02: Add Error State to CollectionMovers

**Wave:** 0
**Parallel with:** T01
**Estimate:** S (< 30 min)

## User Story

As a user, when the collection movers API fails or times out, I want to see a
clear error message instead of an infinite loading skeleton, so I know
something went wrong and can retry.

## Dev Notes

### Current behavior (CollectionMovers.tsx)

The component uses manual `useState` + `useEffect`. On fetch failure the
`.then()` callback does not set data, but `.finally()` sets loading=false. The
result is the `!data` branch shows `movers.noData` -- this is actually correct
for empty data but does NOT distinguish errors from empty results.

### Changes

1. Add an `error` state (`useState<boolean>(false)`).
2. In the `.catch()` (currently absent), set `error = true`.
3. Add an error rendering branch between loading and empty-data checks:
   ```tsx
   if (error) {
     return (
       <div className="bg-slate-800/50 border border-red-500/30 rounded-lg p-4 text-center"
            data-testid="movers-error">
         <p className="text-sm text-red-400">{t("movers.error")}</p>
         <button onClick={retry} className="mt-2 text-xs text-indigo-400 hover:text-indigo-300">
           {t("common.retry")}
         </button>
       </div>
     );
   }
   ```
4. Add a `retry` function that resets error and re-fetches.
5. Add i18n keys:
   - `pt-BR`: `"movers.error": "Erro ao carregar movimentacoes"`
   - `en`: `"movers.error": "Failed to load movers"`

### Verify existing keys

Check if `common.retry` already exists in the i18n files. If not, add:
- `pt-BR`: `"retry": "Tentar novamente"` under `common`
- `en`: `"retry": "Try again"` under `common`
