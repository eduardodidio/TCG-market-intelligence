# F144-T03: Optimize get_movers() — Eliminate N+1 Queries

**Wave:** 1
**Depends on:** nothing (but scheduled after Wave 0 to keep review scope manageable)
**Estimate:** M (1-2 hours)

## User Story

As a user viewing the Market page, I want movers to load within a few seconds
instead of timing out, so I can see which cards are gaining or losing value.

## Problem Analysis

`repository.py:get_movers()` (lines 962-1034) performs:

1. `select(CardRow)` -- loads ALL 105k+ cards into memory
2. For each card: `select(SourceCardRow).where(card_id == card.id)` -- 105k queries
3. For each source_card: 2x `select(PriceObservationRow)` (earliest + latest) -- 200k+ queries

Total: ~300k+ individual SQL queries per call. On Neon PostgreSQL with network
latency, this takes minutes and times out.

## Solution

Replace the entire method body with a single SQL query that:

1. JOINs `cards` -> `source_cards` -> `price_observations`
2. Uses subqueries or window functions to get earliest (after cutoff) and latest
   price per card in one pass
3. Computes change_pct in SQL or in a thin Python post-processing step
4. Returns only the top N gainers and losers

### Recommended SQL approach

```sql
WITH card_prices AS (
    SELECT
        sc.card_id,
        po.external_id,
        po.median_price,
        po.observed_at,
        ROW_NUMBER() OVER (
            PARTITION BY sc.card_id
            ORDER BY po.observed_at ASC
        ) AS rn_asc,
        ROW_NUMBER() OVER (
            PARTITION BY sc.card_id
            ORDER BY po.observed_at DESC
        ) AS rn_desc
    FROM source_cards sc
    JOIN price_observations po
        ON po.external_id = sc.external_id
        AND po.source IN (sc.source, 'jsonld_snapshot')
    WHERE po.median_price IS NOT NULL
      AND po.observed_at >= :cutoff
),
earliest AS (
    SELECT card_id, median_price AS price_start
    FROM card_prices WHERE rn_asc = 1
),
latest AS (
    SELECT card_id, median_price AS price_end
    FROM card_prices WHERE rn_desc = 1
),
movers AS (
    SELECT
        e.card_id,
        c.name_en,
        c.name_pt,
        c.set_code,
        e.price_start,
        l.price_end,
        ((l.price_end - e.price_start) / e.price_start) * 100 AS change_pct
    FROM earliest e
    JOIN latest l ON l.card_id = e.card_id
    JOIN cards c ON c.id = e.card_id
    WHERE e.price_start > 0
      AND e.price_start != l.price_end
)
-- Get top gainers and losers in separate queries or UNION
SELECT * FROM movers ORDER BY change_pct DESC LIMIT :limit
UNION ALL
SELECT * FROM movers ORDER BY change_pct ASC LIMIT :limit
```

### SQLAlchemy implementation

Use `text()` for the CTE query or build it with SQLAlchemy Core expressions.
Given the complexity, raw SQL via `text()` wrapped in `session.execute()` is
the pragmatic choice. The existing index `ix_price_obs_extid_date` on
`(external_id, observed_at)` already covers the JOIN and ORDER BY.

### Important edge cases

- The `latest` query in current code does NOT filter by cutoff (it finds the
  most recent price ever). Preserve this behavior: earliest >= cutoff, latest
  = most recent overall. Adjust the CTE accordingly -- remove the cutoff WHERE
  for the `rn_desc` window or use two separate CTEs.
- Actually, looking more carefully: the current code applies `cutoff` only to
  the `early` query, not to `late`. The `late` query just finds the most recent
  observation overall. The optimized query MUST replicate this: earliest price
  after cutoff vs. latest price ever.

### Revised approach for the asymmetric cutoff

```python
# CTE 1: earliest price AFTER cutoff per card
earliest_cte = (
    select(
        SourceCardRow.card_id,
        PriceObservationRow.median_price.label("price_start"),
        func.row_number().over(
            partition_by=SourceCardRow.card_id,
            order_by=PriceObservationRow.observed_at.asc()
        ).label("rn")
    )
    .join(PriceObservationRow, ...)
    .where(PriceObservationRow.observed_at >= cutoff, ...)
).cte("earliest")

# CTE 2: latest price EVER per card
latest_cte = (
    select(
        SourceCardRow.card_id,
        PriceObservationRow.median_price.label("price_end"),
        func.row_number().over(
            partition_by=SourceCardRow.card_id,
            order_by=PriceObservationRow.observed_at.desc()
        ).label("rn")
    )
    .join(PriceObservationRow, ...)
    .where(PriceObservationRow.median_price.isnot(None))
).cte("latest")
```

### Return type

Keep the same return signature: `tuple[list[tuple], list[tuple]]` where each
tuple is `(card_id, name_en, name_pt, set_code, price_start, price_end, change_pct)`.
