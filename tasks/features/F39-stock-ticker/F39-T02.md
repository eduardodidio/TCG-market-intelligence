# F39-T02 — API Client + Types + useTickerData Hook

**Wave:** 1 (parallel with T01)
**Depends on:** F36 (trending API endpoints must exist)
**Creates:** `frontend/src/hooks/useTickerData.ts`
**Modifies:** `frontend/src/api/trending.ts`, `frontend/src/types/api.ts`

## Objective

Create the data layer for the ticker: a TypeScript type for ticker items,
an API client function that fetches and merges gainers + losers, and a
custom hook that provides auto-refreshing ticker data.

## Deliverables

### 1. Add `TickerItemData` type to `frontend/src/types/api.ts`

```typescript
export interface TickerItemData {
  card_id: number;
  name_en: string;
  name_pt: string | null;
  set_code: string | null;
  price_end: number;
  change_pct: number;
  direction: "up" | "down";
  currency: string;
}
```

This is a slim projection of `TrendingCardEntry` (from F36) with only the
fields the ticker needs.

### 2. Add `fetchTickerData()` to `frontend/src/api/trending.ts`

```typescript
export async function fetchTickerData(
  currency: string,
  signal?: AbortSignal,
): Promise<TickerItemData[]>
```

Implementation:
1. Call `GET /market/trending/gainers?period=7d&limit=10&currency={currency}`
   and `GET /market/trending/losers?period=7d&limit=10&currency={currency}`
   in parallel using `Promise.all`.
2. Map each `TrendingCardEntry` to `TickerItemData`, setting
   `direction: "up"` for gainers and `direction: "down"` for losers.
3. Interleave results: take one gainer, one loser, alternating, until
   both lists are exhausted. If one list is shorter, append remaining
   items from the longer list at the end.
4. Return the interleaved array.

Use `apiGet` from `../api/client.ts`. Handle errors gracefully: if either
request fails, return an empty array (the ticker simply won't show).

### 3. Create `frontend/src/hooks/useTickerData.ts`

```typescript
export function useTickerData(): {
  items: TickerItemData[];
  loading: boolean;
}
```

Implementation:
1. Get `currency` from `useCurrency()` hook.
2. On mount (and when `currency` changes), call `fetchTickerData(currency)`.
3. Set up a `setInterval` of 300,000ms (5 minutes) that re-fetches data.
4. Use `AbortController` for cleanup on unmount and before each new fetch.
5. Store items in state. On re-fetch, replace items seamlessly (no
   loading flash -- keep previous items visible while fetching).
6. `loading` is only `true` on the initial fetch (not on interval
   refreshes).
7. On error, keep previous items (or empty array if no previous data).

## Key Details

- The hook does NOT use the generic `useApi` hook because `useApi` expects
  a single `ApiResponse<T>` return, while this needs to merge two API
  calls. A purpose-built hook is simpler and cleaner.
- The 5-minute interval matches the expected data freshness from F37
  (scheduled scans run every 15-30 min, so 5-min polling is sufficient
  without being wasteful).
- `period=7d` is hardcoded (ticker shows short-term movers). This is not
  user-configurable.
- `limit=10` per direction = up to 20 items total in the ticker.
