# F74-T01 — Backend: DB Schema + Admin Endpoints

**Status:** planned
**Wave:** 1
**Depends on:** —

## User Story

As an admin, I want to create new users with a temporary password and soft-delete users from the admin panel.

## Dev Notes

### Files to modify

1. **`src/database/models.py`** — Add to UserRow:
   ```python
   password_expires_at: Mapped[datetime | None] = mapped_column(DateTime)
   ```
   Run migration: ALTER TABLE users ADD COLUMN password_expires_at DATETIME

2. **`src/api/schemas/admin.py`** — Add schemas:
   ```python
   class CreateUserRequest(BaseModel):
       email: str
       display_name: str | None = None

   class CreateUserResponse(BaseModel):
       user_id: int
       email: str
       display_name: str | None
       temporary_password: str  # shown ONCE to admin
   ```

3. **`src/api/routers/admin.py`** — Add endpoints:

   **POST /admin/users** (create user):
   - Validate email not already registered
   - Generate temporary password: `secrets.token_urlsafe(12)` (16 chars, safe for display)
   - Hash the password with bcrypt
   - Set `password_expires_at = datetime.now()` (immediately expired)
   - Call `repo.create_user(email, display_name, auth_provider="email", password_hash=hashed)`
   - Then `repo.update_user(user.id, password_expires_at=datetime.now())`
   - Grant initial credits (e.g., 50 via CreditService.grant)
   - Return CreateUserResponse with the temporary_password in plaintext

   **DELETE /admin/users/{user_id}** (soft-delete):
   - Cannot delete self: `if user_id == admin.id: raise HTTPException(400, "Cannot delete yourself")`
   - Verify target exists
   - `repo.update_user(user_id, is_active=0)`
   - Return success

4. **`src/database/repository.py`** — Ensure `update_user` can handle `password_expires_at` field (it's generic via **kwargs, should work already)

### Key decisions
- Temporary password is `secrets.token_urlsafe(12)` — strong enough for first access
- Password expires immediately (`password_expires_at = now()`)
- Soft-delete sets `is_active=0` (existing login already checks `is_active`)
- Initial credits: 50 (same as seed user)

## Testing

- POST /admin/users creates user with hashed password
- POST /admin/users returns temporary password in response
- POST /admin/users sets password_expires_at to now
- POST /admin/users rejects duplicate email (409)
- DELETE /admin/users/{id} sets is_active=0
- DELETE /admin/users/{self} returns 400
- DELETE /admin/users/{nonexistent} returns 404
- Non-admin gets 403 on both endpoints
