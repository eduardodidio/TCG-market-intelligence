# F36-T02 — Backend: Batch Price Query in Repository

**Wave:** 1 (parallel with T01)
**Depends on:** F34 shipped
**Modifies:** `src/database/repository.py`

## Objective

Add an efficient batch query method to Repository that loads price series
for all cards with observations in a single query, replacing the N+1
pattern used by `get_movers()`. This is the data-loading foundation for
the trending service.

## Steps

### 1. Add `get_trending_price_data()` to Repository

```python
def get_trending_price_data(
    self, period_days: int
) -> dict[int, list[tuple[date, Decimal]]]:
    """Load price series for all cards with observations in the period.

    Returns a dict mapping card_id to a list of (date, median_price)
    tuples, sorted by date ascending. Only cards with at least one
    non-null median_price observation are included.
    """
```

Implementation:
1. Compute `cutoff = date.today() - timedelta(days=period_days)`.
2. Single query joining `source_cards` and `price_observations`:

```sql
SELECT sc.card_id, po.observed_at, po.median_price
FROM source_cards sc
JOIN price_observations po
  ON po.external_id = sc.external_id
  AND po.source IN (sc.source, 'jsonld_snapshot')
WHERE sc.card_id IS NOT NULL
  AND po.observed_at >= :cutoff
  AND po.median_price IS NOT NULL
ORDER BY sc.card_id, po.observed_at ASC
```

3. Group results into a `dict[int, list[tuple[date, Decimal]]]`.
4. Deduplicate within each card: if multiple observations exist for the
   same date, keep the one with the highest median_price (conservative
   approach matching current behavior).

### 2. Add `get_card_info_batch()` to Repository

```python
def get_card_info_batch(
    self, card_ids: list[int]
) -> dict[int, tuple[str, str | None, str | None, str | None]]:
    """Load card metadata for a batch of card IDs.

    Returns dict mapping card_id to (name_en, name_pt, set_code,
    collector_number).
    """
```

Implementation: single `SELECT` from `cards` table with
`CardRow.id.in_(card_ids)`.

This avoids the trending service needing to do per-card lookups when
building the API response.

## Acceptance Criteria

- [ ] `get_trending_price_data(period_days)` returns correct dict structure

- [ ] Results are sorted by date ascending within each card
- [ ] Duplicate dates per card are deduplicated (keep max price)
