## Objective

Write comprehensive tests for all new code introduced in F36. Cover
pure functions, service layer, API endpoints, and frontend components.

## Steps

### 1. Backend: pure function tests (`tests/unit/analytics/test_trending.py`)

Test `compute_trending_score()`:
- Returns None for fewer than 2 data points.
- Returns None for zero start price.
- Returns None for zero price change.
- Correct `direction` ("up" for increase, "down" for decrease).
- Correct `change_pct` and `change_abs` calculation.
- Correct `consistency` for various patterns:
  - All days up: consistency = 1.0.
  - Alternating up/down: consistency near 0.5.
  - All days down: consistency = 1.0 (for "down" direction).
- Correct `observation_density`: 10 obs in 30 days = 0.333.
- Density capped at 1.0 (e.g., 30 obs in 10 days).
- Recency bonus: latest within 2 days = full bonus; > 7 days = zero.
- Composite score within 0-100 range.
- Deterministic with `reference_date` parameter.
- Deduplication: two observations on same date keeps one.

Test `rank_trending()`:
- Filters by direction (only "up" cards when direction="up").
- Filters by `min_observations` (excludes cards with < 3 obs).
- Filters by `min_price` (excludes sub-$1 cards).
- Filters by `min_consistency` (excludes inconsistent cards).
- Sorts by composite_score descending.
- Applies limit correctly.
- Returns empty list when all cards filtered out.

### 2. Backend: service tests (`tests/unit/services/test_trending_service.py`)

Test `TrendingService`:
- Returns `TrendingResponse` with correct structure.
- Calls `get_trending_price_data()` and `get_card_info_batch()`.
- Cache hit returns cached data with `cached=True`.
- Cache miss computes fresh data with `cached=False`.
- Cache expires after TTL (mock datetime).
- `invalidate_cache()` clears the cache.
- Currency conversion applied to price fields.
- Empty database returns empty card list (no errors).

Use mocks for Repository and CurrencyConverter.

### 3. Backend: endpoint tests (`tests/unit/api/test_trending_endpoint.py`)

Test `GET /market/trending/gainers`:
- Returns 200 with valid `TrendingResponse` envelope.
- Period param defaults to "30d".
- Invalid period returns 422.
- Currency param works (BRL, USD, PILA).
- Limit param respected (ge=1, le=50).

Test `GET /market/trending/losers`:
- Same validations as gainers but direction = "down".

Use FastAPI TestClient with mocked TrendingService dependency.

### 4. Backend: repository tests

Add tests for `get_trending_price_data()` and `get_card_info_batch()`
to the appropriate existing test file (or create new):
- Returns correct dict structure with test data.
- Empty database returns empty dict.
- Only non-null median_price observations included.
- Only cards with card_id in source_cards included.
- Date cutoff filters correctly.
- Deduplication works (same date keeps max price).
