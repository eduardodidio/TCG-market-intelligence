# F99-T02 -- Composite Indexes on Hot Query Paths

**Wave:** 0 (parallel with T01)
**Depends on:** nothing

## User Story

As a user, I want collection and deck queries to be fast, even as my
data grows, so that pages load quickly.

## Problem

Several hot query paths use multi-column WHERE clauses but only have
single-column indexes. SQLite can only use one index per table scan,
so composite indexes on the actual query patterns will improve performance.

## Dev Notes

### New composite indexes to add in models.py

1. **user_collection (user_id, card_id)** -- used by `get_latest_prices_batch`
   join, trending collection-only queries, and ban engine queries.
   Name: `ix_user_collection_user_card`

2. **deck_cards (deck_id, card_id)** -- used by `get_deck_cards_with_ownership`
   and deck valuation queries.
   Name: `ix_deck_cards_deck_card`

3. **price_observations (external_id, observed_at DESC)** -- used by
   `get_latest_prices_batch` (most frequent query in the app, runs once
   per card in collection). The DESC on observed_at helps the `LIMIT 1`
   pattern.
   Name: `ix_price_obs_extid_date`

4. **source_cards (card_id, source)** -- used by `get_latest_prices_batch`
   inner loop (fetches source_cards by card_id then queries each source).
   Name: `ix_source_card_cardid_source`

### Implementation

- Add indexes to `__table_args__` in the respective model classes
- SQLAlchemy `create_all` handles CREATE INDEX IF NOT EXISTS, so this is
  safe for existing databases
- Do NOT remove existing single-column indexes (they serve other queries)

### Verification

After adding, run `EXPLAIN QUERY PLAN` on the key queries to confirm
index usage. Document results in the PR description.

## Testing

- Unit test: verify indexes exist after `create_all` by inspecting
  `inspect(engine).get_indexes(table_name)`
- Unit test: verify existing single-column indexes still exist (no
  accidental removal)
- Performance test (manual, not automated): run `get_latest_prices_batch`
  with 100+ card_ids, compare wall-clock time before/after
