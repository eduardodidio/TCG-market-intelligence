# F99-T01 -- Orphan Record Cleanup (Pre-FK Preparation)

**Wave:** 0 (parallel with T02)
**Depends on:** nothing

## User Story

As a developer, I need to clean orphan records from the database so that
FK constraints can be added without violating referential integrity.

## Problem

Several tables have `card_id` values pointing to non-existent `cards.id`
rows. Adding FK constraints on these columns will fail if orphan references
exist. This task identifies and cleans them before the migration.

## Dev Notes

### Tables to clean (card_id references)

1. **source_cards.card_id** -- orphans where card_id points to a
   non-existent cards.id. SET NULL (keep the source_card, just unlink it).
2. **user_collection.card_id** -- orphans where card_id points to a
   non-existent cards.id. SET NULL.
3. **deck_cards.card_id** -- orphans where card_id points to a
   non-existent cards.id. SET NULL.
4. **card_legalities.card_id** -- orphans where card_id points to a
   non-existent cards.id. DELETE the row (legality without a card is
   meaningless).
5. **legality_history.card_id** -- same as above, DELETE.
6. **evaluation_entries.card_id** -- orphans where card_id points to a
   non-existent cards.id. SET NULL.

### Additional FK references to clean

7. **deck_cards.deck_id** -- orphans where deck_id points to a
   non-existent decks.id. DELETE the row.
8. **credit_balances.user_id** -- orphans where user_id points to a
   non-existent users.id. DELETE the row.
9. **credit_transactions.user_id** -- same, DELETE.

### Implementation

Create a function `cleanup_orphan_references(db_url, *, dry_run=True)`
in `src/database/cleanup.py` that:

1. Opens a session
2. For each table above, runs a LEFT JOIN to find orphans:
   ```sql
   SELECT sc.id FROM source_cards sc
   LEFT JOIN cards c ON sc.card_id = c.id
   WHERE sc.card_id IS NOT NULL AND c.id IS NULL
   ```
3. In dry_run mode, returns counts per table
4. In execute mode, performs the SET NULL / DELETE operations
5. Creates a backup before any mutations (reuse `backup_database`)
6. Runs in a single transaction for atomicity

Return a dataclass `OrphanCleanupResult` with per-table counts.

### CLI integration

Add a `cleanup-orphans` subcommand to the CLI that calls this function,
with `--dry-run` (default True) and `--execute` flags.

## Testing

- Unit test: create DB with orphan records in each table, run cleanup,
  verify orphans are gone and valid records are untouched
- Unit test: dry_run mode returns correct counts without modifying data
- Unit test: empty database (no orphans) returns all-zero counts
- Unit test: refuse to run without backup unless --skip-backup passed
