# F99-T05 -- Fix N+1 in link_orphan_source_cards

**Wave:** 1 (parallel with T03, T04)
**Depends on:** nothing (pure logic fix)

## User Story

As a developer, I want orphan source card linking to run in O(1) queries
instead of O(N) so that large collections do not suffer slow sync times.

## Problem

`Repository.link_orphan_source_cards()` (line 302 of repository.py)
fetches all orphan source_cards, then issues one `SELECT` per orphan to
find the matching card. With 300+ cards, this is 300+ individual queries
inside a single session.

## Dev Notes

### Current code (N+1 pattern)

```python
orphans = session.execute(
    select(SourceCardRow).where(SourceCardRow.card_id.is_(None))
).scalars().all()
for sc in orphans:
    card = session.execute(
        select(CardRow).where(
            CardRow.game == "magic",
            CardRow.set_code == sc.set_code,
            CardRow.collector_number == sc.collector_number,
        )
    ).scalar_one_or_none()
    if card:
        sc.card_id = card.id
```

### Replacement (single UPDATE with JOIN)

Use a single correlated UPDATE statement:

```python
from sqlalchemy import update

stmt = (
    update(SourceCardRow)
    .where(
        SourceCardRow.card_id.is_(None),
        SourceCardRow.set_code.is_not(None),
        SourceCardRow.collector_number.is_not(None),
    )
    .values(
        card_id=select(CardRow.id)
        .where(
            CardRow.game == "magic",
            CardRow.set_code == SourceCardRow.set_code,
            CardRow.collector_number == SourceCardRow.collector_number,
        )
        .correlate(SourceCardRow)
        .scalar_subquery()
    )
)
result = session.execute(stmt)
linked = result.rowcount
```

**SQLite note:** SQLite supports correlated subqueries in UPDATE SET
clauses. This produces a single UPDATE statement that the query planner
can optimize with the existing `ix_card_game_set` index.

However, this will set `card_id = NULL` for orphans that have no matching
card (the subquery returns NULL). To avoid overwriting NULL with NULL
(harmless but confusing rowcount), add a secondary WHERE filter:

```python
.where(
    SourceCardRow.card_id.is_(None),
    SourceCardRow.set_code.is_not(None),
    SourceCardRow.collector_number.is_not(None),
    select(CardRow.id).where(
        CardRow.game == "magic",
        CardRow.set_code == SourceCardRow.set_code,
        CardRow.collector_number == SourceCardRow.collector_number,
    ).correlate(SourceCardRow).exists(),
)
```

### Return value

The method currently returns the count of linked rows. The new
implementation should return `result.rowcount` which gives the same
semantics.
