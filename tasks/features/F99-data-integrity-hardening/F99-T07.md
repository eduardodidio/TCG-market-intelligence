# F99-T07 -- Exchange Rate Fallback to Nearest Historical Rate

**Wave:** 2 (parallel with T06)
**Depends on:** nothing (pure logic fix)

## User Story

As a user viewing prices in USD, I want to see converted prices even on
weekends and holidays (when BCB does not publish rates) so that the
dashboard does not show blank values.

## Problem

`CurrencyConverter._get_rate()` calls `repo.get_closest_rate(target_date)`
which returns the closest rate ON OR BEFORE the target date. This works
for recent dates but returns `None` when:

1. The DB has no rates at all (new deployment)
2. The target_date is before the earliest stored rate
3. There is a gap of many days (e.g., extended holiday + failed fetches)

When `_get_rate` returns `None`, `convert()` returns `None`, and the
frontend shows no price -- a confusing UX.

## Dev Notes

### Current behavior

```python
def get_closest_rate(self, target_date: date) -> ExchangeRateRow | None:
    return session.execute(
        select(ExchangeRateRow)
        .where(ExchangeRateRow.rate_date <= target_date)
        .order_by(ExchangeRateRow.rate_date.desc())
        .limit(1)
    ).scalar_one_or_none()
```

### New behavior

1. First, try the existing query (rate on or before target_date)
2. If no result, try the closest rate AFTER target_date (within 7 days):
   ```sql
   SELECT * FROM exchange_rates
   WHERE rate_date > :target_date
     AND rate_date <= :target_date + 7
   ORDER BY rate_date ASC
   LIMIT 1
   ```
3. If still no result, return `None` (truly no data)

### Implementation

Update `Repository.get_closest_rate` to accept an optional
`max_gap_days: int = 7` parameter:

```python
def get_closest_rate(
    self, target_date: date, *, max_gap_days: int = 7
) -> ExchangeRateRow | None:
    with Session(self.engine) as session:
        # Try on or before
        row = session.execute(
            select(ExchangeRateRow)
            .where(ExchangeRateRow.rate_date <= target_date)
            .order_by(ExchangeRateRow.rate_date.desc())
            .limit(1)
        ).scalar_one_or_none()

        if row is not None:
            # Validate gap
            gap = (target_date - row.rate_date).days
            if gap <= max_gap_days:
                return row

        # Try after (for dates before earliest stored rate)
        upper_bound = target_date + timedelta(days=max_gap_days)
        row = session.execute(
            select(ExchangeRateRow)
            .where(
                ExchangeRateRow.rate_date > target_date,
                ExchangeRateRow.rate_date <= upper_bound,
            )
            .order_by(ExchangeRateRow.rate_date.asc())
            .limit(1)
        ).scalar_one_or_none()
        return row
```

### CurrencyConverter changes

The `CurrencyConverter.convert` method currently returns `None` when no
rate is found. Add a `fallback_to_brl: bool = True` parameter:

- When `fallback_to_brl=True` and rate is `None`, return the original
  BRL value (with a log warning) instead of `None`
- This prevents blank prices on the frontend
- Log the fallback so it is visible in error tracking

### Cache consideration

The existing `_cache` in CurrencyConverter caches by exact date. The
fallback lookup may return a rate for a different date. Cache the mapping
`target_date -> rate` (not `rate_date -> rate`) so subsequent lookups
for the same target_date are fast.

## Testing

- Unit test: rate exists for exact date -- returns it (existing behavior)
- Unit test: rate exists 2 days before target -- returns it
- Unit test: rate exists 8 days before target -- returns None (beyond gap)
- Unit test: no rate before but rate exists 3 days after -- returns it
- Unit test: no rate before, rate exists 10 days after -- returns None
- Unit test: completely empty exchange_rates table -- returns None
- Unit test: CurrencyConverter fallback_to_brl returns BRL value when
  no rate available
- Unit test: CurrencyConverter caches the fallback result correctly
