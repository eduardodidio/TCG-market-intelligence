## User Story

As a collector importing a BRL export (or a USD one), I want each price stored as BRL acquisition price in the right currency, so that my collection value and P&L are correct right after import.

## Implementation details

1. Read the header row → `resolve_columns`. Read all rows once into a list (the files are small).
2. `detection = detect_file_currency(cmap, rows, currency)`.
3. Per row: existing field mapping via `cmap.fields.get(...)`. Price → `parse_money` → `to_brl(amount, row_ccy, today, rate_lookup or (lambda _d: None))`.
   Count `priced` and `converted`, and collect `price_warnings` (row number + reason, capped at 20).
4. `dry_run=True` → return the summary without opening a Session.
5. Return the dict with the new keys listed in `_brief/03-csv-import.md` (`exchange_rate` = str of the rate used, or None).
6. Tests in `tests/collection/test_importer_currency.py` use a tmp SQLite engine (pattern from `test_importer_transaction.py`)
   and a fake `rate_lookup` returning `Decimal("5.40")`.

## Test scenarios

- Happy: each BRL fixture and each USD fixture (parametrized expected stored values).
- Override: user BRL on the USD file; user USD on the BRL file (10,00 → 54.00).
- Edge: empty price cell → None, not counted as priced; quantity `""` → 1, `"2.0"` → 2; BOM header.
- Error: invalid quantity `abc` → row skipped; unparseable price `abc` → price None + warning, row imported; EUR symbol → warning `unsupported_currency`.
- Boundary: 25 bad prices → `price_warnings` has 20 entries + `"... and 5 more"`; dry_run on an empty CSV (header only) → zeros.

## Notes from Developer

- `src/collection/converter.py::row_to_collection_entry` reviewed: no monetary fields present
  (`CollectionEntry` only carries `set_code`, `collector_number`, `name_en`, `name_pt`). No change made,
  covered by a regression test asserting "price" does not appear in its source.
- Row currency precedence implemented as: user `choice` (BRL/USD) wins for every row → else per-row
  `currency` column value (if BRL/USD or a detectable symbol) → else a symbol detected in the price cell
  itself → else the file-level `detection.currency` fallback. Unsupported currencies (e.g. a bare `EUR`
  code/symbol with no BRL/USD signal) are passed through to `to_brl`, which drops the price and adds an
  `unsupported_currency` warning rather than silently defaulting to BRL.
- `dry_run=True` returns `imported` as the count of rows that would be inserted (post `skipped` filtering)
  without touching `Base.metadata.create_all`/`Session` at all, so a dry run against a fresh (non-existent)
  DB file does not create any tables either.
