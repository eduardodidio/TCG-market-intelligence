## User Story

As a user adding cards by text, I want to type `2 Lightning Bolt [m10] NM R$12,50` or `US$3.10`, so that I record what I paid in the correct currency.

## Objective

Extend `parse_batch_text` so `ParsedLine` carries `price` and `price_currency`.

## Dev Notes

Veja `_brief/00-overview.md`, `_brief/01-money-parsing.md` and `_brief/04-purchases-batch.md`.

- File: `src/collection/batch_parser.py` (145 lines). `ParsedLine` dataclass ~L44, `_parse_single_line` ~L80.
- The price token must be extracted and **removed from the text before name extraction**, as `[set]` is.

- `acquisition_price` is **always BRL**. Never store a USD amount as BRL.

## Implementation details

- `_PRICE_RE = re.compile(r"(?:(R\$|US\$|U\$|\$|BRL|USD)\s?|@\s?)(\d[\d.,]*)", re.IGNORECASE)`. Take the **last** match.
- Use `parse_money(token, hint=<symbol currency>)`. `@` gives `price_currency=None` (BRL assumed downstream).
- Invalid number after a symbol → `error="Invalid price: <token>"`.

## Test scenarios

- Happy: BRL token, USD token, `$` bare, `@` token, token before and after `[set]`.
- Edge: two price tokens → last wins; `R$ 12,50` with a space; lower-case `r$`.
- Error: `R$abc` → the symbol is not followed by a digit, so there is no match and the name keeps the text. Document that. `R$1.2.3,4,5` → error `Invalid price`.
- Boundary: `R$0,01`; `R$1000000,01` → error (above the limit).
