## User Story

As a collector importing prices written as `R$ 1.234,56` or `US$ 1,234.56`, I want the amount and its currency parsed correctly, so that a Brazilian-formatted value is never misread as a US one (or the reverse).

## Objective

Implement `src/currency/money.py` with `detect_symbol`, `parse_money`, and `number_format_hint` as pure functions.

- `src/currency/money.py` with the three functions exactly as in the shard. Module docstring lists examples.

## Acceptance criteria

- [ ] `parse_money("R$ 1.234,56") == (Decimal("1234.56"), "BRL")`
- [ ] `parse_money("US$ 1,234.56") == (Decimal("1234.56"), "USD")`; `parse_money("$0.50") == (Decimal("0.50"), "USD")`
- [ ] `parse_money("12,50") == (Decimal("12.50"), None)`; `parse_money("12.50") == (Decimal("12.50"), None)`
- [ ] Ambiguous `1.234` / `1,234` resolved by `hint` as documented
- [ ] `parse_money("")`, `None`, `"abc"`, `"-5"` → amount None
- [ ] `detect_symbol("€ 3,00") == "EUR"`
- [ ] 100% line coverage of `money.py`

## Test scenarios

- Happy: `R$ 9,75`, `R$9,75`, `BRL 9,75`, `US$ 3.10`, `U$ 3.10`, `USD 3.10`, `$3.10`, `3,10`, `3.10`.
- Edge: NBSP between symbol and number; `R$ 1.234,56 (unid.)`; `1.234.567,89`; `1,234,567.89`; leading/trailing spaces; lower-case `r$`.
- Ambiguity: `1.234` with hint BRL → 1234, with hint USD/None → 1.23 (after 0.01 quantize, documented); `1,234` with hint USD → 1234, else 1.23.
- Error: empty, None, `abc`, `R$`, `--`, negative, `1e5` → amount None (no exception).
- Boundary: `0,00` → Decimal("0.00"); `1000000,00` → valid; `1000000,01` → None; half-up `0,005` → `0.01`.
- `number_format_hint`: `12,50`→BRL, `1.234,56`→BRL, `12.50`→USD, `1,234.56`→USD, `12`→None.
