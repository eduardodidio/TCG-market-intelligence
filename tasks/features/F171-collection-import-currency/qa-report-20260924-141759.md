## 3. New test gap found (non-blocking, matches TechLead's finding)

TechLead's review flagged that `batch_add.py:82-96` gates the whole conversion path on `rate_lookup is None` *before* checking the entry's currency, so a caller passing `rate_lookup=None` with a **BRL**-priced entry would incorrectly drop the price and emit a misleading "no exchange rate available" warning — even though `to_brl` itself never needs a rate for BRL. Today's only caller (`POST /collection/batch`) always passes a real `rate_lookup`, so this is not user-reachable yet, but it is untested. I did not add a test for this because:
- It is not reachable from any current caller (confirmed: `collection.py:1790` always supplies `rate_lookup`).
- Fixing it (widening `to_brl` to always be called with a `rate_lookup or (lambda _d: None)` fallback, per TechLead's suggestion) is a `batch_add.py` code change beyond QA's mandate to add missing *tests* for existing acceptance criteria — no AC requires this specific untested combination, and TechLead already recorded it as a retrospective lesson for the next feature to pick up.
- Recommend a follow-up task (not blocking F171 promotion) to add the regression test alongside the one-line `to_brl` fallback fix.
