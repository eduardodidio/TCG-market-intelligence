# Task F85-T07 — CLI Error Cleanup Command

**Feature:** F85
**Wave:** 2
**Type:** backend
**Depends on:** F85-T02 (error logger), F85-T03 (retention utils)
**Status:** done

## User Story

As an operator, I want a CLI command to clean up old error logs, so that
disk usage stays bounded and I can run cleanup on demand or via cron.

## Objective

Add an `error-cleanup` Click command to the CLI that runs retention
cleanup on both the JSONL file and the database.

## Dev Notes

- Relevant file: `src/cli/main.py`
- New command: `error-cleanup`
  - Options:
    - `--max-age-days` (default: from `get_error_max_age_days()`)
    - `--max-entries` (default: from `get_error_max_entries()`)
    - `--dry-run` (show what would be removed without removing)
  - Behavior:
    1. Log current counts (DB rows, JSONL lines)
    2. If not dry-run: call `cleanup_db(repo, max_age_days, max_entries)`
    3. If not dry-run: call `cleanup_jsonl(file_path, max_age_days, max_entries)`
    4. Log results (removed count from each)
  - Use structlog for output (matches existing CLI commands)
- Follow existing CLI command patterns (see `db-backup`, `db-cleanup`)

- **Dry run:** Run with --dry-run, verify no entries removed
- **Custom options:** --max-age-days=7 --max-entries=100 respected
