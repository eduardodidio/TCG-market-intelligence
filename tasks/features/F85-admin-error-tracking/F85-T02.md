# Task F85-T02 — Error Logger Service

**Feature:** F85
**Wave:** 0
**Type:** backend
**Depends on:** (none — uses dict interface, not repo directly)
**Status:** done

## User Story

As a developer, I want a single service I can call to log structured
errors, so that error capture is consistent across the codebase.

## Objective

Create `src/errors/logger.py` with an `ErrorLogger` class that captures
exception context (traceback, module, function, line) and optional request
context, then delegates to pluggable sinks (DB insert + JSONL file).

## Dev Notes

- New module: `src/errors/__init__.py`, `src/errors/logger.py`
- `ErrorLogger` class:
  - Constructor: `__init__(self, sinks: list[Callable[[dict], None]])`
  - Method: `capture(exc: BaseException, *, level: str = "ERROR", request_context: dict | None = None, extra: dict | None = None) -> str`
    - Extracts: `type(exc).__name__`, `str(exc)`, `traceback.format_exception(exc)`, caller module/function/line from traceback
    - Builds the error dict (see F85-README for schema)
    - Generates UUID id
    - Calls each sink with the error dict
    - Returns the error id
  - Method: `capture_warning(message: str, *, module: str | None = None, extra: dict | None = None) -> str`
    - For non-exception warnings (level=WARNING, no traceback)
- Sink interface: any `Callable[[dict], None]`
- Two sink factories (in same module):
  - `make_db_sink(repo: Repository) -> Callable` — calls `repo.insert_error_log(error_dict)`
  - `make_jsonl_sink(file_path: str) -> Callable` — appends JSON line to file
- The service itself must NEVER raise — wrap each sink call in try/except and log via structlog if a sink fails
- Thread-safe: use a threading.Lock around JSONL file writes
- Extract module/function/line from `exc.__traceback__` — walk to the innermost frame

## Acceptance criteria

- [ ] `ErrorLogger.capture()` extracts exception type, message, full traceback string
- [ ] `ErrorLogger.capture()` extracts module, function, line from traceback
- [ ] `ErrorLogger.capture()` includes request_context when provided
- [ ] `ErrorLogger.capture()` returns a UUID string
- [ ] `ErrorLogger.capture_warning()` creates WARNING-level entries without traceback
- [ ] Each sink receives the full error dict
- [ ] If a sink raises, the error is logged via structlog but does not propagate
- [ ] `make_jsonl_sink` appends valid JSON lines to the specified file
- [ ] `make_db_sink` calls `repo.insert_error_log` with the error dict

## Test scenarios

- **Happy path:** Raise ValueError, capture it, verify dict has all fields
- **Request context:** Capture with request_context, verify it appears in dict
- **Warning:** capture_warning produces level=WARNING with no traceback
- **Sink failure:** One sink raises, other sink still receives the dict
- **JSONL sink:** Write 3 errors, read file, verify 3 valid JSON lines
- **Traceback extraction:** Verify module/function/line match the raise site
