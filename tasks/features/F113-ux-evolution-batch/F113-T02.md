# F113-T02: Catalog Page URL Fix + Show All DB Cards

**Status:** planned
**Wave:** 0
**Request:** R7

## User Story

As a user on the Catalog page, I want to see ALL cards from the database
(not an empty/404 page), with the same filter and sort capabilities as
My Collection, so I can browse the full card library.

## Dev Notes

### Root Cause (BUG)

The 3 catalog frontend hooks use the wrong API prefix:

| Hook | Current (WRONG) | Correct |
|------|-----------------|---------|
| `useCatalogCards.ts:91,121` | `/api/catalog/cards` | `/api/v1/catalog/cards` |
| `useCatalogSets.ts:16` | `/api/catalog/sets` | `/api/v1/catalog/sets` |
| `useCatalogStats.ts:17` | `/api/catalog/stats` | `/api/v1/catalog/stats` |

The catalog router is mounted at `prefix="/api/v1"` in `src/api/app.py:380`,
so the full path is `/api/v1/catalog/*`. The hooks are missing the `/v1` segment.

### Fix

1. **`frontend/src/hooks/useCatalogCards.ts`** — change `/api/catalog/cards` to `/api/v1/catalog/cards` (2 occurrences: lines 91 and 121)
2. **`frontend/src/hooks/useCatalogSets.ts`** — change `/api/catalog/sets` to `/api/v1/catalog/sets`
3. **`frontend/src/hooks/useCatalogStats.ts`** — change `/api/catalog/stats` to `/api/v1/catalog/stats`

### Backend validation

The catalog API (`src/api/routers/catalog.py`) already queries ALL `cards`
with `game = 'magic'` — this is correct. It joins Liga prices via
`source_cards` + `price_observations`. The SQL is sound. The only issue
is the frontend URL mismatch.

### Additional: Rarity filter fix

The catalog API accepts `rarity` as a single value (`rarity = :rarity`),
but the frontend sends comma-separated rarity values (e.g. `"R,M"`).
Fix the backend to split comma-separated rarity into `IN (...)` clause,
matching how color filtering already works.

### Additional: Sort options

The Catalog page currently defaults to `sort_by: "name"`. Add price sorting
to match the Explore Cards page — the backend already supports `SortByEnum.price`.
