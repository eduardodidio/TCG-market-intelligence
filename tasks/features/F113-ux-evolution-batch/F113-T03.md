# F113-T03: Auth Redirect + Nav Restructure

**Status:** planned
**Wave:** 0
**Request:** R2 + R8

## User Story

As an unauthenticated user, I want to be redirected to the login page on ANY
route (no public pages), so the app requires sign-in to use.

As a user, I want Achievements and Marketplace to appear under the "Beta Test"
nav section, reducing clutter in the primary navigation.

## Dev Notes

### Part A: Auth Redirect (R2)

**File: `frontend/src/App.tsx`**

Currently, several routes inside `<Layout>` are NOT wrapped with `<ProtectedRoute>`:
- `/cards` (Explore Cards)
- `/cards/:id` (Card Detail)
- `/market/movers`, `/market/trending`, `/market` (Market pages)
- `/banlist`, `/banlist/history` (Ban List)
- `/catalog` (Catalog)
- `/marketplace/share/:code` (Shared Collection)

**Solution**: Add a global auth guard in `Layout` component OR wrap all
remaining `<Route>` elements inside the `<Layout>` route with `<ProtectedRoute>`.

Recommended approach: **Wrap `<Layout>` itself with `<ProtectedRoute>`** by
changing the parent route:

```tsx
{/* Main layout routes — all require auth */}
<Route element={
  <ProtectedRoute>
    <Layout />
  </ProtectedRoute>
}>
```

This means ALL routes inside `<Layout>` require auth. The only exceptions
remain `/login` and `/change-password` which are outside `<Layout>`.

Then REMOVE the individual `<ProtectedRoute>` wrappers from each child route
(they become redundant). Keep `<AdminRoute>` for `/admin`.

**Exception**: The `/marketplace/share/:code` route should stay public (shared
collections). Move it OUTSIDE the Layout block, giving it its own layout or
a minimal layout wrapper.
