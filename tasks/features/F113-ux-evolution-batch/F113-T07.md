# F113-T07: Portfolio/Liga Dashboard Data Flow Fix

**Status:** done
**Wave:** 1
**Request:** R1

## User Story

As a collector with Liga price data, I want the portfolio dashboard and
history charts to display accurate values based on my Liga-priced cards,
so I can track my collection's value over time.

## Dev Notes

### Investigation Results (4 confirmed bugs)

#### Bug A: Backfill missing foil Liga prices

**File:** `src/collectors/portfolio_backfill.py` lines 331-361

`_load_card_external_ids()` adds `liga_{card_id}` patterns but does NOT add
`liga_{card_id}_foil` for foil cards. Real-time snapshots handle foils
correctly (via `get_latest_prices_batch(foil_card_ids=...)`), but backfilled
snapshots undercount foil collection value.

**Fix:** In `_load_card_external_ids()`, detect foil entries (via `is_foil_entry(extras)`)
and add `liga_{card_id}_foil` to the external_ids list. Also pass foil info
to `_find_best_price()` so it checks the foil pattern first.

#### Bug B: Priced count undercounts Liga-only cards

**File:** `src/database/repository.py` lines 1486-1508

`get_collection_summary()` counts `priced_count` by joining `source_cards` to
`price_observations`. Liga prices use direct `external_id = liga_{card_id}` pattern
which may NOT have matching `source_cards` entries (especially for older cards).
Result: dashboard shows fewer "priced" cards than reality.

**Fix:** Augment the priced_count query to also check for Liga direct external_id
patterns: `liga_{card_id}` in price_observations.

#### Bug C: Movers endpoint may miss Liga-only cards

**File:** `src/api/routers/collection.py` lines 368-410

The `/collection/movers` endpoint uses `get_trending_price_data_for_user()` which
queries via `source_cards` JOIN. Liga-only cards without source_cards entries
are excluded from gainers/losers.

**Fix:** Extend the trending data query to include Liga direct external_id patterns.

#### Bug D: No snapshot data exists yet

The `backfill-portfolio` CLI must be run after Liga data collection to seed
historical snapshots. The post-scan hook (`make_portfolio_snapshot_hook`)
creates snapshots going forward, but there's no data for past dates unless
backfill is run.

**Fix:** Document the requirement to run `backfill-portfolio` after initial
Liga data collection. Consider adding a "no data yet" message in the
PortfolioDashboard component when history is empty.
