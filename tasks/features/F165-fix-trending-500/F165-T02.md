# F165-T02 — Add try/except in market router endpoints

**Status:** planned
**Wave:** 1
**Depends on:** none

## User Story

As a user, I want the trending API endpoints to return a valid (empty) response even when the service layer fails, so the frontend can display "no data" instead of an error screen.

## Dev Notes

**File:** `src/api/routers/market.py`

### Changes to `get_trending_gainers()` (line ~133)

Wrap the `service.get_trending()` call in try/except:

```python
@router.get("/trending/gainers", response_model=ApiResponse[TrendingResponse])
def get_trending_gainers(...):
    ...
    days = TRENDING_PERIOD_MAP[period]
    user_id = user.id if collection_only and user else None
    try:
        data = service.get_trending("up", days, limit, converter, currency, user_id=user_id)
        data.period = period
    except Exception as exc:
        logger.warning(
            "trending_gainers_error",
            extra={"error": str(exc), "error_type": type(exc).__name__, "period": period},
        )
        data = TrendingResponse(
            cards=[], period=period, direction="up",
            computed_at=datetime.now(), cached=False,
        )
    return success_response(data=data)
```

### Changes to `get_trending_losers()` (line ~156)

Same pattern, direction="down".

### Changes to `get_volatile()` (line ~257)

The existing try/except on line 280 only wraps the TrendingService calls, but the fallback `repo.get_movers()` is NOT wrapped. Add a second try/except around the fallback block, or use a broader catch that covers both paths. On total failure, return empty TrendingResponse.

### Important

- Import `datetime` is already present
- `TrendingResponse` is already imported
- Use `logger.warning()` (stdlib logging, already set up at module level)
