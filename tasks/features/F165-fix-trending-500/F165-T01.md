# F165-T01 — Broaden exception catch in TrendingService

**Status:** planned
**Wave:** 1
**Depends on:** none

## User Story

As a user viewing the Dashboard, I want the trending sections to gracefully handle all database errors so I never see a 500 error.

## Dev Notes

**File:** `src/services/trending.py`

**Current code (line ~63):**
```python
except OperationalError as exc:
    log.warning("trending_query_timeout", error=str(exc), period_days=period_days)
    price_data = {}
```

**Change to:**
```python
except Exception as exc:
    log.warning(
        "trending_query_error",
        error=str(exc),
        error_type=type(exc).__name__,
        period_days=period_days,
        user_id=user_id,
    )
    price_data = {}
```

**Rationale:** PostgreSQL via psycopg2 can raise `InternalError` (statement_timeout cancellation), `InterfaceError` (connection lost), `DatabaseError` (protocol error), not just `OperationalError`. This matches the pattern already applied in F164's `collection.py` fix (commit `80247c8`).

**Also:** Remove the now-unused `from sqlalchemy.exc import OperationalError` import.
