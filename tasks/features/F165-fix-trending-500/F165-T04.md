# F165-T04 — Add backend tests for error resilience

**Status:** planned
**Wave:** 1
**Depends on:** none

## User Story

As a developer, I want comprehensive tests ensuring that trending/movers endpoints never return 500, so regressions are caught before production.

## Dev Notes

**New file:** `tests/test_trending_error_resilience.py`

### Test cases for TrendingService (unit)

1. **test_get_trending_catches_operational_error** — mock `repo.get_trending_price_data` to raise `sqlalchemy.exc.OperationalError` → returns empty TrendingResponse
2. **test_get_trending_catches_internal_error** — mock to raise `sqlalchemy.exc.InternalError` → same graceful behavior
3. **test_get_trending_catches_interface_error** — mock to raise `sqlalchemy.exc.InterfaceError` → same
4. **test_get_trending_catches_generic_exception** — mock to raise `RuntimeError("connection reset")` → same
5. **test_get_trending_logs_error_context** — verify structlog captures `error_type`, `period_days`, `user_id`
6. **test_get_trending_for_user_catches_exception** — with `user_id` param, mock `get_trending_price_data_for_user` to raise → empty result

### Test cases for market router (integration via TestClient)

7. **test_trending_gainers_returns_200_on_service_error** — patch `TrendingService.get_trending` to raise → expect 200 + empty cards
8. **test_trending_losers_returns_200_on_service_error** — same for losers
9. **test_volatile_returns_200_on_total_failure** — patch both TrendingService and repo.get_movers to raise → expect 200 + empty cards
10. **test_trending_gainers_collection_only_returns_200_on_timeout** — with `collection_only=true` + auth header, patch to raise timeout → expect 200

### Test cases for optimized query (unit)

11. **test_get_trending_price_data_for_user_batches_large_collections** — mock 600 card_ids, verify IN clause is chunked (no single query with 1800 patterns)
12. **test_get_trending_price_data_for_user_merges_results_correctly** — mock batched responses, verify dedup logic works

### Setup

- Use `pytest` fixtures from existing test infrastructure
- Use `unittest.mock.patch` for service/repo mocking
- Use FastAPI `TestClient` for router integration tests
- Follow existing test patterns in `tests/`
