# F41-T02: Repository — legality CRUD methods

**Status:** planned
**Wave:** 1

## User Story

As a developer, I need repository methods to read and write legality data
so the sync orchestrator and API can use them.

## Dev Notes

### Files to modify
- `src/database/repository.py` — add legality methods

### Implementation

1. `upsert_legalities(legalities: list[CardLegality]) -> int`
   - Bulk INSERT ON CONFLICT (card_id, format) DO UPDATE SET status, effective_date, updated_at
   - Returns count of rows affected

2. `insert_legality_changes(changes: list[LegalityChange]) -> int`
   - Bulk INSERT into legality_history
   - Returns count inserted

3. `get_legalities_by_format(format: str, status: str | None = None, limit: int = 200, offset: int = 0) -> list[dict]`
   - JOIN with cards table to get card name, set_code, collector_number
   - Optional status filter (e.g. only "banned")
   - Returns list of dicts with card info + legality status + effective_date
   - Order by card name_en ASC

4. `get_legalities_for_card(card_id: int) -> list[CardLegalityRow]`
   - All formats for a given card
   - Order by format ASC

5. `get_legality_history(card_id: int | None = None, format: str | None = None, limit: int = 50) -> list[LegalityHistoryRow]`
   - Filter by card_id and/or format
   - JOIN with cards for card name
   - Order by changed_at DESC

6. `get_known_formats() -> list[str]`
   - SELECT DISTINCT format FROM card_legalities ORDER BY format

7. `get_legalities_for_cards_batch(card_ids: list[int]) -> dict[int, list[CardLegalityRow]]`
   - Batch fetch for multiple cards (used by collection list)
   - Returns dict keyed by card_id
