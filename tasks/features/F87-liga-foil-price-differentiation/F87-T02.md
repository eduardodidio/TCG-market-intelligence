# F87-T02 — Scan/Refresh Pipeline Stores Foil Prices Separately

**Status:** planned
**Wave:** 0 (parallel with T01, T03)
**Estimate:** medium

## User Story

As a collector with foil cards, when a scan or single-card refresh runs,
I want the system to store the foil price separately from the normal
price so that my foil cards show accurate (higher) prices.

## Dev Notes

### Strategy: External ID Suffix

Use the existing `PriceObservationRow` without schema changes. Foil prices
get a distinct `external_id`:

- Normal: `"liga_{card_id}"`
- Foil: `"liga_{card_id}_foil"`

This naturally separates via the unique constraint
`(source, external_id, observed_at)`.

### What to do

1. **Update `get_current_price` in Liga provider** (`src/providers/liga/provider.py`):
   - Accept an optional `is_foil: bool = False` parameter
   - When `is_foil=True`, use `foil.low or foil.mid or foil.high` instead
     of `normal.low`
   - Return a `PriceSnapshot` with `external_id = f"{card.external_id}_foil"`
   - If no foil prices found, fall back to normal prices (with a log warning)

2. **Update scan orchestrator** (`src/collectors/scan.py`):
   - In `_fetch_price_liga`, detect if the collection entry is foil
     (use `is_foil_entry(extras)` from T01)
   - Pass `is_foil=True` to the provider when applicable
   - Store the observation with the `_foil` suffix external_id

3. **Update single-card refresh** (`src/api/routers/collection.py`):
   - In the `POST /collection/{id}/refresh` endpoint, detect foil
   - Pass `is_foil` to the Liga provider call
   - Store with `_foil` suffix external_id

4. **Update Liga sweep** (`src/collectors/liga_sweep.py`):
   - Pass foil flag through the sweep pipeline

### Key files

- `src/providers/liga/provider.py` — `get_current_price()`, `_get_current_price_unlocked()`
- `src/collectors/scan.py` — `_fetch_price_liga()`
- `src/collectors/liga_scan.py` — scan wrapper
- `src/api/routers/collection.py` — refresh endpoint

### Important

- The Liga parser already extracts foil prices. Do NOT modify the parser.
- When `is_foil=True` but no foil prices are found on the page, log a
  warning and return `None` (do NOT fall back to normal price — that
  would perpetuate the current bug).
- Both normal AND foil prices can be stored in the same scan run (for
  cards that exist in both finishes in the collection).

## Testing

- Unit: Liga provider with `is_foil=True` returns foil prices from parsed HTML
- Unit: Liga provider with `is_foil=True` returns None when no foil section
- Unit: external_id format is `"{base}_foil"` for foil entries
- Unit: scan orchestrator passes is_foil correctly based on extras field
- Integration: refresh endpoint stores foil observation with correct external_id
- Integration: scan run creates separate observations for foil vs normal entries
