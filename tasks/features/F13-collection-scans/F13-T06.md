## User Story

As an API consumer, I want well-defined request/response schemas for scan
endpoints, so that the frontend can reliably trigger and display scans.

## Objective

Create `src/api/schemas/scans.py` with Pydantic models for scan requests
and responses.

## Dev Notes

Existing patterns in `src/api/schemas/`:
- `collection.py` uses Pydantic `BaseModel` with `model_config = ConfigDict(from_attributes=True)`
- Response models use `list[ItemModel]` for collections
- Request models have optional fields with defaults

## Implementation Details

New file: `src/api/schemas/scans.py`

```python
from pydantic import BaseModel, ConfigDict

class ScanRequest(BaseModel):
    scan_type: str = "collection"
    set_codes: list[str] | None = None
    format_name: str | None = None
    rarities: list[str] | None = None
    card_ids: list[int] | None = None
    limit: int | None = None
    dry_run: bool = False

class ScanRunResponse(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    scan_type: str
    filters_json: str
    status: str
    cards_total: int
    cards_processed: int
    cards_failed: int
    observations_saved: int
    error_summary: str | None
    started_at: str | None
    finished_at: str | None
    created_at: str

class ScanListResponse(BaseModel):
    scans: list[ScanRunResponse]
    total: int

class ScanTriggerResponse(BaseModel):
    scan_id: int
    status: str
```
