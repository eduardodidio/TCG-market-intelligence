# F129-T07: Post-Fix Validation Sweep and Accuracy Report

**Wave:** 3 (Validation)
**Depends on:** T04, T05, T06 (all Wave 2 fixes), T03 (analysis)
**Files to modify:** (none -- this is an execution + reporting task)
**Files to create:** `docs/reports/F129-accuracy-report.md`

## User Story

As the project owner, I want to run a final validation sweep after all
fixes are applied and see a clear accuracy report proving we meet the
>80% OK+DRIFT target, so that I have confidence the Liga price data is
reliable for portfolio tracking and market intelligence.

## Problem

After Wave 2 fixes are implemented, we need a final validation cycle to
prove the accuracy targets are met:

1. >80% of cards should be OK or DRIFT (within 20% of Liga lowest buy)
2. 0 cards where our price < Liga's lowest buy
3. No card with >10x deviation unless it is a genuinely different edition

## Dev Notes

### Execution procedure
Follow the procedure from T03 (`docs/procedures/liga-accuracy-validation.md`):

1. Run `liga-sweep --max-age-days 0` (full sweep with all fixes active)
2. Run `liga_collection_compare.py` (enhanced from T01)
3. Review the output CSV and summary

### Accuracy report
Create `docs/reports/F129-accuracy-report.md` with:

1. **Before fix** snapshot (from the brief):
   - BIG_MISMATCH: 273 (59%)
   - MISMATCH: 89 (19%)
   - DRIFT: 57 (12%)
   - OK: 26 (6%)
   - NOT_IN_DB: 15 (3%)

2. **After data-sigla fix** snapshot (from T03 analysis):
   - Record the numbers after the first re-sweep

3. **After Wave 2 fixes** snapshot (this task):
   - Record the final numbers

4. **Remaining deviations**: For any cards still showing BIG_MISMATCH
   after all fixes, document the root cause and whether it is:
   - Expected (mid vs lowest-buy structural difference)
   - Cheap card noise (< R$1.00)
   - Genuine remaining issue (document for future fix)

5. **Acceptance criteria check**:
   - [ ] >80% OK + DRIFT
   - [ ] 0 cards with our price < Liga lowest buy
   - [ ] 0 cards with >10x deviation (excluding documented exceptions)

### What if targets are not met
If the targets are not met after Wave 2:
- Identify the remaining divergence patterns
- Create follow-up tasks (F130+) for any new fix patterns needed
- Do NOT block the feature on perfection -- document known limitations

## Edge Cases

- Liga may update prices between the Wave 2 fix implementation and this
  validation sweep. Some cards may shift status due to natural price
  movement, not our fixes.
- New cards added to the collection since the HTML export will show as
  "extra" in our DB but won't affect the comparison (script only checks
  cards from Liga HTML).
- Cards removed from Liga listings (delisted) may show NO_LIGA_PRICE.

## Testing

- This task is a validation execution, not a code task.
- The "test" is the accuracy report itself.
- Verify all three acceptance criteria are explicitly checked in the report.
- If any criterion is not met, the report must explain why and what
  follow-up is planned.
