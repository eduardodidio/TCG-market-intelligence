# F129-T05: Double-Face / Split Card Name Handling Improvements

**Wave:** 2 (Fixes)
**Depends on:** T03 (analysis must confirm DFC cards are still problematic)
**Parallel with:** T04, T06
**Files to modify:** `src/providers/liga/url.py`, `src/collectors/liga_sweep.py`
**Files to create:** (none)

## User Story

As a price collector, I want double-face cards (DFC) and split cards to
correctly resolve to their Liga page and select the right edition, so that
cards like "The Arkenstone // Seek the Heart" or "Bilbo, Luckwearer //
Burglar's Plot" get accurate prices instead of 690-26000% deviations.

## Problem

The pre-fix comparison shows extreme deviations for DFC cards:

| Card | Deviation |
|------|-----------|
| Thranduil, Sindarin Liege // Silvan Rally | +26226% |
| Bilbo, Luckwearer // Burglar's Plot | +3761% |
| Bofur, Reliable Guardian // Concerted Care | +2788% |
| The Arkenstone // Seek the Heart | +690% |
| Bonecrusher Giant // Stomp | +460% |

The URL builder (`liga_url_for_card_name`) already strips the back face
(splits on " // " and uses front face only). This is correct behavior.
However, the issue may be:

1. **Edition selection failure**: DFC cards may have different collector
   numbers for front/back faces, or Liga may use a different numbering
   scheme for DFC cards.

2. **Name mismatch on Liga**: Liga may store the card under a slightly
   different name format (e.g. with or without the " // " separator).

3. **Wrong card entirely**: The front-face search may return a different
   card if the front-face name is ambiguous.

### Scope gate

This task should ONLY be implemented if the T03 analysis (post data-sigla
fix) still shows significant DFC card deviations. Many of the pre-fix
deviations may have been caused by wrong edition selection, which the
data-sigla fix already addresses.

## Dev Notes

### Investigation first
Before implementing fixes, the developer should:
1. Use the debug script (T02) on 3-5 DFC cards from the mismatch list
2. Check if the Liga page loads correctly for the front-face name
3. Check if edition selection works with data-sigla
4. Identify the actual root cause (URL, edition, or name issue)

### Potential fix 1: Clean card name for Liga search
In `_clean_card_name` (liga_sweep.py), also handle:
- Cards with " // " -- the URL builder already handles this, but verify
  the card_name passed to `search_card` is also cleaned
- Cards with "(Art Card with Signature)" suffix -- strip this
- Cards with parenthesized set annotations

### Potential fix 2: DFC collector number handling
Some DFC cards have collector numbers like "32a" / "32b" for front/back.
Liga may use "32" without the letter suffix. If the edition dropdown has
"32" but we search for "32a", no match is found.

Check `parse_edition_options` -- the regex `(\d+_[\w]+)` should handle
alphanumeric collector numbers. But the comparison in `_select_edition`
is exact string match (`cn == collector_number`). May need to strip
trailing "a"/"b" from collector_number before matching.

### Potential fix 3: Art Card / Signature variant
Cards like "The Arkenstone // Seek the Heart (Art Card with Signature)"
have the Art Card text in the name itself. This should be stripped before
Liga search, similar to how (#xxx) annotations are stripped.

## Edge Cases

- Cards with " // " in the name that are NOT DFC (very rare but possible)
- Collector numbers with letters beyond a/b (e.g. "44a" from Art Series)
- DFC cards where the front face name alone is not unique on Liga
- Cards with three or more faces (extremely rare)
