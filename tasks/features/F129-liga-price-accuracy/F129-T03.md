# F129-T03: Re-sweep + Re-compare Procedure & Divergence Classification

**Wave:** 1 (Analysis)
**Depends on:** T01, T02 (Wave 0 must be complete)
**Files to create:** `docs/procedures/liga-accuracy-validation.md`

## User Story

As the project owner, I want a documented step-by-step procedure to run
a full sweep and comparison so that I can execute it on my Windows machine
(Liga blocks datacenter IPs) and classify the remaining divergences into
actionable buckets.

## Problem

The current comparison data is from BEFORE the data-sigla fix (commit
1686d03). We need to:

1. Run a fresh full sweep with `max-age-days=0` to force all ~560 cards
   through the fixed code path.
2. Re-run the enhanced comparison script (from T01) to get updated numbers.
3. Classify remaining divergences into root-cause buckets to determine
   which Wave 2 fixes are actually needed.

## Dev Notes

### Procedure document
Create `docs/procedures/liga-accuracy-validation.md` with:

1. **Pre-requisites**: Python env, Playwright installed, `.env` with
   DATABASE_URL, machine on residential IP.

2. **Step 1 -- Full sweep**:
   ```
   python -m src.cli.main liga-sweep --max-age-days 0
   ```
   Expected: ~560 cards, ~45-60 minutes at 5s delay.

3. **Step 2 -- Re-export Liga collection** (optional):
   If the user wants fresh Liga buy prices, re-save the 7 HTML pages
   from Liga's collection view. Otherwise use existing HTMLs.

4. **Step 3 -- Run comparison**:
   ```
   python scripts/liga_collection_compare.py
   ```
   Check output in `scripts/debug_output/price_comparison.csv`.

5. **Step 4 -- Classify results**:
   Use the enhanced summary (from T01) to bucket mismatches.
   Record findings in this task file as a post-analysis update.

6. **Step 5 -- Decide Wave 2 scope**:
   Based on classification, decide which of T04/T05/T06 are needed.
   Some may become unnecessary if the data-sigla fix resolves them.

### Expected post-fix outcomes

Based on analysis of the pre-fix data, the data-sigla fix should resolve:
- All cases where wrong edition was selected due to ambiguous collector_number
  (e.g. Orb of Dragonkind, Sol Ring, Inferno of Star Mounts)
- Cases where the selected edition was a rare/expensive variant instead of
  the standard printing

Cases that will likely REMAIN after the fix:
- **Expected mid-vs-buy difference**: Cards where our mid is naturally
  50-100% above Liga's lowest buy. This is structurally expected.
- **Cheap card noise**: Cards under R$1.00 where even R$0.50 difference
  shows as 200%+. These are noise, not bugs.
- **Wrong edition where sigla does not match**: If Scryfall set_code
  differs from Liga's data-sigla for any set, the fix will not help.
- **DFC cards with URL issues**: If the front-face name search returns
  a different card entirely.

### Decision gate

After Step 5, update this task with actual numbers. If >80% are OK+DRIFT,
Wave 2 may be minimal. If significant buckets remain, proceed with the
relevant T04/T05/T06 tasks.

## Edge Cases

- Sweep may be interrupted (KeyboardInterrupt) -- it saves partial results.
  Re-run with same max-age-days=0 to pick up remaining cards.
- Liga may rate-limit during full sweep -- the provider handles 429 with
  backoff. Increase `--delay` to 8-10s if needed.
- Some cards may have been removed from the collection since the HTML export
  was saved -- these will show as NOT_IN_DB in reverse.
