## User Story

As a developer investigating price divergences, I want the comparison script
to correctly match cards with diacritical characters (e.g. Dain, Anduril,
Barad-dur) and distinguish between expected vs problematic mismatches, so
that I can focus debugging effort on genuine bugs rather than noise.

## Problem

The current comparison script has three issues:

1. **Diacritics matching failure**: 15 cards show as NOT_IN_DB because ILIKE
   does not match diacritics properly (e.g. "Dain" vs "Dain"). All 15 are
   LOTR/Hobbit cards with accented characters. The script should normalize
   accented characters or use a more flexible matching strategy.

2. **No directional status**: BIG_MISMATCH does not distinguish between
   "our price is higher" (expected for mid vs lowest-buy) and "our price is
   lower" (genuine bug). The script should split into:
   - `BIG_ABOVE` (our > Liga by >50%) -- likely expected, could be wrong edition
   - `BIG_BELOW` (our < Liga by >50%) -- genuine bug, should never happen

3. **No root-cause bucketing**: The summary does not classify mismatches by
   likely root cause (foil, DFC, wrong edition, expected mid-vs-buy diff).

## Dev Notes

### Diacritics fix
- Use `unidecode` (already available?) or Python `unicodedata.normalize('NFKD')`
  + strip combining chars to create ASCII-safe comparison keys.
- Apply normalization to both Liga HTML names AND DB query parameters.
- Alternative: use PostgreSQL `unaccent()` extension in the query itself.
- Simpler approach: strip diacritics in Python before the ILIKE query, and
  also try exact match first, then fallback to normalized match.

### Directional status
- Split `BIG_MISMATCH` into `BIG_ABOVE` and `BIG_BELOW` based on sign of diff.
- Split `MISMATCH` into `MISMATCH_ABOVE` and `MISMATCH_BELOW` similarly.
- Keep thresholds: >50% = BIG, 20-50% = MISMATCH, 5-20% = DRIFT, <5% = OK.

### Root-cause hints
Add a `hint` column to the CSV output with heuristic classification:
- `foil_card` -- extras contains "Foil"
- `dfc_card` -- name contains " // "
- `art_card` -- edition contains "Art Series" or name contains "Art Card"
- `promo` -- extras contains "Promo" or "Pre Release"
- `variant_ed` -- edition name contains "(Variantes)" or "(Borderless)" etc.
- `cheap_card` -- Liga buy price < R$1.00 (cheap cards naturally have high %)
- `expected` -- positive diff AND no hint flags AND Liga price > R$5

### Summary report
Print a breakdown by hint category at the end, showing how many mismatches
fall into each bucket. This helps prioritize which fix to implement.

## Edge Cases

- Cards with both diacritics AND double-face names (e.g. "Bofur, Reliable
  Guardian // Concerted Care")
- Cards with parentheses in name (e.g. "Art Card with Signature")
- Empty buy_price or sell_price in Liga HTML (should not crash)
