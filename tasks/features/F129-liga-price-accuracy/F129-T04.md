**Wave:** 2 (Fixes)

**Files to create:** `src/providers/liga/sigla_map.py`

## User Story

As a price collector, I want the Liga sweep to correctly match editions even
when Scryfall's set_code differs from Liga's data-sigla, so that cards from
sets with different naming conventions get the right edition selected and
the right price stored.

## Problem

The `_select_edition` method in `provider.py` compares `set_code.lower()`
directly against Liga's `data-sigla`. This works when they match exactly
(e.g. both use "afr" for Adventures in the Forgotten Realms). But some
sets may use different codes:

- Scryfall uses 3-letter codes (e.g. "cmm" for Commander Masters)
- Liga may use longer codes or different abbreviations
- Promo sets, special editions, and variant sets (e.g. "(Variantes)",
  "(Borderless)") may have Liga-specific sigla values

The comparison data shows cards from sets like "Commander Legends
(Variantes)", "Foundations (Borderless)", "Treasure Chest" that have
extreme mismatches -- these likely have sigla mismatches.

### Scope gate

This task should ONLY be implemented if the T03 analysis reveals specific
set_code -> sigla mismatches. If the data-sigla fix resolves all edition
issues, this task is unnecessary.

## Dev Notes

### Sigla mapping module
Create `src/providers/liga/sigla_map.py` with:

```python
# Mapping from Scryfall set_code -> Liga data-sigla
# Only needed for sets where they differ.
# Populated from T03 analysis findings.
SCRYFALL_TO_LIGA_SIGLA: dict[str, str] = {
    # Example: "plst" -> "treasure_chest",  # Treasure Chest / The List
    # Populated after T03 analysis
}

def normalize_sigla(scryfall_set_code: str) -> str:
    """Convert a Scryfall set code to Liga's sigla equivalent."""
    sc = scryfall_set_code.lower()
    return SCRYFALL_TO_LIGA_SIGLA.get(sc, sc)
```

### Provider integration
In `provider.py` `_select_edition`, before the sigla comparison:

```python
from src.providers.liga.sigla_map import normalize_sigla
sc = normalize_sigla(set_code.lower())
sigla_matches = [m for m in matches if m[2] == sc]
```

### Populating the mapping
After T03 analysis:
1. Identify all set_code values in our collection
2. Cross-reference with Liga's data-sigla values from edition dropdowns
3. Add entries to the mapping only for mismatches
4. The debug script batch mode (T02) can help: run a batch of mismatched
   cards, check which sigla values Liga uses, compare with our set_code

### Reverse mapping
Also useful: Liga sigla -> Scryfall set_code, for cases where we need to
display set information from Liga data. But this is lower priority.

## Edge Cases

- Liga may use the same sigla for multiple related sets (e.g. a base set
  and its promo variants). The mapping should handle this.
- New sets will need to be added to the mapping as they release. Consider
  logging a warning when no sigla match is found so we can update the map.
- Some cards may have NO matching sigla at all (e.g. store championship
  promos). The current behavior (skip price) is correct for these.
