# F65-T04: Credit guard on refresh + scan endpoints

**Status:** planned
**Wave:** 1
**Depends on:** T01, T02
**Parallel with:** T03

## User Story

As a collector, when I refresh a card's price or trigger a bulk scan, the
system should deduct credits from my balance. If I have no credits, I should
see a clear "insufficient credits" error (HTTP 402). Admin users bypass all
credit checks.

### Guard pattern (applied to each guarded endpoint)

```python
from src.credits.constants import CARD_REFRESH_COST, BULK_SCAN_COST
from src.credits.exceptions import InsufficientCreditsError

# Inside endpoint handler:

# 1. Admin bypass — skip all credit logic
if not user.is_admin:
    # 2. Pre-check balance (fast-fail before expensive provider call)
    if not credit_svc.check_sufficient(user.id, cost):
        balance = credit_svc.get_balance(user.id)
        raise HTTPException(
            status_code=402,
            detail={
                "code": "INSUFFICIENT_CREDITS",
                "balance": balance.balance,
                "cost": cost,
                "message": "Not enough treasure tokens. Claim your bonus or wait for the next one."
            }
        )

# 3. Execute the action (provider call / scan trigger)
# ... existing logic ...

# 4. Deduct AFTER success (non-admin only)
if not user.is_admin:
    credit_svc.deduct(user.id, cost, reason, reference_id=str(entry_id))
```

### Deduct AFTER success, not before

Credits are deducted only AFTER the provider successfully returns price
data. If the provider fails (404, timeout, rate limit), the user does not
lose credits. Flow:

1. Check balance (fast-fail)
2. Call provider (may fail)
3. Save price observation
4. Deduct credit (only on success)

### Admin bypass

Admin users (`user.is_admin == True`) skip ALL credit checks. The guard
block is entirely bypassed — no balance check, no deduction. This is per
the brief: "Admin users bypass credit checks entirely."

### Bulk scan (POST /scans) integration

The scans endpoint currently uses `require_auth_or_api_key` which returns
a user_id string, not a full User object. To check `is_admin`, this endpoint
needs access to the User. Options:

1. Add `get_current_user` as a dependency (preferred — aligns with other endpoints)
2. Look up user in the endpoint body

Use option 1. Modify `trigger_scan` to accept `user=Depends(get_current_user)`.
The API key path should also resolve to a User object so is_admin can be checked.
If the auth is via API key only (no JWT), treat as non-admin unless the API key
maps to an admin user.

For bulk scan, deduct 5 credits BEFORE launching the background thread
(unlike single refresh which deducts after). This is because the scan runs
asynchronously and we cannot guarantee the deduction happens. The pre-check
already confirmed sufficient balance.

### Error response format

All 402 responses use the same structure:
```json

        "code": "INSUFFICIENT_CREDITS",
        "balance": 3,
        "cost": 5,

    }
}
```
