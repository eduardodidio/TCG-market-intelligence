# F24-T06: Fix Dashboard Coverage & Collection Value

- **Wave:** 1
- **Status:** planned
- **Depends on:** none
- **Type:** fullstack

## User Story

As a collector, I want the dashboard to accurately show my collection's
coverage percentage and total estimated value so I can track my portfolio.

## Objective

Investigate why dashboard shows only 23% coverage and why collection value
may be underestimated (~10k expected via Liga Magic). Fix the root causes.

## Dev Notes

**Coverage metric:**
- `GET /api/v1/collection/summary` returns `linked_count` / `total_unique`
- `linked_count` = entries where `card_id IS NOT NULL`
- 23% means only 23% of collection entries are linked to canonical cards
- This is likely correct — many collection entries imported from CSV may
  not have been matched/linked to canonical `cards` table entries

**Investigation steps:**
1. Query actual numbers: total collection entries, linked entries, unlinked
2. For unlinked entries, check common patterns: missing set_code? wrong
   collector_number? Portuguese-only names?
3. Check if `sync-collection` CLI was run — this links entries to cards
4. Check if the matching logic in `src/collection/matcher.py` is failing
   for certain card patterns

**Collection value metric:**
- `get_collection_total_value(user_id)` sums `median_price * quantity`
  for all linked entries that have price observations
- If only 23% are linked, value will be ~23% of actual
- Value depends on: (a) card linking rate, (b) price observation coverage

**Possible fixes:**
1. **Improve the dashboard display** — show both "linked coverage" and
   "price coverage" separately, with explanatory text
2. **Show unlinked count** — "X cards need linking — run sync to improve"
3. **Show price coverage** — "Y of Z linked cards have price data"
4. **Add a "Sync Collection" button** on dashboard if coverage is low
5. **Improve matching** — if matcher.py has gaps, fix them (separate task)

**Frontend changes:**
- `Dashboard.tsx` — add coverage breakdown KPIs:
  - "Linked" = cards matched to price source (X%)
  - "Priced" = linked cards with at least one observation (Y%)
  - "Value Coverage" = % of collection with price data
- Add contextual help text explaining what coverage means
- Add action button: "Improve Coverage" → triggers sync

**Backend changes (if needed):**
- `collection.py` summary endpoint — add `priced_count` (linked entries
  with at least one price observation)
- Repository: new method `get_priced_collection_count(user_id)`

**Files to touch:**
- `frontend/src/pages/Dashboard.tsx` — coverage breakdown + value explanation
- `src/api/routers/collection.py` — add priced_count to summary
- `src/database/repository.py` — query for priced entries count
