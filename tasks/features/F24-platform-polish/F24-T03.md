# F24-T03: Fix Collection Card Detail "Not Found"

- **Wave:** 1
- **Status:** planned
- **Depends on:** none
- **Type:** fullstack

## User Story

As a collector, when I click a card in My Collection, I want to see its
detail page instead of "Collection entry not found".

## Objective

Fix the navigation from My Collection to CollectionCardDetail so the
correct entry ID is passed and the backend lookup succeeds.

## Dev Notes

**Root cause investigation checklist:**

1. **Frontend navigation** — Check how `MyCollection.tsx` builds the link
   to `/collection/:id`. Verify it uses `entry.id` (the `user_collection.id`
   PK), not `entry.card_id` or some other field.

2. **Backend lookup** — `src/api/routers/collection.py` endpoint
   `GET /collection/{entry_id}` calls `repo.get_collection_entry(entry_id)`.
   This queries `UserCollectionRow` by `id`. Check if the IDs in the
   database actually match what the frontend sends.

3. **API response shape** — Verify `fetchCollection()` returns entries with
   an `id` field that maps to `user_collection.id`. Check `types/api.ts`
   `CollectionEntry` interface.

4. **User isolation** — The `get_collection_entry` method does NOT filter
   by `user_id`. If the entry exists, it returns it regardless of owner.
   This is NOT the bug but should be noted.

**Likely fix areas:**
- `frontend/src/pages/MyCollection.tsx` — check the `<Link>` or `onClick`
  navigation target
- `frontend/src/api/collection.ts` — check `fetchCollectionEntry(id)` call
- `src/api/routers/collection.py` — check response serialization of list
  endpoint (does it include `id`?)
- `src/api/schemas/` — check if collection entry schema includes `id`

**Compare with Explore Cards flow:**
- Explore Cards uses `GET /cards/{card_id}` (canonical card ID)
- Collection uses `GET /collection/{entry_id}` (user_collection PK)
- Both should work the same way — click → navigate → fetch detail

## Testing

- Framework: Vitest + pytest
- Frontend test: `frontend/src/__tests__/MyCollection.test.tsx`
