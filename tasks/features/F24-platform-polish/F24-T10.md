# F24-T10: Language Selector + User Preference

- **Wave:** 3
- **Status:** planned
- **Depends on:** F24-T08, F24-T09
- **Type:** fullstack

## User Story

As a user, I want to choose my preferred language on the login page and in
settings so the platform remembers my language preference.

## Objective

Add a language selector component visible on the login page and in the
user settings/nav area. Persist preference to backend (user profile) and
sync with i18n on load.

## Dev Notes

### Frontend:

1. **LanguageSelector component** (`frontend/src/components/LanguageSelector.tsx`):
   - Dropdown or toggle showing: "EN" | "PT-BR" with flag icons
   - Calls `setLanguage()` from LanguageContext
   - Compact variant for nav/header, full variant for login page

2. **Login page** (`frontend/src/pages/Login.tsx`):
   - Add LanguageSelector in top-right corner of login form
   - Language selection applies immediately (form labels update)
   - Selected language persists to localStorage

3. **Layout/Nav** (`frontend/src/components/Layout.tsx`):
   - Add LanguageSelector in sidebar footer or header area
   - Near the user menu / currency toggle

4. **Auth flow integration:**
   - On login success, read user's `preferred_language` from profile
   - If set, override localStorage language with server preference
   - On language change while authenticated, PATCH to save preference

### Backend:

1. **User model** (`src/database/models.py`):
   - Add `preferred_language` column to `UserRow` (VARCHAR(10), nullable,
     default "en")

2. **Auth/preferences endpoint:**
   - `PATCH /api/v1/auth/me/preferences` already exists (used for
     preferred_currency). Extend to accept `preferred_language` field.
   - `GET /api/v1/auth/me` — include `preferred_language` in response

3. **Migration:**
   - Add column with `ALTER TABLE users ADD COLUMN preferred_language
     VARCHAR(10) DEFAULT 'en'`
   - Or handle via SQLAlchemy `Column(default="en")` + create_all
