# F24-T04: Fix Explore Cards Missing Images

- **Wave:** 1
- **Status:** planned
- **Depends on:** none
- **Type:** frontend

## User Story

As a user browsing Explore Cards, I want to see card images for all cards,
including those with Portuguese names like "Teste de Resistencia" and
"Remora Mistica".

## Objective

Fix the image resolution chain so cards with Portuguese-only names or
unusual set codes still display images via Scryfall.

## Dev Notes

**Current image fallback chain (CardTile.tsx):**
1. `scryfallImageUrl(setCode, collectorNumber)` — by set+number
2. On error → `scryfallImageByName(name)` — by exact English name
3. On error → placeholder SVG

**Problem analysis:**
- Cards stored with Portuguese names (`name_pt`) but `scryfallImageByName`
  uses the name as-is. Scryfall `named?exact=` requires the **English** name.
- If `name_en` is available in the card data, use it for the Scryfall lookup.
- If only `name_pt` is available, the name-based fallback will fail.

**Fix approach:**
1. Check `CardTile.tsx` — what field is used for the image name fallback?
   Should use `card.name_en` (English name), not `card.name_pt` or
   `card.name` (which may be Portuguese).
2. Check `Cards.tsx` — what fields does the API return? The `/cards` endpoint
   returns canonical cards which have both `name_en` and `name_pt`.
3. Check `scryfallImageUrl` — if `set_code` or `collector_number` is missing
   or malformed, the primary URL will 404. Ensure the MYP→Scryfall set code
   mapping handles these cards.
4. Check `utils/setCodeMap.ts` — verify the set codes for the failing cards
   are mapped correctly.

**Specific cards to investigate:**
- "Teste de Resistencia" (Test of Endurance) — check set_code, collector_number
- "Remora Mistica" (Mystic Remora) — check set_code, collector_number

**Files to touch:**
- `frontend/src/components/CardTile.tsx` — use `name_en` for Scryfall fallback
- `frontend/src/utils/scryfall.ts` — possibly add name_en parameter
- `frontend/src/types/api.ts` — verify Card type has `name_en`
