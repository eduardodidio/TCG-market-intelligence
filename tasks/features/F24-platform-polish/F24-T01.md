# F24-T01: i18n Infrastructure Setup

- **Wave:** 0
- **Status:** planned
- **Depends on:** none
- **Type:** frontend

## User Story

As a user, I want the platform to support multiple languages so that I can
use it in my preferred language (English or Portuguese).

## Objective

Set up react-i18next with EN and PT-BR translation files, language
detection, and localStorage persistence. No strings extracted yet — this
is scaffolding only.

## Dev Notes

- Install: `react-i18next`, `i18next`, `i18next-browser-languagedetector`
- Create `frontend/src/i18n/` directory with:
  - `i18n.ts` — i18next init config (fallbackLng: "en", interpolation, detection)
  - `locales/en.json` — empty structure with top-level keys: `common`, `nav`, `dashboard`, `cards`, `collection`, `decks`, `auth`, `chart`, `market`
  - `locales/pt-BR.json` — same structure, empty values
- Create `frontend/src/contexts/LanguageContext.tsx`:
  - `language` state (en | pt-BR)
  - `setLanguage(lang)` — changes i18next language + saves to localStorage
  - Key: `tcg_language`
- Import i18n config in `main.tsx` (before React render)
- Create `frontend/src/hooks/useLanguage.ts` — context consumer hook
- DO NOT extract strings yet (that's T08)
- DO NOT change any existing component text

## Testing

- Framework: Vitest + React Testing Library
- Test file: `frontend/src/__tests__/i18n.test.ts`
- Test scenarios:
  1. i18next initializes without errors
  2. Default language is "en"
  3. Switching language persists to localStorage
  4. LanguageContext provides language and setLanguage
  5. useLanguage hook works in a wrapped component
