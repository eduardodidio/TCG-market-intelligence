# F173-T03 — Tabelas `meta_decks`/`meta_deck_cards` + `MetagameRepository`

- **Wave:** 1
- **Type:** backend
- **Depends on:** F173-T01
- **Status:** planned

## User Story
As the collector and the API, I want a dedicated repository for metagame snapshots, so
that decklists, rank, meta share and snapshot date are persisted and queried efficiently
on SQLite and Neon PostgreSQL.

## Objective
Criar os modelos SQLAlchemy e o `MetagameRepository` em arquivos novos, sem tocar
`src/database/models.py` nem `src/database/repository.py`.

## Dev Notes
Veja `_brief/00-overview.md` e `_brief/02-persistence.md` (schema e assinaturas exatas).
- `from src.database.models import Base, CardRow, UserCollectionRow` — mesmo `Base`.
- Estilo dos modelos: copiar o de `NewsItemRow` em `src/database/models.py:634`
  (`Mapped[...]`, `mapped_column`, `__table_args__`).
- `Repository` (`src/database/repository.py`) expõe `self.engine`; `from_repo` usa isso.
- Resolução de carta: `from src.decks.importer import _find_card_id` (assinatura
  `(session, name_en, set_code, collector_number) -> int | None`). Fallback para cartas
  duplas: se `" // "` no nome e não resolveu, tentar a primeira face; se nome sem `//`
  não resolveu, tentar `name_en LIKE '<nome> // %'` único.
- `replace_snapshot` recebe objetos com os atributos de `MetaDeckEntry`/`MetaCardEntry`
  (definidos por T04 em paralelo em `src/metagame/sources/base.py`). **Não importe
  `base.py` aqui**; tipar com `Sequence[Any]` / Protocol local e acessar por atributo.
  Nos testes use `types.SimpleNamespace`.
- `card_ids` param de `replace_snapshot`: `dict[(deck_external_id, card_name), int|None]`
  OU resolva internamente se `None` — escolha: aceitar `resolver: Callable | None`;
  se None, usa `self.resolve_card_id` com cache dict local. Documente na docstring.
- Neon: evitar N+1 — `get_deck_cards` e `owned_quantities` são queries únicas com `IN`.

## Implementation details
- `src/metagame/models.py`: `MetaDeckRow`, `MetaDeckCardRow` (+ relationship opcional).
- `src/metagame/repository.py`: `MetagameRepository` com os métodos de `02-persistence.md`.
  `__init__` chama `Base.metadata.create_all(engine, tables=[MetaDeckRow.__table__, MetaDeckCardRow.__table__])`.
  SQLite: habilitar FK cascade não é garantido → `replace_snapshot` deleta cartas
  explicitamente antes dos decks.

## Acceptance criteria
- [ ] Tabelas criadas automaticamente em engine SQLite em memória.
- [ ] `replace_snapshot` idempotente (2x mesmo dia = mesmo nº de linhas).
- [ ] `list_decks` default = snapshot mais recente, ordenado por `rank`, com `total`.
- [ ] `get_deck_cards` batch, `owned_quantities` soma quantidades por card_id do usuário.
- [ ] `resolve_card_id` cobre exato, nome único, carta dupla, não encontrado.
- [ ] Cobertura ≥ 90% em `src/metagame/models.py` e `repository.py`.

## Test scenarios
- Happy: salvar 3 decks c/ cartas → list por formato retorna rank 1..3.
- Edge: dois snapshots (ontem/hoje) → default retorna hoje; `snapshot_date=ontem` retorna ontem.
- Edge: formato sem dados → `([], 0)` e `latest_snapshot_date → None`.
- Edge: carta não resolvida → `card_id NULL` persistido.
- Error: `get_deck(999)` → None.
- Boundary: `limit=1, offset=2`; `owned_quantities` com lista vazia → `{}`; usuário com
  2 linhas da mesma carta (qty 1 + 3) → 4.
- Idempotência: `replace_snapshot` 2x.
- `list_formats` com 2 formatos.
