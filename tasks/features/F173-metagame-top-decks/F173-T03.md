## User Story
As the collector and the API, I want a dedicated repository for metagame snapshots, so
that decklists, rank, meta share and snapshot date are persisted and queried efficiently
on SQLite and Neon PostgreSQL.

## Objective
Criar os modelos SQLAlchemy e o `MetagameRepository` em arquivos novos, sem tocar
`src/database/models.py` nem `src/database/repository.py`.

## Notes from Developer
- `replace_snapshot(fmt, source, snapshot_date, decks, card_ids=None, *, resolver=None)`:
  both options are supported. Priority: `card_ids[(external_id, card_name)]` → `resolver(card)` →
  `self.resolve_card_id` memoised per call by `(name.lower(), set_code, collector_number)`.
- Card ids are resolved **before** the write transaction opens. Resolving inside it opened a
  nested `Session` which, on SQLite `:memory:` (single shared connection), rolled back the
  pending inserts. T09 resolvers should not write to the DB.
- `list_formats()` `deck_count` = number of decks in the format's **latest** snapshot; sorted by format.
- `get_deck_cards(ids)` returns a key for every requested id (`[]` when the deck has no cards).
- Known limitation (inherited from `_find_card_id`): name-only resolution returns `None` when a
  name has several printings (e.g. "Sol Ring" in many sets), unless adapters provide
  set/collector number. T05/T10 valuation may want a name-based price fallback — flag for TechLead.
- Pre-existing, unrelated: `tests/unit/database/` has 50 failures (SQLite FK errors in
  `test_repository_marketplace.py` etc.). They reproduce with this task's files removed.
- Parallel Wave agents share `.coverage` in the worktree, which gets corrupted; run with a private
  `COVERAGE_FILE=...` to get accurate numbers.
