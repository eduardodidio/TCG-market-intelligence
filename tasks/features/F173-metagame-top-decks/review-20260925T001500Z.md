## 1. Architecture

- Clean vertical slice: `src/metagame/` package (models/repository/http/sources/
  collector/valuation) never touches `src/database/models.py` or
  `src/database/repository.py`; new tables share `Base` and are created via
  `Base.metadata.create_all(engine, tables=[...])`, exactly as the plan required.
- `valuation.py` is dependency-free (no DB imports) and pure — good, matches T05's
  intent and is trivially testable.
- `collector.py` never imports concrete adapters (`edhrec`/`mtgtop8`); it takes an
  injected `sources: Mapping[str, MetaSource]`, keeping the format→source binding in
  `sources/__init__.py` only. Per-format `try/except` isolation means one broken
  source doesn't kill the whole run (AC2 spirit).
- `repository.py` imports `_find_card_id` from `src.decks.importer` — a private
  (`_`-prefixed) helper reused across package boundaries. Not blocking (it's read-only
  reuse of proven card-matching logic, not a cyclic dependency), but it's technically
  reaching into another package's private API. **IMPORTANT, non-blocking**: consider
  promoting `_find_card_id` to a public shared helper in a follow-up so `metagame`
  doesn't depend on `decks`' internals.
- Only `T15` touches shared files (`app.py`, `main.py`, README, locales, `.gitignore`),
  exactly as planned; `App.tsx`, `Layout.tsx`, `database/models.py`, `repository.py`
  are untouched. `/decks/ranking` route is reused via query params (`view`, `format`),
  no new route added — matches the "no rota nova" constraint.

## 2. Code quality

- `PoliteFetcher` (T04): robots.txt checked per host before every request, cached per
  origin; conservative fail-closed defaults (`disallow_all=True` on network error or
  5xx from `robots.txt`, `allow_all=True` only on a definite 4xx meaning "no robots.txt
  file"); `min_interval_s=3.0` enforced, and `Crawl-delay` from robots.txt used when
  larger. Retry/backoff via `tenacity`, honoring `Retry-After` up to a 300s cap. This
  satisfies AC3.
- `collect_metagame` resolves all card IDs *before* opening `replace_snapshot`'s write
  transaction (comment explains why — the resolver opens its own sessions). Good call,
  avoids nested-transaction/session interleaving bugs.
- `MetagameRepository.replace_snapshot` deletes cards explicitly instead of relying on
  `ON DELETE CASCADE` (SQLite doesn't enforce it by default) — correct and explicitly
  commented as to why.
- `router/meta_decks.py`: no N+1 (`get_deck_cards` batches by `IN`, prices/owned/images
  are single batched queries), `owned_pct`/`missing_value_brl` correctly `None` for
  anonymous users via `get_optional_user`.
- `valuation.value_meta_deck`: basic lands priced at R$0 and counted as owned, handles
  the "all-basics" edge case (`has_value` check) so an all-land bracket doesn't report
  `total_value_brl=None`. Percentages use `ROUND_HALF_UP` consistently. Good edge-case
  coverage confirmed in `test_valuation.py`.
- CLI (T12/T15) duplicates a small `_resolve_db` callback from `src/cli/main.py` with an
  explicit comment explaining why (avoiding a circular import) — acceptable, it's 4
  lines, not worth a shared module for this scope.
- Wave-4 dev caught and fixed a real gap: `bats/collect-metagame.bat` from T12 was never
  actually committed because `bats/` is gitignored and nobody used `git add -f`. This is
  exactly the kind of cross-Wave regression TechLead should watch for — it was caught
  and corrected within the feature, no action needed now, but flagged as a retro seed
  below.

## Retrospective Seeds

- **Pattern:** A file created inside a `.gitignore`'d directory (`bats/`) was marked
  "done" by its owning task (T12) but never actually reached git because nobody ran
  `git add -f`. It was silently missing until the next Wave's dev happened to notice.
- **Role(s) affected:** developer, architect
- **Lesson:** When a task's file list includes a path under a gitignored directory
  (check `.gitignore` before closing the task), the task's Definition of Done must
  include `git status --ignored` (or an explicit `git add -f <path>` + `git show
  HEAD:<path>`) to confirm the file actually landed in the commit, not just on disk.

- **Pattern:** Registration-only Waves (a task that only wires an already-built module
  into a shared entrypoint, like T15 here) are exactly where "planned but not actually
  connected" bugs hide, because the interesting logic was already tested in isolation
  in an earlier Wave.
- **Role(s) affected:** architect, developer
- **Lesson:** Keep pairing every registration-only Wave with a small dedicated
  `test_*_registration.py` (as T15 did here) that imports the real app/CLI and asserts
  the route/command is actually reachable — don't rely on the earlier Wave's unit tests
  to catch a missing wire-up.
