# F173-T04 — `PoliteFetcher` (robots, rate limit, cache, retry) + Protocol `MetaSource`

- **Wave:** 1
- **Type:** backend
- **Depends on:** F173-T01
- **Status:** planned
- **Maps to AC:** AC3, AC8, AC9

## User Story
As the maintainer, I want every external metagame request to go through one polite HTTP
layer, so that we respect robots.txt/ToS, never hammer a site, and reuse cached pages.

## Objective
Implementar `src/metagame/http.py` e o contrato de fontes `src/metagame/sources/base.py`
+ registry vazio em `sources/__init__.py`.

## Dev Notes
Veja `_brief/00-overview.md` e `_brief/01-sources-and-collection.md` (assinaturas exatas).
- Deps já existentes: `httpx`, `tenacity`, `structlog`; stdlib `urllib.robotparser`,
  `hashlib`, `json`, `time`. **Não adicionar dependências.**
- Leia o ADR de T01 para UA, intervalos e TTLs definidos; use-os como defaults.
- `robots.txt`: baixar via o mesmo `httpx.Client` (não `RobotFileParser.read()`, que usa
  urllib sem proxy/UA) e `parser.parse(text.splitlines())`. 404 em robots → tudo permitido;
  erro de rede em robots → tratar como "não permitido" (conservador) e logar.
- Injetar `clock`/`sleep` para testar rate limit sem dormir. Injetar `client` (use
  `httpx.MockTransport` nos testes).
- Cache em `cache_dir` (default `data/cache/metagame/`), criar com `mkdir(parents=True, exist_ok=True)`.
  `data/cache/` ainda não está no `.gitignore` (T15 adiciona) — não commitar cache.
- Logging com `structlog.get_logger()` (padrão `src/services/news_fetcher.py`).

## Implementation details
- `src/metagame/http.py`: `PoliteFetcher`, `RobotsDisallowed`, `FetchError`.
  `get_text(url, ttl_hours=None, use_cache=True)`, `get_json(...)`; `use_cache=False`
  suporta a flag `--no-cache` da CLI (ainda grava o cache).
- `src/metagame/sources/base.py`: `FORMATS`, `MetaCardEntry`, `MetaDeckEntry`, `MetaSource`

  `def get_sources(fetcher) -> dict[str, MetaSource]: return {}` com comentário
  `# populated by F173-T12`.

## Acceptance criteria
- [ ] URL desautorizada por robots → `RobotsDisallowed`, sem request à URL.
- [ ] Dois GETs no mesmo host respeitam `min_interval_s` (ou `Crawl-delay` maior).
- [ ] Cache hit dentro do TTL não chama transport; expirado refaz request.
- [ ] 429/5xx fazem retry (máx 3) e depois `FetchError`; 404 → `FetchError` sem retry.
- [ ] Header `User-Agent` enviado.
- [ ] Cobertura ≥ 90% em `http.py` e `base.py`.

## Test scenarios
- Happy: GET permitido → texto; segundo GET → do cache (transport chamado 1x + robots 1x).
- Edge: `Crawl-delay: 10` > min_interval → sleep ≥ 10.
- Edge: robots 404 → permitido. Robots com erro de rede → RobotsDisallowed.
- Error: 429 com `Retry-After: 2` → sleep(2) e retry; 500 x3 → FetchError; JSON inválido em `get_json` → FetchError.
- Boundary: TTL exatamente expirado; `ttl_hours=0` sempre refaz; hosts diferentes não compartilham rate limit.
- `normalize_colors("gUw")` → `"WUG"`; `""`/None → None.
