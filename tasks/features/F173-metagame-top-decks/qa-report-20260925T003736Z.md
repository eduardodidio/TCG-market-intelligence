## Live / network checks (pending-user)

This sandbox's outbound HTTPS proxy returns `403` for `edhrec.com`/`mtgtop8.com`
(CONNECT blocked), so a real end-to-end collection run against the live sources could
not be executed here. What *was* verified live in this sandbox:
- `python -m src.cli.main collect-metagame -f commander --limit 2 --dry-run` runs to
  completion, logs `metagame_robots_unreachable` → `metagame_robots_disallowed` →
  `edhrec_top_list_failed` → summary `0 formats collected with data, 0 decks, 0 cards`,
  and exits 0. This confirms the fail-closed safety path (AC3) end-to-end without
  needing live network, but does **not** confirm a real collection against EDHREC/
  MTGTop8 in production. **Recommend the user run `collect-metagame` once from a
  machine with real network access (e.g. via `bats/collect-metagame.bat` or directly)
  before relying on `/api/v1/meta-decks` in `homol`,** to confirm the live adapters
  parse real EDHREC/MTGTop8 responses correctly (the unit tests use fixtures, not live
  HTML/JSON).
- Browser exercise of `/decks/ranking?view=meta&format=commander` was not performed
  (no dev server / browser available in this headless run); component-level tests
  (`MetaDecksPanel`, `MetaDeckRow`, `TopDecksPage`) cover the UI logic but a manual
  click-through is still pending-user.
