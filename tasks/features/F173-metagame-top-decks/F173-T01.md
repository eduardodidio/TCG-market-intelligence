# F173-T01 — SPIKE de fontes de metagame + ADR + fixtures + scaffolding

- **Wave:** 0
- **Type:** docs / spike
- **Depends on:** —
- **Status:** planned

## User Story
As the product owner, I want a short, documented evaluation of metagame data sources
(ToS, robots.txt, formato do dado, estabilidade), so that we only collect data we are
allowed to collect and the adapters are built against the right source.

## Objective
Time-boxed (~15 min) SPIKE que escolhe a fonte por formato, registra em ADR, salva
fixtures reais para os testes dos adapters e cria os diretórios que as Waves seguintes usam.

Veja `_brief/00-overview.md` e `_brief/01-sources-and-collection.md`.

- ADRs existentes: `docs/adr/0001…0013-*.md`, formato: `# ADR-00NN: Title` / `## Status` /
  `## Context` / `## Decision` / `## Consequences` (ver `docs/adr/0013-guest-user-role-system.md`).

- Pesquisa: WebFetch/WebSearch/curl são permitidos neste SPIKE (proxy do ambiente;
  ver `/root/.ccr/README.md` se falhar TLS). Buscar p/ cada candidata: `robots.txt`,
  página de Termos, se existe API/export oficial, URL da página de meta por formato,
  URL/format da decklist, campos (rank, arquétipo, meta share %, nº decks, data, cartas).
  Candidatas: EDHREC (Commander; JSON em `json.edhrec.com/pages/...`), MTGTop8,
  MTGGoldfish, mtgdecks.net; opcional Moxfield/Archidekt.
- Critério de descarte: ToS proíbe coleta automatizada OU robots.txt desautoriza as URLs
  necessárias. Critério de desempate: menor nº de requests/coleta, dado estruturado
  (JSON/texto) > HTML, presença de meta share.
- Sem rede? Escreva fixtures sintéticas fiéis à estrutura documentada publicamente e marque
  "fixtures sintéticas — revalidar na 1ª coleta real" no ADR.

## Implementation details
1. `docs/adr/00NN-metagame-deck-sources.md` com: matriz fonte × {ToS, robots, formato,
   campos, requests/coleta, risco}; **decisão por formato** (tabela `SOURCE_FOR_FORMAT`);
   política de coleta (UA identificado, ≥3s/host ou Crawl-delay, cache 24h páginas de meta /
   7d decklists, frequência semanal, atribuição + link para a fonte na UI);
   URLs exatas que os adapters vão usar; consequências (fragilidade de scraping, plano B).
2. Fixtures em `tests/fixtures/metagame/<source>/`: p/ cada fonte escolhida, 1 página de
   meta de 1 formato + 1–2 decklists (reduzir a ≤ 200 KB cada; remover scripts/ads se HTML).
   Incluir `README.md` na pasta com URL de origem e data da captura.
3. Scaffolding: `src/metagame/__init__.py` (docstring "Metagame top decks (F173)"),
   `src/metagame/sources/` (diretório vazio c/ `.gitkeep` — T04 cria os `.py`),
   `tests/unit/metagame/__init__.py`, `frontend/src/components/meta/.gitkeep`.
4. Se a fonte construída escolhida ≠ MTGTop8, atualizar a linha T08 em `F173-README.md`
   e `F173-T08.md` com o nome da fonte (único ajuste permitido nos arquivos de plano).

## Testing
Spike/docs — sem testes novos. Rodar `pytest tests/unit/metagame -q` (coleta vazia OK)
e `ruff check src/metagame`.

## Test scenarios
- Happy: fonte permitida e com dados → escolhida.
- Edge: fonte sem meta share (Commander) → ADR define rank por popularidade (`deck_count`).
- Error: fonte bloqueada por ToS/robots → descartada com motivo.
- Boundary: formato sem nenhuma fonte válida → ADR marca formato como "não suportado" e
  T08/T12 o omitem de `SOURCE_FOR_FORMAT`.
