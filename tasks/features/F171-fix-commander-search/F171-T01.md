# F171-T01 — Catalog seeder: enrich existing cards on conflict

**Wave:** 1
**Depends on:** none
**Files to change:**
- `src/catalog/seeder.py`
- `src/database/compat.py` (if `dialect_insert` helper needs adjustment)

## User Story

As a system operator, when I run `catalog seed` after price collection has
already created bare card rows, I want the seeder to UPDATE those rows with
Scryfall metadata (type_line, rarity, color_identity, mana_cost, image_uri)
so that all downstream features (commander search, deck builder, catalog
filters) work correctly.

## Dev Notes

### Current behavior (broken)

```python
# seeder.py line 59-74
stmt = (
    dialect_insert(session.get_bind(), CardRow)
    .values(game="magic", name_en=..., type_line=..., ...)
    .on_conflict_do_nothing(index_elements=["game", "set_code", "collector_number"])
)
```

When a card already exists (created by `Repository.upsert_card` with NULL
metadata), the `on_conflict_do_nothing` silently discards the Scryfall data.

### Fix

Change `on_conflict_do_nothing` to `on_conflict_do_update` for the metadata
columns. The update should only overwrite NULL values OR always overwrite with
Scryfall data (Scryfall is the authoritative source for these fields).

Recommended approach -- always overwrite metadata from Scryfall since it is
the canonical source:

```python
stmt = (
    dialect_insert(session.get_bind(), CardRow)
    .values(game="magic", name_en=..., type_line=..., ...)
    .on_conflict_do_update(
        index_elements=["game", "set_code", "collector_number"],
        set_={
            "type_line": stmt.excluded.type_line,
            "rarity": stmt.excluded.rarity,
            "color_identity": stmt.excluded.color_identity,
            "mana_cost": stmt.excluded.mana_cost,
            "image_uri": stmt.excluded.image_uri,
            "name_pt": stmt.excluded.name_pt,
        },
    )
)
```

### Important: dialect_insert compatibility

Check `src/database/compat.py` to see if the `dialect_insert` helper returns
a PostgreSQL or SQLite insert object. The `on_conflict_do_update` API differs
slightly between `sqlalchemy.dialects.postgresql.insert` and
`sqlalchemy.dialects.sqlite.insert`. The `excluded` pseudo-table is available
on both but verify the syntax works for the project's dual-dialect setup.

### Update SeedResult counter

Currently the code increments `cards_inserted` when `rowcount > 0` and
`cards_skipped` otherwise. With `on_conflict_do_update`, updates also return
`rowcount > 0`. Add a `cards_updated` counter (already defined in the
dataclass but never incremented) to distinguish inserts from updates. One way:
check if `rowcount > 0` and the card already existed (use a pre-check or
just count all as "upserted").
