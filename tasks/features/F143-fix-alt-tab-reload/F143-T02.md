# F143-T02 — Remove redundant visibilitychange handlers from DeckList + MyCollection

**Status:** pending
**Wave:** 0
**Depends on:** --

## Objective

Remove the hand-rolled `visibilitychange` handlers from `DeckList.tsx` and
`MyCollection.tsx`. These duplicate functionality that belongs in hooks, and
they add unnecessary API call cascades on tab focus.

## Changes

### 1. `frontend/src/pages/DeckList.tsx`

- Remove the entire `useEffect` block at lines 38-47 (the visibilitychange
  handler with 30s debounce).
- Remove `lastFetchedAtRef` (line 18) since it is only used by that handler.
- The deck list will still load on mount via the `loadDecks()` effect (line
  33-35). Users can navigate away and back to get fresh data, or the page
  can be enhanced later with `useApi` + `refetchOnFocus` if needed.
- Do NOT refactor DeckList to use `useApi` in this task — that would be a
  larger change with higher risk. Just remove the redundant handler.

### 2. `frontend/src/pages/MyCollection.tsx`

- Remove the entire `useEffect` block at lines 408-418 (the visibilitychange
  handler that increments `refreshKey`).
- Remove `lastFetchedAtRef` (line 406) since it is only used by that handler.
- MyCollection already refetches when the user interacts (search, filter,
  sort, refresh button, scan). The auto-refetch on tab focus causes the
  entire card grid to re-render, which is the most visible "page reload"
  the user complains about.

## Acceptance Criteria

- [ ] No `visibilitychange` listener in DeckList.tsx.
- [ ] No `visibilitychange` listener in MyCollection.tsx.
- [ ] Both pages still load data on mount.
- [ ] Both pages still refresh data on explicit user actions (navigate, search, refresh button).
- [ ] Existing tests pass (`cd frontend && npm test`).
- [ ] No regressions in DeckList or MyCollection test suites.
