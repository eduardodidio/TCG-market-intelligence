# F93-T04 — Graceful 401 Redirect with Return URL

**Wave:** 1
**Status:** planned
**Estimate:** XS (extra small)

## User Story

As a user whose session has fully expired (both tokens invalid), I want to be redirected to the login page with a message explaining what happened, and after logging in I want to return to the page I was on.

## Dev Notes

### Current behavior
- `handleUnauthorized()` redirects to `/login` but does NOT preserve the current URL
- ProtectedRoute uses `returnTo` query param — but `handleUnauthorized()` doesn't
- No user-facing message explaining why they were redirected

### Implementation

1. **Update `frontend/src/api/client.ts`**:
   - In the final redirect (after refresh fails), use `window.location.pathname` to build: `/login?returnTo=${encodeURIComponent(currentPath)}&expired=1`
   - Skip if already on `/login` (existing guard)

2. **Update `frontend/src/pages/Login.tsx`**:
   - Read `expired` query param
   - If present, show amber banner: "Your session has expired. Please log in again." (i18n key: `auth.sessionExpired`)
   - After successful login, redirect to `returnTo` param (already works via line 19)

3. **Add i18n key**:
   - `auth.sessionExpired`: EN "Your session has expired. Please log in again." / PT-BR "Sua sessão expirou. Faça login novamente."

### Files
- `frontend/src/api/client.ts` — add returnTo + expired params to redirect
- `frontend/src/pages/Login.tsx` — show expired session banner
- `frontend/src/i18n/locales/en.json` — 1 key
- `frontend/src/i18n/locales/pt-BR.json` — 1 key

## Testing
