# F93-T01 — Silent Token Refresh on 401

**Wave:** 0
**Status:** planned
**Estimate:** S (small)

## User Story

As a logged-in user, when my access token expires mid-session, I want the app to silently refresh my token using the refresh token so I don't get kicked to the login page unexpectedly.

## Dev Notes

### Current behavior
- `client.ts` `handleUnauthorized()` (line 10-16): on any 401, immediately clears tokens and redirects to `/login`
- Refresh token (30d) is only used on AuthContext mount — never during normal API calls
- User loses session after 24h even though refresh token is valid for 30 days

### Implementation

1. **Create `frontend/src/hooks/useAuthRefresh.ts`** — utility module (not a hook, just exported functions):
   - `tryRefreshToken()`: reads refresh token from localStorage, calls `POST /api/v1/auth/refresh`, stores new tokens, returns success/failure
   - `isRefreshing` flag + promise deduplication: if multiple 401s fire simultaneously, only one refresh attempt runs; others await the same promise

2. **Update `frontend/src/api/client.ts`**:
   - Replace `handleUnauthorized()` with `handleUnauthorizedWithRetry(retryFn)`
   - On 401: call `tryRefreshToken()`. If refresh succeeds, retry the original request once with new token. If refresh fails (401/network error), then clear tokens + redirect to `/login` (current behavior)
   - Add a `_isRetry` internal flag to prevent infinite retry loops

3. **Key edge case**: `POST /auth/refresh` itself returns 401 → do NOT retry, go straight to login redirect

### Files
- `frontend/src/api/client.ts` — modify `handleUnauthorized`, all 4 API methods
- `frontend/src/api/useAuthRefresh.ts` — new file (pure functions, no React)
