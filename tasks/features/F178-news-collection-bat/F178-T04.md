## User Story
As the site owner running the local routine, I want a `fetch-news` command with a dry-run source check and a meaningful exit code, so that the `.bat` can tell me when collection failed.

## Objective
Create a standalone click command `fetch_news_command` in a new module (registered in `main.py` later by T07).

## Implementation details
- Options: `--db`, `--max-per-source` (int, default 20, `click.IntRange(1, 200)`), `--check-sources` (flag), `--source` (multiple).
- Output: summary block identical to old command + per-source lines `  [OK]  MTGGoldfish  http=200 entries=20 new=5` / `  [FAIL] MTG Official http=404 error=...`.
- `--check-sources` → `fetch_news(None, dry_run=True, ...)`, no Repository created.
- `ctx.exit(1)` when no source `ok`.

## Acceptance criteria
- [ ] `python -c "from src.cli.news_cmd import fetch_news_command"` works without importing `src.cli.main`.
- [ ] Exit code 0/1 as specified.
- [ ] `--check-sources` creates no DB connection (Repository not instantiated).
- [ ] Unknown `--source` → usage error (exit 2).
- [ ] Coverage of `news_cmd.py` ≥ 90%; `ruff check src/` clean.

## Testing

- Patch `src.services.news_fetcher.fetch_news` (or pass a MockTransport-backed setup) — no network.
- Run: `pytest tests/cli/test_news_cmd.py -v` then `ruff check src/`.

## Test scenarios
- Happy: mixed sources (1 ok, 1 fail) → exit 0, both lines printed, summary numbers match.
- Error: all fail → exit 1, `[FAIL]` lines.
- Dry run: `--check-sources` → `fetch_news` called with `dry_run=True`, `repo=None`; Repository not constructed (patch & assert not called).
- `--source mtggoldfish` (case-insensitive) filters sources; unknown name → exit 2.
- Boundary: `--max-per-source 0` → rejected by IntRange; `200` accepted.
- `--db sqlite:///...` explicit URL used over auto-detect.
