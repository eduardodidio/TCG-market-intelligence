# F178-T08 — Live source validation (user machine) and source pruning

- **Wave:** 4
- **Type:** ops / test
- **Depends on:** F178-T07
- **Status:** planned
- **Maps to AC:** AC8, AC10

## User Story
As the site owner, I want the default feed list to contain only feeds that actually respond, so that the first `fetch-news.bat` run fills the News page.

## Objective
Run `fetch-news --check-sources` against the real internet, prune/fix broken URLs in `SOURCES`, then run one real collection into Neon.

## Dev Notes
Veja `_brief/00-overview.md`, `_brief/01-diagnosis.md` e `_brief/02-fetcher.md`.
- The cloud sandbox blocks outbound HTTP to feed hosts (proxy 403). If `--check-sources` shows all failures with proxy/CONNECT errors, **stop and ask the user** to run it locally:
  `python -m src.cli.main fetch-news --check-sources` and paste the output.
- Writing to Neon (shared production data) requires explicit user confirmation — the real run (`bats\fetch-news.bat`) is executed **by the user**, not the agent.
- Candidate replacements if a default fails: Scryfall `https://scryfall.com/blog/rss` ↔ `/blog/feed.atom`; Wizards news — if no working RSS exists, drop it rather than scraping HTML (out of scope).
- Keep at least 2 working sources; if fewer, stop and ask.

## Implementation details
- Edit only the `SOURCES` list in `src/services/news_fetcher.py` (and any test that asserts default source names).
- Append results to the "Live validation log" section of `docs/prd/F178-news-collection-bat.md` (date, source, http, entries).

## Acceptance criteria
- [ ] `--check-sources` output (from user or sandbox) recorded in the PRD.
- [ ] Every remaining default source `ok=True` with `entries > 0`.
- [ ] After the user runs `bats\fetch-news.bat`, `GET /api/v1/news/status` reports `total_items > 0` and the News page shows the grid.
- [ ] `pytest tests/services/test_news_fetcher.py tests/cli/test_news_cmd.py -q` still green.

## Testing
- Live: `python -m src.cli.main fetch-news --check-sources` (no writes) — record per-source status in the PRD validation log; if the sandbox proxy blocks feeds, record it as pending-user.
- Automated: `pytest tests/services/test_news_fetcher.py tests/cli/test_news_cmd.py tests/api/test_news.py -q` (no network in unit tests).
- Regression: `ruff check src/` and `cd frontend && npm test` stay green.

## Test scenarios
- Happy: ≥2 sources ok, real run inserts items, second run inserts 0 (idempotent).
- Error: a source 404/403 → removed or URL fixed; all fail → escalate to user.
- Edge: a source returns HTML instead of XML → recorded as `FeedParseError`, removed.
- Boundary: `--max-per-source 30` (value used by the `.bat`) respected.
