# F119-T03: Seeder + Catalog + Cleanup Dialect Guards

**Status:** planned
**Wave:** 1 (depends on T01, parallel with T02)

## User Story

As a developer, I want the catalog seeder, catalog API, and cleanup
utilities to work with both SQLite and PostgreSQL so that catalog
operations work in production on Neon.

## Dev Notes

### 1. seeder.py — Replace sqlite_insert

Replace:
```python
from sqlalchemy.dialects.sqlite import insert as sqlite_insert
```
With:
```python
from src.database.compat import dialect_insert, is_sqlite
```

Locations (2 usages):
- `_upsert_cards_batch()` — CardRow (L60)
- `_upsert_source_cards_batch()` — SourceCardRow (L116)

Pass engine to `dialect_insert()`.

### 2. seeder.py — Guard _setup_sqlite_pragmas()

Replace:
```python
if str(engine.url).startswith("sqlite"):
```
With:
```python
if is_sqlite(engine):
```

PRAGMAs should only run for SQLite. PostgreSQL uses WAL by default and
enforces FKs natively.

### 3. catalog.py — Verify raw SQL compatibility

The catalog router uses raw SQL with `'liga_' || CAST(c.id AS TEXT)`.
This syntax works identically in PostgreSQL — `||` is the string
concatenation operator in both dialects. **No changes needed.**

Verify these 5 query locations still work:
- L107, L120, L244, L290, L327

### 4. cleanup.py — Guard VACUUM calls

VACUUM in PostgreSQL is automatic (autovacuum). Manual VACUUM is valid
but unnecessary and can be slow. Guard the 4 VACUUM calls:

```python
from src.database.compat import is_sqlite

# Replace:
conn.execute(text("VACUUM"))

# With:
if is_sqlite(engine):
    conn.execute(text("VACUUM"))
```

Locations: L122, L419, L638, and cli/main.py L1314 (but that's T04).

### Files changed

- `src/catalog/seeder.py` — import swap + 2 upserts + PRAGMA guard
- `src/api/routers/catalog.py` — no changes (verify only)
- `src/database/cleanup.py` — guard 3 VACUUM calls
