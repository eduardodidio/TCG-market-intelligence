# F119-T02: Repository + Achievements Upsert Migration

**Status:** planned
**Wave:** 1 (depends on T01)

## User Story

As a production user, I want price observations, exchange rates, card
legalities, portfolio snapshots, and achievements to be stored correctly
in PostgreSQL using proper upsert semantics.

## Dev Notes

### 1. repository.py — Replace sqlite_insert with dialect_insert

Replace:
```python
from sqlalchemy.dialects.sqlite import insert as sqlite_insert
```
With:
```python
from src.database.compat import dialect_insert, is_sqlite
```

Then every `sqlite_insert(SomeRow)` becomes `dialect_insert(self.engine, SomeRow)`.

Locations (5 usages):
- `record_price_observations()` — PriceObservationRow (L386, L424)
- `upsert_exchange_rate()` — ExchangeRateRow (L2101)
- `upsert_legalities()` — CardLegalityRow (L2505)
- `upsert_portfolio_snapshot()` — PortfolioSnapshotRow (L3927)

### 2. repository.py — Guard _setup_sqlite_pragmas()

Already guarded with `if str(self.engine.url).startswith("sqlite")` — just
verify it works with a postgresql:// URL (should be a no-op).

### 3. repository.py — Guard _ensure_fk_constraints()

Already guarded with `if not str(self.engine.url).startswith("sqlite"): return`.
PostgreSQL enforces FK constraints natively from the model definitions.
No change needed — just verify.

### 4. achievements.py — Replace sqlite_insert

Replace:
```python
from sqlalchemy.dialects.sqlite import insert as sqlite_insert
```
With:
```python
from src.database.compat import dialect_insert
```

Locations (2 usages):
- `_grant_achievement()` — AchievementRow (L259)
- `grant_achievement()` — AchievementRow (L281)

Need to pass the engine to `dialect_insert()`. The service functions receive
a `Session` — get engine via `session.get_bind()`.

### Files changed

- `src/database/repository.py` — import swap + 5 call sites
- `src/services/achievements.py` — import swap + 2 call sites
