# F95-T05: Migrate all remaining empty states to shared component

**Wave:** 2
**Depends on:** T01

## User Story

As a user, I want all empty states across the application to look and
behave consistently so that the platform feels polished and I always know
what action to take.

## Dev Notes

### Pages to migrate

1. **DeckList** (`frontend/src/pages/DeckList.tsx`, lines 79-89)
   - Current: bare `<div>` with `text-center py-12 text-slate-400`
   - Target: `<EmptyState title={t("decks.noDecks")} description={t("decks.noDecksHint")} icon={/* deck icon */} actions={[{ label: t("decks.importDeck"), onClick: () => setShowImport(true) }]} />`
   - data-testid: keep `deck-empty-state` by wrapping or adjusting

2. **Evaluations** (`frontend/src/pages/Evaluations.tsx`, lines 111-123)
   - Current: bare `<div>` with text + Link to /cards
   - Target: `<EmptyState title={t("evaluations.empty")} description={t("onboarding.evalEmptyDesc")} icon={/* search icon */} actions={[{ label: t("nav.exploreCards"), onClick: () => navigate("/cards") }]} />`

3. **Schedules** (`frontend/src/pages/Schedules.tsx` or wherever schedules empty state lives)
   - Current: uses `t("schedules.empty")` as plain text
   - Target: wrap in `<EmptyState message={t("schedules.empty")} actions={[{ label: t("schedules.new"), onClick: openNewScheduleForm }]} />`

4. **Top Decks** (`frontend/src/pages/TopDecksPage.tsx`)
   - Check for `t("topDecks.noDecks")` usage
   - Wrap in EmptyState with deck icon and "Import a deck" CTA

5. **Scans** (`frontend/src/pages/Scans.tsx` or equivalent)
   - Check for `t("scans.noScans")` usage
   - Wrap in EmptyState with action to start a new scan

6. **Admin sections** -- check for bare "no data" strings in admin tabs.

### Approach

- Import `EmptyState` in each file.
- Replace ad-hoc empty state markup with `<EmptyState>`.
- Preserve existing `data-testid` attributes where tests depend on them
  (wrap EmptyState in a div with the testid if needed).
- Use `useNavigate()` for link-style actions (navigate to another page).
- Use existing handler callbacks for in-page actions (open modals).

### i18n keys needed

- `onboarding.evalEmptyDesc` (new description for evaluations empty state)
- Other pages may already have adequate strings; reuse where possible.

## Testing

- **Files:** test files for each migrated page
- Tests per page:
  1. Empty state renders EmptyState component (check for `data-testid="empty-state"`)
  2. Action button triggers correct behavior (navigation or modal open)
  3. Non-empty state still renders content (no regression)
- ~10-12 tests expected across all migrated pages (2-3 per page).
