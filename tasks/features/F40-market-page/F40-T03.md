# F40-T03 -- Frontend: MarketPage Shell + Section Composition

**Wave:** 1 (parallel with T02)
**Depends on:** T01 (backend endpoints)
**Produces:** The MarketPage component and all section wrappers.

## Objective

Build the MarketPage component that composes all market sections into a
single scrolling view. Wire API client functions for the new endpoints.
Create section wrapper components for Top Decks preview and volatile
cards that import existing components from F35/F36.

## Deliverables

### 1. API Client Functions (`frontend/src/api/market.ts`)

Add to existing file:

```typescript
export function fetchMarketSummary(
  params?: Record<string, string>,
): Promise<ApiResponse<MarketSummaryResponse>> {
  return apiGet<MarketSummaryResponse>("/api/v1/market/summary", params);
}

export function fetchVolatile(
  params?: Record<string, string>,
): Promise<ApiResponse<VolatileResponse>> {
  return apiGet<VolatileResponse>("/api/v1/market/volatile", params);
}
```

### 3. TopDecksPreview Component (`frontend/src/components/TopDecksPreview.tsx`)

A compact section showing the top 5 decks by value. Fetches from
`/api/v1/decks/ranking?limit=5&sort_by=total_value`.

Layout:
- Section header: "Top Decks by Value" + "View All" link to `/decks/ranking`.
- Numbered list (1-5). Each row shows: rank, deck name, total value
  (formatted with currency), value change badge (green/red %), and a
  mini `DeckSparkline` (imported from F35).
- Loading: `SkeletonTable` with 5 rows.
- Error/empty: graceful hide (return null) -- this section is optional.

Graceful degradation: if the `/decks/ranking` endpoint returns 404 or
error (F35 not shipped), the component renders nothing (returns `null`).
The parent page does not break.

### 4. VolatileSection Component (`frontend/src/components/VolatileSection.tsx`)

A horizontal scrollable row of volatile cards. Same visual pattern as
`TrendingSection` from F36.

Props:
```typescript
interface VolatileSectionProps {
  period: string;
  currency: string;
}
```

Behavior:
- Fetches from `/api/v1/market/volatile` with period and currency.
- Renders cards using `TrendingCard` from F36 (if available) or a
  simple card tile fallback.
- Section header: "Most Volatile" + "View All" link (optional, could
  link to `/market/movers`).
- Loading/error/empty states.
- Graceful degradation: if endpoint returns empty or errors, hide section.

### 5. MarketPage Component (`frontend/src/pages/MarketPage.tsx`)

The main composition page. Route: `/market`.

Structure:
```
<div>
  <h1>Market Overview</h1>
  <PeriodSelector value={period} onChange={setPeriod} />

  <MarketSummaryKpis data={summaryData} loading={...} currency={...} />

  {/* Trending Gainers -- reuse TrendingSection from F36 */}
  <TrendingSection direction="up" period={period} />
  {/* Fallback: <MoversPreview ... type="gainers" /> */}

  {/* Trending Losers -- reuse TrendingSection from F36 */}
  <TrendingSection direction="down" period={period} />
  {/* Fallback: <MoversPreview ... type="losers" /> */}

  {/* Most Volatile */}
  <VolatileSection period={period} currency={currency} />

  {/* Top Decks */}
  <TopDecksPreview period={period} currency={currency} />
</div>
```

State management:
- `period` state (default "30d"), shared across all sections.
- `currency` from `useCurrency()` hook.
- Summary data fetched via `useApi` with `fetchMarketSummary`.
- Each section component manages its own data fetching internally.

Fallback strategy for F35/F36 dependencies:
- Use dynamic imports with try/catch or conditional rendering.
- If `TrendingSection` import fails, render `MoversPreview` instead
  (already exists, uses `/market/movers` data).
- If `TopDecksPreview` data fails, section is hidden.
- If `VolatileSection` data fails, section is hidden.
- `MarketSummaryKpis` always renders (uses `/market/summary`).

Page title: `Market | TCG Market` (via `useEffect` + `document.title`).

## Constraints

- Each section component fetches its own data (no prop-drilling of API
  responses through MarketPage). This keeps sections independent and
  allows graceful degradation per section.
- MarketPage only manages shared state: period and currency.
- Import F35/F36 components conditionally -- do NOT hard-fail if they
  are not available.
- No authentication required on this page.
- Reuse existing components maximally. If creating a new visual element,
  check first whether KpiCard, MoversTable, MoversPreview, or
  TrendingCard can serve the purpose.
