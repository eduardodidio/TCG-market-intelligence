# F66-T02: Frontend admin page with user table and credit management

**Status:** planned
**Wave:** 1
**Depends on:** T01

## User Story

As an admin, I want a web interface at /admin where I can see all users with
their treasure token balances and quickly add credits to any user, so I can
manage the economy without using the API directly.

## Dev Notes

### New page: `frontend/src/pages/AdminPanel.tsx`

Two sections/tabs:
1. **Users** (default): Table with columns: Name, Email, Admin, Balance, Actions
   - "Add Credits" button per row → opens small input modal
   - "Grant" button confirms and calls PATCH /admin/users/{id}/credits
2. **Dashboard**: Platform stats cards (total users, scans, cards, credits flow)

### New API client: `frontend/src/api/admin.ts`

```tsx
export function fetchAdminUsers(limit?: number, offset?: number)
export function adjustUserCredits(userId: number, amount: number, reason?: string)
export function fetchAdminDashboard()
```

### Admin-only route guard

Create `AdminRoute` component (or extend `ProtectedRoute`):
```tsx
function AdminRoute({ children }) {
  const { user } = useAuth();
  if (!user?.is_admin) return <Navigate to="/" />;
  return children;
}
```

### Update AuthContext / UserProfile type

Add `is_admin: boolean` to the user type in the frontend auth context.

### Route registration in `App.tsx`

```tsx
<Route path="/admin" element={
  <AdminRoute><AdminPanel /></AdminRoute>
} />
```

### Navigation update in `Layout.tsx`

Add admin nav item (conditional on `user.is_admin`):
```tsx
{ to: "/admin", labelKey: "nav.admin", requiresAuth: true, requiresAdmin: true }
```

Update nav filtering logic to check `requiresAdmin`.
