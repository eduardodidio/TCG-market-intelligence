# F126-T02: TreasureModal — Audit & Fix Viewport Centering

**Status:** planned
**Wave:** 0
**Depends on:** none

## User Story

As a user, when I click on the Treasure token in the sidebar, I want the
expanded 3D treasure view to appear truly centered on the full screen, not
visually confined or misaligned.

## Dev Notes

### Current state
- `TreasureModal` already uses `createPortal(modal, document.body)` (line 231)
  and `fixed inset-0 z-[9999]` — DOM-wise it should escape parent transforms.
- `TreasureBalance` lives inside the sidebar `<aside>` which has
  `transform transition-all duration-200` — this means `getBoundingClientRect()`
  for `originRect` is correct, but the CSS stacking context could interfere
  with the backdrop if the sidebar has a higher stacking order.
- Image uses `max-h-[70vh] max-w-[90vw]` which is generous.

### Investigation & potential fixes

1. **Verify z-index stacking**: The sidebar is `z-30`, the modal backdrop is
   `z-[9999]`. This should be fine, but verify the sidebar doesn't create a
   stacking context that puts its children above the portal. If it does,
   ensure the portal's z-index wins.

2. **Ensure image sizing is generous**: Current `max-h-[70vh] max-w-[90vw]`
   is good. Consider bumping to `max-h-[80vh]` to match CardPreviewModal for
   consistency.

3. **Test collapsed sidebar**: When sidebar is collapsed (`w-16`), the
   treasure thumbnail is tiny. Verify the fly-in animation origin calculation
   still works correctly from the collapsed position.

4. **Backdrop blur**: Consider adding `backdrop-blur-sm` to the overlay for
   visual consistency with CardPreviewModal.

### Files
- `frontend/src/components/TreasureModal.tsx`
- `frontend/src/components/TreasureBalance.tsx` (if originRect needs adjustment)

### Acceptance Criteria
- [ ] TreasureModal renders viewport-centered when opened from both expanded and collapsed sidebar
- [ ] Image fills generously (min `max-h-[80vh]`)
- [ ] Backdrop covers entire viewport with no gaps
- [ ] Fly-in animation works correctly from collapsed sidebar thumbnail
- [ ] No visual clipping or z-index conflicts with sidebar
