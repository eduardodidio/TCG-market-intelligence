# F126-T03: Update Tests for Portal Behavior

**Status:** planned
**Wave:** 0
**Depends on:** none

## User Story

As a developer, I want the test suite to correctly validate that modals
render via portals to `document.body`, so regressions in viewport-level
rendering are caught automatically.

## Dev Notes

### Current state
- `CardPreviewModal.test.tsx` has 12 tests that render the modal inline
  and query via `screen.getByTestId`. After T01 adds `createPortal`, these
  tests may need adjustment since the modal DOM will be in `document.body`
  rather than the render container.
- React Testing Library's `render()` + `screen` queries search the whole
  document by default, so most tests should still work. But any tests that
  check the modal's DOM position relative to a parent will need updating.

### Changes required

1. **CardPreviewModal tests**: Verify all existing tests pass after portal
   change. Add one explicit test that confirms the modal renders as a child
   of `document.body`:
   ```ts
   expect(document.body.querySelector('[data-testid="modal-backdrop"]')).toBeInTheDocument();
   ```

2. **TreasureModal tests**: If tests exist, verify they still pass after
   T02 changes. If no test file exists, add basic portal + close tests.

3. **Integration tests**: Verify `CardTile.test.tsx`, `DeckCardTile.test.tsx`,
   `CatalogCardTile.test.tsx` click-to-preview tests still work with portal.
