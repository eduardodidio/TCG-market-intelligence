# F131-T05 — Final Fantasy Set Scan

## User Story

As a collector interested in Magic: The Gathering x Final Fantasy
cards, I want those sets to appear in the catalog with Liga prices so
that I can browse and track prices for FF cards.

## Dev Notes

### Context

The Final Fantasy Universes Beyond collaboration for Magic: The
Gathering has the following Scryfall set codes (verify at seed time):

- **`fft`** — "Final Fantasy" (main set, released 2025-06-13,
  ~286 cards)
- **`ffc`** — "Final Fantasy Commander" (Commander decks,
  released 2025-06-13)
- **`sft`** — "Final Fantasy Starter Kit" (if exists, starter decks)

These need to be confirmed against Scryfall's set list at
`https://api.scryfall.com/sets` before seeding. The set codes may
differ from the above; the developer must verify.

The catalog seeding pipeline is:
1. `catalog seed` — downloads Scryfall bulk data and upserts all cards
   into the `cards` table (this is a global operation; FF cards will be
   included automatically if the bulk data is recent enough).
2. `catalog scan --set <code>` — runs `liga_sweep` with
   `collection_only=False` for a specific set.

### Implementation Steps

This is primarily an operational task (running CLI commands), but may
require a fresh catalog seed if the current bulk data predates the FF
set release.

**Step 1: Verify set codes** -- DONE (see Research Findings above)

**Step 2: Catalog seed (if needed)**

1. Check if FF cards already exist in the catalog:
   ```
   python -m src.cli.main catalog stats
   ```
   And query the DB for FF set codes:
   ```sql
   SELECT set_code, COUNT(*) FROM cards WHERE set_code IN ('fin', 'fic') GROUP BY set_code;
   ```
2. If FF cards are missing, run a fresh catalog seed:
   ```
   python -m src.cli.main catalog seed
   ```
   This downloads the latest Scryfall bulk data (~120MB) and upserts
   all cards. Existing cards are updated; new cards are inserted.

**Step 3: Verify set code mappings** -- DONE (no new mappings needed)

**Step 4: Run Liga scans** (user must run from residential IP)

1. For each confirmed FF set code, run:
   ```
   python -m src.cli.main catalog scan --set fin --delay 5 --batch-size 20
   python -m src.cli.main catalog scan --set fic --delay 5 --batch-size 20
   ```
   Estimated time: `fin` has 599 cards at 5s delay = ~50 min.
   `fic` has 486 cards at 5s delay = ~40 min.
2. Monitor output for errors (edition mismatches, missing cards on
   Liga).
3. After scanning, verify prices appear:
   ```
   python -m src.cli.main catalog stats
   ```

   Alternatively, use the new **Refresh All Set** button (T03) from
   the catalog page to queue price update requests, then run:
   ```
   python -m src.cli.main process-price-requests
   ```

**Step 5: Verify in frontend**

1. Navigate to `/catalog`, filter by the FF set code (`fin` or `fic`).
2. Verify cards appear with images and Liga prices.

### Key Decisions

- This task is mostly operational (running commands), not code changes.
  The developer should document what was done and any issues
  encountered.
- If Liga does not yet have FF cards listed, the scan will return 0
  prices. This is expected for very new sets — document the finding
  and the scan can be re-run later.
- The catalog seed is idempotent; re-running it is safe.
- Liga scans are rate-limited (5s delay between cards by default) and
  can take significant time for large sets. Plan accordingly.
