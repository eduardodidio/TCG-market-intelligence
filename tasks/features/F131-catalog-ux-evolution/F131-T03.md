# F131-T03 — Refresh All Set (Backend Endpoint + Frontend)

## User Story

As a catalog browser, I want to click "Refresh All" for a selected set
so that all cards in that set get queued for Liga price updates in one
action, instead of clicking each card individually.

## Dev Notes

### Context

The catalog currently has no bulk refresh capability. The collection
page's "Refresh All" on `Cards.tsx` iterates over visible cards and
calls `POST /api/v1/cards/{card_id}/refresh-price` sequentially (one
request per card). This is fine for small lists but does not scale for
catalog sets (hundreds of cards).

A better approach for the catalog: a dedicated backend endpoint that
queues all cards in a set at once. The existing
`price_update_requests` table (F130) supports batch insertion.

The `liga_sweep.py` module already supports `collection_only=False`
for catalog mode, and the CLI `catalog scan --set <code>` invokes it.
However, running a full Liga sweep from an API endpoint is not viable
(it takes minutes with Playwright). Instead, the endpoint should queue
individual `price_update_requests` rows for each card in the set,
which the local `process-price-requests` CLI command will pick up.

### Implementation Steps

**Backend: `src/api/routers/catalog.py`**

1. Add a new endpoint: `POST /catalog/scan` (or `/catalog/sets/{set_code}/refresh`).
2. Accept `set_code` as a required parameter (path or body).
3. Query all card IDs in the set from the `cards` table
   (`WHERE set_code = :set_code AND game = 'magic'`).
4. Deduct credits: cost = number of cards in the set (1 credit per card).
   Use `CreditService.check_sufficient()` before deducting.
5. Bulk-insert `price_update_requests` rows for each card in the set
   (use `repo.create_price_update_request(card_id, user_id)` in a loop,
   or add a batch method to the repository).
6. Return `{ status: "queued", set_code, card_count, total_cost }`.
7. Guard: require authentication (`get_current_user`).
8. Guard: check that the set exists in the catalog (return 404 if not).
9. Guard: optionally cap the max cards per request (e.g., 1000) to
   prevent accidental abuse.

**Backend: `src/database/repository.py`** (optional optimization)

- Add `create_price_update_requests_batch(card_ids, user_id)` for
  efficient bulk insertion instead of N individual inserts. Use
  `session.execute(insert(PriceUpdateRequestRow), [{"card_id": cid, "user_id": uid, "status": "pending"} for cid in card_ids])`.

**Frontend: `frontend/src/api/catalog.ts`** (new or extend existing)

1. Add `refreshCatalogSet(setCode: string): Promise<ApiResponse<...>>`
   that calls `POST /api/v1/catalog/scan` with `{ set_code: setCode }`.

**Frontend: `frontend/src/pages/CatalogPage.tsx`**

1. Import `refreshCatalogSet` and `CostBadge`, `CreditConfirmModal`,
   `useCredits`.
2. Add a "Refresh All Set" button next to the results count, visible
   only when a set is selected (`selectedSet !== ""`).
3. Clicking the button opens a `CreditConfirmModal` showing the cost
   (number of cards in the set, available from the set's `card_count`
   in `sets`).
4. On confirm, call `refreshCatalogSet(selectedSet)`.
5. Show progress/queued feedback after the call succeeds.

### Files to Modify

- `src/api/routers/catalog.py` — new `POST /catalog/scan` endpoint
- `src/database/repository.py` — optional batch method for
  `price_update_requests`
- `frontend/src/api/catalog.ts` — new API function (create file or
  extend existing API module)
- `frontend/src/pages/CatalogPage.tsx` — button, modal, state

### Key Decisions

- Queue via `price_update_requests` (not inline Liga sweep) because
  Liga requires Playwright on a residential IP. The API server (Render)
  cannot run Liga directly.
- Credit cost = 1 per card in the set, consistent with per-card refresh.
- The button only appears when a set filter is active, to prevent
  accidentally queuing the entire 100k+ card catalog.
