## User Story
As a mantenedor do TEDHC Market, I want um diagnóstico reproduzível, com números, de por que o histórico dos cards da coleção fica vazio, so that a correção ataque a causa raiz em vez de repetir as tentativas de F33/F34/F112/F168.

## Objective
Confirmar o setup da feature (branch, diretórios, comandos de teste) e entregar um script **read-only** que mede, por entrada da coleção, quais séries de preço existem vs. o que o endpoint atual devolve, e um `diagnosis.md` que confirma/refuta as hipóteses H1–H6.

## Testing
- Framework: pytest. Comando: `pytest tests/scripts/test_diagnose_collection_history.py -q`.
- Fixture: `Repository("sqlite:///:memory:")` ou `tmp_path / "t.db"` — seguir padrão de `tests/test_price_snapshot.py` (cria tabelas via Repository). Inserir linhas com `repo.insert_price_observations([HistoricalPrice(...)])`.

## Test scenarios
- Happy: card normal com 3 dias de `liga_{id}` e 0 source_cards → `current_endpoint_points == 0`, `available_points == 3`, H1 sinalizado.
- Foil: entrada `extras="Foil"` com `liga_{id}_foil` e `liga_{id}` → reporta ambas as séries e flag `mixed_variants`.
- `daily_snapshot` presente para source_card MYP → contado como perdido pelo endpoint atual (H2).
- Mesmo dia com liga + myp → `duplicate_dates >= 1` (H5).
- Edge: entrada com `card_id=None` → diagnóstico `unlinked`, sem exceção.
- Edge: `--entry-id` inexistente → exit code 1 com mensagem.
- Boundary: `--sample 0` → resumo vazio sem divisão por zero.
- Read-only: contagem de `price_observations` idêntica antes/depois de `main()`.
