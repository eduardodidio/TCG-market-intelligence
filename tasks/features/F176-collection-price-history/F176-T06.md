# F176-T06 — Snapshot diário automático ao fim do liga-sweep

**Wave:** 2
**Type:** backend
**Depends on:** F176-T05
**Status:** planned

## User Story
As a colecionador, I want que o histórico ganhe um ponto novo toda vez que a rotina local de preços roda, so that eu não dependa de lembrar de rodar um comando extra.

## Objective
Ao final de um `run_liga_sweep` não-dry-run com ≥1 card processado, chamar `run_daily_snapshot(repo)` (best-effort) e expor a contagem em `LigaSweepResult.daily_snapshot_created`.

## Dev Notes
Veja `_brief/00-overview.md` e `_brief/03-snapshot-backfill.md`.

- `src/collectors/liga_sweep.py`: `LigaSweepResult` (dataclass L23–31), `run_liga_sweep` (L139–305). O bloco final dispara `on_complete` (L283–293) e retorna o resultado. Inserir o snapshot **depois** de `on_complete` e antes do `return`.
- Caminho real de produção: `push-all.bat` → `python -m src.cli.main liga-sweep` → `run_liga_sweep` (CLI registra só o alert hook, `main.py` ~L1181) → por isso a gravação diária vai **dentro** de `run_liga_sweep`, não num hook registrado em `main.py`/`app.py` (arquivos de alto risco do lote).
- Import local dentro da função (`from src.collectors.price_snapshot import run_daily_snapshot`) para evitar ciclo e manter import-time leve.
- O snapshot é global (todas as séries com real ≤30d), idempotente por dia — rodar a cada sweep é seguro.
- `KeyboardInterrupt` durante o sweep: ainda tentar o snapshot (o que já foi gravado vale), exceto se `total_processed == 0`.
- Nunca propagar exceção do snapshot: `log.warning("liga_sweep_daily_snapshot_failed", error=str(exc))`.
- structlog: `log.info("liga_sweep_daily_snapshot", created=n)`.

## Implementation details
- `LigaSweepResult`: `daily_snapshot_created: int = 0` (último campo, com default → construções existentes continuam válidas).
- `run_liga_sweep(..., snapshot_after: bool = True)`; condição: `not dry_run and snapshot_after and total_processed > 0`.
- `tests/collectors/test_liga_sweep_daily_snapshot.py` (novo); revisar `tests/collectors/test_liga_sweep.py` e `tests/collectors/test_liga_scan_wrapper.py` — onde o teste não quer o efeito, passar `snapshot_after=False` ou patch de `src.collectors.price_snapshot.run_daily_snapshot`.

## Acceptance criteria
- [ ] Sweep com ≥1 processado grava `daily_snapshot` de hoje (verificado em SQLite in-memory com provider mockado).
- [ ] `dry_run=True` ou `snapshot_after=False` ou 0 processados → snapshot não chamado.
- [ ] Falha no snapshot não altera contagens nem levanta exceção.
- [ ] Testes existentes de liga_sweep verdes; ruff limpo.

## Testing
- pytest + `pytest-asyncio`/`asyncio.run` conforme padrão de `tests/collectors/test_liga_sweep.py` (copiar o mock de provider e de `repo.get_cards_for_liga_scan` de lá).
- `pytest tests/collectors/test_liga_sweep.py tests/collectors/test_liga_sweep_daily_snapshot.py tests/collectors/test_liga_scan_wrapper.py -q`.
- Patch `asyncio.sleep` para testes rápidos (ver padrão existente).

## Test scenarios
- Happy: 2 cards processados → `run_daily_snapshot` chamado 1×; `result.daily_snapshot_created == retorno mockado`.
- Integração leve: SQLite real + provider fake devolvendo `normal.mid=10` para o card A; card B tem só uma observação real de 3 dias atrás. Após o sweep: A tem `liga/liga_{A}` de hoje e **nenhum** `daily_snapshot` hoje (T05 pula ids com observação real no dia); B tem `daily_snapshot/liga_{B}` de hoje com o preço de 3 dias atrás.
- `dry_run=True` → não chamado; `snapshot_after=False` → não chamado.
- 0 elegíveis → não chamado.
- `run_daily_snapshot` levanta `RuntimeError` → sweep retorna normalmente, `daily_snapshot_created == 0`, warning logado.
- `on_complete` levanta exceção → snapshot ainda roda.
