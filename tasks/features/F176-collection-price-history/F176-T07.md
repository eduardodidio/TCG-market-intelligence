## User Story
As a endpoints de histórico (coleção, métricas, card), I want uma única função que carregue e combine as séries certas, so that as três telas mostrem o mesmo histórico.

## Objective
Criar `src/services/collection_price_history.py` com `load_series`, `first_real_observation` e `build_history`, carregando todas as séries da variante em **uma** query e retornando série mesclada + meta.

Veja `_brief/00-overview.md`, `_brief/02-key-resolution.md` e `_brief/04-api-ui.md`.

## Notes from Developer

- **Backfill marker (ADR 0017 §4):** `resolve_history_keys` (T03) does not emit
  `daily_snapshot_backfill` keys, so `build_history` adds a `daily_snapshot_backfill` key next to each
  `daily_snapshot` key (`_with_backfill_keys`). Both sources count as snapshots in `meta`
  (`SNAPSHOT_SOURCES`) and are excluded from `first_real_observation`. In the merge, backfill still
  gets `UNKNOWN_SOURCE_PRIORITY` (5) instead of 9, because T03's `SOURCE_PRIORITY` doesn't list
  it. It still loses to manual/liga/jsonld/myp. It would only beat a `daily_snapshot` row on the same
  day, which the backfill never writes. Follow-up: add `"daily_snapshot_backfill": 9` to
  `price_history_keys.SOURCE_PRIORITY`.
- **"Single query" AC:** `load_series` runs exactly 1 SELECT on `price_observations`.
  `build_history` runs 2 in total: `load_series` plus the `MIN()` in `first_real_observation`, which
  has no period filter, as the task requires. Both counts are covered by tests.
- `load_series([])` / `first_real_observation` with only snapshot keys skip the query entirely.
- Coverage: `src/services/collection_price_history.py` 100%; 21 tests; ruff check + format clean.
