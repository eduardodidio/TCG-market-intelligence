# F176-T04 — Schemas de resposta: `PriceHistoryMeta`, `meta`, `PriceObservation.source`

**Wave:** 1
**Type:** backend
**Depends on:** F176-T01
**Status:** planned

## User Story
As a frontend da coleção, I want que a resposta de histórico diga a variante, as fontes e desde quando há dados, so that a UI explique o gráfico e o estado vazio.

## Objective
Adicionar campos **opcionais e retrocompatíveis** aos schemas Pydantic de histórico.

## Dev Notes
Veja `_brief/00-overview.md` e `_brief/02-key-resolution.md`.

- `src/api/schemas/collection.py` L44: `CollectionHistoryResponse(observations, summary)` — usado por `/collection/{id}/history` e `/cards/{id}/history` (`cards.py` importa o mesmo schema: verificar com `grep -rn CollectionHistoryResponse src`).
- `src/api/schemas/cards.py` L50: `PriceObservation` — usado em vários endpoints e em `src/analytics/aggregation.py` (`aggregate_weekly` cria novas instâncias). Campo novo precisa de default `None` para não quebrar esses construtores.
- Mudança **somente aditiva** — outras features do lote (F171/F174) podem editar outras classes desses arquivos. Adicionar a classe nova logo acima de `CollectionHistoryResponse`; não reordenar/reformatar o resto do arquivo.
- Pydantic v2 (`BaseModel`, `Literal` de `typing`).

## Test scenarios
- Happy: `PriceHistoryMeta(variant="foil", sources=["liga"], first_observed_at=date(...), real_points=3, snapshot_points=2)` serializa com `model_dump(mode="json")` em datas ISO.
- Default: `CollectionHistoryResponse()` → `meta is None`, `observations == []`.
- Error: `variant="etched"` → `ValidationError`.
- Boundary: `real_points=0`, `first_observed_at=None` válidos.
- Retrocompat: `PriceObservation(observed_at=..., median_price=...)` sem `source` → `source is None`; `aggregate_weekly` continua funcionando (rodar `tests/analytics` se existir teste de aggregation).
