# F112-T05 — CLI Command `backfill-portfolio`

**Wave:** 1
**Status:** planned

## User Story

As an operator, I want a single CLI command to seed portfolio history data, so I can bootstrap the dashboard after deployment.

## Dev Notes

### Location
- `src/cli/main.py` — new Click command `backfill-portfolio`

### Interface
```
python -m src.cli.main backfill-portfolio [OPTIONS]

Options:
  --db TEXT         Database URL (default: env or sqlite:///market_data.db)
  --user-id TEXT    Backfill for a specific user (default: all active users)
  --days INT        Number of days of history to generate (default: 30)
  --skip-prices     Skip acquisition price backfill (only do snapshots)
  --dry-run         Show what would be done without writing
```

### Logic
1. Instantiate `Repository(db_url)`
2. Get target users: specific user_id or all users with collection entries
3. For each user:
   a. Run `backfill_acquisition_prices(repo, user_id)` (unless `--skip-prices`)
   b. Run `backfill_portfolio_snapshots(repo, user_id, days)`
   c. Run `take_snapshot(user_id, repo)` for today's real snapshot
4. Print summary table:
   ```
   User        Prices Updated  Snapshots Filled  Today's Value
   user123     42/50           28/30             R$ 1,234.56
   ```

### Constraints
- Idempotent: safe to run multiple times
- If `--dry-run`, print what would happen without DB writes
- Progress output via `click.echo` (not structlog) for CLI readability

## Testing

- Unit test: verify dry-run produces no DB writes
