# F112-T02 — Backfill Synthetic Portfolio Snapshots

**Wave:** 0
**Status:** planned

## User Story

As a collector, I want to see my portfolio value chart with ~30 days of history, so I can visualize how my collection's value has changed over time.

## Dev Notes

### Location
- `src/collectors/portfolio_backfill.py` (extend from T01)

### Logic: `backfill_portfolio_snapshots(repo, user_id, days=30)`
1. Determine date range: `[today - days, today]`
2. For each date `d` in the range:
   a. Get the user's collection entries (as of that date — use entries where `created_at <= d`)
   b. For each entry with a `card_id`, find the latest `price_observations` row with `observed_at <= d`
   c. If no observation on day `d`, use forward-fill: carry the last known price
   d. Compute `total_value_brl = SUM(price * quantity)` for all entries
   e. Count `priced_card_count` (entries that had a price) and `total_card_count`
   f. Upsert into `portfolio_snapshots` for `(user_id, d)`
3. Skip dates that already have a snapshot (don't overwrite real snapshots with synthetic ones)
4. Return summary: `{days_filled: N, days_skipped: N}`

### Optimization
- Pre-load all price observations for the user's cards in the date range in a single query
- Build a dict `{card_external_id: [(date, price), ...]}` sorted by date
- For each day, binary search or iterate to find the latest price <= date (forward-fill)
- This avoids N_days * N_cards individual queries

### Constraints
- Only backfill for dates AFTER the earliest `price_observations.observed_at` for any of the user's cards
- If a date already has a real snapshot (from `take_snapshot()`), do NOT overwrite it
- Log clearly that these are synthetic/estimated snapshots

## Testing

- Unit test: verify existing snapshots are not overwritten
