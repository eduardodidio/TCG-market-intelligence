# F112-T03 — Auto-Snapshot Hook on Scan Completion

**Wave:** 1
**Status:** planned

## User Story

As a collector, I want portfolio snapshots to be taken automatically after every price scan, so the portfolio chart accumulates data without manual intervention.

## Dev Notes

### Location
- `src/services/scan_hooks.py` — add `make_portfolio_snapshot_hook()`
- `src/api/app.py` — register the hook at startup

### Logic: `make_portfolio_snapshot_hook(db_url)`
1. Create a new `ScanHook` function
2. On scan completion, determine which user(s) were affected:
   a. From the `scan_run`, get the `user_id` (if it's a user-scoped scan)
   b. If it's an admin/global scan, snapshot ALL active users (users with collection entries)
3. For each affected user, call `take_snapshot(user_id, repo)`
4. Log the result

### Registration
- In `app.py` lifespan (where other hooks are registered), add:
  ```python
  portfolio_hook = make_portfolio_snapshot_hook(db_url)
  default_registry.register(portfolio_hook)
  ```

### Edge Cases
- If `take_snapshot()` fails for one user, log the error and continue with other users
- Idempotent: `take_snapshot()` already uses upsert (same date = update)
- Performance: snapshot is lightweight (1 aggregate query per user), but batch for admin scans

## Testing

- Unit test: mock registry, verify hook is called after scan
- Unit test: verify per-user snapshot is created
- Unit test: verify error in one user doesn't block others
- Integration test: trigger scan, verify portfolio_snapshots row created
