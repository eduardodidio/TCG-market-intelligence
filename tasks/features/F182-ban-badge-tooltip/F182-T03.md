## User Story

As a user viewing my collection, when I hover over a BanBadge on a card
tile, I want to see a tooltip listing which formats the card is banned or
restricted in, so I can quickly understand the card's legality status
without navigating to the detail page.

## Dev Notes

### BanBadge.tsx changes

1. **Extend props interface** to accept an optional `formats` array:

```typescript
interface BanBadgeProps {
  status: "banned" | "restricted";
  recentlyChanged?: boolean;
  formats?: Array<{ format: string; status: string }>;
}
```

2. **Build tooltip text** from the `formats` array. Use a native `title`
   attribute (no new dependencies). Capitalize format names for readability.

```typescript
const tooltipText = formats?.length
  ? formats
      .map((f) => {
        const formatName = f.format.charAt(0).toUpperCase() + f.format.slice(1);
        const statusLabel = f.status === "banned"
          ? t("banEngine.badgeBanned")
          : t("banEngine.badgeRestricted");
        return `${formatName}: ${statusLabel}`;
      })
      .join("\n")
  : undefined;
```

3. **Render the title attribute** on the outer `<span>`:

```tsx
<span
  data-testid={`ban-badge-${status}`}
  title={tooltipText}
  className={...}
>
  {label}
</span>
```

### i18n keys

No new i18n keys are strictly required since the tooltip reuses existing
`banEngine.badgeBanned` and `banEngine.badgeRestricted` keys for the
status labels, and format names come directly from the API data (which
are standard English format names like "commander", "legacy", "standard").

However, if we want a header line in the tooltip, add:

**en.json** (inside `banEngine` object):
```json
"tooltipHeader": "Format legality:"
```

**pt-BR.json** (inside `banEngine` object):
```json
"tooltipHeader": "Legalidade por formato:"
```

Then the tooltip becomes:
```
Format legality:
Commander: BANNED
Legacy: RESTRICTED
```

### Backward compatibility

The `formats` prop is optional with no default. When not provided (e.g.,
BanBadge used outside MyCollection), no `title` attribute is rendered.
This ensures zero breakage for existing callers.

## Testing

Add the following test cases to `frontend/tests/components/BanBadge.test.tsx`:

1. **Renders tooltip with formats list when formats provided:**
   ```tsx
   render(
     <BanBadge
       status="banned"
       formats={[
         { format: "commander", status: "banned" },
         { format: "legacy", status: "restricted" },
       ]}
     />
   );
   const badge = screen.getByTestId("ban-badge-banned");
   expect(badge).toHaveAttribute("title");
   expect(badge.getAttribute("title")).toContain("Commander");
   expect(badge.getAttribute("title")).toContain("Legacy");
   ```

2. **No tooltip when formats not provided:**
   ```tsx
   render(<BanBadge status="banned" />);
   const badge = screen.getByTestId("ban-badge-banned");
   expect(badge).not.toHaveAttribute("title");
   ```

3. **No tooltip when formats is empty array:**
   ```tsx
   render(<BanBadge status="restricted" formats={[]} />);
   const badge = screen.getByTestId("ban-badge-restricted");
   expect(badge).not.toHaveAttribute("title");
   ```

4. **Existing tests unchanged** -- all 4 current tests must still pass.
