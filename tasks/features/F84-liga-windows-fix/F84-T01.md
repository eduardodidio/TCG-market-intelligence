# F84-T01 — Replace async Playwright with sync-in-thread on Windows

**Wave:** 0
**Status:** done

## User Story

As a user running the app on Windows, I want Liga card refresh to work so I can get Liga prices without switching to Linux.

## Dev Notes

### Problem
`src/providers/liga/provider.py` lines 96-102 check `sys.platform == "win32"` and set `self._unavailable = True`, making every subsequent call raise `LigaError("Liga provider is unavailable on this platform")`.

The root cause: Playwright's **async** API internally uses `asyncio.create_subprocess_exec` which requires `ProactorEventLoop` on Windows, but uvicorn uses `SelectorEventLoop`.

### Solution
On Windows, use Playwright's **sync API** (`playwright.sync_api`) running inside `asyncio.to_thread()`. This sidesteps the event loop issue entirely because sync Playwright manages its own subprocess internally.

**Architecture:**
1. In `open()`, detect Windows and import `playwright.sync_api` instead
2. Create a helper class or methods that wrap sync Playwright calls
3. Use `asyncio.to_thread()` to run blocking sync Playwright operations from the async context
4. Keep the async API path for Linux/macOS (no regression)

**Implementation approach:**

```python
# In open():
if sys.platform == "win32":
    self._use_sync = True
    from playwright.sync_api import sync_playwright
    # Start sync playwright in a thread
    self._sync_pw = sync_playwright().start()
    self._sync_browser = self._sync_pw.chromium.launch(headless=...)
    self._sync_context = self._sync_browser.new_context(...)
    self._sync_page = self._sync_context.new_page()
else:
    # existing async path
    ...

# In _fetch_page():
if self._use_sync:
    return await asyncio.to_thread(self._fetch_page_sync, url)
else:
    # existing async path
    ...
```

Key considerations:
- `asyncio.to_thread()` runs the sync function in a default executor thread
- The `self._lock` (asyncio.Lock) still serializes requests from the async side
- `close()` must also handle sync cleanup via `to_thread()`
- The sync Playwright instance should be started in `open()` via `to_thread()` too, since `sync_playwright().start()` blocks
