## User Story

As a user, when I click "refresh price" on a card, I want my request to be
queued and processed later, with a clear message that it's in the queue, so
that I'm not blocked by a 503 error on the production server.

As an admin running the local machine, I want a CLI command that processes
pending price requests via Liga, so that queued requests get fulfilled.

## Problem

The `POST /cards/{id}/refresh-price` endpoint (cards.py:260-349) calls
`LigaMagicProvider.search_card()` directly. On Render, this fails because:
1. Playwright is not installed
2. Liga blocks datacenter IPs

Users see 503 errors. The endpoint needs to queue instead of executing.

## Dev Notes

### Endpoint refactor (cards.py)

Replace the current implementation of `refresh_card_price()`:

**Before**: Call Liga directly -> store price -> return updated card.
**After**: Insert into `price_update_requests` -> return queued status.

```python
@router.post("/{card_id}/refresh-price")
async def refresh_card_price(card_id, ...):
    # 1. Validate card exists
    # 2. Check credits (keep existing credit check)
    # 3. Deduct credit immediately (charge at request time)
    # 4. Call repo.create_price_update_request(card_id, user.id)
    # 5. Return response with message "queued"
```

Response format change:
- Current: returns `ApiResponse[CardSummary]` with updated price
- New: returns `ApiResponse[dict]` with `{ "status": "queued", "request_id": N,
  "message": "Price update request queued. It will be processed shortly." }`
- Keep the same HTTP 200 status code (not 202) for simplicity

### New endpoint: GET /cards/{card_id}/price-request-status

Add a lightweight endpoint for the frontend to check request status:
```python
@router.get("/{card_id}/price-request-status")
async def get_price_request_status(card_id, user, repo):
    request = repo.get_user_price_request_for_card(user.id, card_id)
    if not request:
        return success_response(data={"status": "none"})
    return success_response(data={
        "status": request.status,
        "requested_at": request.requested_at.isoformat(),
        "processed_at": request.processed_at.isoformat() if request.processed_at else None,
        "result_price": float(request.result_price) if request.result_price else None,
    })
```

### CLI command: process-price-requests

Add to `src/cli/main.py`:

```python
@cli.command("process-price-requests")
@click.option("--limit", default=50, help="Max requests to process")
@click.option("--delay", default=2.0, help="Seconds between requests")
@click.option("--dry-run", is_flag=True)
def process_price_requests(db, limit, delay, dry_run):
    """Process pending price update requests via Liga."""
```

Implementation:
1. Get pending requests from repo (oldest first, limit N)
2. For each request:
   a. Set status to "processing"
   b. Get card info (name, set_code, collector_number)
   c. Call Liga provider to fetch price (same logic as current endpoint)
   d. On success: store HistoricalPrice observation, update request
      status="completed", result_price=price
   e. On failure: update status="failed", error_message=str(error),
      increment attempts
   f. Sleep(delay) between requests
3. Print summary: processed, succeeded, failed

## Edge Cases

- Card has no name (name_en/name_pt both null): skip, set status="failed"
- Liga rate limit during processing: respect backoff, mark as "failed" with
  retryable error, don't increment attempts past max
- Processing interrupted (crash): "processing" status requests older than
  10min should be reset to "pending" at start of processing run
- Same card requested by multiple users: process once, update all pending
  requests for that card_id
