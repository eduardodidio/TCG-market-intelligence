## User Story

As a system, I need a persistent queue for price update requests so that user
requests submitted on the Render server can be processed later from a local
machine with Liga/Playwright access.

## Problem

The current `POST /cards/{id}/refresh-price` endpoint calls Liga directly via
Playwright. On Render (production), Playwright is not installed and Liga blocks
datacenter IPs. Users clicking refresh get 503 errors. We need a queue to
decouple request submission from processing.

## Dev Notes

### New model: PriceUpdateRequestRow

Add to `src/database/models.py`:

```python
class PriceUpdateRequestRow(Base):
    __tablename__ = "price_update_requests"

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    card_id: Mapped[int] = mapped_column(
        Integer, ForeignKey("cards.id", ondelete="CASCADE"), nullable=False
    )
    user_id: Mapped[int] = mapped_column(
        Integer, ForeignKey("users.id", ondelete="CASCADE"), nullable=False
    )
    status: Mapped[str] = mapped_column(
        String(20), nullable=False, default="pending"
    )
    # status values: pending, processing, completed, failed
    requested_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.now)
    processed_at: Mapped[datetime | None] = mapped_column(DateTime)
    result_price: Mapped[Decimal | None] = mapped_column(Numeric(12, 2))
    error_message: Mapped[str | None] = mapped_column(Text)
    attempts: Mapped[int] = mapped_column(Integer, default=0)

    __table_args__ = (
        Index("ix_price_update_req_status", "status"),
        Index("ix_price_update_req_card", "card_id"),
        Index("ix_price_update_req_user", "user_id"),
        Index("ix_price_update_req_requested", "requested_at"),
    )
```

### Repository methods

Add to `repository.py`:

1. **`create_price_update_request(card_id, user_id) -> PriceUpdateRequestRow`**
   - Check for existing `pending` request for same card_id in last 24h
   - If exists, return the existing one (deduplication)
   - If not, insert new row with status="pending"

2. **`get_pending_price_requests(limit=50) -> list[PriceUpdateRequestRow]`**
   - Return oldest pending requests, ordered by requested_at ASC
   - Optionally filter by max attempts (< 3)

3. **`update_price_request_status(request_id, status, result_price=None, error_message=None)`**
   - Update status, processed_at (if completed/failed), result_price, error_message
   - Increment attempts counter

4. **`get_price_requests(status=None, limit=50, offset=0) -> tuple[list, int]`**
   - For admin listing: paginated, filterable by status
   - Return (rows, total_count) tuple

5. **`get_user_price_request_for_card(user_id, card_id) -> PriceUpdateRequestRow | None`**
   - Get the latest request for this user+card combo
   - Used by frontend to show request status

### Table creation
- SQLAlchemy `create_all()` will auto-create the table on startup.
- For existing Neon DB, the table will be created automatically since we use
  `Base.metadata.create_all(engine)` at repo init.

## Edge Cases

- Concurrent requests for same card from different users: each gets their own
  request row, but processing deduplicates (processes once, updates both)
- Card deleted while request is pending: CASCADE delete handles cleanup
- User deleted while request is pending: CASCADE delete handles cleanup
- Request stuck in "processing" (crashed processor): add timeout -- requests
  in "processing" for > 10 minutes revert to "pending"
