# F130-T06: Frontend Queued Feedback on Price Refresh

**Wave:** 2 (Frontend Queue)
**Parallel with:** T07
**Depends on:** T04, T05 (API must be defined)
**Files to modify:** `frontend/src/api/cards.ts`, `frontend/src/components/CardTile.tsx`, `frontend/src/components/DeckCardTile.tsx`
**Files to create:** (none)

## User Story

As a user, when I click the refresh button on a card, I want to see a clear
message that my request has been queued and will be processed soon, instead of
a loading spinner that eventually fails with an error.

## Problem

Currently the frontend:
1. Calls `refreshCardPrice(cardId)` which POSTs to `/cards/{id}/refresh-price`
2. Shows a spinning refresh icon while waiting
3. On success: updates the displayed price
4. On failure: silently fails (catch block is empty)

After the backend change (T05), the endpoint returns `{ status: "queued" }`
instead of an updated price. The frontend needs to:
1. Show a "queued" confirmation message/toast
2. Optionally poll or show a badge indicating pending update
3. Stop expecting an immediate price update

## Dev Notes

### API layer (cards.ts)

1. Add new function:
```typescript
export function getCardPriceRequestStatus(cardId: number) {
  return apiGet<{ status: string; requested_at?: string; result_price?: number | null }>(
    `/api/v1/cards/${cardId}/price-request-status`
  );
}
```

2. Update `refreshCardPrice` return type to handle the new response shape:
```typescript
// Response is now { status: "queued", request_id: number, message: string }
export function refreshCardPrice(cardId: number) {
  return apiPost<{ status: string; request_id: number; message: string }>(
    `/api/v1/cards/${cardId}/refresh-price`, {}
  );
}
```

### CardTile.tsx changes

1. Replace the `handleRefresh` function:
   - On success: show a toast/inline message "Solicitacao recebida" instead of
     updating the price
   - Change the refresh icon to a clock/queue icon after successful queue
   - Add i18n keys: `cards.priceUpdateQueued`, `cards.priceUpdateQueuedDesc`

2. Add a "queued" visual state:
   - After clicking refresh and getting "queued" response, show a small
     clock badge or change the refresh button color to indicate pending
   - Store in local component state (not persistent -- resets on page nav)

3. Toast/feedback options (pick simplest):
   - **Option A**: Inline text below the price: "Atualizacao solicitada"
     (fades after 3s)
   - **Option B**: Use existing toast system if available
   - **Option A is preferred** for simplicity

### DeckCardTile.tsx changes

Same pattern as CardTile -- if it has a refresh button, update to show
queued feedback.

### i18n strings

Add to translation files:
```json
{
  "cards.priceUpdateQueued": "Update requested",
  "cards.priceUpdateQueuedDesc": "Your price update request is in the queue and will be processed shortly.",
  "cards.priceUpdatePending": "Update pending"
}
```

## Edge Cases

- User clicks refresh multiple times: first click queues, subsequent clicks
  show "already in queue" (backend deduplicates)
- User navigates away and back: queued state is lost (acceptable -- the
  request is still in the backend queue)
- Network error on the POST: show generic error message, don't change state
