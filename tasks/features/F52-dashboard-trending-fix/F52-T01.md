# F52-T01 — Debug and Fix Trending Data Display

**Status:** planned
**Wave:** 0
**Estimate:** medium

## User Story

As a user viewing the dashboard, I want to see trending gainers and losers
cards, so I can quickly identify market movements.

## Dev Notes

### Investigation Steps

1. **Check API response shape**: Hit `GET /market/trending/gainers?period=30d`
   directly and compare the response shape with what `TrendingSection`
   expects (`TrendingResponse`).

2. **Check `useApi` unwrapping**: In `frontend/src/hooks/useApi.ts`, verify
   whether `useApi` returns the raw HTTP response or the unwrapped `data`
   field from the `ApiResponse<T>` envelope.

3. **Check `fetchTrending` return**: In `frontend/src/api/trending.ts`,
   verify the function returns `TrendingResponse` directly or wrapped.

4. **Fix signal forwarding**: `TrendingSection.tsx:35` receives `signal`
   but doesn't pass it to `fetchTrending`. Add signal parameter to
   `fetchTrending` and forward it to `apiGet`.

### Likely Fix

The most probable cause is an **API response envelope mismatch** introduced
when `market.py` was refactored in F44 (shared data arch). The endpoint
may now return `ApiResponse[TrendingResponse]` (wrapping in `{ data }`),
but the frontend `fetchTrending` may return the full envelope while
`TrendingSection` expects the inner `TrendingResponse` directly.

**Fix**: Ensure `fetchTrending` in `trending.ts` extracts `response.data`
from the API response, or adjust `TrendingSection` to handle the envelope.

Also pass `signal` through the call chain for proper abort handling.
