# F43-T02: Repository — paginated history + card ban history

**Status:** planned
**Wave:** 1

## User Story

As a developer, I need repository methods that support paginated,
filterable ban history queries and card-specific history lookups so the
API layer can serve them.

## Dev Notes

### Files to modify
- `src/database/repository.py` — add new methods (extends F41-T02 methods)

### Implementation

1. `get_legality_history_paginated(card_id: int | None, format: str | None, date_from: date | None, date_to: date | None, limit: int = 50, offset: int = 0) -> tuple[list[dict], int]`
   - Extends F41's `get_legality_history` with date range filtering and
     total count
   - JOIN with cards table to get: name_en, name_pt, set_code,
     collector_number (for image URL construction)
   - Filter: `changed_at >= date_from` if provided
   - Filter: `changed_at <= date_to` if provided
   - Returns tuple of (result_rows, total_count)
   - Total count query uses same filters but no limit/offset
   - Order by changed_at DESC

2. `get_card_ban_history(card_id: int) -> list[LegalityHistoryRow]`
   - All legality_history rows for a specific card
   - All formats included
   - Order by changed_at DESC, format ASC
   - No pagination (card-level history is bounded)

3. `get_ban_events_for_impact(card_id: int) -> list[LegalityHistoryRow]`
   - Same as get_card_ban_history but only returns rows where
     new_status is "banned" or "restricted" OR old_status was "banned"
     or "restricted" (actual ban/unban transitions)
   - Used by the impact stub endpoint to enumerate events worth
     analyzing
   - Order by changed_at ASC (chronological for analysis)

### Notes
- If F41-T02's `get_legality_history` already covers some of this,
  the developer should extend it rather than duplicate. The key
  additions are: date range filters, total count, and the card-specific
  variant.
- The paginated method returns dicts (not Row objects) because it
  includes joined card data.
