# F43-T03: API — enhanced history endpoint + card history + impact stub

**Status:** planned
**Wave:** 1

## User Story

As a frontend developer, I need API endpoints to query paginated ban
history with date filters, fetch a card's full ban timeline, and get
(stubbed) price impact data for ban events.

## Dev Notes

### Files to modify
- `src/api/routers/banlist.py` — extend router (created by F41-T04)

### Implementation

1. **Enhance `GET /banlist/history`** (from F41-T04):
   - Add query params:
     - `date_from: date | None = None`
     - `date_to: date | None = None`
     - `offset: int = 0`
   - Change return type to `LegalityHistoryResponse` (paginated wrapper)
   - Call `get_legality_history_paginated` from T02
   - Include `image_url` in each entry (construct Scryfall URL from
     set_code + collector_number using existing pattern)
   - Keep existing `format`, `card_id`, `limit` params

2. **Add `GET /banlist/history/{card_id}`** (new):
   - Path param: `card_id: int`
   - Returns `list[CardBanHistoryEntry]`
   - Call `get_card_ban_history(card_id)` from T02
   - Verify card exists (404 if not found)
   - Public endpoint (no auth)

3. **Add `GET /banlist/impact/{card_id}`** (new, stub):
   - Path param: `card_id: int`
   - Query param: `window_days: int = 7`
   - Returns `list[BanImpactSchema]`
   - Implementation:
     a. Call `get_ban_events_for_impact(card_id)` from T02
     b. For each event, construct `BanImpactSchema` with:
        - format, old_status, new_status, changed_at from the row
        - window_days from query param
        - price_before = None, price_after = None
        - absolute_change = None, percent_change = None
        - data_available = False
     c. Return the list
   - Verify card exists (404 if not found)
   - Public endpoint (no auth)
   - NOTE: This is intentionally a stub. A future feature will wire in
     actual price lookups from price_observations around ban dates.

### Route ordering
- Ensure `/banlist/history/{card_id}` is registered BEFORE
  `/banlist/history` to avoid path conflicts (FastAPI matches in order).
  Alternatively use a distinct prefix like `/banlist/card/{card_id}/history`.
  The developer should choose the cleanest approach — if there is a
  conflict, use `/banlist/card/{card_id}/history` as fallback.
