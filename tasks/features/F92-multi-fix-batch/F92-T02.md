# F92-T02: MYP Search Fallback on Render

**Status:** planned
**Wave:** 1
**Type:** fix (backend)

## User Story
As a user on the Render deployment, when I search for a card in the Explore
Cards page, I want the search to work using the MYP provider as a fallback
when the Liga provider (Playwright) is not available, instead of getting a
503 error.

## Dev Notes

### Changes

1. **`src/api/routers/card_search.py`**:
   - After the existing Liga provider lookup (lines 64-78), if `liga_provider`
     is None, look for MYP provider in the registry as fallback
   - Use MYP's search endpoint: the provider has a `search_card(query)` method
     that calls `/produto/search?marca=magic&term={q}`
   - If MYP provider is also unavailable, return 503
   - Adapt the result mapping: MYP search returns different fields than Liga
     (it returns `idproduto`, `nomeenproduto`, `codigoproduto` etc.)
   - For MYP results, build WebSearchResult with:
     - `card_name` from `nomeenproduto` or `nomeptproduto`
     - `normal_price` = None (MYP search doesn't return prices directly)
     - `liga_url` = None (not a Liga result)
     - `local_card_id` = check local DB by name

2. **Check `src/providers/myp/provider.py`**: verify `search_card` method
   exists and its return type. The search parser is in `src/parsers/myp.py`.

### Scope
- Backend only, no frontend changes needed (same API contract)
- MYP search doesn't require Playwright — uses curl_cffi HTTP

## Testing
- Unit test: mock registry with no Liga provider, verify MYP fallback is used
- Unit test: mock registry with neither provider, verify 503
- Integration: verify search endpoint returns results on environments
  without Playwright
