# F92-T01: Refresh All Token Cost Display

**Status:** planned
**Wave:** 1
**Type:** fix (frontend-only)

## User Story
As a user, when I click "Refresh All" on my collection page, I want the
confirmation modal to show the actual token cost (equal to the number of
cards that will be scanned), not a placeholder value. I also want the
PT-BR labels to consistently say "token(s)" instead of "ficha(s)".

## Dev Notes

### Changes

1. **`frontend/src/pages/MyCollection.tsx`** line ~314:
   - Change `useState(5)` to `useState(0)` for `previewCost`
   - The real cost is loaded from `fetchScanPreview` in `loadPreview()`,
     so `0` is just the initial value before the API responds

2. **`frontend/src/i18n/locales/pt-BR.json`** — update these keys under `credits`:
   - `confirmTitle`: `"Gastar Fichas de Tesouro?"` -> `"Gastar Tokens de Tesouro?"`
   - `confirmCost`: `"Esta acao custa {{cost}} ficha(s)"` -> `"Esta acao custa {{cost}} token(s)"`
   - `spend`: `"Gastar {{cost}} Ficha"` -> `"Gastar {{cost}} Token"`
   - `insufficient`: `"Fichas insuficientes!"` -> `"Tokens insuficientes!"`

### Scope
- No backend changes
- No EN locale changes needed (already says "token(s)")

## Testing
- Verify CreditConfirmModal shows `0` (or loading state) before preview loads,
  then updates to the real card count
- Verify PT-BR strings say "token" not "ficha" in all credit-related modals
- Existing frontend tests for CreditConfirmModal should still pass
