# F15-T02: Fix Full-Art Card Images Using Set Code Mapping
- **Wave:** 1
- **Type:** frontend + backend
- **Depends on:** F15-T01
- **Status:** planned

## User Story
As a collector, I want to see images for my full-art, borderless, extended
art, and showcase cards so that my collection view is visually complete.

## Objective
Update the image URL generation pipeline (backend `_scryfall_image_url` and
frontend `scryfallImageUrl`) to use the set code mapping from T01, and
improve the fallback chain so that cards with variant set codes display
images reliably.

## Dev Notes

### Current behavior
1. Backend `_scryfall_image_url(set_code, collector_number)` builds
   `api.scryfall.com/cards/{set_code}/{collector_number}?format=image`
   using the raw MYP set code -- returns 404 for variant codes.
2. Frontend `CollectionCardTile` uses `card.image_url` (from backend) as
   primary, then falls back to `scryfallImageByName(card.name_en)`.
3. The name-based fallback works only if `name_en` is populated, and it
   returns the default printing (not the variant art).

### Fix strategy
1. **Backend** (`src/api/routers/collection.py`): use
   `map_to_scryfall_set_code()` from T01 when building the image URL.
   This fixes the `image_url` field in the API response.
2. **Frontend** (`scryfallImageUrl` in `utils/scryfall.ts`): optionally
   accept a raw set code and map it. OR, keep the frontend simple and
   just rely on the backend-provided `image_url` (preferred approach,
   since the backend already sends it).
3. **Fallback chain** in `CollectionCardTile`:
   - Primary: backend `image_url` (now mapped)
   - Fallback 1: `scryfallImageByName(name_en)` if name_en exists
   - Fallback 2: placeholder SVG icon
4. The `CardTile` component (Explore page) uses `set_code` and
   `collector_number` from the `cards` table, which uses Scryfall-
   compatible codes -- no change needed there.

### Files to change
- `src/api/routers/collection.py`: import and use `map_to_scryfall_set_code`
  in `_scryfall_image_url`
- `frontend/src/utils/scryfall.ts`: add optional set code mapping for
  direct frontend use (e.g., in `CardTile` if ever given variant codes)
- `frontend/src/pages/MyCollection.tsx`: ensure fallback chain is robust

## Acceptance Criteria
- [ ] Borderless cards (e.g., `bldmr`, `bl2x2`) show correct card images
- [ ] Extended art cards (e.g., `exdmu`, `eafic`) show correct card images
- [ ] Showcase cards (e.g., `srltr`, `skmh2`) show correct card images
- [ ] Secret Lair cards (e.g., `sld158`) show correct card images
- [ ] Cards with unknown variant codes still show name-based fallback image
- [ ] Cards with no `name_en` show placeholder SVG (no broken image icon)
- [ ] No regression on standard set code images (Explore Cards page)
