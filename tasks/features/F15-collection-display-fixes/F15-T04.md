# F15-T04: Collection Card Detail View with Collection Metadata
- **Wave:** 1
- **Type:** frontend + backend
- **Depends on:** none
- **Status:** planned

## User Story
As a collector, when I click on a card in my collection, I want to see
all relevant information including collection-specific data (quantity,
quality, language, extras) alongside price data and card details, so I
have a complete view of what I own.

## Objective
Create a dedicated collection card detail view (or enhance the existing
CardDetail page) so that collection cards show full information when
clicked, regardless of whether they are linked to a canonical card.

## Dev Notes

### Current behavior
1. **Linked cards** (`card_id != null`): `<Link to={/cards/${card_id}}>`.
   Opens `CardDetail.tsx` which fetches `/api/v1/cards/{id}`. Shows card
   name, set, price, price chart, sources, external links. Does NOT show
   collection-specific data (quantity, quality, language, extras).
2. **Unlinked cards** (`card_id == null`): `<Link to={/cards?name=X&set=Y}>`.
   Opens Explore Cards page filtered by name/set. Often shows "No cards
   found" because the card is not in the `cards` table -- dead end.

### Proposed approach: Collection-aware detail route

**Option A (recommended): New route `/collection/{id}` with dedicated page**
- New page `CollectionCardDetail.tsx` at route `/collection/:id`
- New backend endpoint `GET /api/v1/collection/{id}` returning the
  collection entry with all its metadata
- If the collection entry has a `card_id`, also fetch and display the
  canonical card data (price history, sources) via existing endpoints
- Collection links in `MyCollection.tsx` always point to `/collection/{id}`
  (using the collection entry ID, not the card_id)

This approach is cleaner because:
- Every collection card is clickable with a guaranteed destination
- No dead-end for unlinked cards
- Collection metadata is always visible
- Can still show price data for linked cards

**Option B: Enhance CardDetail with collection context**
- Pass collection data via URL state or query params
- More coupled, harder to maintain

### Backend changes

New endpoint in `src/api/routers/collection.py`:
```python
@router.get("/{entry_id}", response_model=ApiResponse[CollectionCardDetail])
def get_collection_entry(entry_id: int, repo: Repository = Depends(get_db)):
    ...
```

New schema `CollectionCardDetail` extends `CollectionCard` with:
- All existing `CollectionCard` fields
- `price_history`: list of price observations (if linked)
- `source_cards`: list of source cards (if linked)
- `created_at`, `updated_at` from canonical card (if linked)
- `scryfall_url`, `ligamagic_url`: pre-built external links

New repository method:
```python
def get_collection_entry(self, entry_id: int, user_id: str) -> UserCollectionRow | None:
    ...
```

### Frontend changes

New page `frontend/src/pages/CollectionCardDetail.tsx`:
- Route: `/collection/:id`
- Layout: similar to `CardDetail.tsx` (two-column: info + chart)
- Left panel: card image, name, set info, **collection metadata section**
  (quantity, quality, language, extras badges), price, external links
- Right panel: price chart (if linked and has history), or empty state
- Breadcrumb: Collection > Card Name

Update `MyCollection.tsx`:
- Change all card links from `/cards/{card_id}` to `/collection/{id}`
- Remove the unlinked-card fallback to Explore page

Update router config:
- Add route `/collection/:id` -> `CollectionCardDetail`

## Acceptance Criteria
- [ ] Clicking any collection card (linked or unlinked) opens a detail view
- [ ] Detail view shows card name (EN + PT), set code, collector number
- [ ] Detail view shows collection metadata: quantity, quality, language, extras
- [ ] Detail view shows card image (using mapped Scryfall URL from T01/T02)
- [ ] For linked cards: detail view shows latest price and price chart
- [ ] For linked cards: detail view shows source links (MYP)
- [ ] For unlinked cards: detail view shows "Not yet linked" status gracefully
- [ ] External links (Scryfall, LigaMagic) are present
- [ ] Breadcrumb navigates back to Collection page
- [ ] No dead-end for any collection card click
