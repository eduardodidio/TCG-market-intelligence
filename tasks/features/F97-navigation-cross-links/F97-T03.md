# F97-T03: Ownership Badge on Trending Cards

**Wave:** 1
**Depends on:** --

## User Story

As a collector viewing trending cards (on Market page or Trending page), I
want to see a small badge indicating which cards are already in my collection,
so I can quickly identify cards I own that are gaining or losing value.

## Current State

- `TrendingCardEntry` (api.ts:416) does NOT have a `collection_entry_id` or
  `in_collection` field.
- The trending API (`GET /market/trending/gainers|losers`) returns card data
  from the trending cache, which does not include ownership info.
- The `collectionOnly` toggle on Trending.tsx already filters by collection
  server-side, but individual cards lack an ownership indicator.

## Dev Notes

### Approach A (preferred -- frontend-only, no backend change)

Use a lightweight client-side ownership lookup. The collection summary or
a minimal collection list endpoint already exists. Fetch the user's
collection card IDs once (a small Set<number>) and check membership
client-side.

1. Create a hook `useOwnedCardIds()` that:
   - If not authenticated, returns an empty Set.
   - Fetches `GET /collection?limit=9999&fields=card_id` (or the existing
     collection list) and extracts card_ids into a `Set<number>`.
   - Caches in a `useMemo`/`useRef` with a reasonable TTL or re-fetches
     on window focus.
2. Pass `ownedCardIds: Set<number>` into `TrendingSection` as an optional
   prop, which passes it to `TrendingCard` and `TrendingListItem`.
3. In `TrendingListItem.tsx` and `TrendingCard.tsx`, show a small badge
   (e.g., a green checkmark or a small "Owned" pill) when
   `ownedCardIds.has(entry.card_id)`.

### Approach B (backend change -- adds `in_collection` to trending response)

Add `in_collection: bool` to the trending Pydantic schema and join against
`user_collection` in the trending query. This is cleaner but requires backend
changes and cache invalidation considerations.

**Recommend Approach A** since it is frontend-only, aligns with the brief
constraint, and avoids cache complexity.

### Badge Design

- TrendingListItem: small green circle or checkmark icon to the right of the
  set code badge, with `title={t("trending.inCollection")}`.
- TrendingCard: small badge overlay in the top-right corner of the card image.
- Use `data-testid="owned-badge"` for testing.
- Only show when user is authenticated and card is owned.

## Testing

- TrendingListItem: render with `ownedCardIds` containing the card_id, assert
  `owned-badge` appears. Render without, assert it does not appear.
- TrendingCard: same pattern.
- TrendingSection: verify `ownedCardIds` prop is forwarded correctly.
- useOwnedCardIds: mock fetch, assert Set contains expected IDs.

## Acceptance Criteria

- [ ] Trending cards show ownership badge when user owns the card
- [ ] Badge is not shown for unauthenticated users
- [ ] Badge is not shown for cards not in collection
- [ ] Works on both `variant="cards"` and `variant="list"` rendering modes
