# F77-T02: Diagnostic Logging for Liga Refresh Flow

**Status:** planned
**Wave:** 0

## User Story
As a developer, I want structured logs at each stage of the Liga refresh flow (URL construction, page fetch, HTML size, parse result) so I can quickly diagnose future Liga pricing failures.

## Dev Notes

### Files to Modify
- `src/providers/liga/provider.py` — add `structlog` calls in `_search_card_unlocked`:
  - Log the constructed URL
  - Log HTML response length (not full HTML)
  - Log parsed result summary (has_normal, has_foil, price values)
- `src/api/routers/collection.py` — log the card name used for Liga search and the prices dict received

### Approach
- Use `structlog` (already in project) at `debug` level for verbose data, `warning` for empty prices
- Log `html_length=len(html)` to distinguish "empty page" from "page loaded but parser missed prices"

## Testing
- Unit test: verify log output contains expected fields (mock structlog or capture logs)
- Verify no sensitive data (full HTML) is logged at info/warning level
