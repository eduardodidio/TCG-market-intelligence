# F136-T05: Review & Consistency -- Audit Portfolio Components for Acquisition-Only Data

**Wave:** 2 (Consistency Audit)
**Depends on:** T03, T04 (dashboard and collection filter must be implemented)
**Status:** planned

## User Story

As a user of the portfolio features, I want all investment-related views to be
consistent -- movers should reflect investment cards, the export should match
the dashboard, and P&L badges should only appear on cards with cost basis -- so
that I can trust the numbers across the entire application.

### API Client: `frontend/src/api/collection.ts`

Update `fetchCollectionMovers()` signature:

```typescript
export function fetchCollectionMovers(
  days: number = 7,
  limit: number = 5,
  investmentOnly: boolean = false,
): Promise<ApiResponse<CollectionMoversData>> {
  const params: Record<string, string> = {
    days: String(days),
    limit: String(limit),
  };
  if (investmentOnly) params.investment_only = "true";
  return apiGet<CollectionMoversData>("/api/v1/collection/movers", params);
}
```

### Consistency Checks

- Dashboard movers and PortfolioDashboard movers should both show
  investment-only cards (same data source, same filter).
- Portfolio summary numbers (invested, current, P&L) should match the sum of
  individual PnlBadge values across collection cards with acquisition prices.
- Export CSV data should match the dashboard KPI totals.
- `cards_without_acquisition` + `invested_card_count` should equal total
  collection count (verify in tests).

### Edge Cases

- Zero investment cards: movers with `investment_only=true` should return empty,
  not error.
- Cards with acquisition price but no market price: they appear in "investment"
  count but not in movers (movers requires 2+ price data points).
- Export with zero investment cards: should return empty CSV or helpful message.
