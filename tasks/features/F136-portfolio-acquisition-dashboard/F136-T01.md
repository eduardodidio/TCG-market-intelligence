# F136-T01: Backend -- Add `has_acquisition_price` Filter to Collection List Endpoint

**Wave:** 0 (Backend Filters)
**Parallel with:** T02
**Status:** planned

## User Story

As a collector, I want to filter my collection to show only cards with (or
without) acquisition prices, so I can quickly identify which cards need cost
basis data and which ones are already tracked as investments.

## Dev Notes

### Repository: `src/database/repository.py`

**`list_collection()`** -- add `has_acquisition_price: bool | None = None` param:

```python
def list_collection(
    self,
    user_id: str,
    name_search: str | None = None,
    set_code: str | None = None,
    sort_by: str = "name",
    sort_dir: str = "asc",
    offset: int = 0,
    limit: int = 50,
    after_id: int | None = None,
    has_acquisition_price: bool | None = None,  # NEW
) -> list[UserCollectionRow]:
```

Filter logic:
- `has_acquisition_price=True` -> `WHERE acquisition_price IS NOT NULL`
- `has_acquisition_price=False` -> `WHERE acquisition_price IS NULL`
- `has_acquisition_price=None` (default) -> no filter (backward compatible)

**`count_collection()`** -- add matching param so pagination total is correct:

```python
def count_collection(
    self,
    user_id: str,
    name_search: str | None = None,
    set_code: str | None = None,
    has_acquisition_price: bool | None = None,  # NEW
) -> int:
```

### API: `src/api/routers/collection.py`

**`list_collection()`** endpoint -- add query parameter:

```python
has_acquisition_price: bool | None = Query(
    default=None,
    description="Filter by acquisition price presence: true=with price, false=without price",
),
```

Pass through to `repo.list_collection()` and `repo.count_collection()`.

### Edge Cases

- `has_acquisition_price=false` combined with `sort_by=price` should still work
  (cards without acquisition price may still have market prices).
- `has_acquisition_price` combined with `name` and `set` filters: all filters
  AND together.
- Empty results should return `[]` with `total: 0` in meta (existing behavior).

## Testing

### Backend unit tests (`tests/api/test_collection_acquisition_filter.py`)

1. `GET /api/v1/collection?has_acquisition_price=true` returns only entries
   where `acquisition_price IS NOT NULL`.
2. `GET /api/v1/collection?has_acquisition_price=false` returns only entries
   where `acquisition_price IS NULL`.
3. `GET /api/v1/collection` (no param) returns all entries (backward compat).
4. Filter combined with `name` search: both filters apply.
5. Filter combined with `set` filter: both filters apply.
6. Pagination `total` reflects filtered count.
7. `has_acquisition_price=false` with `sort_by=price&sort_dir=desc` works.

### Repository unit tests (`tests/database/test_repo_acquisition_filter.py`)

1. `list_collection(has_acquisition_price=True)` returns correct subset.
2. `list_collection(has_acquisition_price=False)` returns correct subset.
3. `list_collection(has_acquisition_price=None)` returns all (default).
4. `count_collection(has_acquisition_price=True)` matches list length.
5. `count_collection(has_acquisition_price=False)` matches list length.
