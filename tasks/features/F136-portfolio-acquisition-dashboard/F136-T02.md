# F136-T02: Backend -- Portfolio Summary `cards_without_acquisition` + Movers `investment_only`

**Wave:** 0 (Backend Filters)
**Parallel with:** T01
**Status:** planned

## User Story

As a collector viewing my portfolio dashboard, I want to see how many cards are
missing acquisition prices (so I know the data quality of my investment tracking)
and I want the movers section to optionally show only cards I have cost basis
for (so gainers/losers reflect actual investment performance).

## Dev Notes

### Schema: `src/api/schemas/collection.py`

**`PortfolioSummary`** -- add `cards_without_acquisition` field. The existing
`unpriced_card_count` field (currently never populated) should also be populated
-- it represents cards with acquisition price but no current market price.

```python
class PortfolioSummary(BaseModel):
    total_invested: float
    total_current_value: float
    total_pnl: float
    total_pnl_pct: float | None = None
    invested_card_count: int = 0
    unpriced_card_count: int = 0         # existing, now populated
    cards_without_acquisition: int = 0   # NEW: cards missing cost basis
```

### Repository: `src/database/repository.py`

Add helper method to count entries without acquisition price:

```python
def count_entries_without_acquisition(self, user_id: str) -> int:
    """Count collection entries where acquisition_price IS NULL."""
```

This is a simple `SELECT COUNT(*) FROM user_collection WHERE user_id = ?
AND acquisition_price IS NULL`.

### API: `src/api/routers/collection.py`

**`portfolio_summary()`** endpoint -- populate the two counts:

1. `cards_without_acquisition` = `repo.count_entries_without_acquisition(user_id)`
2. `unpriced_card_count` = count of entries in `entries` (those with
   acquisition_price) where no current market price was found in `prices_map`.

The `unpriced_card_count` calculation: iterate `entries` (already fetched),
count those where `entry.card_id` is None or `prices_map.get(entry.card_id)`
is None or has no usable price.

**`collection_movers()`** endpoint -- add `investment_only` query param:

```python
investment_only: bool = Query(
    default=False,
    description="When true, only include cards with acquisition_price in movers",
),
```

Implementation: when `investment_only=True`, fetch the set of card_ids that have
acquisition prices (`repo.get_collection_entries_with_acquisition(user_id)` ->
extract card_ids) and filter `trending` dict to only include those card_ids
before computing changes.

### Edge Cases

- User with zero cards: `cards_without_acquisition=0`, `unpriced_card_count=0`.
- User with all acquisition prices set: `cards_without_acquisition=0`.
- `investment_only=false` (default): movers behave exactly as before (backward
  compatible).
- Cards with acquisition price but `card_id IS NULL` (unlinked): they have cost
  basis but no market price -- counted in `unpriced_card_count`.

## Testing

### Backend unit tests (`tests/api/test_portfolio_summary_acquisition.py`)

1. `portfolio-summary` includes `cards_without_acquisition` field.
2. `cards_without_acquisition` is correct count (mix of with/without prices).
3. `unpriced_card_count` is populated (entries with acquisition but no market
   price).
4. All cards have acquisition price: `cards_without_acquisition=0`.
5. No cards have acquisition price: `invested_card_count=0`,
   `cards_without_acquisition=total_count`.

### Backend unit tests (`tests/api/test_movers_investment_only.py`)

1. `GET /movers?investment_only=true` only returns cards with acquisition price.
2. `GET /movers?investment_only=false` returns all cards (default behavior).
3. `GET /movers` (no param) returns all cards (backward compat).
4. `investment_only=true` with no investment cards: empty gainers/losers.

### Repository unit tests

1. `count_entries_without_acquisition()` returns correct count.
2. `count_entries_without_acquisition()` returns 0 when all have prices.
