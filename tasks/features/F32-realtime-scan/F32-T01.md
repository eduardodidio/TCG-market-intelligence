# F32-T01 -- ScanEvent Domain Model + In-Memory Event Bus

**Wave:** 0
**Depends on:** nothing
**Estimated effort:** small

## Objective

Create the `ScanEvent` dataclass and an in-memory pub/sub event bus that the
scan orchestrator will publish to and the SSE endpoint will consume from.

## Deliverables

### 1. ScanEvent dataclass

File: `src/domain/events.py`

```python
@dataclass
class ScanEvent:
    event_type: str          # "card_scanned" | "scan_started" | "scan_complete"
    scan_id: int
    timestamp: str           # ISO 8601
    # Per-card fields (None for scan_started/scan_complete)
    external_id: str | None = None
    card_name: str | None = None
    price_found: bool = False
    price: Decimal | None = None
    currency: str | None = None
    error: str | None = None
    # Running totals
    cards_processed: int = 0
    cards_total: int = 0
    cards_failed: int = 0
    observations_saved: int = 0
```

Add a `to_sse_json()` method that serializes to a JSON string suitable for
SSE `data:` lines.

### 2. ScanEventBus

File: `src/events/scan_bus.py`

Module-level singleton pattern (dict of `scan_id -> list[asyncio.Queue]`):

- `subscribe(scan_id) -> asyncio.Queue` -- creates a new queue for a
  consumer, adds it to the subscribers list for that scan_id.
- `unsubscribe(scan_id, queue)` -- removes the queue from subscribers.
- `publish(event: ScanEvent)` -- puts the event into all subscriber queues
  for that scan_id. Non-blocking (`put_nowait`). If a queue is full
  (bounded at 100 events), log a warning and skip.
- `cleanup(scan_id)` -- removes all queues for that scan_id.
- Thread safety: the scan orchestrator runs in a background thread but
  publishes via `asyncio.Queue`. Use `call_soon_threadsafe` or a
  thread-safe wrapper for cross-thread publishing.
