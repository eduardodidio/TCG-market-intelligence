### 2. Integration Tests

File: `tests/integration/api/test_scan_sse_e2e.py`

End-to-end test using TestClient:
1. Create a scan via `POST /scans`
2. Connect to `GET /scans/{id}/stream?token=<jwt>`
3. Verify events arrive in order: `scan_started`, N x `card_scanned`,
   `scan_complete`
4. Verify event data fields match expected values
5. Verify stream closes after `scan_complete`

This requires a test database with a few collection cards and mock MYP
responses (reuse existing test fixtures).

File: `tests/integration/api/test_scan_sse_auth.py`

- Test: 401 without token
- Test: 401 with invalid token
- Test: 200 with valid JWT
- Test: 200 with valid API key

### 3. Diagrams

File: `docs/diagrams/F32-architecture.mmd`

Component diagram showing:
- Scan orchestrator (background thread) -> Event Bus -> SSE Endpoint
- SSE Endpoint -> Browser EventSource
- Fallback: Browser -> Polling Endpoint -> DB

File: `docs/diagrams/F32-journey.mmd`

User journey (BPMN-style):
1. User clicks "Refresh All"
2. Frontend triggers scan (POST)
3. Frontend connects to SSE stream
4. For each card: event arrives, progress updates, card highlights
5. Scan completes, final summary shown
6. Alt: SSE fails, fallback to polling
