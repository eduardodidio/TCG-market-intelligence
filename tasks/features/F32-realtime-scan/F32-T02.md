# F32-T02 -- Scan Orchestrator: Publish Events to Event Bus

**Wave:** 1
**Depends on:** T01 (event bus exists)
**Estimated effort:** small

## Objective

Modify `src/collectors/scan.py` to publish `ScanEvent` objects to the event
bus after each card is processed. The existing DB update logic is unchanged.

## Changes

### File: `src/collectors/scan.py`

1. Import `ScanEvent` and `scan_bus`.

2. After `repo.update_scan_run(run_id, cards_total=cards_total)`, publish a
   `scan_started` event:
   ```python
   scan_bus.publish(ScanEvent(
       event_type="scan_started",
       scan_id=run_id,
       timestamp=datetime.now().isoformat(),
       cards_total=cards_total,
   ))
   ```

3. Inside `process_entry`, after updating the shared counters (both success
   and failure paths), publish a `card_scanned` event:
   ```python
   scan_bus.publish(ScanEvent(
       event_type="card_scanned",
       scan_id=run_id,
       timestamp=datetime.now().isoformat(),
       external_id=external_id,
       card_name=entry.get("name_en", ""),
       price_found=<bool>,
       price=<Decimal or None>,
       currency=<str or None>,
       error=<str or None>,
       cards_processed=cards_processed,
       cards_total=cards_total,
       cards_failed=cards_failed,
       observations_saved=observations_saved,
   ))
   ```

4. After the final `repo.update_scan_run` (completion), publish a
   `scan_complete` event with final totals and status.

5. In the `except` block (scan failure), publish a `scan_complete` event
   with `error` field set.

6. In the `finally` block, call `scan_bus.cleanup(run_id)` after a short
   delay (e.g., 5 seconds via `asyncio.sleep`) to give SSE clients time to
   receive the final event before the queue is removed.

### Thread safety note

`run_scan` runs inside a background thread (via `threading.Thread` in
`scans.py` router). The event bus `publish` method must handle cross-thread
calls. If using `asyncio.Queue`, the publisher should use a thread-safe
mechanism (see T01).

## Tests

File: `tests/collectors/test_scan_events.py`

- Mock the event bus, run a scan with 2-3 test cards
- Assert `scan_started` event is published with correct `cards_total`
- Assert one `card_scanned` event per card with correct fields
- Assert `scan_complete` event is published with final totals
- Assert events are published even when cards fail (with error field)
- Assert cleanup is called after scan completes

- [ ] `scan_complete` event published when scan finishes

- [ ] All existing scan tests still pass
