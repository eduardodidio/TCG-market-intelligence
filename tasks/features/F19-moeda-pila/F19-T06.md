# F19-T06: User Currency Preference Wiring (F22 Auth Integration)

- **Wave:** 3
- **Status:** planned
- **Depends on:** F19-T05 (all display points are currency-aware), F22 (auth system exists)

## Description

Wire the user's currency preference into the F22 authentication/user profile system.
When a user logs in, their preferred currency is loaded from their profile and injected
into the frontend currency context. The user can change their preferred currency from
a settings page or currency selector widget, and the preference is persisted to the
backend.

This task bridges F19 (Pila currency) with F22 (auth/user system). It assumes F22
provides:
- A user model with extensible preferences/settings
- An API endpoint to read/update user preferences
- A frontend auth context with user data

## Implementation Details

### Backend

- Add `preferred_currency` field to the user preferences model (default: `"BRL"`)
- Add/extend `PATCH /api/v1/users/me/preferences` to accept `preferred_currency`
- Validate that the currency code exists in the F18 currency registry
- Return `preferred_currency` in the user profile response

### Frontend

- Read `preferred_currency` from the user profile on login
- Store it in a React context (or extend F18's currency context)
- Provide a `useCurrency()` hook that returns `{ currency, setCurrency }`
- Currency selector widget (dropdown or toggle) in the navbar or settings page
- On change: update backend preference + update local context
- On logout: revert to default BRL

## Acceptance Criteria

- [ ] User profile includes `preferred_currency` field (default "BRL")
- [ ] `PATCH /api/v1/users/me/preferences` accepts and validates `preferred_currency`
- [ ] Invalid currency codes are rejected with 400 error
- [ ] Frontend loads preferred currency on login
- [ ] Currency selector allows choosing between available currencies (including PILA)
- [ ] Selecting PILA persists the preference and immediately updates all price displays
- [ ] Page refresh preserves the selected currency (loaded from profile)
- [ ] Unauthenticated users see BRL (default)
- [ ] All existing tests pass
- [ ] Backend tests for preference CRUD
- [ ] Frontend tests for currency context and selector
