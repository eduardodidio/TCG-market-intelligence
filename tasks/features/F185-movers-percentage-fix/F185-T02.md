**Wave:** 0
**Type:** backend
**Depends on:** (none)
**Status:** done

## User Story

As a user viewing the volatile cards list, I want the data to exclude dirty
outliers, so that the volatile cards shown are genuinely volatile, not noise.

## Objective

Apply sanity filters to the market volatile endpoint and the market summary
endpoint, which both call `repo.get_movers()` with `limit=9999` and then
process the raw results.

## Dev Notes

- File: `src/api/routers/market.py`
- `get_movers` endpoint at line 67 calls `market_data.get_top_movers()`
- Market summary at line 229 calls `repo.get_movers(days=days, limit=9999)`
  and computes avg change from ALL movers — dirty data inflates averages
- Market volatile at line 325 calls `repo.get_movers(days=days, limit=9999)`
  and sorts by `abs(change_pct)` — extreme outliers dominate
- After T01 fixes `get_movers()` itself, these endpoints will automatically
  benefit from the R$0.50 floor + 1000% cap
- **However**, verify that `market_data.get_top_movers()` (service layer)
  doesn't re-introduce unfiltered data
- File: `src/services/market_data.py` line 157 — calls `self._repo.get_movers()`
  so it will inherit T01 fixes automatically
- Main work: add tests verifying the endpoints respect the filters
