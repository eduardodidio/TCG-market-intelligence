# F122-T01 — Collection Scroll CLS Fix

## User Story

As a collector, I want the card grid to load without layout shift so that the page does not jump around while I scroll or wait for data.

## Dev Notes

### Root Cause Analysis

Three sources of Cumulative Layout Shift (CLS) in `MyCollection.tsx`:

1. **SkeletonCard height mismatch** — `Skeleton.tsx` line 21 uses `h-40` (fixed 10rem) but real cards use `aspect-[5/7]` (ratio-based). On different screen widths, the skeleton is shorter or taller than real cards, causing a jump when data loads.

2. **Full grid replacement pattern** — `MyCollection.tsx` lines 848-857 render `{loading && <skeletons>}` and lines 886-943 render `{!loading && <cards>}`. The entire grid is swapped, which causes a flash. This is acceptable for the initial load but could be smoother.

3. **Async widgets above grid** — `PortfolioDashboard` (line 687), `SetCompletionSection` (line 702-704), and `BanAlertBanner` (line 690-699) load asynchronously and push the grid down when they appear. They have no reserved height.

### Implementation Steps

**File: `frontend/src/components/Skeleton.tsx`** (line 18-26)
- Change `SkeletonCard` to use `aspect-[5/7]` instead of `h-40` to match real card proportions.
- Add the same `p-3` info section skeleton below the image area to match `CollectionCardTile` structure.
- Updated skeleton:
  ```
  <div className="rounded-lg bg-slate-800 border border-slate-600 overflow-hidden">
    <div className={`${pulseBase} aspect-[5/7] w-full`} />
    <div className="p-3">
      <div className={`${pulseBase} h-4 w-3/4 mb-2`} />
      <div className={`${pulseBase} h-4 w-1/2`} />
    </div>
  </div>
  ```

**File: `frontend/src/pages/MyCollection.tsx`**
- Lines 687-704: Wrap `PortfolioDashboard`, `BanAlertBanner`, and `SetCompletionSection` in a container with `min-h-[<value>]` or use CSS `contain: layout` to prevent them from shifting the grid when they load.
- Alternative (simpler): give each async section a fixed `min-h` placeholder. For example, PortfolioDashboard gets `min-h-[200px]` when data is null, collapsing to auto when loaded.
- The sticky filter bar (line 707) with `ScanProgressBar`/`ScanSummaryCard` already uses `sticky top-0`, so it should not cause CLS. Verify that its height changes during scan do not push content (sticky elements should not).
