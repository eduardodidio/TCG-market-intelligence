# F122-T03 — Set Completion Fix + Owned/Unowned View

## User Story

As a collector, I want set completion to show accurate percentages (not fake 100% for sets without catalog data) and I want to click a set to see ALL cards in that set with owned cards highlighted and unowned cards faded, so that I can plan which cards to acquire next.

## Dev Notes

### Sub-issue A: Wrong 100% for sets without catalog data

**Root cause**: `collection.py` line 539 — `"total": max(total, owned_count)`. When `totals_by_set.get(set_code, 0)` returns 0 (set not in Scryfall catalog), `total` becomes `owned_count`, making every such set show 100%.

Affected sets (not in Scryfall catalog): awot, eftle, ex, fnmp, mi, ne, pro, sc, sc9, us, vi — these are custom/promo set codes from manual collection entries.

**Fix in `src/api/routers/collection.py`** (lines 531-543):
- When `total == 0` (no catalog data for this set), keep `total = owned_count` BUT add a flag `"has_catalog": False` to the response.
- Alternative (simpler): filter out sets where `totals_by_set.get(set_code, 0) == 0` from the completion bar entirely. These sets have no meaningful completion to track.
- **Recommended approach**: add `"has_catalog": bool` flag to the response. Let the frontend decide how to display. Sets without catalog data show "X cards" instead of "X of Y".

Updated backend code:
```python
for set_code, set_name, owned_count in collection_sets:
    catalog_total = totals_by_set.get(set_code, 0)
    has_catalog = catalog_total > 0
    data.append(
        {
            "set_code": set_code,
            "set_name": set_name or set_code,
            "owned": owned_count,
            "total": catalog_total if has_catalog else owned_count,
            "has_catalog": has_catalog,
        }
    )
```

**Fix in `frontend/src/components/SetCompletionBar.tsx`** (lines 82-152):
- Accept new `hasCatalog?: boolean` prop.
- When `hasCatalog === false`, show "X cards (no catalog)" instead of "X of Y" and hide the progress bar fill (or show it as grey/indeterminate).
- Update `SetCompletionSection` and `SetCompletionEntry` type to include `has_catalog`.

**Fix in `frontend/src/api/collection.ts`** (lines 191-201):
- Add `has_catalog: boolean` to `SetCompletionEntry` interface.

### Sub-issue B: Click set shows owned/unowned view

Currently, clicking a set in `SetCompletionBar` navigates to `/collection?set=${setCode}` (line 95), which shows only owned cards from that set.

**Goal**: Show ALL cards from the Scryfall catalog for that set, with owned cards at full opacity and unowned cards faded (opacity-40).

**Backend approach** — New endpoint or extend existing:

Option 1 (recommended): Add a query param to the catalog endpoint `GET /api/v1/catalog/cards?set_code=X&with_ownership=true` that includes an `owned: boolean` field in each `CatalogCardItem`.

**File: `src/api/routers/catalog.py`**
- Add `with_ownership: bool = Query(default=False)` and `user_id: str | None` (optional auth) to `list_catalog_cards`.
- When `with_ownership=True`, LEFT JOIN against `user_collection` to add an `owned` boolean:
  ```sql
  LEFT JOIN user_collection uc
    ON uc.card_id = c.id AND uc.user_id = :user_id
  ```
- Add `owned: bool = False` field to `CatalogCardItem`.
- The endpoint stays public when `with_ownership=False` (no auth needed). When `with_ownership=True`, require auth.

**File: `frontend/src/components/SetCompletionBar.tsx`** (line 95):
- Change click navigation from `/collection?set=${setCode}` to `/catalog?set_code=${setCode}&owned_view=1`.
- Only do this when `hasCatalog` is true. When `hasCatalog` is false, keep the current behavior (navigate to `/collection?set=${setCode}`).

**File: `frontend/src/pages/CatalogPage.tsx`**:
- Read `owned_view` URL param. When present, fetch catalog cards with `with_ownership=true`.
- Render owned cards at full opacity, unowned cards at `opacity-40` with a visual indicator (e.g., "Not owned" badge or dashed border).
- Add a toggle or badge showing "Showing set completion view" with a link back to collection.
