# F122-T04 — Daily Scan Automation via GitHub Actions

## User Story

As the platform operator, I want Liga price sweeps and portfolio snapshots to run automatically every day so that prices stay fresh and portfolio history accumulates without manual intervention.

## Dev Notes

### Context

- The project has `liga-sweep` and `snapshot-portfolio` CLI commands in `src/cli/main.py`.
- Render free tier spins down after inactivity, so APScheduler (in `scheduler/service.py`) cannot reliably run cron jobs.
- The database is Neon PostgreSQL, accessible via `DATABASE_URL` (connection string with `?sslmode=require`).
- Python version: 3.14 (specified in `pyproject.toml`).
- The project uses `pip install -e .` with `pyproject.toml` (no requirements.txt).

### Implementation Steps

**File: `.github/workflows/daily-scan.yml` (new)**

Create the workflow with this structure:

```yaml
name: Daily Liga Sweep + Portfolio Snapshot

on:
  schedule:
    # Run at 06:00 UTC (03:00 BRT) — low traffic window
    - cron: "0 6 * * *"
  workflow_dispatch:
    # Allow manual trigger from GitHub Actions UI
    inputs:
      max_age_days:
        description: "Skip cards with Liga price newer than N days"
        required: false
        default: "1"

env:
  DATABASE_URL: ${{ secrets.DATABASE_URL }}
  TCG_SECRET_KEY: ${{ secrets.TCG_SECRET_KEY }}

jobs:
  liga-sweep:
    runs-on: ubuntu-latest
    timeout-minutes: 120
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python 3.14
        uses: actions/setup-python@v5
        with:
          python-version: "3.14"
          allow-prereleases: true

      - name: Install dependencies
        run: pip install -e .

      - name: Run Liga sweep
        run: |
          python -m src.cli.main liga-sweep \
            --max-age-days ${{ github.event.inputs.max_age_days || '1' }} \
            --batch-size 20 \
            --batch-pause 60 \
            --delay 5

      - name: Take portfolio snapshots
        run: python -m src.cli.main snapshot-portfolio
```

### Key Decisions

1. **Cron time**: 06:00 UTC = 03:00 BRT. Liga Magic has lowest traffic at night. GitHub Actions cron can have up to 15-minute delay, which is acceptable.

2. **Timeout**: 120 minutes. Liga sweep with `--delay 5` and `--batch-pause 60` for ~200 collection cards takes ~60-90 minutes worst case.

3. **Python 3.14**: Use `allow-prereleases: true` with `setup-python` since 3.14 may not be in GA channel.

4. **Dependencies**: `pip install -e .` installs from `pyproject.toml`. No separate requirements.txt needed. Note: `curl_cffi` requires system-level `libcurl`, which is available on `ubuntu-latest`.

5. **Secrets needed**: `DATABASE_URL` (Neon connection string) and `TCG_SECRET_KEY` (for any auth-related imports). Both must be added to GitHub repo Settings > Secrets > Actions.

6. **`workflow_dispatch`**: Allows manual trigger with configurable `max_age_days`. Default is 1 (skip cards refreshed in last 24h).

7. **No `liga-sweep --db` flag**: The CLI auto-resolves the DB URL from `DATABASE_URL` env var via `config.py._load_dotenv()` / `get_db_url()`. Since we set `DATABASE_URL` in the workflow env, no `--db` flag is needed.

### Potential Issue: curl_cffi on Linux

`curl_cffi` ships pre-built wheels for Linux x86_64, so `pip install` should work without extra system deps on `ubuntu-latest`. If it fails, add a step:
```yaml
- name: Install system deps
  run: sudo apt-get update && sudo apt-get install -y libcurl4-openssl-dev
```
