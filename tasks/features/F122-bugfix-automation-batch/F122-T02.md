# F122-T02 — Price Sort Integrity Review

## User Story

As a collector, I want my collection sorted by price to show cards in the correct order so that I can quickly find my most/least valuable cards.

## Dev Notes

### Investigation Summary

The backend sort logic is **correct** (verified in `repository.py` lines 1577-1600):
- Price sort joins `_latest_price_subquery()`, orders by `null_flag` (NULLs last), then `median_price` in requested direction, then `id` as tiebreaker.
- The API endpoint at `collection.py` lines 101-122 passes `sort_by` and `sort_dir` directly to `repo.list_collection()`.

Since the backend is correct, the issue is likely client-side. Focus investigation on these areas:

### Potential Client-Side Issues

1. **Currency conversion reorder** — `collection.py` lines 110 and the converter logic: if the API converts prices to USD/PILA on the server side, the sort is done before conversion. Check `collection.py` to see if conversion happens after the query. If prices are converted with varying exchange rates per card (unlikely but possible), sort order could break. **Action**: read the full `list_collection` endpoint to verify conversion happens after sort but preserves order.

2. **Live scan updates reorder** — `MyCollection.tsx` lines 440-449: when `lastScannedCard` updates, `setCards` maps over the array and updates `latest_price` for matching cards. This changes prices in-place without re-sorting, so cards that get new prices appear out of order until the next full fetch. **Action**: after scan completes (in `handleRefreshComplete`), the `refreshKey` increment triggers a full refetch which re-sorts. But during a scan, order will be stale. Document this as expected behavior or add a local re-sort after scan updates.

3. **Pagination offset drift** — `MyCollection.tsx` lines 597-618: `handleLoadMore` uses `offset` to fetch the next page. If prices change between page fetches (e.g., during a scan), the offset-based pagination can skip or duplicate cards. **Action**: this is a known limitation of offset pagination with changing data. The `c.id ASC` tiebreaker in the backend helps but does not fully solve it.

4. **URL param sync** — `MyCollection.tsx` lines 532-541: URL params only include `sort` and `dir` when they differ from defaults (`price`/`desc`). The `buildParams` function at lines 544-558 always sends `sort_by` and `sort_dir` to the API. Verify these are consistent.

### Implementation Steps

**File: `frontend/src/pages/MyCollection.tsx`**
- Lines 440-449: After updating a card's price via scan, do NOT re-sort locally (it would break pagination). Instead, add a comment explaining this is expected behavior during active scans.
- Add a test that verifies `buildParams` includes `sort_by` and `sort_dir` for all sort options.

**File: `src/api/routers/collection.py`**
- Read the full `list_collection` endpoint (lines 101-190) to verify currency conversion preserves sort order. If conversion happens after the DB query, sort is preserved (prices are just multiplied by a constant rate). Document this.

- Lines 1577-1600: Add a backend test that verifies price sort with mixed NULL/non-NULL prices, foil entries, and manual prices.
