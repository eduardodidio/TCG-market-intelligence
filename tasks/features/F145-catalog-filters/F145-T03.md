# Task F145-T03 — Add "Owned" toggle filter

**Feature:** F145
**Wave:** 1
**Type:** frontend
**Depends on:** (none)
**Status:** planned

## User Story

As a logged-in user browsing the catalog, I want to toggle an "Owned" filter
so I can quickly see only the cards I already have (or only the ones I am
missing from a set).

## Objective

Add an "Owned" filter toggle row to the CatalogPage filter bar. Three states:
All (default), Owned, Not Owned. When active, the filter passes
`with_ownership=true` to the API and client-side filters by the `owned`
field on each card.

## Dev Notes

### Current state

- `useCatalogCards` already supports `with_ownership` filter param (line 38
  of `useCatalogCards.ts`). When `with_ownership=true`, the API response
  includes `owned: boolean | null` on each card.
- The existing `ownedView` mode (line 299 of CatalogPage) already uses
  `with_ownership` and renders owned/unowned cards differently (opacity).
  This was designed for the set-completion click-through flow.
- The new "Owned" toggle is a general-purpose filter, not tied to
  `owned_view=1` from set completion. It should be a separate filter that
  works independently.

### Implementation plan

1. Add state variable:
   ```tsx
   const [ownedFilter, setOwnedFilter] = useState<"all" | "owned" | "not_owned">(
     () => (searchParams.get("owned_filter") as "all" | "owned" | "not_owned") ?? "all"
   );
   ```

2. When `ownedFilter !== "all"`, set `with_ownership: "true"` in the filters
   object so the API returns the `owned` field.

3. Client-side post-filter: after receiving cards from the hook, filter by
   `owned` field:
   - `"owned"` -> keep cards where `card.owned === true`
   - `"not_owned"` -> keep cards where `card.owned === false`
   - `"all"` -> no filtering

   Note: client-side filtering is acceptable because the backend does not
   have a native `owned_only` query param. The `with_ownership` param only
   annotates cards, it does not filter them. If performance is an issue in
   the future, a backend param can be added.

4. Render three toggle chips in the filter bar (inside the collapsible
   filter section), similar to MyCollection's acquisition filter chips
   (lines 780-815 of MyCollection.tsx):
   ```
   Ownership: [All] [Owned] [Not Owned]
   ```

5. Only show the ownership filter when the user is authenticated (guests
   cannot own cards).

6. Persist `owned_filter` in URL search params.

7. Include `ownedFilter` in `hasActiveFilters` check (when not "all").

## Acceptance criteria

- [ ] Three ownership chips render inside filter section when user is authenticated
- [ ] Chips do not render for unauthenticated users
- [ ] Selecting "Owned" shows only cards where `owned === true`
- [ ] Selecting "Not Owned" shows only cards where `owned === false`
- [ ] Selecting "All" removes the filter (shows all cards)
- [ ] Active chip has distinct visual style (cyan bg, matching other filter chips)
- [ ] `owned_filter` persists in URL params; page reload restores filter
- [ ] Filter badge count in the Filters toggle button includes owned filter when active
- [ ] Clear Filters resets owned filter to "all"

## Test scenarios

- **Happy path:** Authenticated user clicks "Owned" -> only owned cards shown
- **Happy path:** User clicks "Not Owned" -> unowned cards shown, can identify missing cards
- **Edge case:** User is not authenticated -> ownership chips not rendered
- **Edge case:** API returns `owned: null` for a card -> treated as not owned
- **Edge case:** Switching from "Owned" to "All" restores full card list
- **Boundary:** No cards are owned in current set -> "Owned" filter shows empty state
