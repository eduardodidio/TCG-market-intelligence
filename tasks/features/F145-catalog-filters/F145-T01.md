# Task F145-T01 — Extend catalog sort enum (rarity + collector_number)

**Feature:** F145
**Wave:** 0
**Type:** backend
**Depends on:** (none)
**Status:** planned

## User Story

As a user browsing the catalog, I want to sort cards by rarity or collector
number, so that I can find specific cards faster when exploring a set.

## Objective

Add `rarity` and `collector_number` to `SortByEnum` in the catalog router
and wire them to the correct SQL columns in the query builder.

## Dev Notes

- File: `src/api/routers/catalog.py`
- `SortByEnum` currently has: `name`, `set_code`, `price` (line 67-70).
- `sort_col_map` (around line 212) maps enum values to SQL column
  expressions. Add:
  - `rarity` -> `c.rarity` (the `cards` table column)
  - `collector_number` -> `c.collector_number`
- For rarity sort, define a CASE expression to impose M > R > U > C order
  (not alphabetical). Example:
  ```python
  SortByEnum.rarity: "CASE c.rarity WHEN 'M' THEN 0 WHEN 'R' THEN 1 WHEN 'U' THEN 2 WHEN 'C' THEN 3 ELSE 4 END"
  ```
- For `collector_number`, the column is text. Use a numeric cast so that
  "2" sorts before "10":
  ```python
  SortByEnum.collector_number: "CAST(c.collector_number AS INTEGER)"
  ```
  Wrap in a TRY/COALESCE for non-numeric collector numbers (e.g., "2a"):
  PostgreSQL: `CAST(regexp_replace(c.collector_number, '[^0-9]', '', 'g') AS INTEGER)`
  or simpler: just use `c.collector_number` as text sort (acceptable for MVP).
- No migration needed — this is a query-time change only.
