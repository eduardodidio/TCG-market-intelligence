# F172-T11 — Frontend: `SuggestionRequestForm`

- **Wave:** 2
- **Type:** frontend
- **Depends on:** F172-T06 (`CommanderSearch`), F172-T07 (API + types)
- **Status:** planned

## User Story

As a player, I want to describe the deck I want (a commander and notes, or colors and an archetype), so that the daily routine can build it for me.

## Objective

Create the request form with per-format fields, client validation, and submit/success/error handling.

## Dev Notes

See `_brief/00-overview.md`, `_brief/02-suggestion-persistence-api.md` (validation rules) and `_brief/04-frontend-flow.md` (component "SuggestionRequestForm").

- Reuse `CommanderSearch` from `frontend/src/components/decks/CommanderSearch.tsx` (T06) and `createDeckSuggestion` plus the constants from `frontend/src/api/deckSuggestions.ts` (T07).
- The color toggle visuals can copy `MTG_COLORS` from `DeckBuildWizard.tsx`. Add "C" (colorless, `bg-slate-400`). Selecting C clears WUBRG and vice versa.
- Notes: a `<textarea maxLength={1000}>` with a counter `n/1000`.
- The client validation mirrors the server's. The server errors (`resp.errors[0].message`) are still displayed.
- On success: show the banner, reset the form (keep the format), and call `onCreated(resp.data)`.
- i18n `deckSuggest.form.*` with English defaults.

## Implementation details

`export function SuggestionRequestForm({ onCreated }: { onCreated: (s: DeckSuggestion) => void })`.
State: `format`, `commander`, `colors`, `archetype`, `notes`, `submitting`, `error`, `success`.
Body: commander → `{format_name, commander_card_id, notes}`. Others → `{format_name, colors, archetype, notes}`.

## Acceptance criteria

- [ ] Commander format shows the search + notes only. Other formats show colors + archetype + notes.
- [ ] Submit is disabled until valid, and while submitting (no double submit).
- [ ] The success banner is shown and `onCreated` is called with the returned item.
- [ ] A 400/429 message is shown inline and the form keeps its values.

## Testing

Mock `../../../api/deckSuggestions` (keep the real constants via `vi.importActual`), and mock `../CommanderSearch` with a stub that has a button calling `onSelect({card_id: 7, name_en: "Atraxa", ...})`.

## Test scenarios

- Happy: commander + notes → the body contains `commander_card_id: 7` and the notes. Modern + R,G + aggro → the correct body.
- Edge: switching format resets the format-specific fields; the C toggle clears the others; whitespace-only notes are sent as null; the counter updates.
- Error: the API returns `errors: [{message: "Too many open requests"}]` → shown; a rejected promise → a generic error, and submitting resets.
- Boundary: 1000 chars allowed (maxLength); no archetype → disabled; no colors → disabled; commander not selected → disabled.
