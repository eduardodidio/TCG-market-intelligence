## User Story

As a player, I want the daily routine to turn my request into a full deck that uses my cards first and prices what's missing, so that
I know what to buy and how much it costs.

## Objective

Implement `src/deck_suggestions/processor.py`: claim pending requests, build the prompt from the user's collection, call the runner,
parse, resolve names to catalog cards, enrich with owned quantity and BRL prices, and persist done/failed/retry.

## Dev Notes

See `_brief/00-overview.md`, `_brief/02-suggestion-persistence-api.md` (result contract) and `_brief/03-claude-processor.md` (processor section).

- Collection table: `UserCollectionRow` (`src/database/models.py:101`): `user_id` (str), `card_id` (nullable FK), `name_en`, `name_pt`, `quantity`.
  Join `CardRow` on `card_id` for `color_identity` / `type_line`. Rows with `card_id` NULL are still owned (by name), but `color_identity` is unknown,
  so keep them only if the request is ≥ 3 colors, or drop them (document the choice in the docstring).
- Prices: `Repository.get_latest_prices_batch(card_ids)` → `PriceObservationRow.median_price` (Decimal → float, 2 dp).
  CLAUDE.md: the Liga sweep stores `mid` as the market price, and the batch helper already applies source priority.
- Name resolution: `CardRow.name_en` exact (`func.lower(...) == name.lower()`), in chunks of 200 via `IN` on lowercase.
  Fallback: `name_pt`, then the DFC front face (`name_en LIKE 'X // %'`).
- Basic lands (see T04 constant) → `is_owned=True`, `unit_price=0`, and they never count as missing.
- The commander (if any) is added to `result["commander"]` and counted in `summary.total_cards` (100 for commander).
- The processor receives `repo: Repository` and `runner`. Tests inject a fake runner (`class FakeRunner: provider="fake"; model="m"; def run(self, p): return canned`).

## Implementation details

`ProcessSummary`, `load_owned_cards`, `resolve_cards`, `enrich` (pure: parsed + request fields + owned map + resolved map + prices → result dict),
`process_pending_suggestions(repo, runner, *, limit=5, dry_run=False)`. `generated_at = datetime.now().isoformat(timespec="seconds")`.
Log each request outcome with structlog (`deck_suggestion_done`, `deck_suggestion_failed`, with `request_id` and counts, no prompt text).

- [x] Owned cards are flagged with `owned_quantity`. `missing_quantity = max(0, qty - owned)`. `missing_cost` and the `missing_cost_brl` sum are correct.

- [x] `dry_run` changes nothing.

## Test scenarios

- Happy: commander request, 3 of 5 suggested cards owned, 2 priced → summary (owned 3, missing 2, cost = sum).
- Edge: owned qty 1 vs suggested 4 (modern) → missing 3; a basic land never missing; a PT name returned by Claude resolves via `name_pt`; DFC front face;
  duplicated printings → prefer the owned card_id; a user with an empty collection → the prompt has no owned list and still works.
- Error: runner raises transient ×3 across runs → failed on the 3rd; non-transient → failed immediately; garbage text → failed; an unexpected exception in `enrich` → failed, and the next request is still processed.
- Boundary: `limit=1` with 3 pending → only the oldest processed; no pending → summary total 0; all names unresolved → done with `missing_cost_brl` None + a warning.

## Notes from Developer

- `load_owned_cards(repo, user_id)` takes the `Repository` (not a bare engine) because it needs
  `get_latest_prices_batch`. It returns an `OwnedCollection` (`linked`, `unlinked`, `card_ids`)
  instead of a plain list, so that `resolve_cards` can prefer owned printings and the prompt can
  treat unlinked rows separately.
- Collection rows with `card_id` NULL always count toward `owned_quantity` (matched by EN or PT name).
  They go into the prompt only when the request has 3+ colors, because their color identity is unknown.
- `resolve_cards(engine, names, owned_card_ids)` returns a dict keyed by `name.lower()`. Only
  `game == "magic"` rows match. Printing preference: owned → has image → highest id. DFC handling covers
  both directions: "Front" → catalog "Front // Back", and "Front // Back" → catalog "Front".
- `is_owned` means fully owned (`missing_quantity == 0`). Basic lands: owned = quantity, `unit_price=0`.
  `missing_cost` is 0.0 whenever nothing is missing. `missing_cost_brl` is None when no non-basic card has a known cost.
- If Claude lists the commander in `cards`, it is removed (with a warning). The commander dict carries the
  same owned/price fields as the cards (a superset of `{name_en, card_id}`).
- `dry_run` counts `pending` rows (capped at `limit`) without claiming anything.
- `mark_done` runs inside the per-request try, so a persistence error only fails that request.
