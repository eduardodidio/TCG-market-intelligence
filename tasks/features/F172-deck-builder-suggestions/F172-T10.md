- **Wave:** 2

- **Depends on:** F172-T01
- **Status:** planned

## User Story

As a player, I want to choose between building my own deck and asking for a suggestion before anything else, so that I start the
right flow.

## Objective

Create a presentational component with two large option cards. It is wired into the wizard by T14.

## Dev Notes

See `_brief/00-overview.md` and `_brief/04-frontend-flow.md` (component "DeckBuildModeChooser").

- Style: reuse the option-card look from `DeckBuildWizard.tsx` step 1 (`p-4 rounded-lg border bg-slate-800 border-slate-600 hover:border-slate-500`).
  Layout `grid grid-cols-1 md:grid-cols-2 gap-4`.
- i18n keys under `deckSuggest.mode.*` with English `defaultValue`. T18 adds pt-BR.
  Defaults: "Build my own deck" / "Pick format, colors and archetype — generated instantly."; "Deck suggestion" / "Claude builds a deck around your collection. Processed once a day."
- Accessible: real `<button type="button">`, with `aria-describedby` for the description.

## Implementation details

`export function DeckBuildModeChooser({ onChoose }: { onChoose: (mode: "manual" | "suggestion") => void })`.
testids: `mode-chooser`, `mode-option-manual`, `mode-option-suggestion`.

## Acceptance criteria

- [ ] Clicking each option calls `onChoose` with the right mode.
- [ ] It is keyboard accessible (Enter/Space via the native button).
- [ ] Test file exists and passes.

## Test scenarios

- Happy: click manual → `onChoose("manual")`; click suggestion → `onChoose("suggestion")`.
- Edge: rendering without a crash when `t` returns keys (no defaultValue).
- Error: n/a (presentational). Assert that `onChoose` is not called on render.
- Boundary: both buttons have an accessible name (`getByRole("button", { name: /…/ })`).
