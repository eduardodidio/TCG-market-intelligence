## Retrospective Seeds

- **Pattern:** A frontend task (T12) drifted from the planned i18n key namespace (`deckSuggest.*` → `deckSuggestions.*`), and the fix was patched around in a later wave (T18 added both namespaces) instead of corrected at the source.
- **Role(s) affected:** developer, techlead
- **Lesson:** When a later Wave's task (here T18, doing i18n) discovers an earlier task used a different key namespace than planned, prefer fixing the earlier component's keys directly (cheap, isolated change) over adding a parallel namespace "just to be safe" — the latter leaves permanent dead keys that outlive the retro note. TechLead should treat this class of drift as IMPORTANT, not MINOR, since it compounds across features that keep adding to the wrong namespace by copy-paste.
- **Pattern:** Wave summaries across F172 consistently reported work "uncommitted in the worktree" at hand-off to the next Wave, relying on the next Wave to build on an uncommitted working tree rather than a commit boundary.
- **Role(s) affected:** architect, developer
- **Lesson:** Consider requiring a Wave-end commit as a hard gate before the next Wave starts, so `git diff --stat HEAD~1..HEAD` style verification (used by wave-summary mode) stays reliable instead of depending on informal "uncommitted state" notes.
