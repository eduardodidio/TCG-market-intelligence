# F172-T08 — Backend: `/deck-suggestions` router + schemas

- **Wave:** 2
- **Type:** backend
- **Depends on:** F172-T02 (`is_commander_eligible`), F172-T03 (repository)
- **Status:** planned

## User Story

As a player, I want to register a suggestion request and immediately see it listed with its status, so that I don't have to wait for Claude
while I'm in the app.

## Objective

Implement the 5 endpoints of `_brief/02` in a NEW router + schemas module. Registration in `app.py` happens in T17.

## Dev Notes

See `_brief/00-overview.md` and `_brief/02-suggestion-persistence-api.md` (API, schemas, validation, save-as-deck, result contract).

- Router: `APIRouter(prefix="/deck-suggestions", tags=["decks"])`. Auth: `user_id: str = Depends(require_auth_or_api_key)`
  and `repo: Repository = Depends(get_db)`, both from `src.api.deps` (same as `src/api/routers/decks.py`).
- Envelope: `ApiResponse[...]`, `success_response(data=...)` from `src/api/schemas/envelope.py`. Errors: `api_error(status, ErrorCode.X, msg, field=?)`.
  The codes exist: `VALIDATION_ERROR`, `VALIDATION_LIMIT_EXCEEDED`, `RESOURCE_NOT_FOUND`, `RESOURCE_CONFLICT`.
- POST returns **201**: `@router.post("", status_code=201, ...)`. DELETE returns 204 (see `delete_deck` in `decks.py:694`).
- Save-as-deck reuses `repo.create_deck` / `repo.add_deck_cards`, like `generate_deck_endpoint` (`decks.py:~323`).
  For idempotency, if `saved_deck_id` is set and `repo.get_deck(saved_deck_id)` (check the actual method name in `src/database/repository.py`) exists, return it.
- Colors ⇄ list via `colors_to_str` / `colors_from_str` from `src/deck_suggestions/repository.py`.
- `summary` in the list response = `load_result(row)["summary"]` when done (else None). `result` only in GET `/{id}`.
- Do NOT edit `src/api/app.py` (T17).

## Implementation details

- `src/api/schemas/deck_suggestions.py`: `SUGGESTION_FORMATS`, `SUGGESTION_ARCHETYPES`, `DeckSuggestionCreate`, `DeckSuggestionSave(deck_name: str | None = Field(None, min_length=1, max_length=300))`,
  `SuggestionSummary`, `DeckSuggestionSchema`, `DeckSuggestionSavedResponse(deck_id: int)`, and a `to_schema(row, include_result: bool)` helper.
- `src/api/routers/deck_suggestions.py`: `create_suggestion`, `list_suggestions`, `get_suggestion`, `save_suggestion_as_deck`, `delete_suggestion`.
  A private `_validate_create(body, repo) -> dict` implements the validation rules.

## Acceptance criteria

- [ ] All rules of `_brief/02` "Validation rules" are enforced with 400 + a clear message (pt-BR or English, consistent with `decks.py`: English).
- [ ] Commander colors come from the card, not the client.
- [ ] A 6th open request → 429.
- [ ] Another user's request → 404 on get/save/delete.
- [ ] Save on a non-done request → 409. A second save → the same deck_id, and no new deck is created.
- [ ] ≥ 95% coverage for both new modules.

## Test scenarios

- Happy: a commander request (a legendary creature with ci "WUBG") → 201, pending, colors `["W","U","B","G"]`; a modern request with colors ["r","R","g"] + aggro → colors `["R","G"]`;
  list newest first; get with result after `mark_done`; save → deck with commander + cards; delete pending → 204.
- Edge: notes "   " → None; commander request with client colors → ignored; `?status=done` filter; `limit` bounds 1..50; colorless `["C"]`.
- Error: unknown format; commander without an id; a non-existent card; a non-legendary card; non-commander without colors or archetype; colors `["X"]`; `["C","W"]`;
  archetype "foo"; notes 1001 chars (422 from pydantic or 400: assert whichever is implemented, consistently); invalid `?status=`; save when pending (409); delete when done (409).
- Boundary: exactly 5 open → the 6th is rejected, but a `failed` or `done` request doesn't count; `deck_name` of 300 chars accepted, 301 rejected.
