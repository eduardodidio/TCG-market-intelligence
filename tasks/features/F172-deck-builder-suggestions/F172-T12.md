## User Story

As a player, I want to see all my suggestion requests and their status, so that I know which ones are ready.

## Objective

Create a presentational list with status badges, selection, refresh, and delete for pending items.

## Dev Notes

See `_brief/00-overview.md` and `_brief/04-frontend-flow.md` (component "SuggestionRequestList").

- It is presentational: the data fetching lives in `DeckSuggestionPanel` (T14). Props:
  `{ items: DeckSuggestion[]; selectedId: number | null; loading: boolean; onSelect(id): void; onRefresh(): void; onDelete(id): void }`.
- Status badge colors: pending amber, processing cyan, done green, failed red. Use `title={error_message}` on failed.
- Dates: `new Date(created_at).toLocaleDateString("pt-BR")` (the project is BR-first). Check whether a date helper already exists in `frontend/src/utils/` and reuse it.
- Delete asks for confirmation with `window.confirm` (the simplest option. Reuse `GauchoDialog.tsx` if there is an established confirm pattern).
- An empty state that reuses `frontend/src/components/EmptyState.tsx` if its API fits.

## Implementation details

Row label: commander → `commander_name`. Else → `colors.join("")` + ` · ` + archetype. Prefix with the format label.
testids: `suggestion-list`, `suggestion-row-{id}`, `suggestion-status-{id}`, `suggestion-delete-{id}`, `suggestion-refresh`, `suggestion-list-empty`, `suggestion-list-loading`.

## Acceptance criteria

- [x] Each status renders its badge text.
- [x] The selected row is highlighted, and a click calls `onSelect`.
- [x] Delete appears only for pending rows and calls `onDelete` after confirmation.
- [x] Loading and empty states are shown.

## Testing

- Targeted: `cd frontend && npx vitest run src/components/decks/__tests__/SuggestionRequestList.test.tsx`.
- Use `vi.spyOn(window, "confirm")` for the delete confirmation.
- Then `cd frontend && npm test` and `npm run build`.

## Test scenarios

- Happy: 4 items (one per status) → 4 rows with the right badges; a click selects.
- Edge: a done item with a summary shows "61/100 na coleção"; a commander vs a non-commander label.
- Error: a failed item shows the error tooltip; confirm returns false → `onDelete` is not called.
- Boundary: an empty list → the empty state; loading with items → the items plus a spinner (no flicker to empty).

## Notes from Developer

- Dates use the existing `formatDate` helper (`frontend/src/utils/format.ts`, DD/MM/YYYY) instead of `new Date(...).toLocaleDateString("pt-BR")`. It gives the same output without timezone day-shift.
- Empty state reuses `EmptyState` (compact), wrapped in `data-testid="suggestion-list-empty"`. While `loading` with no items only the spinner shows (no flicker to empty).
- Delete uses `window.confirm`. `GauchoDialog` is not a generic confirm pattern.
- A done row with a `summary` shows `"{owned}/{total} na coleção"` (testid `suggestion-owned-{id}`, extra).
- i18n: strings use `t(key, { defaultValue })` under `deckSuggestions.list.*` / `deckSuggestions.status.*`. Locale JSONs are shared with parallel Wave 2 tasks, so they were not edited. Keys can be added in T14/T17.
- Fixtures `mockDeckSuggestion` / `mockDeckSuggestionList` are defined inline in the test file (T13/T14 run in parallel, so there is no shared fixture file).
- Full `npm test`: 17 failures come from outside this task (`tests/components/UpdatePrompt.test.tsx` imports a missing module, Layout nav count assertions, and ~1s timeout flakes that pass in isolation). `npm run build` passes.
