## User Story

As a player, I want Claude to receive a clear request that includes the cards I own, so that the suggestion reuses my collection and
comes back in a format the app can show.

## Objective

Implement `src/deck_suggestions/prompt.py`: collection filtering, prompt construction, and robust response parsing. No DB and no network.

## Test scenarios

- Happy: a Commander request with 3 owned cards produces a prompt with the commander name and the owned lines. A valid response gives 99 cards + no warnings.
- Edge: owned cards outside the colors are filtered; colorless owned cards are kept; a "C" request keeps only colorless cards; duplicates merged (qty summed);
  a notes injection attempt containing `</observacoes_do_usuario>` is neutralised; notes None → no block.
- Error: empty string, non-JSON, `{"cards": []}`, `cards` not a list, a card without a name → `SuggestionParseError`.

## Notes from Developer

- **151 cards → rejected** (`SuggestionParseError`), not truncated. 150 entries are accepted.
- `_SINGLETON_FORMATS` is imported from `src/decks/builder.py`. It also contains `"duel"`, so duel is treated as singleton too.
- `expected_deck_size`: `commander`/`duel` → 100, everything else → 60. For singleton formats the expected sum of `cards` is `size - 1`, because the commander is not listed. So commander → 99 and brawl/oathbreaker → 59. A mismatch is only a warning.
- `filter_owned_for_request`: an empty `colors` list is treated like `["C"]` (colorless only). Color identities are read letter by letter (`WUBRG`), so `"WU"`, `"W,U"` and `"C"` all work. Owned entries with qty ≤ 0 or no name are skipped.
- `parse_response` checks candidates in order: first the fenced block, then the full text. It returns the first balanced `{…}` that `json.loads` accepts, so prose like "deck {sugerido}" before the JSON does not break parsing. If no candidate parses: "JSON inválido". If nothing is balanced: "Nenhum objeto JSON".
- Non-int quantities: a numeric string or a whole float is accepted. Anything else (including bool) becomes 1 with a warning. `category` is truncated to 60 chars and `reason` to 300 (not specified in the brief).
- Notes: both the opening and closing `observacoes_do_usuario` tags are stripped from user text, the text is trimmed and truncated to 1000 chars, and blank notes produce no block.
- Public helpers `is_basic_land`, `is_singleton_format` and `BASIC_LANDS` are exported for T09 (`enrich` treats basics as owned).
- Coverage: `prompt.py` 100% line + branch (68 tests). Run with `-o addopts=""` if `--cov` addopts misbehave.
