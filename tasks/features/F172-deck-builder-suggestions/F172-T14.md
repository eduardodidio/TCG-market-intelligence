# F172-T14 — Frontend: `DeckSuggestionPanel` + mode switch in the wizard

- **Wave:** 3
- **Type:** frontend
- **Depends on:** F172-T06, F172-T10, F172-T11, F172-T12, F172-T13
- **Status:** planned

## User Story

As a player, I want `/decks/build` to ask me which mode I want and then show either the builder or my suggestion requests, so that both
flows live in one place.

## Objective

Compose the form, list and result into `DeckSuggestionPanel`, and make `DeckBuildWizard` render the chooser, the manual wizard, or the panel based on `?mode=`.

## Dev Notes

See `_brief/00-overview.md` and `_brief/04-frontend-flow.md` (sections "DeckSuggestionPanel" and "Wizard integration").

- **Do not touch `App.tsx` / `Layout.tsx`.** The route `/decks/build` already exists (`App.tsx:352`). Use `useSearchParams` from `react-router-dom`.
- Panel data flow: on mount `listDeckSuggestions()`. `onCreated` → prepend + select. On select → `getDeckSuggestion(id)` (it has `result`).
  `onDelete` → `deleteDeckSuggestion` then remove. `onRefresh` → reload the list and the selected detail.
  Keep the latest detail in state. Handle errors with the existing `ErrorBanner.tsx` (check its props).
- Layout: form on top (collapsible after the first submit is optional). Below that, `grid md:grid-cols-[320px_1fr] gap-4` with the list and the result. Single column on mobile.
- Wizard: keep the root `data-testid="page-deck-build-wizard"` for all modes, and keep the breadcrumb + title. When there is a mode, show a "← Trocar modo" button (`mode-switch-back`) that clears the param.
  The manual mode renders the current 4 steps with no behavior change.
- **Test impact:** `frontend/src/pages/__tests__/DeckBuildWizard.test.tsx` renders `<MemoryRouter>` without a query. Update it to
  `initialEntries={["/decks/build?mode=manual"]}` for the existing tests, and add new tests for the chooser + suggestion mode.

## Implementation details

- `frontend/src/components/decks/DeckSuggestionPanel.tsx` (+ `__tests__/DeckSuggestionPanel.test.tsx`).
- `frontend/src/pages/DeckBuildWizard.tsx`: `const [searchParams, setSearchParams] = useSearchParams(); const mode = searchParams.get("mode");`
  An invalid mode value → the chooser.

## Acceptance criteria

- [ ] `/decks/build` → chooser. `?mode=manual` → the 4-step wizard. `?mode=suggestion` → the panel.
- [ ] Creating a request adds it to the list immediately with status pending, and the success banner is visible.
- [ ] Selecting a done item shows the result view with the save button.
- [ ] All existing wizard tests pass (with `?mode=manual`). `npm run build` passes.

## Testing

`cd frontend && npx vitest run src/components/decks src/pages/__tests__/DeckBuildWizard.test.tsx`, then `npm test` and `npm run build`.
In the panel tests, mock the API module. The child components can be the real ones (integration style) or light stubs. Prefer the real ones where it is cheap.

## Test scenarios

- Happy: chooser → click suggestion → the URL param is set → the panel loads the list (2 items) → select a done item → the detail is fetched → the result is shown.
- Edge: `?mode=bogus` → chooser; "Trocar modo" → chooser; the list is empty initially and the form submit adds the first item.
- Error: `listDeckSuggestions` returns errors → an error banner, and the form is still usable; `getDeckSuggestion` fails → an error in the result area.
- Boundary: deleting the selected item clears the selection; rapid selection changes → the last one wins (guard with a request id like T06).
