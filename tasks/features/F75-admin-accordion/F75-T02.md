# F75-T02 — Migrate Liga Status, Schedules, Scans into Accordion

**Status:** planned
**Wave:** 2
**Depends on:** F75-T01

## User Story

As an admin, I want Liga Status, Schedules, and Scans all accessible from the admin panel accordion without navigating to separate pages.

## Dev Notes

### Files to modify

1. **`frontend/src/pages/AdminPanel.tsx`** — Add 3 new accordion sections:

   **Liga Status section:**
   - Extract the content logic from `AdminLigaStatus.tsx` into a reusable component `AdminLigaSection`
   - Move to `frontend/src/components/admin/AdminLigaSection.tsx`
   - Reuse same API calls (collection/liga-status, collection/liga-missing)
   - Lazy-load data only when section is opened

   **Schedules section:**
   - Extract content logic from `Schedules.tsx` into `AdminSchedulesSection`
   - Move to `frontend/src/components/admin/AdminSchedulesSection.tsx`
   - Reuse same API calls (schedules CRUD)
   - Preserve form toggle, create/edit/delete functionality

   **Scans section:**
   - Extract content logic from `Scans.tsx` into `AdminScansSection`
   - Move to `frontend/src/components/admin/AdminScansSection.tsx`
   - Reuse same API calls (scans list, trigger)
   - Preserve scan form and history table

2. **Extract existing sections too:**
   - `frontend/src/components/admin/AdminUsersSection.tsx` — from AdminPanel users tab
   - `frontend/src/components/admin/AdminDashboardSection.tsx` — from AdminPanel dashboard tab

### Key decisions
- Each section is a self-contained component with its own state and data fetching
- Data is fetched lazily when section is first opened (useEffect on isOpen)
- Original page files (AdminLigaStatus.tsx, Schedules.tsx, Scans.tsx) can be deleted after migration OR kept as thin wrappers that redirect to /admin

### i18n keys needed (~5)
- `admin.section.users`, `admin.section.dashboard`, `admin.section.ligaStatus`
- `admin.section.schedules`, `admin.section.scans`

## Testing

- Liga Status section renders KPIs and missing cards table
- Schedules section renders schedule list and create form
- Scans section renders scan history and trigger form
- Each section only fetches data when opened
- All CRUD operations work within accordion context
