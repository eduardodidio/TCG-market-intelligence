# F59-T01 — Backend: LigaMagic refresh endpoint

**Status:** planned
**Wave:** 1
**Depends on:** —

## User Story

As a collector, I want an API endpoint that fetches the current price of a
card from LigaMagic so the frontend can offer a one-click LigaMagic refresh.

## Dev Notes

### Endpoint

`POST /collection/{entry_id}/refresh-liga`

- Auth: `require_auth_or_api_key` (same as existing refresh)
- Query params: `currency` (BRL/USD/PILA, default BRL)
- Response: `ApiResponse[CollectionCardDetail]` (same schema as MYP refresh)

### Logic

1. Validate entry exists, belongs to user (IDOR check)
2. Entry must have `name_en` or `name_pt` (Liga searches by name, not external_id)
3. Instantiate `LigaMagicProvider` with default config
4. Call `provider.search_card(card_name)` — returns price dict
5. Extract `normal.mid` (or `normal.low` as fallback) price
6. If no price found → return 200 with warning in `errors[]`
7. If price found:
   - Need a card_id to store price. If entry has no card_id, auto-create
     canonical card (same pattern as manual price endpoint)
   - Create `HistoricalPrice(source="liga", external_id=f"liga_{card_name}",
     observed_at=now, median_price=price)`
   - Insert via `repo.insert_price_observations()`
8. Return updated `_build_collection_detail()`
9. Always close provider in `finally` block

### Error handling

- `LigaNotFoundError` → 200 + warning "Card not found on LigaMagic"
- `LigaRateLimitError` → 200 + warning "LigaMagic rate limited, try again later"
- `LigaError` / timeout → 200 + warning with error message
- Never 500 — always degrade gracefully to warning
