# F98-T01 -- Backend: Computed Summary Fields on ScanRun API

**Wave:** 0
**Depends on:** --

## User Story

As a frontend developer, I need the scan API to return structured summary
counts (priced, not found, rate limited) so I can display a meaningful
scan results card without parsing raw error JSON on the client.

## Current State

- `ScanRunRow` stores `cards_total`, `cards_processed`, `cards_failed`,
  `observations_saved`, and `error_summary` (a JSON array of strings like
  `["card_name: NotFoundError: ...", "card_name: RateLimitError: ..."]`).
- `ScanRunResponse` exposes all columns directly but has no derived fields.
- The `_row_to_response` helper in `scans.py` does a 1:1 mapping.

## Dev Notes

### 1. Add computed fields to `ScanRunResponse`

File: `src/api/schemas/scans.py`

Add three optional int fields to `ScanRunResponse`:

```python
not_found_count: int = 0
rate_limited_count: int = 0
priced_count: int = 0
```

`priced_count` = `observations_saved` (alias for clarity in the API).
`not_found_count` and `rate_limited_count` are computed by parsing
`error_summary`.

### 2. Implement parsing in `_row_to_response`

File: `src/api/routers/scans.py`

Add a helper function `_parse_error_counts(error_summary: str | None)` that:

1. Returns `{"not_found": 0, "rate_limited": 0}` if `error_summary` is
   None or empty.
2. Parses the JSON array of error strings.
3. Counts strings containing `"NotFoundError"` as `not_found`.
4. Counts strings containing `"RateLimitError"` as `rate_limited`.
5. Returns the counts dict.

Update `_row_to_response` to call this helper and populate the new fields:

```python
counts = _parse_error_counts(row.get("error_summary"))
return ScanRunResponse(
    ...existing fields...,
    not_found_count=counts["not_found"],
    rate_limited_count=counts["rate_limited"],
    priced_count=row["observations_saved"],
)
```

### 3. SSE scan_complete event

The `scan_complete` SSE event already carries `cards_processed`,
`cards_total`, `cards_failed`, and `observations_saved`. Add
`not_found_count` and `rate_limited_count` to the SSE payload by extending
the final `scan_bus.publish` call in `src/collectors/scan.py` to include
these counts.

Add two optional fields to `ScanEvent` in `src/domain/events.py`:

```python
not_found_count: int = 0
rate_limited_count: int = 0
```

In `run_scan` (scan.py), track `not_found_count` and `rate_limited_count`
as running counters alongside `cards_failed`. Increment `not_found_count`
in the `NotFoundError` except block and `rate_limited_count` in the
`RateLimitError` exhausted block. Pass them to the final `scan_complete`
event.
