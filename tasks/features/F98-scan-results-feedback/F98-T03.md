# F98-T03 -- Frontend: useCollectionRefresh Summary State

**Wave:** 1
**Depends on:** T01

## User Story

As a user, after a bulk refresh I want the scan results to remain visible
until I dismiss them, rather than disappearing after 2 seconds.

## Current State

- `useCollectionRefresh` sets `isDone = true` on `scan_complete` and then
  clears all state (isDone, progress, lastScannedCard) after
  `COMPLETE_DISPLAY_MS` (2000ms) via `setTimeout`.
- The hook exposes `progress: RefreshProgress | null` but no structured
  summary data (not_found_count, rate_limited_count, etc.).
- The SSE `scan_complete` event already carries `cards_processed`,
  `cards_total`, `cards_failed`, `observations_saved`. After T01 it will
  also carry `not_found_count` and `rate_limited_count`.

## Dev Notes

### 1. Add `ScanSummary` state to the hook

Import the `ScanSummary` interface from `ScanSummaryCard` (or define it in
a shared types file).

Add state:

```typescript
const [summary, setSummary] = useState<ScanSummary | null>(null);
const startTimeRef = useRef<number>(0);
```

Set `startTimeRef.current = Date.now()` in `startRefresh`.

### 2. Update `handleComplete`

In the `handleComplete` callback:

1. Build a `ScanSummary` object from the `scan_complete` event fields:
   - `cardsTotal: event.cards_total`
   - `cardsProcessed: event.cards_processed`
   - `cardsFailed: event.cards_failed`
   - `observationsSaved: event.observations_saved`
   - `notFoundCount: event.not_found_count ?? 0`
   - `rateLimitedCount: event.rate_limited_count ?? 0`
   - `durationMs: Date.now() - startTimeRef.current`
2. Call `setSummary(summary)`.
3. **Remove** the `setTimeout` that clears state after `COMPLETE_DISPLAY_MS`.
   The summary should persist until explicitly dismissed.
4. Still call `onCompleteRef.current?.()` for collection refetch.

### 3. Add `dismissSummary` callback

```typescript
const dismissSummary = useCallback(() => {
  setSummary(null);
  setIsDone(false);
  setProgress(null);
  setLastScannedCard(null);
}, []);
```

### 4. Update return interface

Add to `UseCollectionRefreshReturn`:

```typescript
summary: ScanSummary | null;
dismissSummary: () => void;
```

### 5. Update `ScanStreamEvent` type

File: `frontend/src/hooks/useScanStream.ts` (or wherever `ScanStreamEvent`
is defined).

Add optional fields:

```typescript
not_found_count?: number;
rate_limited_count?: number;
```

These are populated from the SSE `scan_complete` event JSON payload.

### 6. Fallback for polling mode

When using polling fallback (fetching GET `/scans/{id}`), the response
now includes `not_found_count`, `rate_limited_count`, `priced_count` from
T01. Map these into the summary object the same way.

## Testing

File: `frontend/tests/hooks/useCollectionRefresh.test.ts`

1. `summary is populated on scan_complete` -- after SSE complete event,
   `summary` is not null and contains expected counts.
2. `summary persists until dismissSummary called` -- summary remains
   non-null after 5 seconds; calling `dismissSummary` sets it to null.
3. `dismissSummary clears all done state` -- after dismiss, `isDone` is
   false, `progress` is null.
4. `durationMs is calculated from start time` -- verify duration is
   approximately `Date.now() - startTime`.
5. `fallback polling populates summary` -- when SSE is unavailable and
   polling returns a completed scan, summary is populated from the API
   response fields.
