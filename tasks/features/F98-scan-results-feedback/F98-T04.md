# F98-T04 -- Frontend: Undo Delete Toast

**Wave:** 2
**Depends on:** --

## User Story

As a user, when I delete a collection card I want a 5-second undo window
so I can recover from accidental deletions without re-importing.

## Current State

- `DeleteEntryButton` renders a confirmation dialog (are you sure?).
- On confirm, `CollectionCardDetail` calls `deleteCollectionEntry(entryId)`
  immediately and navigates to `/collection`.
- The API endpoint (`DELETE /collection/{id}`) performs a hard delete.
- There is no undo mechanism.

## Dev Notes

### Approach: Delayed Execution

Instead of adding soft-delete to the database (schema migration, cleanup
cron, query filter changes), implement undo as a frontend-only delayed
execution pattern:

1. On confirm, navigate to `/collection` immediately.
2. Show an `UndoToast` at the bottom of the screen with a 5-second
   countdown.
3. If the user clicks "Undo" within 5 seconds, cancel the pending delete
   and navigate back to the card detail page.
4. After 5 seconds, execute the actual `DELETE` API call.

### 1. New component `UndoToast`

File: `frontend/src/components/UndoToast.tsx`

Props:

```typescript
interface UndoToastProps {
  message: string;          // e.g., "Sol Ring deleted"
  durationMs?: number;      // default 5000
  onUndo: () => void;       // cancel callback
  onExpire: () => void;     // timer expired, execute delete
}
```

Behavior:
- Renders a fixed-position toast at the bottom center.
- Shows a progress bar that shrinks over `durationMs`.
- "Undo" button calls `onUndo` and removes the toast.
- On timer expiry, calls `onExpire` and removes itself.
- Dark theme: slate-700 bg, white text, cyan-400 undo button.

### 2. State management via context or layout-level state

The toast needs to survive navigation from `/collection/:id` to
`/collection`. Options:

**Option A (recommended): Layout-level state.** Add a `pendingDelete`
state to the Layout component (or a small context). The delete handler
sets `pendingDelete = { entryId, entryName }`, navigates, and the Layout
renders `UndoToast`. On undo, clear `pendingDelete` and navigate back.
On expire, call `deleteCollectionEntry(entryId)`.

**Option B: URL state.** Navigate to `/collection?undoDelete={id}&name={name}`.
The collection page reads the params, shows the toast, and handles undo/expire.
Simpler but leaks implementation into the URL.

Use Option A.

### 3. Create `usePendingDelete` hook or context

File: `frontend/src/hooks/usePendingDelete.ts` (or context)

```typescript
interface PendingDelete {
  entryId: number;
  entryName: string;
}

interface UsePendingDeleteReturn {
  pendingDelete: PendingDelete | null;
  setPendingDelete: (pd: PendingDelete) => void;
  clearPendingDelete: () => void;
  executeDelete: () => Promise<void>;
}
```

### 4. Update `CollectionCardDetail`

Replace the delete handler:

```typescript
// Before:
await deleteCollectionEntry(entryId);
navigate("/collection");

// After:
setPendingDelete({ entryId, entryName: displayName });
navigate("/collection");
```

### 5. Update Layout

Render `UndoToast` when `pendingDelete` is non-null:

```tsx
{pendingDelete && (
  <UndoToast
    message={t("collection.deleteUndoMessage", { name: pendingDelete.entryName })}
    onUndo={() => {
      clearPendingDelete();
      navigate(`/collection/${pendingDelete.entryId}`);
    }}
    onExpire={async () => {
      await executeDelete();
      clearPendingDelete();
    }}
  />
)}
```
