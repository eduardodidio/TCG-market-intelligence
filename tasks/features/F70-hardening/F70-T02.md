## User Story

As a platform operator, I need the server to refuse to start when critical
auth env vars are missing, so that production deployments can never run
with open auth bypass.

## Problem

`src/auth/dependencies.py:141-143` allows any request through as
`api_key_user` when `TCG_API_KEY` is not set and no JWT token is present.
This is a dev convenience that becomes a security hole in production.

## Dev Notes

### Changes

1. **Startup validation** in `src/api/app.py` lifespan:
   ```python
   env = os.environ.get("TCG_ENV", "development")
   if env != "development":
       if not os.environ.get("TCG_JWT_SECRET"):
           raise RuntimeError("TCG_JWT_SECRET required in non-dev environments")
       if not os.environ.get("TCG_API_KEY"):
           log.warning("TCG_API_KEY not set — API key auth disabled")
   ```

2. **Log warning in dev mode** when bypass activates:
   ```python
   # dependencies.py line 142
   if expected is None and not token:
       log.warning("dev_mode_auth_bypass", path=str(request.url))
       return "api_key_user"
   ```

3. **Add TCG_ENV to start.sh** with default `development`.

### Files to modify

- `src/api/app.py` — add env var validation in lifespan
- `src/auth/dependencies.py` — add warning log on bypass
- `start.sh` — add `export TCG_ENV=development`
