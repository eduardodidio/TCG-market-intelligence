## Residual note (not blocking, carried from TechLead's re-review)

TechLead's `review-20260924-200545.md` flags a narrower, pre-existing
edge case: first-ever credit for a brand-new user with no
`CreditBalanceRow` yet takes no row lock (nothing to lock), so two
concurrent first-time credits could both `INSERT` a balance row; the
`credit_balances.user_id` unique constraint converts this into an
`IntegrityError` (crash, retried via `backfill_all_rewards`'s
per-user `try/except`) rather than a silent double-credit. This is not
the AC3/AC4 race this feature was rejected for, is not a regression from
`9519b44`, and mirrors an existing pattern already in production
(`repository.py::update_credit_balance`). Not blocking. Confirmed same
assessment independently by reading `achievement_rewards.py:100-103` and
`src/database/models.py:319`.
