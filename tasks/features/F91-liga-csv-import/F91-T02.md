# F91-T02: Backend — encoding auto-detect + new fields + set code normalization

**Status:** planned
**Wave:** 1
**Depends on:** T01

## User Story

As a collector, I want to import my LigaMagic CSV export and have all
accented characters preserved correctly, my edition names in Portuguese
stored, and variant set codes automatically mapped to Scryfall codes.

## Dev Notes

### Changes to `src/collection/importer.py`

1. **Encoding auto-detect** — Replace hardcoded `utf-8`:
   ```python
   def _detect_encoding(file_path: Path) -> str:
       raw = file_path.read_bytes()
       try:
           raw.decode("utf-8")
           return "utf-8"
       except UnicodeDecodeError:
           return "cp1252"  # Liga default
   ```
   Use detected encoding in `open()` call. Remove `errors="replace"`.

2. **New columns** — Read `Edicao (PTBR)` → `set_name_pt` and
   `Comentario` → `notes`:
   ```python
   set_name_pt = (row.get("Edicao (PTBR)") or "").strip() or None
   notes = (row.get("Comentario") or "").strip() or None
   ```
   Add both to `rows_to_insert` dict.

3. **Set code normalization** — After reading `set_code`, pass through
   `map_to_scryfall_set_code`:
   ```python
   from src.utils.set_code_map import map_to_scryfall_set_code
   set_code = map_to_scryfall_set_code(set_code)
   ```
   This maps `smbro` → `bro`, `cbafr` → `afr`, etc. Standard codes pass
   through unchanged.

4. **Store original Liga set code** — Keep the original Liga code in a new
   field or in `notes` for traceability? Decision: store original in
   `set_name_pt` context (Liga already fills `Edicao (PTBR)`). No extra
   column needed.

### Edge Cases

- BOM (Byte Order Mark): UTF-8 BOM (`\xef\xbb\xbf`) — `utf-8-sig` handles
  this. Try `utf-8-sig` before `cp1252`.
- Empty `Edicao (PTBR)` rows (Liga sometimes omits PT edition name) — already
  handled by `or None` fallback.
- Collector numbers with leading zeros (e.g. `001`) — strip() preserves them.
