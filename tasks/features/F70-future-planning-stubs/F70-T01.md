## User Story

As a product owner, I want future feature directions documented in ADRs so the
team has a shared understanding of planned capabilities and can reference them
during sprint planning.

## Dev Notes

### ADR 1: Subscription Plans (docs/adr/00XX-subscription-plans.md)

Sketch out:
- **Tiers**: Free (10 credits/day via hourly bonus), Basic, Pro, Enterprise
- **Data model**: `subscription_plans` table (id, name, monthly_credits,
  bonus_multiplier, price_brl, active), `user_subscriptions` table (user_id,
  plan_id, started_at, expires_at, status)
- **Credit integration**: Monthly fixed credit grant + bonus multiplier on
  hourly claims
- **Payment**: Placeholder — no payment gateway integration yet
- **Status**: PROPOSED — not implemented

### ADR 2: Dragon Mascot Branding (docs/adr/00XX-dragon-mascot.md)

Sketch out:
- **Concept**: Elder Dragon character sits atop treasure token pile
- **Usage**: Premium plan selection UI, credit purchase flow
- **Visual**: Dragon "negotiates" with user about treasure token packages
- **Implementation**: SVG/Lottie animation on subscription page
- **Status**: CONCEPT — no design assets yet

### ADR 3: Credit Auto-Claim Middleware (docs/adr/00XX-credit-auto-claim.md)

Sketch out:
- **Design**: FastAPI middleware checks `last_bonus_at` on every authenticated
  request. If 12h+ elapsed, auto-grants 5 credits and updates timestamp.
- **Trade-offs**: Adds ~1 DB query per authenticated request vs explicit
  `/credits/claim-bonus` endpoint
- **Decision**: Start with explicit endpoint (F65), consider middleware later
  based on user feedback
- **Status**: DEFERRED — F65 ships explicit claim first
