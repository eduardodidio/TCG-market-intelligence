# F27-T04: Fix converter fallback — handle None rate gracefully

**Status:** planned
**Wave:** 1
**Depends on:** none

## User Story

As a user, when I select USD but no exchange rate is available, I want to
see a clear indication rather than incorrect BRL values shown with USD symbol.

## Dev Notes

### Problem

`CurrencyConverter.convert()` returns `None` when no exchange rate is found.

In `market.py`:
```python
price_start=converter.convert(g[3], today, currency) or g[3],
```
The `or g[3]` fallback shows BRL value under USD label — misleading.

In `cards.py`:
```python
price = converter.convert(raw_price, ..., currency) if raw_price else None
```
This correctly returns `None` — card shows "no price data". Less misleading
but still loses data.

### Fix strategy

1. **market.py**: When currency != "BRL" and convert returns None, keep prices
   as `None` (not BRL fallback). The frontend already handles null prices.

2. **cards.py**: Already correct (returns None). No change needed.

3. **collection.py**: Audit same pattern. Apply same fix if needed.

4. **Frontend**: When prices are `None` due to missing rate, the existing
   "no price data" / "--" display is acceptable. Optionally add a tooltip
   or message saying "exchange rate unavailable".

### Files to modify

1. `src/api/routers/market.py` — remove `or g[3]` / `or lo[3]` fallback for non-BRL
2. `src/api/routers/collection.py` — audit and fix same pattern if present

## Testing

- Unit: movers endpoint with currency=USD, no exchange rate -> prices are None
- Unit: movers endpoint with currency=BRL -> prices unchanged (BRL passthrough)
- Unit: movers endpoint with currency=USD, rate seeded -> prices converted
