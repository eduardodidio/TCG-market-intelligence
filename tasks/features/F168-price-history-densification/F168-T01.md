# F168-T01 -- Daily Price Snapshot Service

**Wave:** 0 (parallel with T02)
**Type:** backend
**Depends on:** nothing
**Status:** planned

## User Story

As a platform operator, I want the system to record a daily price
observation for every card that has a known price, so that price history
graphs are populated even for cards outside user collections.

## Objective

Create a service module that reads the latest known price for every card
in the database and inserts a `price_observations` row with
`source='daily_snapshot'` for today's date. Must be idempotent (safe to
run multiple times per day due to the unique constraint on
`(source, external_id, observed_at)`).

## Dev Notes

### Key existing patterns

- `src/database/repository.py` has `get_latest_prices_batch(card_ids)`
  which returns the best price per card_id using source priority logic.
  However, for the snapshot we need ALL cards with prices, not just a
  batch of known IDs.

- `PriceObservationRow` unique constraint: `(source, external_id,
  observed_at)` -- inserting with `on_conflict_do_nothing` makes this
  naturally idempotent.

- The existing `has_snapshot_for_date()` method checks for
  `jsonld_snapshot` source. Our new source is `daily_snapshot` -- a
  different source string to distinguish from scan-created observations.

- `insert_price_observations()` already handles batch inserts with
  `on_conflict_do_nothing`. We can reuse this with
  `HistoricalPrice` objects.

### New repository method needed

Add `get_all_latest_prices(self) -> list[tuple[str, str, Decimal]]` to
`repository.py` that returns `(source, external_id, median_price)` for
every source_card that has at least one price observation. Use a CTE with
`ROW_NUMBER()` partitioned by external_id, ordered by observed_at DESC
to get the latest price per card. This is a read-only query -- no credit
cost.

SQL approach:
```sql
WITH latest AS (
  SELECT po.source, po.external_id, po.median_price,
         ROW_NUMBER() OVER (
           PARTITION BY po.external_id
           ORDER BY po.observed_at DESC
         ) AS rn
  FROM price_observations po
  WHERE po.median_price IS NOT NULL
)
SELECT source, external_id, median_price
FROM latest WHERE rn = 1
```

### Snapshot service

Create `src/collectors/price_snapshot.py` with:

```python
def run_daily_snapshot(repo: Repository) -> int:
    """Snapshot all current prices into daily_snapshot observations.
    Returns count of new observations inserted."""
```

Steps:
1. Call `repo.get_all_latest_prices()` to get current prices
2. Build `HistoricalPrice` objects with `source='daily_snapshot'`,
   `observed_at=date.today()`, `median_price=<latest_price>`
3. Call `repo.insert_price_observations(observations)` in batches
4. Return count of inserted rows

### Important constraints

- Source string: `'daily_snapshot'` (not `'jsonld_snapshot'`)
- Do NOT copy `tcg_price`, `last_sold_price`, or `quantity_available` --
  only `median_price` matters for history graphs
- Use batches of 500 (existing pattern in `insert_price_observations`)
- Must work on both SQLite and PostgreSQL

## Acceptance Criteria

- [ ] `get_all_latest_prices()` returns one row per external_id with the
      latest non-null median_price
- [ ] `run_daily_snapshot()` creates observations with source=`daily_snapshot`

- [ ] No external API calls -- reads only from existing DB data
- [ ] Works on both SQLite and PostgreSQL

## Testing

Framework: pytest (`tests/`)
Run: `pytest tests/test_price_snapshot.py -v`

### Test scenarios

1. **Happy path**: DB with 3 cards having prices -> snapshot creates 3
   observations with source=`daily_snapshot` and today's date
2. **Idempotency**: run twice -> second run returns 0
3. **No prices**: empty DB -> returns 0, no errors
4. **Mixed prices**: some cards with prices, some without -> only priced
   cards get snapshots
5. **Multiple sources**: card with both liga and myp prices -> picks
   latest by date (ROW_NUMBER logic)
