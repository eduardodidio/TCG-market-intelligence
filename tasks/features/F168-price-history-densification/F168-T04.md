# F168-T04 -- Frontend Chart UX for Sparse Data

**Wave:** 1 (parallel with T03)
**Type:** frontend
**Depends on:** nothing (frontend-only changes)
**Status:** planned

## User Story

As a user viewing a card's price history, I want to see a meaningful
chart even when there are only 1-3 data points, so that I understand
the card has a price and history is being built.

## Objective

Improve `PriceChart.tsx` to handle sparse data gracefully:
1. For 1 data point: show a horizontal reference line at the current
   price with a clear "price since" label
2. For 2-6 data points: show connected dots with dashed segments between
   gaps (already partially handled via `connectNulls`)
3. Improve the sparse data notice to be more informative
4. Add the `daily_snapshot` source to the history endpoint's accepted
   sources so snapshot data appears in charts

## Dev Notes

### Backend change (small)

In `src/api/routers/cards.py`, the `get_history()` endpoint fetches
observations using:
```python
prices = repo.get_price_series(
    source=[sc.source, "jsonld_snapshot"],
    external_id=sc.external_id,
    days=days,
)
```

Add `"daily_snapshot"` to the source list:
```python
prices = repo.get_price_series(
    source=[sc.source, "jsonld_snapshot", "daily_snapshot"],
    external_id=sc.external_id,
    days=days,
)
```

Also add `"daily_snapshot"` to `get_price_series_batch()` where it
builds the source filter for sparklines (search for `jsonld_snapshot`
in that method).

### Frontend changes

#### PriceChart.tsx

Current behavior for sparse data (< 7 points):
- Shows amber notice "Building price history -- N data points..."
- Shows dots on lines (`dot={isSparse ? { r: 3, fill: "..." } : false}`)
- Uses `connectNulls` on all lines

Improvements:
1. **Single data point**: When `observations.length === 1`, show a
   `ReferenceLine` at the median_price value with a label showing the
   price. Replace the chart with a simpler display: a horizontal dashed
   line + the price value + "Price as of DD/MM" text.

2. **Sparse notice enhancement**: Update the notice text to include the
   date range: "Building price history -- N data points from DD/MM to
   DD/MM. Daily snapshots will fill this chart over time."

3. **Visual**: For 2-3 points, increase dot radius to 5 for better
   visibility. Keep the existing `type="monotone"` interpolation which
   already connects points smoothly.

#### i18n updates

Update both `en.json` and `pt-BR.json`:
```json
"chart.singlePoint": "Current price as of {{date}}",
"chart.sparseDataRange": "Building price history -- {{count}} data points from {{from}} to {{to}}. Daily snapshots will fill this chart over time."
```

Keep existing `sparseData` key as fallback for when dates are unavailable.

### Important

- Do NOT change behavior for dense data (>= 7 points)
- Do NOT remove existing `connectNulls` behavior
- The `ReferenceLine` component is already imported from recharts
  (check imports -- if not, it's available in the recharts package
  already used)
- Keep the existing zoom/brush functionality for dense charts
