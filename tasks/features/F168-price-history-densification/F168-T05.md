## User Story

As a developer, I want integration tests covering the full snapshot
pipeline and updated documentation, so that the feature is properly
validated and discoverable.

## Objective

Write integration tests that verify the end-to-end flow: snapshot
creation -> history API -> chart data. Update project diagrams and
README.

## Dev Notes

### Integration test approach

Create `tests/integration/test_snapshot_pipeline.py` that:

1. Sets up an in-memory SQLite database with:
   - 3 cards with source_cards and price observations (liga source)
   - 1 card with no prices
2. Runs `run_daily_snapshot()` and verifies observations created
3. Calls the `/cards/{id}/history` endpoint and verifies `daily_snapshot`
   observations appear in the response
4. Runs `backfill_snapshots(days=3)` and verifies multi-day creation
5. Verifies idempotency (second run creates 0)

### API integration test

Use the existing test patterns from `tests/api/` directory:
- Use `TestClient` from FastAPI
- Mock authentication for admin endpoint
- Verify `POST /api/v1/admin/jobs/snapshot-prices` returns correct count

### Verify sparkline batch endpoint

The `get_price_series_batch()` method needs to include `daily_snapshot`
source. Write a test that:
1. Creates a card with only `daily_snapshot` observations
2. Calls `/cards/price-trends?card_ids=X`
3. Verifies the sparkline data includes the snapshot prices

## Testing

Framework: pytest (`tests/`)
Run: `pytest tests/integration/test_snapshot_pipeline.py -v`

### Test scenarios

1. **Full pipeline**: create cards -> snapshot -> query history -> verify
2. **Sparkline integration**: snapshot -> price-trends endpoint -> verify
3. **Admin endpoint auth**: admin=200, non-admin=403, no-auth=401
4. **Backfill + snapshot**: backfill 3 days -> daily snapshot -> verify
   4 total observations (3 backfill + 1 daily, or 3 if same day)
5. **Empty DB**: no cards -> snapshot returns 0 -> no errors
