# F168-T03 -- Backfill Snapshots CLI

**Wave:** 1
**Type:** backend
**Depends on:** T01
**Status:** planned

## User Story

As an admin, I want to retroactively create price history entries from
existing price data, so that cards already in the database immediately
have at least one historical data point for the chart.

## Objective

Add a `backfill-snapshots` CLI command that creates `daily_snapshot`
observations for all priced cards that do not yet have any
`daily_snapshot` observation. Unlike the daily `snapshot-prices` (which
only writes today's date), this command can optionally backfill multiple
days by replicating the current price across a date range.

## Dev Notes

### Approach

The simplest and most useful approach: for every card that has a latest
price but zero `daily_snapshot` observations, create one observation for
today. This gives every priced card at least 1 data point immediately.

Optionally, with `--days N`, create observations for the last N days
using the same latest price. This is an approximation (the price may
have changed), but it gives the chart something to draw. The `--days`
flag defaults to 1 (just today).

### Implementation

Add to `src/collectors/price_snapshot.py`:

```python
def backfill_snapshots(repo: Repository, days: int = 1) -> int:
    """Create daily_snapshot observations for cards missing them.

    For each card with a known price but no daily_snapshot rows,
    creates observations for the last `days` days using the current
    latest price.

    Returns total count of new observations inserted.
    """
```

Steps:
1. Call `repo.get_all_latest_prices()` (from T01) to get all current prices
2. Call a new method `repo.get_cards_with_daily_snapshots()` that returns
   the set of external_ids that already have at least one `daily_snapshot`
   observation
3. Filter to only cards missing snapshots
4. For each missing card, create `HistoricalPrice` objects for the last
   N days (using `date.today() - timedelta(days=i)` for i in range(days))
5. Bulk insert via `repo.insert_price_observations()` (idempotent)

### New repository method

Add `get_external_ids_with_source(self, source: str) -> set[str]`:
```python

```

### CLI command

Add to `src/cli/main.py`:
```python
@cli.command("backfill-snapshots")
@click.option("--db", default=None, callback=_resolve_db, ...)
@click.option("--days", default=1, type=int,
              help="Number of days to backfill (default: 1 = today only)")
def backfill_snapshots_cmd(db, days):
    """Backfill daily snapshots for cards missing price history."""
    from src.collectors.price_snapshot import backfill_snapshots
    from src.database.repository import Repository

    repo = Repository(db)
    count = backfill_snapshots(repo, days=days)
    click.echo(f"Backfill complete: {count} observations created.")
```

### Important constraints

- `days` should be capped at 90 to prevent accidentally creating
  thousands of rows per card
- Use `on_conflict_do_nothing` (already in `insert_price_observations`)
  so re-running is safe
- Log progress every 1000 cards for visibility

## Testing

Framework: pytest (`tests/`)
Run: `pytest tests/test_price_snapshot.py -v`

### Test scenarios

1. **Happy path**: 5 cards with prices, 0 snapshots -> creates 5 observations
2. **Partial backfill**: 5 cards, 2 already have snapshots -> creates 3
3. **Multi-day**: `days=3` -> creates 3 observations per card
4. **Days cap**: `days=100` -> caps to 90 with warning log
5. **Idempotency**: run twice -> second run creates 0
6. **No priced cards**: empty DB -> returns 0
