### Root Cause: Zero Collection Value

The 30 cards with price observations are from the F01 DMR backfill (card_ids
1-30). The 124 linked collection entries from F10 sync created **new** card
rows (card_ids 241+) via MYP search matching. These new cards have no source
cards with price observations because MYP's price history pages changed format
during the F10 sync and returned 0 new observations.

There is zero overlap between the set of card_ids that have price data
(F01: ids 1-30, all DMR) and the set of card_ids linked to collection
entries (F10: ids 241+, various sets). Even the 2 DMR cards in the
collection (Tormod's Crypt dmr, Chain Lightning dmr) were matched to
different canonical cards (Chain Lightning was name-matched to LEG/137
instead of DMR/113).

### Items NOT Checked (require live server)

The following acceptance criteria could not be verified programmatically
and require starting the API + frontend servers in a live environment:

- Dashboard visual rendering with non-zero collection value
- Cards page visual display with prices
- CardDetail Scryfall image loading and price chart rendering

These criteria are marked unchecked above. They will pass once fresh
price data is collected (requires MYP parser update for new page format).

### Recommendation

To get non-zero collection value and price-backed KPIs, one of:
1. **Update MYP parser** to handle the new price history page format
2. **Re-backfill DMR** after parser fix, which would populate prices for
   the 30 existing DMR source_cards
3. **Reconcile card_ids** so that collection entries linked during F10
   sync point to the same card_ids as the F01 backfill source_cards

Option 1 is the correct long-term fix. Options 2-3 are workarounds.
