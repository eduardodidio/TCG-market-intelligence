## User Story

As a platform operator, I want to sync my collection with MYP price data,
so that the dashboard shows real prices and portfolio value for my cards.

## Objective

Run the `sync-collection` CLI command to search MYP for each collection
card, fetch price history, and store observations in the database.

## Dev Notes

Veja `_brief/00-overview.md` e `_brief/01-operational-pipeline.md`.

- CLI: `python -m src.cli.main sync-collection`
- Prerequisite: T01 (set codes normalized) and T02 (match report reviewed)
- Uses `skip_matched=True` by default — skips already-linked entries
- Pipeline per card: search → match → fetch details → upsert card →
  fetch history → store observations → link collection entry
- Rate-limited: asyncio.Semaphore(3), 1s delay
- Expected runtime: ~35-40 min for 548 unlinked cards
- Back up DB before running (cleanup already does this, but be safe)

## Implementation Details

1. Run `python -m src.cli.main db-backup` (safety backup before sync)
2. (Optional) Test with small batch: `python -m src.cli.main sync-collection --limit 5`
3. Run full sync: `python -m src.cli.main sync-collection`
4. Monitor progress via structlog output
5. Review summary: matched, unmatched, ambiguous, errors, observations saved

### Findings

1. **Parser bug fixed:** `parse_search_results()` used wrong field names
   (`id`/`nome`/`slug`) vs MYP's actual API (`idproduto`/`nomeenproduto`/
   `slugnomeenproduto`). Fixed in `src/parsers/myp.py` with fallback chain.
   4 new tests added.

2. **MYP product pages 404:** 396 cards matched but their product pages
   return HTTP 404. MYP has restructured/removed many old product entries.

3. **Price history pages broken:** `/magic/preco/{id}/{slug}?dias=N`
   redirects to homepage. `window.precoChartConfig` JS variable no longer
   present. **0 price observations collected.**

4. **Cards linked:** 124 collection entries now have `card_id` set (3 from
   F01 backfill + 121 from this sync).

### Blocker for Full Price Data

MYP has restructured their site. The provider (`src/providers/myp/provider.py`)
needs to be updated to find the new price data source (likely AJAX/API endpoints
instead of server-rendered JS). This is a separate feature, not F11 scope.
