# F55-T01 -- Matcher Best-Effort for Ambiguous Matches

**Status:** planned
**Wave:** 0

## User Story

As a collector, I want cards with multiple MYP printings to still get linked
to a price source, so that I can see approximate prices instead of no data
at all.

## Context

When `_try_name_match()` in `src/collection/matcher.py` finds multiple name
matches but cannot narrow by set code, it returns `status="ambiguous"` with
`myp_result=None`. This causes bulk-canonize and sync-collection to skip
the card entirely, leaving it without a price source.

For TCG pricing, different printings of the same card (e.g., "Abrade" in HOU
vs 2XM) have approximately the same market price. Picking the first candidate
is strictly better than returning nothing.

## Dev Notes

### File: `src/collection/matcher.py`

Modify `_try_name_match()` (lines 101-168). Change the final `return` block
(lines 161-168) from returning `status="ambiguous"` with `myp_result=None`
to returning `status="matched"` with `confidence="best_effort"` and
`myp_result=name_matches[0]` (first candidate).

Before (current, lines 161-168):
```python
# Multiple name matches, none narrowed by set -> ambiguous
return MatchResult(
    status="ambiguous",
    collection_entry=entry,
    myp_result=None,
    confidence="none",
    candidates=results,
)
```

After:
```python
# Multiple name matches, none narrowed by set -> best-effort pick
# For pricing, any printing of the same card has ~same price.
return MatchResult(
    status="matched",
    collection_entry=entry,
    myp_result=name_matches[0],
    confidence="best_effort",
    candidates=results,
)
```

Also handle the case on lines 142-149 where `len(name_set_matches) > 1`
(multiple name+set matches). Currently this falls through to the
`len(name_matches) == 1` check (which fails) and then to ambiguous. Add an
explicit branch after `len(name_set_matches) == 1`:

```python
if len(name_set_matches) > 1:
    # Multiple name+set matches (e.g., same card, same set, diff arts)
    return MatchResult(
        status="matched",
        collection_entry=entry,
        myp_result=name_set_matches[0],
        confidence="best_effort",
        candidates=results,
    )
```

### Downstream impact

- `src/collectors/bulk_canonize.py` -- line 134 checks
  `match.status == "matched"`. With this fix, previously-ambiguous cards
  will now flow into the matched branch. No code change needed.
- `src/collectors/sync_collection.py` -- same pattern, no change needed.
- `src/api/routers/collection.py` canonize endpoint -- same pattern, no
  change needed.

### Logging

Add a structlog `log.info()` call inside the new best-effort branch so
matches are auditable:
```python
import structlog

log = structlog.get_logger()
# Inside the best_effort branch:
log.info(
    "matcher_best_effort",
    entry_name=entry.name_en,
    entry_set=entry.set_code,
    picked_id=name_matches[0].external_id,
    candidates=len(name_matches),
)
```

Note: matcher.py is currently a pure module with no logging. Adding structlog
is acceptable since it is already a project dependency and the import is
lightweight.
