### BanAnalyzer service (`src/services/ban_analyzer.py`)

Pure functions (no class state, receives `repo` as parameter):

1. `get_banned_collection_cards(repo, user_id, format_filter=None, days=30)`:
   - Calls `repo.get_banned_collection_cards(user_id, format_filter)`
   - Calls `repo.get_recently_changed_card_ids(user_id, days)` to enrich
     each entry with `recently_changed` flag
   - Computes `image_url` using `map_to_scryfall_set_code`
   - Returns `list[BannedCollectionCard]`

2. `get_ban_summary(repo, user_id, days=30)`:
   - Calls `repo.get_collection_ban_summary(user_id)`
   - Calls `repo.get_recently_changed_card_ids(user_id, days)` for count
   - Extracts distinct formats from banned cards
   - Returns `BanSummary`

3. `get_card_legalities_with_changes(repo, card_id, days=30)`:
   - Calls `repo.get_card_legalities_with_history(card_id, days)`
   - Maps rows to `CardLegalityWithChange` schemas
   - Sorts: banned first, then restricted, then legal, then not_legal
   - Returns `list[CardLegalityWithChange]`

### Design decisions
- Keep it as pure functions, not a class — matches project style
  (see `src/analytics/indicators.py`)
- No caching — queries are fast (small collection, indexed tables)
- `days` parameter defaults to 30 but caller can override
