# F42-T01: Repository — ban-related query methods

**Status:** planned
**Wave:** 0

## User Story

As a developer, I need efficient SQL queries that join `user_collection`
with `card_legalities` and `legality_history` (from F41) so the ban engine
can retrieve banned cards and recent changes without N+1 queries.

## Dev Notes

### Files to modify
- `src/database/repository.py` — add new methods

### Implementation

1. Add `get_banned_collection_cards(user_id, format_filter=None, statuses=None)`:
   - JOIN `user_collection` ON `card_legalities` via `card_id`
   - Default statuses: `["banned", "restricted"]`
   - Optional format filter (e.g. `"standard"`, `"modern"`)
   - Returns list of rows with: `entry_id`, `card_id`, `name_en`, `name_pt`,
     `set_code`, `collector_number`, `format`, `status`, `effective_date`,
     `quantity`, `image_url` (computed)
   - Only includes cards where `user_collection.card_id IS NOT NULL`
   - Single query, no N+1

2. Add `get_collection_ban_summary(user_id)`:
   - COUNT DISTINCT card_id where status in (banned, restricted) for the user
   - Returns dict: `{"banned_count": int, "restricted_count": int}`
   - Single aggregate query

3. Add `get_card_legalities_with_history(card_id, days=30)`:
   - Fetch all rows from `card_legalities` for the given card_id
   - LEFT JOIN `legality_history` to find if there was a change in the
     last N days for each (card_id, format) pair
   - Returns list of dicts: `{"format": str, "status": str,
     "effective_date": date|None, "recently_changed": bool,
     "change_date": datetime|None, "old_status": str|None}`
   - Used by the card detail page

4. Add `get_recently_changed_card_ids(user_id, days=7)`:
   - Find card_ids in the user's collection that appear in
     `legality_history` with `changed_at` in the last N days
   - Returns `set[int]` for O(1) lookup in the tile rendering loop
   - Used by MyCollection page to add visual highlight

### Query pattern

Follow existing repository patterns:
- Use `self.engine` and `text()` for raw SQL (consistent with rest of repo)
- Return named tuples or Row objects
- No ORM relationship loading — keep it simple
