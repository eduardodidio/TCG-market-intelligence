# F174-T05 — `CardFilterBar` component + `useCardListFilters` hook

**Wave:** 1
**Type:** frontend
**Depends on:** F174-T01
**Status:** planned

## User Story

As a user, I want the same filter bar on Trades as on Minha Coleção, so that I don't need to learn two UIs.

## Objective

Extract the collection sticky filter bar into a reusable `CardFilterBar`, and add a URL-synced `useCardListFilters` hook.

## Dev Notes

Veja `_brief/00-overview.md` e `_brief/02-frontend-kit.md`.

## Acceptance criteria

- [ ] The default `data-testid` is `sticky-filter-bar`, and the container classes are identical to MyCollection's.
- [ ] The SetIconFilter row renders only when `setOptions` is non-empty.
- [ ] The actions row (`filter-bar-actions`) + GridSizeToggle renders only when `gridSize` and `onGridSizeChange` are both given. `actions` renders before the toggle.
- [ ] `children` render between the set filter and the actions row.
- [ ] The hook initialises from `?name&set&sort&dir`, falls back to the defaults on invalid `dir`, writes changes with `replace`, removes default/empty keys, and keeps other params (e.g. `tab`).
- [ ] `debouncedSearch` updates after 300 ms (fake timers).

## Testing

Vitest + Testing Library. Mock `react-i18next` (`t: k => k`). Use `vi.useFakeTimers()` for the debounce. Command: `cd frontend && npm test`.

## Test scenarios

- Happy: typing calls `onSearchChange`. Picking a sort calls `onSortChange('price','desc')`. Clicking a set icon calls `onSetSelect`.
- Edge: `setOptions=[]` → no `set-icon-filter`. Without `gridSize` → no `filter-bar-actions`. Custom `testId`.
- Hook edge: URL `?dir=sideways` → default dir. URL `?tab=seller&name=x` → changing the sort keeps `tab=seller`.
- Error: `onSetSelect` undefined while options exist → the row is not rendered (no crash).
- Boundary: resetting to defaults removes `sort`/`dir` from the URL, and an empty search removes `name`.
