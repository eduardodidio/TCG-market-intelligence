## User Story

As a trader, I want to filter my duplicates and my trade partners' matching cards, so that I focus on the cards I care about.

## Objective

Add `CardFilterBar` to `TradeMatchesPage` (server-side for duplicates, client-side for matches), use `GRID_SIZE_CONFIG`, and convert the page and `DuplicatesList` to the slate palette.

## Dev Notes

Veja `_brief/00-overview.md`, `_brief/02-frontend-kit.md` e `_brief/03-trade-pages.md`.

- The details are in `_brief/03-trade-pages.md` → TradeMatchesPage.
- The backend contract (implemented in parallel by T08): `/api/v1/trade/duplicates?search&set_code&sort_by&sort_dir`
  and `/api/v1/trade/duplicates/sets` (an `ApiResponse` envelope, so use `apiGet` from `api/client.ts` like the others).
- `useApi(fetcher, deps)` (`hooks/useApi.ts`): the fetcher must be memoised with the filter values so a filter change refetches.
- Sort options: `DUPLICATES_SORT_OPTIONS` (default `quantity-desc`) for duplicates, and `MATCH_SORT_OPTIONS` (default `name-asc`) for match tabs.
- The existing test `pages/__tests__/TradeMatchesPage.test.tsx` (owned by this task) mocks the `tradeMatch` api
  and `useAuth`. Update it for the new params and add test cases. Keep the existing assertions passing where the behaviour is unchanged.
- `DuplicatesList.tsx`: add the optional `gridClasses` prop and the slate palette. Update `components/__tests__/DuplicatesList.test.tsx` if the class assertions change.

## Test scenarios

- Happy: type a search on duplicates → the fetcher is called with `search`. Switch to theyHave → filter by set → only matching thumbnails.
- Edge: all partners filtered out → `tradeFilters.noResults`. The sets API returns an empty list → no set row. Switching tabs resets the sort to the tab default.
- Error: a fetch returns an error → the existing error/empty handling. Unauthenticated → loginRequired.
- Boundary: 200 duplicates (limit). A partner with exactly 1 matched card after filtering is still shown.
