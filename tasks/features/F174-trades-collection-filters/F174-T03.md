## User Story

As a trader, I want marketplace and duplicate lists to be searchable, filterable by set and sortable, so that I find tradeable cards fast.

## Objective

Create `src/marketplace/trade_queries.py` with `TradeQueries` (listings, listing sets, duplicates, duplicate sets) plus unit tests, without touching `repository.py`.

## Acceptance criteria

- [ ] Default `list_listings()` returns the same rows/order/keys as `Repository.list_marketplace_entries()` on the same data (asserted in a test).
- [ ] Default `list_duplicates()` returns the same rows/order/total as `Repository.get_user_duplicates()` (asserted).
- [ ] Sort by name/set/number/price in asc/desc works. NULL prices come last in both directions, and the `id` tiebreaker keeps the order deterministic.
- [ ] Search matches `name_en` OR `name_pt`, case-insensitive. Set filter is case-insensitive.
- [ ] The set facets return `{set_code, set_name, count}`, exclude the viewer (listings) and only include qty>1 with card_id (duplicates).
- [ ] An unknown sort_by/sort_dir raises `ValueError`.
- [ ] Coverage of `src/marketplace/trade_queries.py` is ≥ 90%. `ruff check src/` is clean.

## Test scenarios

- Happy: 3 shared users × cards in 2 sets → filter by set, search 'bolt', and sort price desc.
- Edge: a card with no price (card_id None or no observations) sorts last for both asc and desc. `name_pt` NULL. Empty search string ('   ') is ignored.
- Edge: the `exclude_user_id` viewer's own cards are absent from listings and from the listing sets.
- Error: `sort_by='drop table'` → ValueError. `sort_dir='up'` → ValueError.
- Boundary: limit=1/offset paging returns disjoint, deterministic pages. offset beyond total → []. Duplicates with quantity==1 are excluded, and quantity==2 is included.
