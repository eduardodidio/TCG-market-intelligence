# F174-T02 — i18n `tradeFilters` keys (en + pt-BR)

**Wave:** 0
**Type:** frontend
**Depends on:** —
**Status:** planned

## User Story

As a Brazilian trader, I want the new trade filters labelled in my language, so that I understand the sort and status options.

## Objective

Add ONE new top-level `tradeFilters` block to `en.json` and `pt-BR.json` (append-only).

## Dev Notes

Veja `_brief/00-overview.md` e `_brief/03-trade-pages.md`.

- Files: `frontend/src/i18n/locales/en.json`, `frontend/src/i18n/locales/pt-BR.json`.
- These JSONs are **shared across the F171–F179 batch**. To minimise merge conflicts:
  add the block as the **last** top-level key (before the final `}`), and do
  NOT reorder, reformat or edit any existing key. Keep 2-space indentation.
- The exact keys and EN/PT strings are in `_brief/03-trade-pages.md` → "i18n keys".
- Existing keys reused by other tasks (do not duplicate): `sort.nameAZ`,
  `sort.nameZA`, `sort.set`, `sort.cardNumber`, `sort.priceHighLow`,
  `sort.priceLowHigh`, `marketplace.*`, `tradeMatch.*`.

## Implementation details

- Append `"tradeFilters": {…}` to both files with identical key sets.
- Validate with `node -e "JSON.parse(require('fs').readFileSync('frontend/src/i18n/locales/en.json'))"` (and pt-BR).

## Acceptance criteria

- [ ] Both files are valid JSON.
- [ ] Both files have the identical `tradeFilters` key tree (including the `status.*` subkeys for pending/accepted/rejected/completed/cancelled).
- [ ] `git diff` shows only additions (plus the comma on the previous last key).
- [ ] `cd frontend && npm test` passes (if a locale key-parity test exists, it passes).

## Testing

Run `cd frontend && npm test` (Vitest). If `frontend/src/i18n/__tests__` has a parity test, it must pass. Otherwise do a manual key-parity check with a one-off node script (not committed).

## Test scenarios

- Happy: the keys resolve in both languages.
- Edge: accents in pt-BR (Concluída, Você) are stored as UTF-8, not escaped.
- Error: a trailing-comma mistake → JSON.parse fails → fix before finishing.
- Boundary: no existing key is modified (diff check).
