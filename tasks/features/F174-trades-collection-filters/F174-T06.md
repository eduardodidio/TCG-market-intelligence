# F174-T06 — TradeCard → collection-style tile

**Wave:** 1
**Type:** frontend
**Depends on:** F174-T01
**Status:** planned

## User Story

As a trader, I want my trades shown as card tiles like my collection, so that I recognise cards at a glance.

## Objective

Rewrite `components/TradeCard.tsx` as a grid tile (aspect-[5/7] image, status badge, actions) with an optional `compact` prop, keeping all testids and callbacks.

## Dev Notes

Veja `_brief/00-overview.md` e `_brief/03-trade-pages.md`.

- The current component is a horizontal row (`flex gap-4`, thumbnail `w-16`), and its only caller is `pages/MyTrades.tsx`.
- Tile anatomy to mirror: `MarketplaceCardTile` in `pages/Marketplace.tsx` and
  `CollectionCardTile` in `pages/MyCollection.tsx` (`Card3DTilt` wrapper, `bg-slate-800 rounded-lg
  overflow-hidden border border-slate-600 hover:border-cyan-400/50`, `aspect-[5/7]` image area,
  `p-3 space-y-1.5` body).
- Image: `CardImage` (`components/CardImage.tsx`) with `src=scryfallImageUrl(set_code, collector_number)`
  and `fallbackSrc=scryfallImageByName(card_name)` (`utils/scryfall.ts`).
- The status label uses `t(`tradeFilters.status.${trade.status}`)` (keys from T02). The i18n mock in tests returns the key.
- Keep the testids `trade-card-{id}`, `trade-status-{id}`, `accept-btn-{id}`,
  `reject-btn-{id}`, `confirm-btn-{id}`, `trade-completed-{id}` and `trade-pending-{id}`, the prop
  names, and the `STATUS_STYLES` map.
- `compact` hides the counterparty code and fee line (actions and status always stay visible).

## Acceptance criteria

- [ ] It renders as a tile with an aspect-[5/7] image, and the status badge is overlaid top-left.
- [ ] Seller + pending → accept/reject shown. Accepted → confirm shown + pending message. Completed → email box.
- [ ] Buyer + pending → no accept/reject.
- [ ] `compact` hides the counterparty code and the fee line.
- [ ] All the listed testids exist. Callbacks receive `trade.id`.

## Testing

Vitest + Testing Library. Mock `react-i18next`. `Card3DTilt` can render as is (see `components/__tests__/Card3DTilt.test.tsx` for any needed mocks). Command: `cd frontend && npm test`.

## Test scenarios

- Happy: seller/pending → click accept → onAccept(id).
- Edge: an unknown status falls back to the pending style. Image error → fallback by name. Missing `counterparty_share_code`.
- Error: a handler is undefined → clicking does nothing (no throw).
- Boundary: compact vs non-compact. A long card name is truncated (has a `title` attr).
