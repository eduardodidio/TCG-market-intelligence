## User Story

As a trader, I want the marketplace to filter, sort and resize like my collection, so that browsing is familiar and fast.

## Objective

Refactor `pages/Marketplace.tsx` to use `CardFilterBar` + `useCardListFilters` + `GRID_SIZE_CONFIG` + infinite scroll, and extract `MarketplaceCardTile`.

## Acceptance criteria

- [ ] `sticky-filter-bar` with search, sort, set icons (when sets exist) and a grid toggle.
- [ ] Changing search/set/sort triggers `fetchListings` with `search`/`set_code`/`sort_by`/`sort_dir`, offset 0, and updates the URL (`name`,`set`,`sort`,`dir`).
- [ ] `?search=bolt` legacy URL seeds the search box.
- [ ] Grid classes follow `GRID_SIZE_CONFIG[gridSize]`, and the tile is compact on `sm`.
- [ ] Infinite scroll appends the next page when `hasMore`. A stale response is ignored.
- [ ] The interest modal, success toast and "Minhas trocas" link still work. Testids `page-marketplace`, `marketplace-card-*` and `interest-btn-*` are kept.

## Testing

Vitest + Testing Library. `vi.mock('../../api/marketplace')`, mock `react-i18next`, `MemoryRouter`. Mock `useInfiniteScroll` to capture the callback, or stub `IntersectionObserver`. Command: `cd frontend && npm test`.

## Test scenarios

- Happy: load → 40 items → trigger loadMore → 80 items with offset=40.
- Edge: the sets API returns [] → no set filter. Listing with null price → 'noData'. Less than 40 results → no more loading.
- Error: fetchListings rejects → ErrorBanner, and retry calls it again. fetchListingSets rejects → the page still works without a set row.
- Boundary: a rapid search change while a request is in flight → only the latest result is rendered.
