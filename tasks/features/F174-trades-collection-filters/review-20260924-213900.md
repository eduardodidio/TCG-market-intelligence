## Fix verification

The rewrite in Wave 1 (T06) changed `TradeCard.tsx`'s status badge to
render a translated label (`t('tradeFilters.status.<status>')`, e.g.
"Pending") instead of the raw lowercase `trade.status` string the legacy
test asserted. The fix adds `data-status={trade.status}` as a separate
DOM attribute alongside the translated visible text, and updates the two
legacy assertions to check `toHaveAttribute("data-status", status)`
instead of `toHaveTextContent(status)`. This is exactly the second option
the prior review offered ("keep the raw status string in the DOM... so
the legacy assertion keeps working") and is minimal — it doesn't touch
the translated visible label T06 intentionally added, and doesn't touch
any other file.

## Retrospective Seeds

- **Pattern:** the fix for a component-output regression correctly added
  a stable `data-*` hook and repointed only the two failing assertions,
  rather than reverting the i18n change or leaving the legacy test
  broken. This is the right shape for future "translated visible text
  breaks an old text-content assertion" fixes: expose the raw value as a
  `data-*` attribute rather than asserting on translated strings.
  **Role(s) affected:** developer
  **Lesson:** when a component starts rendering translated text where a
  raw value used to be, add a `data-*` attribute carrying the raw value
  so language-independent assertions (existing or new) don't have to
  couple to i18n copy.
- **Pattern:** `tests/pages/MyTrades.test.tsx` (legacy, unowned) gained 2
  more failing tests within an already-failing file due to T10's page
  rewrite; this doesn't trip the file-level AC7 gate but is a real
  coverage/quality regression the wave summaries didn't surface.
  **Role(s) affected:** developer, qa
  **Lesson:** when an AC7-style gate is defined at file granularity, also
  spot-check whether an already-failing legacy file gained *additional*
  failing tests within it — that's invisible to a file-name diff but is
  still a real regression worth a follow-up task.
