# F174-T08 — Duplicates: search/set/sort + `GET /trade/duplicates/sets`

**Wave:** 2
**Type:** backend
**Depends on:** F174-T03
**Status:** planned
- **Maps to AC:** AC5, AC6

## User Story

As a collector with spare copies, I want to search, filter and sort my duplicates, so that I pick what to offer in trades.

## Objective

Extend `GET /api/v1/trade/duplicates` with `search`, `set_code`, `sort_by`, `sort_dir`, and add `GET /api/v1/trade/duplicates/sets`.

## Dev Notes

Veja `_brief/00-overview.md` e `_brief/01-backend.md`.

- File: `src/api/routers/trade_match.py` (`list_duplicates` at ~L20). Keep the `ApiResponse`
  envelope (`success_response(result, total=total)`) and the `DuplicateCard` schema mapping.
- Use `TradeQueries(repo).list_duplicates(user.id, ...)`.
- `/duplicates/count` stays on `repo.get_user_duplicates` (unchanged).
- Validation: `search: str | None = Query(None, max_length=100)`, `set_code: str | None = Query(None, max_length=10)`,
  `sort_by: str = Query("quantity", pattern="^(quantity|name|set|number|price)$")`,
  `sort_dir: str = Query("desc", pattern="^(asc|desc)$")`.
- The new `/duplicates/sets` endpoint uses `response_model=ApiResponse[list[dict]]` (or a small
  `SetFacet` pydantic model defined **locally in the router file** to avoid touching the shared schemas).
- Declare the static routes (`/duplicates/count`, `/duplicates/sets`) together. There are no path-param
  routes under `/duplicates`.

## Implementation details

- `src/api/routers/trade_match.py`: extend `list_duplicates` and add `list_duplicate_sets`.

## Acceptance criteria

- [ ] Without the new params, the response (items, order, total) is unchanged.
- [ ] `search` and `set_code` filter the results, and `total` reflects the filters.
- [ ] Sorting works for all whitelisted keys. Invalid → 422.
- [ ] `/trade/duplicates/sets` requires auth (401/403 as the other endpoints) and returns only qty>1 sets.
- [ ] Existing tests pass. `ruff check src/` is clean.

## Testing

- pytest + `TestClient` with `app.dependency_overrides[get_current_user]` and `get_db` (existing pattern in `tests/api/test_trade_match_router.py`).
- Command: `pytest tests/api/test_trade_match_router.py -q`.
- Then the full suite: `pytest tests/ --cov=src --cov-report=term-missing`.
- Lint: `ruff check src/`.

## Test scenarios

- Happy: search 'sol' + sort name asc.
- Edge: a user with no duplicates → `[]`, total 0, and sets `[]`. An uppercase set_code matches a lowercase row.
- Error: `search` over 100 chars → 422. `sort_by=quality` → 422. No auth → the rejection used by the other endpoints.
- Boundary: limit=200 max. Quantity exactly 2 is included, and 1 is excluded.
