# F174-T07 — Marketplace listings: sort params + `GET /listings/sets`

**Wave:** 2
**Type:** backend
**Depends on:** F174-T03
**Status:** planned
- **Maps to AC:** AC3, AC6

## User Story

As a trader browsing the marketplace, I want to sort listings and pick a set from icons, so that I find the best offers quickly.

## Objective

Extend `GET /api/v1/marketplace/listings` with `sort_by`/`sort_dir`, and add `GET /api/v1/marketplace/listings/sets`, both via `TradeQueries`.

## Dev Notes

Veja `_brief/00-overview.md` e `_brief/01-backend.md`.

- Files: `src/api/routers/marketplace.py` (`browse_listings` at ~L49, `get_shared_collection` at ~L70)
  and `src/marketplace/service.py` (`get_listings` at L43).
- **Route order:** declare `@router.get("/listings/sets")` ABOVE `@router.get("/listings/{share_code}")`.
- Validation: `sort_by: str = Query("name", pattern="^(name|set|number|price)$")`,
  `sort_dir: str = Query("asc", pattern="^(asc|desc)$")`.
- `MarketplaceService.get_listings(..., sort_by="name", sort_dir="asc")` → `TradeQueries(self.repo).list_listings(...)`.
  The existing `test_service.py` tests call `get_listings` without the new kwargs and must still pass.
- The sets endpoint uses `get_optional_user` and returns `{"sets": [...]}`.
- **No change to `src/api/app.py`** (the router is already included).

## Implementation details

- `browse_listings`: new params → service.
- New `list_listing_sets` endpoint.
- `MarketplaceService.get_listings`: new kwargs and delegation to `TradeQueries`.
- `tests/marketplace/test_router.py`: add test cases.

## Acceptance criteria

- [ ] `GET /marketplace/listings` without the new params returns the same payload/order as before.
- [ ] `?sort_by=price&sort_dir=desc` orders by price with nulls last.
- [ ] `?sort_by=foo` or `?sort_dir=up` → 422.
- [ ] `GET /marketplace/listings/sets` returns `{sets:[{set_code,set_name,count}]}` and is not captured by `/listings/{share_code}`.
- [ ] An authenticated viewer's own sets are excluded. Anonymous works.
- [ ] Existing marketplace tests pass. `ruff check src/` is clean.

## Testing

- pytest + FastAPI `TestClient` with `dependency_overrides` (existing pattern in `tests/marketplace/test_router.py`).
- Command: `pytest tests/marketplace -q`.
- Then the full suite with coverage: `pytest tests/ --cov=src --cov-report=term-missing`.
- Lint: `ruff check src/`.

## Test scenarios

- Happy: sort by name desc. Filter set + sort by price.
- Edge: no shared collections → `{sets: []}`. The share_code literally named 'sets' is not a concern (codes are random).
- Error: invalid sort → 422 with the FastAPI validation body.
- Boundary: limit=100 max, limit=101 → 422 (existing). offset past the end → empty list.
