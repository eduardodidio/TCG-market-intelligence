`python3 -m pytest` instead, which resolves to the project's pytest 9.1.1 +
pytest-cov 7.1.0 environment. This is a pre-existing environment quirk, not
an F174 issue — noting it here so it doesn't get re-discovered from scratch
next time.

## Non-blocking observations (carried from TechLead review + reconfirmed)

1. `tests/pages/MyTrades.test.tsx` (legacy, unowned) was already failing
   on 1 test at the pre-F174 baseline ("renders breadcrumb"). After T10's
   page rewrite it now fails on 3 tests within the same file
   ("renders breadcrumb", "shows empty state when no trades", "shows
   status badges") — all `getByText` selectors broken by the tile-based
   rewrite. This does **not** trip the file-level AC7 gate (the file was
   already failing) but is a real, additional coverage gap inside an
   already-red file. Recommend a follow-up task to update or retire this
   legacy test file rather than leave it silently more broken.
2. The 109 backend failures are pre-existing/environmental (confirmed
   identical on the pre-F174 baseline) and mostly trace to sandboxed
   network egress being blocked for Liga/MYP/Scryfall calls, plus one
   apparently-unrelated currency-fallback regression
   (`test_returns_none_when_no_rate`) that predates this feature. None
   touch marketplace/trade code. Out of scope for F174 to fix.
