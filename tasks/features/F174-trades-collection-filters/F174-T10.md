## User Story

As a trader managing requests, I want to filter my trades by name, set and status, so that I act on pending requests quickly.

## Objective

Refactor `pages/MyTrades.tsx` to use `CardFilterBar` (search/set/sort/grid) + status `FilterChips`, client-side filtering, and a grid of `TradeCard` tiles.

## Acceptance criteria

- [ ] `sticky-filter-bar` with search, sort, set icons and a grid toggle, plus status chips (`filter-chips`).
- [ ] Trades are rendered in `grid ${GRID_SIZE_CONFIG[gridSize].gridClasses}` as `TradeCard` tiles, with `compact` passed through.
- [ ] Tabs keep `trade-tabs`/`tab-buyer`/`tab-seller`, show filtered counts, and persist `?tab=seller`.
- [ ] Filtered empty → `tradeFilters.noResults`. Unfiltered empty → the role-specific message.
- [ ] Accept/reject/confirm still call the API and reload. INSUFFICIENT_CREDITS still maps to `marketplace.insufficientForTrade`.
- [ ] Loading uses `SkeletonCard` in the grid.

## Testing

Vitest + Testing Library. `vi.mock('../../api/marketplace')` (`fetchMyTrades`, `respondToInterest`, `confirmAgreement`), mock `react-i18next`, and `MemoryRouter initialEntries={['/marketplace/my-trades?tab=seller']}`. Command: `cd frontend && npm test`.

## Test scenarios

- Happy: 5 trades → search 'bolt' → 1 tile. Status chip 'pending' → only pending.
- Edge: `?tab=seller` on load selects the seller tab. Set options come from the trades. Sort by date asc/desc and by status.
- Error: fetchMyTrades rejects → ErrorBanner with retry. confirmAgreement rejects with INSUFFICIENT_CREDITS → the translated message.
- Boundary: 0 trades, 1 trade, and 100 trades (render smoke). Clearing all filters restores the full list.
