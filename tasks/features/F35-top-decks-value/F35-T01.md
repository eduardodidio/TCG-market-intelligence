# F35-T01: Domain models for deck valuation

**Status:** planned
**Wave:** 0

## User Story

As a developer, I need domain dataclasses for deck valuation results so
that the valuation service and API schemas have a shared contract.

## Dev Notes

### Files to modify
- `src/domain/models.py` — add new dataclasses

### Implementation

Add three dataclasses to `src/domain/models.py`:

1. **`DeckValuation`**:
   - `total_value: Decimal | None` — sum of (card_price * quantity)
   - `priced_cards: int` — count of cards with known prices
   - `unpriced_cards: int` — count of cards without prices

2. **`DeckValuePoint`**:
   - `date: date` — observation date
   - `total_value: Decimal` — deck value at that date

3. **`DeckValueChange`**:
   - `current: Decimal` — current period value
   - `previous: Decimal` — previous period value
   - `delta: Decimal` — absolute change (current - previous)
   - `delta_pct: Decimal` — percent change

All use `Decimal` for price arithmetic, consistent with existing
analytics models. Import `date` from `datetime` (already imported).
