# F38-T01 -- Dashboard Integration: Hero, Trending Sections, Compact Stats

**Wave:** 1 (parallel with T02)
**Depends on:** F36 shipped (TrendingSection component, fetchTrending API client, types)
**Modifies:** `frontend/src/pages/Dashboard.tsx`

## Objective

Rework the Dashboard page to replace the text-only `MoversPreview` with
F36's visual `TrendingSection` components, add a hero header, and
consolidate the Market Overview KPIs into a compact summary strip.

## Steps

### 1. Add imports

Add to Dashboard.tsx:
```typescript
import { TrendingSection } from "../components/TrendingSection";
```

Remove the `MoversPreview` import and the `fetchMovers` import (no longer
used on this page). Remove the `MoversResponse` type import if only used
here.

### 2. Remove movers fetch

Remove the `useApi<MoversResponse>` call for `fetchMovers`. The
`TrendingSection` component handles its own data fetching internally
(it calls `fetchTrending()` via `useApi` inside itself, as built in F36).

Remove the `hasMoversData` variable and the `MoversPreview` rendering
block.

Update the `loading` variable to no longer depend on `movers.loading`
(only `stats.loading` remains for the KPI section).

### 3. Add hero header

Replace the current title section:

```tsx
{/* Hero header */}
<div className="mb-8">
  <h1 className="text-3xl font-bold text-white">
    {t("landing.heroTitle")}
  </h1>
  <p className="mt-1 text-sm text-slate-400">
    {t("landing.heroSubtitle")}
  </p>
  {freshnessIndicator && (
    <div className="mt-2">{freshnessIndicator}</div>
  )}
</div>
```

### 4. Consolidate Market Overview into compact strip

Replace the 4-card Market Overview KPI grid with a single-row compact
summary. This frees vertical space for the trending sections:

```tsx
{/* Market summary strip */}
{hasMarketData && (
  <div
    className="mb-8 flex flex-wrap items-center gap-6 rounded-lg bg-slate-800 border border-slate-600 px-6 py-4"
    data-testid="market-summary-strip"
  >
    <div className="flex items-center gap-2">
      <span className="text-sm text-slate-400">{t("landing.cardsTracked")}</span>
      <span className="text-sm font-semibold text-white">{marketStats?.total_cards ?? 0}</span>
    </div>
    <div className="h-4 w-px bg-slate-600" aria-hidden="true" />
    <div className="flex items-center gap-2">
      <span className="text-sm text-slate-400">{t("landing.observations")}</span>
      <span className="text-sm font-semibold text-white">{marketStats?.total_observations ?? 0}</span>
    </div>
    <div className="h-4 w-px bg-slate-600" aria-hidden="true" />
    <div className="flex items-center gap-2">
      <span className="text-sm text-slate-400">{t("landing.avgPrice")}</span>
      <span className="text-sm font-semibold text-white">
        <CurrencyIndicator currency={currency} size={14} />
        {" "}{formatCurrency(marketStats?.avg_price ?? null, currency)}
      </span>
    </div>
  </div>
)}
```

Keep the empty state for when `!hasMarketData`.

### 5. Add trending sections

After the collection KPIs and market summary strip, add the two trending
sections:

```tsx
{/* Em Alta */}
<div className="mb-8" data-testid="landing-trending-up">
  <TrendingSection
    direction="gainers"
    period="30d"
    currency={currency}
    limit={10}
  />
</div>

{/* Em Baixa */}
<div className="mb-8" data-testid="landing-trending-down">
  <TrendingSection
    direction="losers"
    period="30d"
    currency={currency}
    limit={10}
  />
</div>
```

The `TrendingSection` component (from F36) already handles:
- Data fetching via `fetchTrending()`
- Section header with directional icon and i18n title
- Horizontal scrollable row of `TrendingCard` tiles
- Skeleton loading placeholders
- Empty state when no trending cards
- Error state with retry
- "Ver mais" / "View All" link (ensure it points to `/market/trending`)

### 6. Verify "Ver mais" link target

Confirm that F36's `TrendingSection` renders a link to `/market/trending`.
If it does not include one by default, add a "Ver mais" link after each
`TrendingSection`:

```tsx
<Link
  to="/market/trending"
  className="mt-3 inline-block text-sm text-cyan-400 hover:text-cyan-300 transition-colors"
>
  {t("common.viewAll")}
</Link>
```

### 7. Update loading skeleton

Update the loading skeleton to reflect the new layout:
- Keep `SkeletonKpi` grid for collection KPIs
- Replace `SkeletonTable` pair with two rows of `SkeletonCard` (3-4 cards
  each) to preview the trending sections

```tsx
{/* Trending skeleton */}
<div className="mb-8">
  <div className="animate-pulse bg-slate-700 rounded h-6 w-32 mb-4" />
  <div className="flex gap-4 overflow-hidden">
    {Array.from({ length: 4 }).map((_, i) => (
      <div key={i} className="shrink-0 w-44">
        <SkeletonCard />
      </div>
    ))}
  </div>
</div>
```

Repeat for the second trending section skeleton.

### 8. Preserve collection KPIs

The collection KPI section (unique cards, copies, value, coverage) remains
unchanged. It renders above the market summary strip and trending sections.

## Final Layout Order

1. Hero header (title + subtitle + freshness)
2. Collection KPIs (4-card grid, unchanged)
3. Market summary strip (compact single-row)
4. "Em Alta" TrendingSection (gainers, 30d, limit 10)
5. "Em Baixa" TrendingSection (losers, 30d, limit 10)

## Acceptance Criteria

- [ ] `MoversPreview` is no longer imported or rendered on Dashboard
- [ ] `fetchMovers` is no longer called from Dashboard
- [ ] Hero header displays project title, subtitle, and freshness indicator
- [ ] Market Overview is a compact single-row strip (not 4 separate KPI cards)
- [ ] Two `TrendingSection` components render: one for gainers, one for losers
- [ ] Both sections use `period="30d"`, `limit={10}`, and `currency` from hook
- [ ] Collection KPIs remain unchanged
- [ ] Loading skeleton shows card placeholders (not table placeholders)
- [ ] Dashboard renders without errors when trending API returns empty
- [ ] Dashboard renders without errors when trending API returns an error
- [ ] Layout is responsive (stacks on mobile)
