# F94-T01: Litestream Dockerfile Integration

**Status:** planned
**Wave:** 0
**Depends on:** none

## User Story

As a deployer, I want the Docker image to include Litestream so that the
SQLite database is automatically restored on startup and continuously
replicated to R2, surviving container restarts and redeployments.

## Dev Notes

### Changes

1. **Dockerfile** — Add Litestream binary install stage:
   ```dockerfile
   # Download Litestream
   ARG LITESTREAM_VERSION=0.3.13
   ADD https://github.com/benbjohnson/litestream/releases/download/v${LITESTREAM_VERSION}/litestream-v${LITESTREAM_VERSION}-linux-amd64.tar.gz /tmp/litestream.tar.gz
   RUN tar -C /usr/local/bin -xzf /tmp/litestream.tar.gz && rm /tmp/litestream.tar.gz
   ```

2. **render-start.sh** — Replace direct uvicorn exec with Litestream wrapper:
   ```bash
   # If LITESTREAM_REPLICA_URL is set, use litestream for restore+replicate
   if [ -n "$LITESTREAM_REPLICA_URL" ]; then
     echo "==> Restoring database from R2..."
     litestream restore -if-replica-exists -config /app/litestream.yml /data/tcg_market.db
     echo "==> Starting with Litestream replication..."
     exec litestream replicate -exec "sh /app/render-start-app.sh" -config /app/litestream.yml
   else
     echo "==> No LITESTREAM_REPLICA_URL set, starting without replication..."
     exec sh /app/render-start-app.sh
   fi
   ```

3. **render-start-app.sh** (new) — Extract current app startup logic from
   render-start.sh (exchange rate seed, user seed, uvicorn exec)

4. **Dockerfile** — Copy litestream.yml and both start scripts:
   ```dockerfile
   COPY litestream.yml render-start.sh render-start-app.sh ./
   ```

### Key decisions

- Litestream wraps the app process (`-exec`), so it handles graceful
  shutdown and final WAL sync automatically
- `-if-replica-exists` flag means first deploy (no backup yet) starts fresh
  without errors
- Keep render-start.sh as the entrypoint — backward compatible if
  LITESTREAM_REPLICA_URL is not set (local dev, tests)
