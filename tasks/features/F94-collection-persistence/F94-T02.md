# F94-T02: Litestream Config + Render Environment

**Status:** planned
**Wave:** 0
**Depends on:** none

## User Story

As a deployer, I want a Litestream config file that points to my R2 bucket
and the correct SQLite path, and the Render service configured with the
required credentials, so replication works out of the box.

## Dev Notes

### Changes

1. **litestream.yml** (new, project root):
   ```yaml
   dbs:
     - path: /data/tcg_market.db
       replicas:
         - type: s3
           bucket: $LITESTREAM_REPLICA_BUCKET
           path: db
           endpoint: $LITESTREAM_ENDPOINT
           access-key-id: $LITESTREAM_ACCESS_KEY_ID
           secret-access-key: $LITESTREAM_SECRET_ACCESS_KEY
           retention: 72h
           sync-interval: 1s
   ```

2. **render.yaml** — Add new env vars (sync: false, user provides via
   Render dashboard):
   ```yaml
   - key: LITESTREAM_REPLICA_BUCKET
     sync: false
   - key: LITESTREAM_ENDPOINT
     sync: false
   - key: LITESTREAM_ACCESS_KEY_ID
     sync: false
   - key: LITESTREAM_SECRET_ACCESS_KEY
     sync: false
   ```

3. **docs/adr/0007-sqlite-persistence-litestream.md** — ADR documenting
   the decision to use Litestream + R2 over managed PostgreSQL or periodic
   dumps.

4. **README.md** — Add "Persistence" section explaining setup:
   - Create R2 bucket on Cloudflare (free)
   - Generate R2 API token (Object Read & Write)
   - Set 4 env vars on Render dashboard
   - Next deploy auto-restores and replicates

### Key decisions

- `retention: 72h` keeps 3 days of WAL snapshots (enough for recovery)
- `sync-interval: 1s` balances durability vs R2 request cost (free tier
  has 10M ops/mo, 1/s = ~2.6M/mo, well within budget)
- Env vars use `sync: false` so secrets are set manually on Render
  dashboard, never committed to repo
- The `disk` block in render.yaml is kept for documentation but is
  effectively a no-op on free tier
