# F94-T04: Health Check + Replication Monitoring

**Status:** planned
**Wave:** 1
**Depends on:** T01, T02

## User Story

As an operator, I want the health endpoint to report replication status and
last backup age, so I can detect if replication has stalled before data is
lost.

## Dev Notes

### Changes

1. **src/api/app.py** (or health router) — Extend `/health` response:
   ```json
   {
     "status": "healthy",
     "db_exists": true,
     "db_size_mb": 12.3,
     "replication": {
       "enabled": true,
       "provider": "litestream-r2",
       "last_wal_sync": "2026-08-31T12:00:00Z"
     }
   }
   ```
   - `replication.enabled`: true if `LITESTREAM_REPLICA_BUCKET` is set
   - `last_wal_sync`: parse from Litestream generation file or check
     R2 latest object timestamp (optional, can be "unknown" initially)

2. **src/api/routers/admin.py** — Add `GET /admin/replication-status`:
   - Returns detailed replication info (bucket, endpoint, retention)
   - Auth-protected (admin only)
   - Calls `litestream generations` subprocess if available

3. **render-start.sh** — Ensure Litestream restore result is logged:
   ```bash
   litestream restore -if-replica-exists ... 2>&1 | tee /tmp/litestream-restore.log
   ```

### Key decisions

- Health check remains lightweight — just checks env var presence and
  DB file existence, no network calls to R2
- Detailed status (generations, WAL lag) is admin-only endpoint
- Keep it simple: v1 just reports enabled/disabled + DB size
