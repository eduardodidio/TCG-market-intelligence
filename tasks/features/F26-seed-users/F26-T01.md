# F26-T01: CLI seed-users Command

- **Wave:** 0
- **Status:** planned
- **Depends on:** none
- **Type:** backend

## User Story

As a developer/admin, I want to run `python -m src.cli.main seed-users`
to create the initial users so I don't have to manually call the API.

## Dev Notes

### 1. Add `seed-users` command to `src/cli/main.py`

```python
@cli.command("seed-users")
@click.option("--db", default="sqlite:///tcg_market.db", help="Database URL")
def seed_users(db: str):
    """Create initial seed users (idempotent)."""
```

### 2. Implementation

- Define seed data inline (no config file needed for 2 users):
  ```python
  SEED_USERS = [
      {"email": "eduardo.didio", "display_name": "Eduardo Didio", "password": "mudar@123"},
      {"email": "anderson.serafim", "display_name": "Anderson Serafim", "password": "mudar@123"},
  ]
  ```
- For each user:
  1. Check `repo.get_user_by_email(email)` — if exists, log skip
  2. Otherwise, hash password with `hash_password()` and call `repo.create_user()`
  3. Log result (created / skipped)

### 3. Use existing infrastructure

- `src/auth/passwords.hash_password` for bcrypt hashing
- `src/database/repository.Repository.create_user` for DB insert
- `src/database/repository.Repository.get_user_by_email` for existence check

### 4. No new dependencies

Everything needed already exists.

## Testing

- Framework: pytest
- Test with in-memory SQLite DB
- Test cases:
  1. First run creates both users
  2. Second run skips both (idempotent)
  3. Passwords verify correctly via `verify_password`
- Integration: run CLI command via `click.testing.CliRunner`

## Acceptance Criteria

- [ ] `python -m src.cli.main seed-users` creates eduardo.didio and anderson.serafim
- [ ] Running twice logs "skipped" for existing users, no error
- [ ] Passwords are bcrypt-hashed (not plaintext in DB)
- [ ] `verify_password("mudar@123", stored_hash)` returns True
- [ ] Tests cover create + idempotent scenarios
