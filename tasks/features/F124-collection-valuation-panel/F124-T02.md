## User Story

As a collector, I want the Liga page URL of each price to be stored next to
its price key, so that the app can always link to the page the price came from.

## Objective

Add table `liga_card_urls` and two repository methods, working on SQLite and PostgreSQL.

## Dev Notes

Veja `_brief/00-overview.md` e `_brief/03-liga-link.md` (sections "Decision", "Model", "Repository API").

  `Mapped`/`mapped_column`, `String`, `DateTime`, `datetime` already imported.

## Implementation details

1. `LigaCardUrlRow` exactly as in `_brief/03-liga-link.md` (`external_id` String(100) PK, `url` String(1000) not null, `updated_at`).
2. `Repository.upsert_liga_card_url(self, external_id: str, url: str) -> None` — upsert, sets `updated_at=datetime.now()`; raises `ValueError` for empty external_id/url or url > 1000 chars (validation at boundary).
3. `Repository.get_liga_card_url(self, external_id: str) -> str | None`.
4. No changes to any existing query.

- Happy: insert + get; update same key changes URL.
- Two keys `liga_42` and `liga_42_foil` stored independently.
- Unknown key → None.
- Errors: empty external_id → ValueError; empty url → ValueError; url of 1001 chars → ValueError; 1000 chars accepted (boundary).
- Idempotent: upsert same (key, url) twice → still one row.
