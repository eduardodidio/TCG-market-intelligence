## User Story

As a contributor (human or AI), I want clear security policies, contribution
guidelines, and AI-specific context so that I know what is expected and can
work effectively without asking redundant questions.

## Objective

Create three docs under `docs/`:

1. `docs/SECURITY.md` -- security policies and practices
2. `docs/CONTRIBUTING.md` -- how to contribute
3. `docs/AI_CONTEXT.md` -- context specifically for AI agents/LLMs

## Dev Notes

- SECURITY.md should reflect the guardrails already in CLAUDE.md (no secrets
  in code, no force push, etc.) plus web-scraping ethics.
- CONTRIBUTING.md is lightweight for now (solo project) but establishes the
  pattern for when collaborators join.
- AI_CONTEXT.md is a distilled version of CLAUDE.md + MEMORY.md that any LLM
  (not just Claude) can use to understand the project quickly.

## Implementation Details

### docs/SECURITY.md

Sections:
1. **Secrets Management** -- no hardcoded secrets, use .env, .env is gitignored
2. **Dependencies** -- pin major versions in pyproject.toml, review before
   adding new deps
3. **Data Scraping Ethics** -- respect robots.txt, rate limiting, no API abuse
4. **Git Safety** -- no force push, no --no-verify, no secrets in commits
   (reference CLAUDE.md guardrails)
5. **Reporting Vulnerabilities** -- contact info / process

### docs/CONTRIBUTING.md

Sections:
1. **Getting Started** -- link to SETUP.md
2. **Development Workflow** -- link to DEVELOPMENT.md
3. **Feature Process** -- use `/create-feature` slash command, follow Waves
   workflow
4. **Code Style** -- link to DEVELOPMENT.md coding style section
5. **Pull Requests** -- describe what a good PR looks like
6. **Documentation** -- every feature must update README.md, may need new docs
7. **Testing** -- every feature must maintain or increase test coverage

### docs/AI_CONTEXT.md

Sections:
1. **Project Summary** -- one paragraph: what, why, how
2. **Tech Stack** -- Python 3.14, SQLite/SQLAlchemy, curl_cffi, Click, structlog
3. **Key Files** -- CLAUDE.md, pyproject.toml, src/ layout
4. **Architecture** -- link to ARCHITECTURE.md, brief layer summary
5. **Current State** -- F01 shipped (MYP Cards backfill working), F02 in progress
6. **Conventions** -- ruff, pytest, conventional commits, Waves workflow
7. **What NOT to Do** -- reference CLAUDE.md guardrails (no force push, no
   secrets, no disabling tests)
8. **Common Tasks** -- how to run tests, lint, backfill, add a provider
