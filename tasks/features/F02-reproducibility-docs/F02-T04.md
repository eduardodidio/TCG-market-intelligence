# F02-T04: SETUP.md + DEVELOPMENT.md

## User Story

As a new contributor, I want step-by-step setup instructions (SETUP.md) and a
development guide (DEVELOPMENT.md) so that I can go from zero to a working dev
environment and know the team's coding conventions.

## Objective

Create two docs under `docs/`:

1. `docs/SETUP.md` -- prerequisites, installation, first run
2. `docs/DEVELOPMENT.md` -- coding conventions, testing, linting, commit style

## Dev Notes

- SETUP.md should reference the bootstrap scripts from F02-T02 and the Makefile
  from F02-T01.
- DEVELOPMENT.md should codify the conventions already visible in the codebase:
  ruff for linting, pytest + pytest-asyncio for tests, structlog for logging.
- Keep both docs practical -- copy-paste commands, not prose essays.

## Implementation Details

### docs/SETUP.md

Sections:
1. **Prerequisites** -- Python >= 3.11, make, git
2. **Quick Start (Mac)** -- `./bin/bootstrap-mac.sh`
3. **Quick Start (Linux)** -- `./bin/bootstrap-linux.sh`
4. **Manual Setup** -- step-by-step: clone, venv, pip install, copy .env
5. **Verify Installation** -- `make test`, `make lint`
6. **First Run** -- `make run-backfill SET=dominaria-remastered LIMIT=5`
7. **Troubleshooting** -- common issues (Cloudflare 403, Python version)

### docs/DEVELOPMENT.md

Sections:
1. **Project Structure** -- brief tree (link to ARCHITECTURE.md for details)
2. **Coding Style** -- ruff config, line length 100, target py311
3. **Testing** -- pytest conventions, fixtures directory, async tests
4. **Linting & Formatting** -- `make lint`, `make format`
5. **Adding a New Provider** -- checklist (implement ABC, add parser, register)
6. **Commit Messages** -- conventional commits style
7. **Branch Strategy** -- main-only for now, feature branches when team grows
8. **Useful Make Targets** -- table of all targets from Makefile

## Testing

- **Framework:** manual review + cross-reference validation
- **Command:** `grep -oP 'make \w+' docs/SETUP.md docs/DEVELOPMENT.md | sort -u` and verify each target exists in Makefile
- **Strategy:** follow SETUP.md on a conceptual fresh machine, verify all make targets referenced actually exist, verify all file paths resolve

## Test Scenarios

1. SETUP.md references only existing files (bootstrap scripts, Makefile, .env.example)
2. DEVELOPMENT.md ruff config matches pyproject.toml
3. All `make` targets mentioned exist in Makefile
4. Commands use correct module paths (`src.cli.main`, not `src/cli/main.py`)
