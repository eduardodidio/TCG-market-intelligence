## User Story

As a stakeholder or future developer, I want to see the planned API surface
(API.md), the project roadmap (ROADMAP.md), and a summary of key decisions
(DECISIONS.md) so that I understand where the project is headed and why
certain choices were made.

## Objective

Create three docs under `docs/`:

1. `docs/API.md` -- planned REST API surface (not yet implemented)
2. `docs/ROADMAP.md` -- feature roadmap with phases
3. `docs/DECISIONS.md` -- index of all architecture decisions (links to ADRs)

## Dev Notes

- API.md documents the *planned* API, not an existing one. This is a design
  document that will guide the future API feature.
- ROADMAP.md should reflect what is mentioned in the README "Future" section
  plus the living docs feature (F02).
- DECISIONS.md is a lightweight index that links to individual ADRs.

## Implementation Details

### docs/API.md

Sections:
1. **Status** -- Not yet implemented. This doc describes the planned API.
2. **Base URL** -- `http://localhost:8000/api/v1` (planned)
3. **Authentication** -- TBD (initially none for local use)
4. **Endpoints** (planned):
   - `GET /cards` -- list cards with filters (game, set, name)
   - `GET /cards/{id}` -- card details with latest price
   - `GET /cards/{id}/history` -- price history with period filter
   - `GET /sets` -- list all collected sets
   - `GET /market/movers` -- top gainers/losers over a period
   - `GET /market/stats` -- aggregate market statistics
   - `POST /collect/backfill` -- trigger backfill for a set (admin)
   - `POST /collect/update` -- trigger incremental update (admin)
5. **Response Format** -- JSON, standard envelope with `data`, `meta`, `errors`
6. **Pagination** -- cursor-based for lists
7. **Error Codes** -- standard HTTP codes + domain-specific error schema
