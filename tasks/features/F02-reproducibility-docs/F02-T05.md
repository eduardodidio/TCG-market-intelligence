## User Story

As a developer working on data collection or analysis, I want detailed docs on
our data sources (how we scrape, rate limits, gotchas) and database schema
(tables, relationships, indexing) so that I can write correct queries and
add new sources without breaking things.

## Objective

Create two docs under `docs/`:

1. `docs/DATA_SOURCES.md` -- everything about MYP Cards and future sources
2. `docs/DATABASE.md` -- schema documentation, relationships, idempotency

## Dev Notes

- MYP Cards details are well-documented in MEMORY.md -- transfer that
  knowledge to DATA_SOURCES.md.
- Database schema is defined in `src/database/models.py` -- document the
  tables, columns, constraints, and the idempotency strategy.
- This is reference material that developers and AI agents consult frequently.

## Implementation Details

### docs/DATA_SOURCES.md

Sections:
1. **Overview** -- what sources exist (MYP Cards), what is planned
2. **MYP Cards (mypcards.com)**
   - Domain and Cloudflare protection
   - robots.txt policy (allows `User-agent: *`, blocks ClaudeBot)
   - URL patterns:
     - Editions: `/magic/edicoes?page={1..48}`
     - Card listing: `/magic/{set-slug}`
     - Card detail: product page with JSON-LD
     - Price history: `/magic/preco/{id}/{slug}?dias={30|90|180|365|1095}`
     - Search: `/produto/search?marca=magic&term={q}`
   - Data extraction methods:
     - JSON-LD `@type: Product` (sku, productID, price, name)
     - `window.precoChartConfig` JS variable (labels, series)
   - SKU format: `magic_{set}_{number}` maps to Scryfall codes
   - Card names: PT in JSON-LD, EN via search API
   - Rate limiting: configurable delay (default 1s)
   - Known limitations: weekly resolution, max 1095 days, PT-only names
3. **Planned Sources** -- Liga Magic, Scryfall (metadata), CardMarket, TCGPlayer
4. **Adding a New Source** -- implement `CardSourceProvider` ABC, reference
   DEVELOPMENT.md

### docs/DATABASE.md

Sections:
1. **Overview** -- SQLite via SQLAlchemy, single-file DB
2. **Schema Diagram** -- Mermaid ER diagram code block
3. **Tables**
   - `cards` -- canonical identity (game, name_en, name_pt, set_code,
     collector_number). PK: id. Unique: (game, set_code, collector_number)
   - `source_cards` -- per-source card data (source, external_id, sku, url).
     FK: card_id -> cards. Unique: (source, external_id)
   - `price_observations` -- immutable price snapshots (source, external_id,
     observed_at, median_price, tcg_price, last_sold_price, quantity_available).
     Unique: (source, external_id, observed_at)
   - `collection_errors` -- failed attempts (source, external_id, url,
     error_type, error_message, resolved, created_at)
4. **Idempotency Strategy** -- unique constraints on observations, upsert logic
5. **Indexes** -- document existing indexes and rationale
6. **Migration Strategy** -- currently none (SQLAlchemy create_all), note
   future Alembic adoption
