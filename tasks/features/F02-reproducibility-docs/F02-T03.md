# F02-T03: ARCHITECTURE.md

**Wave:** 1
**Type:** docs
**Depends on:** F02-T01 (Makefile must exist so doc can reference `make` targets)
**Maps to AC:** AC7
**Status:** done

## User Story

As a developer or AI agent reading the project for the first time, I want a
single ARCHITECTURE.md that explains the system's layers, data flow, and key
design decisions so that I can orient myself without reading every source file.

## Objective

Create `docs/ARCHITECTURE.md` -- a living architecture document that describes
the layered structure, component responsibilities, data flow from HTTP to
SQLite, and extension points.

## Dev Notes

- This is the single most important doc for onboarding. Keep it concise but
  complete.
- Reference the actual module paths (`src/domain/`, `src/providers/`, etc.).
- Include a text-based layer diagram (ASCII or Mermaid code block).
- Mention the Provider abstraction (`CardSourceProvider` ABC) as the primary
  extension point.
- Reference ADR-0001 for framework choice, and note ADR-0002 will cover
  the web stack.

## Implementation Details

Create `docs/ARCHITECTURE.md` with these sections:

1. **Overview** -- one-paragraph summary of what the system does
2. **Layer Diagram** -- Mermaid code block showing:
   CLI -> Collectors -> Providers -> Parsers -> Domain Models -> Database
3. **Layers** -- one subsection per layer:
   - `src/cli/` -- Click CLI, entry point
   - `src/collectors/` -- orchestration (backfill, update, retry)
   - `src/providers/` -- HTTP clients per data source
   - `src/parsers/` -- HTML/JSON-LD/JS extraction
   - `src/domain/` -- pure dataclasses + ABC interfaces
   - `src/database/` -- SQLAlchemy models + repository
4. **Data Flow** -- step-by-step: discover sets -> list cards -> fetch details
   -> parse -> upsert
5. **Extension Points** -- how to add a new source (implement
   `CardSourceProvider`, add parser, register in collector)
6. **Key Design Decisions** -- link to `docs/adr/` for each ADR
7. **Diagrams** -- link to `docs/diagrams/` for Mermaid files
