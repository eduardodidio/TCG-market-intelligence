# T02 — Fix push-db stale frontend cache

## User Story
As a user, after the admin runs push-db, I should not need to manually logout and login to see updated data.

## Bug Analysis
After `/db/restore`:
- Backend calls `_invalidate_db_caches()` (disposes SQLAlchemy engine, clears singletons) ✓
- Frontend still holds stale user state in React memory and localStorage tokens
- API calls may fail (401) or return stale data from old DB

## Dev Notes
**Backend:** `src/api/routers/db_sync.py`
- Add a `db_version` counter (stored in a simple file or DB metadata table) incremented on each restore
- Add `X-DB-Version` response header to all API responses (middleware)
- OR simpler: add a `GET /api/v1/health/db-version` endpoint returning a timestamp/counter

**Frontend:** `frontend/src/api/client.ts`
- On each API response, check `X-DB-Version` header
- If version changed from last known, clear localStorage tokens and force page reload
- OR: periodic health check (every 60s) that detects DB version change

**Simplest approach:**
1. `/db/restore` writes a restore timestamp to a file/table
2. Add middleware that includes `X-DB-Version: <timestamp>` in all responses
3. Frontend `apiGet`/`apiPost` wrapper checks header, if changed → `localStorage.clear()` + `window.location.reload()`

## Testing
- Backend: test that /db/restore increments version, test middleware adds header
- Frontend: test that version change triggers reload (mock window.location)
