# F23-T10: Frontend Deck View Page (ownership overlay)

- **Wave:** 4
- **Status:** planned
- **Depends on:** F23-T08, F23-T09
- **Type:** frontend

## Description

Create the deck detail view page with the core UX feature: cards not in
the user's collection appear with a darkened overlay and tooltip.

### DeckView page (`frontend/src/pages/DeckView.tsx`)

- Fetches deck detail via `fetchDeck(id)` on mount.
- Header section:
  - Deck name (large)
  - Description (if present)
  - Summary stats: total cards, owned, missing, ownership %
  - Delete button (with confirmation)
  - Back link to `/decks`
- Card grid (same layout as MyCollection: `grid-cols-2 sm:3 md:4 xl:6`).

### DeckCardTile component (`frontend/src/components/DeckCardTile.tsx`)

Based on `CollectionCardTile` from `MyCollection.tsx`, with additions:

**For cards IN the collection (`in_collection: true`):**
- Normal display (same as collection card tile).
- Click navigates to `/collection/:collection_entry_id`.
- Quantity badge shows deck quantity.

**For cards NOT in the collection (`in_collection: false`):**
- Darkened overlay: CSS classes `opacity-50 brightness-50` on the card image,
  or a semi-transparent dark overlay div.
- Hover tooltip: "Card nao esta na sua colecao" (use `title` attribute or
  a custom tooltip component).
- Click navigates to `/cards/:card_id` if card_id exists, otherwise no
  navigation (or show a minimal info panel).
- Visual indicator: a small icon or badge indicating "not owned".

**Shared behavior:**
- Image loading with fallback (same pattern as CollectionCardTile).
- Price display in BRL.
- Set code + collector number badges.
- Quantity badge.

### Route registration

Add to `frontend/src/App.tsx`:
```tsx
const DeckView = lazy(() => import("./pages/DeckView").then(m => ({ default: m.DeckView })));
// Route: /decks/:id
```

### Delete flow

- Delete button shows confirmation dialog.
- On confirm: calls `deleteDeck(id)`.
- On success: navigate to `/decks`.
- On error: show error banner.
