# F23-T02: Domain Models (DeckSummary, DeckCardDetail)

- **Wave:** 0
- **Status:** planned
- **Depends on:** none
- **Type:** backend

## Description

Add domain dataclasses to `src/domain/models.py` for the deck feature.
These are pure data containers used across layers (API, service, frontend
contract).

**DeckSummary:**
- `id` -- int
- `name` -- str
- `description` -- str | None
- `total_cards` -- int (sum of quantities)
- `unique_cards` -- int (count of distinct entries)
- `owned_cards` -- int (cards present in user collection)
- `ownership_pct` -- float (0-100)
- `created_at` -- datetime
- `updated_at` -- datetime

**DeckCardDetail:**
- `id` -- int (deck_card row id)
- `name_en` -- str
- `set_code` -- str | None
- `collector_number` -- str | None
- `quantity` -- int
- `card_id` -- int | None
- `in_collection` -- bool
- `owned_quantity` -- int
- `collection_entry_id` -- int | None (user_collection.id if owned)
- `image_url` -- str | None
- `latest_price` -- float | None

Follow existing `@dataclass` patterns in `src/domain/models.py`.
