# F148-T03 — Enqueue price fetch from catalog (verify & improve)

**Status:** planned
**Wave:** 0
**Estimated effort:** S

## User Story

As a user browsing the catalog, I want to request a price fetch for any card
that doesn't have a price yet, and get clear feedback that the request was
queued and will be processed.

## Dev Notes

### Current State
- Per-card refresh button already exists in `CatalogCardTile` (line 165-198)
- It calls `refreshCardPrice(card.id)` → `POST /cards/{card_id}/refresh-price`
- Polling via `usePriceRequestPolling` already shows queued/completed/failed states
- The button appears on hover for all cards (priced or unpriced)

### Problem
- For unpriced cards, the "No price data" text makes the refresh button less
  discoverable — users may not realize they can request a price
- The button only shows on hover, which is not obvious for unpriced cards

### Solution
- For cards WITHOUT a price (`liga_price === null`), make the refresh button
  always visible (not just on hover) with a different style — e.g., a small
  "Buscar Preco" / "Fetch Price" text link or a more prominent refresh icon
- Add a subtle CTA text like "Clique para buscar" below "No price data"
- Keep the existing hover-only behavior for cards that already have prices

### Files to modify
1. `frontend/src/pages/CatalogPage.tsx` — CatalogCardTile, adjust visibility
   logic for refresh button when `liga_price === null`
