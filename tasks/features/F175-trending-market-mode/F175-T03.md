# F175-T03 — Market query includes direct Liga/manual prices

- **Wave:** 1
- **Type:** backend
- **Depends on:** F175-T01
- **Status:** planned

## User Story
As a user browsing Tendências with "minha coleção" unchecked, I want the market-wide ranking to use the Liga sweep prices, so that I see the market's real gainers and losers instead of an empty list.

## Objective
Create `src/database/trending_queries.load_market_trending_prices` (union of source_cards + direct
`liga_`/`manual_` observations, aggregated in SQL) and make `Repository.get_trending_price_data` delegate to it.

## Dev Notes
Veja `_brief/00-overview.md`, `_brief/01-root-cause.md` e `_brief/02-market-query.md`.
- The current code to copy for path 1 is in `src/database/repository.py:1070-1117`. The reference for the
  direct patterns is `get_trending_price_data_for_user` (lines 1119-1218), which stays unchanged.
- Models: `SourceCardRow`, `PriceObservationRow` in `src/database/models.py` (do NOT edit models.py).
  Index `ix_price_obs_card_date (source, external_id, observed_at)`.
- Liga sweep: `source="liga"`, `external_id="liga_{card_id}"` / `"liga_{card_id}_foil"`; manual:
  `source="manual"`, `external_id="manual_{card_id}"`. `liga_catalog_{set}_{num}` belongs to catalog
  source_cards and is already covered by path 1. It must NOT be parsed as a card_id.
- Postgres: `if "postgresql" in str(engine.url): session.execute(text("SET LOCAL statement_timeout = '12s'"))`.
- In `LIKE`, `_` is a wildcard: use `.like("liga\\_%", escape="\\")` or filter by regex in Python
  after `source IN ('liga','manual')`. The Python regex `^(?:liga|manual)_(\d+)(?:_foil)?$` is the
  final authority.
- Keep all prices as `Decimal(str(x))`.

## Implementation details
- New `src/database/trending_queries.py`:
  - `_EXTID_RE = re.compile(r"^(?:liga|manual)_(\d+)(?:_foil)?$")`
  - `parse_direct_card_id(external_id: str) -> int | None` (pure, testable)
  - `load_market_trending_prices(engine, period_days) -> dict[int, list[tuple[date, Decimal]]]`
    - path 1: current source_cards join
    - path 2: `select(external_id, observed_at, func.max(median_price)).where(source.in_(["liga","manual"]), observed_at >= cutoff, median_price.isnot(None)).group_by(external_id, observed_at)`
    - merge + same-date dedup (keep the highest) + sort ascending.
- `src/database/repository.py`: replace the BODY of `get_trending_price_data` with a delegation (plus the import). No other edits.

## Acceptance criteria
- [ ] A card with only `liga_{id}` observations shows up in the result with its dated series.
- [ ] `liga_{id}_foil` and `manual_{id}` map to the same `id`; same date → highest price.
- [ ] `liga_catalog_*` never turns into a card_id through path 2.
- [ ] Path 1 (source_cards) is preserved: existing tests for `get_trending_price_data` pass.
- [ ] Observations before the cutoff or with `median_price NULL` are ignored.
- [ ] `ruff check src/` clean.

## Test scenarios
- Happy: 5 days of `liga_42` rising → `{42: [5 points ascending]}`.
- Happy: source_cards MYP + liga for the same card → merged series, dedup per day.
- Edge: `liga_42` and `liga_42_foil` on the same day with different prices → the highest wins.
- Edge: `liga_catalog_mh3_12`, `liga_abc`, `manual_` → ignored by path 2.
- Boundary: observation exactly on `cutoff` is included; `cutoff - 1 day` is excluded.
- Error: `median_price` NULL ignored; empty DB → `{}`.
- Unit: `parse_direct_card_id` for every pattern above.
