## Retrospective Seeds

- **Pattern:** When a task explicitly says "fix the frontend only if a test reveals a bug"
  (F175-T05), the Developer correctly left the source untouched after tests passed, rather than
  making speculative "just in case" edits. Worth reinforcing as a norm — tests-first, code
  changes only when a test fails.
- **Role(s) affected:** developer
- **Lesson:** Keep encoding "test first, then decide if a code fix is needed" instructions
  explicitly in task files for changes suspected-but-unconfirmed to be buggy; it avoids
  unnecessary diffs and keeps review scope tight.

- **Pattern:** T07 used a file-backed SQLite DB instead of `:memory:` specifically because
  `TestClient` issues requests from a different thread than the test setup thread.
- **Role(s) affected:** developer, qa
- **Lesson:** Any new API-level test against FastAPI's `TestClient` + SQLite should default to a
  temp-file DB, not `:memory:`, to avoid a class of "works locally, flaky in CI" bugs from
  per-connection SQLite state.

Verdict: APPROVED
