## User Story
As a maintainer, I want API tests that run against a real (SQLite) database in both toggle modes, so that the empty-market regression cannot come back silently.

## Objective
Create `tests/unit/api/test_f175_trending_market_mode.py`, which exercises
`/api/v1/market/trending/{gainers,losers}` with and without `collection_only` over real data (not a mocked repo).

## Implementation details

- Autouse fixture that resets `market._trending_service` before/after each test.

## Acceptance criteria
- [ ] Market mode (without `collection_only`, authenticated or anonymous) returns the Liga-only card (AC1) and the MYP card (AC2).
- [ ] `collection_only=true` returns only the user's card (AC3).
- [ ] Repo patched to raise on the 1st call → `200` with `cards: []`; after that, the real repo → cards (AC4, end to end).
- [ ] `pytest tests/ --cov=src --cov-report=term-missing` fully green.

## Testing
- Framework: pytest + FastAPI TestClient over a real SQLite in-memory `Repository` (no mocked repo, except the one exception-injection case).
- Run: `pytest tests/unit/api/test_f175_trending_market_mode.py -v`.
- Then the full suite: `pytest tests/ --cov=src --cov-report=term-missing` and `ruff check src/`.

## Test scenarios
- Happy: gainers market → contains the rising Liga card; losers market → contains the falling card.
- Happy: collection → only the owned card; market → owned + not owned.
- Edge: anonymous user with `collection_only=true` → market mode (current router behavior).
- Edge: data only in `liga_catalog_*` without `source_cards` → does not break (ignored).
- Boundary: `period=7d` with points 8 days old → excluded; `limit=1` → 1 card.
- Error: invalid period → 422; repo exception → 200 empty, not cached.
