# F175-T02 — Read-only diagnostic script

- **Wave:** 0
- **Type:** infra
- **Depends on:** —
- **Status:** planned

## User Story
As a developer, I want a read-only script that measures each price source feeding market trending, so that the root-cause hypothesis is confirmed against real data before and after the fix.

## Objective
Create `scripts/diagnose_trending_f175.py`. It prints row/card counts per source path, timings, and
the ranked count for each period (7/30/90d), in market mode and optionally for a user.

## Dev Notes
Veja `_brief/00-overview.md` e `_brief/01-root-cause.md`.
- Follow the style of the existing `scripts/*.py` (e.g. `scripts/liga_collection_compare.py`).
  Use `src.config` to get the DB URL (it loads `.env` / `DATABASE_URL`, with fallback
  `sqlite:///tcg_market.db`) and build a `Repository` the same way the CLI does
  (see how `src/cli/` builds it).
- **Read-only**: only SELECTs. No writes, no cache invalidation, and no registration in `src/cli/main.py`
  (a shared file in the batch).
- Report:
  1. `repo.get_trending_price_data(days)` → cards, total points, elapsed seconds.
  2. Direct count: `price_observations` with `source IN ('liga','manual')` and
     `external_id LIKE 'liga\_%' / 'manual\_%'` (excluding `liga_catalog_%`) in the period →
     rows, distinct external_ids, elapsed.
  3. `compute_trending_score` + `rank_trending` over item 1 → number of gainers and losers.
  4. `--user-id N` (optional): the same with `get_trending_price_data_for_user`.
  After T03 lands, item 1 must include item 2; the script serves as the before/after check for AC5.
- Args: `--days 7 30 90` (default all), `--user-id`.

## Acceptance criteria

- [ ] It makes no writes to the DB (review: SELECT only).
- [ ] `summarize` is covered by a unit test.

## Testing
pytest; test in `tests/unit/scripts/test_diagnose_trending_f175.py` (create the folder with `__init__.py`
if the tests package needs it; check `tests/unit/` for the convention). Command:
`pytest tests/unit/scripts/test_diagnose_trending_f175.py`.

## Test scenarios
- Happy: price_data with 3 cards, 1 of them trending up → summary counts correctly.
- Edge: empty price_data → zeros, no exception.
- Boundary: card with exactly 3 dates (the `min_observations` limit) is counted in ranked.
- Error: invalid `--days` (0 or negative) → argparse error / exit code != 0.
