# F175-T05 — Frontend: regression test for the "minha coleção" toggle

- **Wave:** 1

- **Depends on:** F175-T01
- **Status:** planned

## User Story
As a user, I want unchecking "minha coleção" to reload both lists in market mode, so that I can switch between my collection and the whole market.

## Objective
Add Vitest tests that cover both toggle modes on the `Trending` page. Fix the frontend (minimal
change) only if a test reveals a bug.

## Implementation details
- New `frontend/src/pages/__tests__/TrendingCollectionToggle.test.tsx`.
- Mock `fetchTrending` so that it returns different cards per mode (e.g. "Owned Card" when
  `params.collection_only === "true"`, "Market Card" otherwise).
- Conditional: if you find a race condition or a missing refetch, fix it in `TrendingSection.tsx`/`useApi.ts` and record the cause in the completion note.

## Acceptance criteria
- [ ] Test: authenticated, default → `fetchTrending` called with `collection_only: "true"` for gainers and losers.
- [ ] Test: clicking the toggle → new calls without `collection_only` (or with `"false"`, if you chose the explicit param) and "Market Card" rendered in both sections.
- [ ] Test: unauthenticated → toggle absent, market mode.
- [ ] `cd frontend && npm test` and `npm run build` pass.

## Testing
- Framework: Vitest + @testing-library/react + user-event (already in the project).
- Run the new file: `cd frontend && npx vitest run src/pages/__tests__/TrendingCollectionToggle.test.tsx`.
- Then run the full suite `cd frontend && npm test` and `npm run build` to guarantee no regression in Trending/TrendingSection tests.

## Test scenarios
- Happy: default collection → uncheck → market list.
- Happy: uncheck and check again → back to "Owned Card".
- Edge: market returns `cards: []` → `EmptyState` with `trending.noTrending` (no crash).
- Error: `fetchTrending` rejects in market mode → `ErrorBanner` with retry; the retry calls the mock again.
- Race: a slow collection response that resolves after the market one must not overwrite the list (if `useApi` does not abort/ignore it, that is a bug to fix).
