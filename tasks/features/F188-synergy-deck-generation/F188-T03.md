# F188-T03: Integrate Synergy Scoring into Builder

- **Wave:** 1
- **Type:** backend
- **Depends on:** T01, T02
- **Status:** planned

## User Story

As a user generating a deck, I want the builder to select cards that
synergize with my commander's strategy, not just random cards that match
colors and rarity.

## Objective

Modify `src/decks/builder.py` to use the synergy scoring engine from T02
when selecting cards. Cards with higher synergy scores are preferred over
cards that merely match colors. The `oracle_text` column from T01 provides
the data source for analysis.

## Dev Notes

### Changes to `_query_candidates()`

Currently `_query_candidates()` queries CardRow but does NOT fetch
`oracle_text`. It must now include `oracle_text` in the SELECT so that
`_select_cards()` can score candidates.

No changes to the SQL WHERE clause needed -- the synergy scoring happens
in Python after candidates are fetched.

The function already returns `list[CardRow]` and `CardRow` will have
`oracle_text` after T01, so no return type change is needed.

### Changes to `_select_cards()`

Current signature:
```python
def _select_cards(
    candidates: list[CardRow],
    target_count: int,
    singleton: bool,
    budget_remaining: Decimal | None,
    prices: dict[int, Decimal],
    owned_ids: set[int],
    prioritize_owned: bool,
) -> list[dict]:
```

New signature adds `commander_keywords` and `synergy_weight`:
```python
def _select_cards(
    candidates: list[CardRow],
    target_count: int,
    singleton: bool,
    budget_remaining: Decimal | None,
    prices: dict[int, Decimal],
    owned_ids: set[int],
    prioritize_owned: bool,
    commander_keywords: CommanderKeywords | None = None,
    synergy_weight: float = 0.7,
) -> list[dict]:
```

**Sorting logic changes:**

Current sorting is: owned first, then price ascending.

New sorting: compute a composite score for each candidate:
```python
from src.decks.synergy import score_synergy, CommanderKeywords

def _candidate_sort_key(card: CardRow) -> tuple:
    syn_score = 0.0
    if commander_keywords and card.oracle_text:
        syn_score = score_synergy(
            card.oracle_text, card.type_line, commander_keywords
        )

    # Rarity bonus: mythic=0.3, rare=0.2, uncommon=0.1, common=0.0
    rarity_bonus = {"mythic": 0.3, "rare": 0.2, "uncommon": 0.1}.get(
        card.rarity or "", 0.0
    )

    # Composite: weighted blend of synergy and rarity
    composite = synergy_weight * syn_score + (1 - synergy_weight) * rarity_bonus

    owned_priority = 0 if card.id in owned_ids else 1
    price_sort = float(prices.get(card.id, Decimal("999999")))

    # Primary: owned first (if enabled), then composite DESC, then price ASC
    return (
        owned_priority if prioritize_owned else 0,
        -composite,      # negate so higher composite sorts first
        price_sort,
    )

candidates = sorted(candidates, key=_candidate_sort_key)
```

**Card dict output enrichment:**

Each card dict in the returned list gains a `synergy_score` field:
```python
syn_score = 0.0
if commander_keywords and card.oracle_text:
    syn_score = score_synergy(card.oracle_text, card.type_line, commander_keywords)

selected.append({
    ...existing fields...,
    "synergy_score": round(syn_score, 2),
})
```

### Changes to `generate_deck()`

1. After resolving `commander_card`, extract commander keywords:
   ```python
   from src.decks.synergy import extract_commander_keywords, CommanderKeywords

   commander_keywords: CommanderKeywords | None = None
   if commander_card and commander_card.oracle_text:
       commander_keywords = extract_commander_keywords(
           commander_card.oracle_text,
           commander_card.type_line or "",
       )
   ```

2. Pass `commander_keywords` and `params.synergy_weight` to every
   `_select_cards()` call.

3. Add `synergy_score` to the commander's own card dict entry (always 1.0
   since the commander is inherently 100% synergistic with itself).

`cards` is typed as `list[dict]`. But add a docstring note.

## Acceptance Criteria

1. `_select_cards()` accepts optional `commander_keywords` and `synergy_weight` parameters.
2. When `commander_keywords` is provided, candidates are sorted by composite score (synergy * weight + rarity * (1-weight)) instead of pure rarity.
3. When `commander_keywords` is None (non-commander formats), behavior is identical to current (backward compatible).
4. Each card dict in the generated deck includes `"synergy_score"` (float 0.0-1.0).
5. The commander's own card dict always has `synergy_score: 1.0`.
6. `GeneratedCardSchema` includes `synergy_score: float | None = None`.
7. Existing tests in `test_builder.py` still pass without modification.
8. Verify `npm run build` passes (GeneratedCard type in frontend will need synergy_score -- but this is handled in T06/T07 Wave 2; the backend can ship the field even if frontend doesn't consume it yet).

## Testing

### Test file

### Test scenarios

1. **Synergy sorting -- high-synergy card beats high-rarity card** -- given a mythic with synergy 0.0 and a common with synergy 0.8, synergy_weight=0.7, the common is selected first.
2. **Synergy sorting -- rarity breaks ties when synergy is equal** -- given two cards with synergy 0.5, the higher rarity card is selected first.
3. **Commander keywords extracted and passed** -- mock a commander with oracle_text "Whenever an Elf enters, draw a card" and type_line "Legendary Creature \u2014 Elf Druid", verify that generated deck cards include non-zero synergy_scores.
4. **No commander (non-singleton) -- backward compatible** -- generate a 60-card Modern deck with no commander, verify behavior matches pre-F188 (sorted by rarity+owned, synergy_score=0.0 on all cards).
5. **Commander without oracle_text -- graceful fallback** -- commander_card.oracle_text is None, verify generate_deck completes without error, synergy_score=0.0 on all cards.
6. **synergy_weight=0.0 reverts to pure rarity** -- verify that setting weight to 0 reproduces the old behavior.
7. **synergy_weight=1.0 ignores rarity** -- verify that setting weight to 1.0 sorts purely by synergy score.
8. **Commander card dict has synergy_score 1.0** -- the commander entry in all_cards always has synergy_score=1.0.
9. **Owned priority still works with synergy** -- when prioritize_owned=True, owned cards still sort before non-owned within the same composite score tier.
10. **Budget enforcement still works** -- synergy does not override budget checks.
