# F188-T05: Add synergy_weight to DeckBuildParams + API Endpoint

- **Wave:** 1
- **Type:** backend
- **Depends on:** T02
- **Status:** planned

## User Story

As a user building a deck, I want to control how much synergy influences
card selection versus rarity/power level, so that I can tune the builder
to my preference (e.g. "maximum synergy" vs "best cards regardless of
theme").

## Objective

Add a `synergy_weight` parameter to `DeckBuildParams` and expose it
through the deck generation API endpoint. This parameter controls the
blend between synergy score and rarity when the builder selects cards
(consumed by T03's integration in `_select_cards`).

## Dev Notes

### DeckBuildParams change

In `src/domain/models.py`:

```python
@dataclass
class DeckBuildParams:
    ...existing fields...
    synergy_weight: float = 0.7  # 0.0 = pure rarity, 1.0 = pure synergy
```

Default 0.7 means synergy contributes 70% and rarity 30% to the
composite selection score.

### DeckGenerateRequest schema change

In `src/api/schemas/decks.py`:

```python
class DeckGenerateRequest(BaseModel):
    ...existing fields...
    synergy_weight: float = Field(default=0.7, ge=0.0, le=1.0)
```

Validation: must be between 0.0 and 1.0 inclusive.

### DeckGenerateResponse schema change

In `src/api/schemas/decks.py`, add aggregate synergy info:

```python
class DeckGenerateResponse(BaseModel):
    ...existing fields...
    synergy_weight: float | None = None
    avg_synergy_score: float | None = None
```

### Endpoint change

In `src/api/routers/decks.py`, `generate_deck_endpoint()`:

```python
params = DeckBuildParams(
    ...existing params...,
    synergy_weight=request.synergy_weight,
)
```

And when building the response:
```python
# Compute average synergy from generated cards
synergy_scores = [
    c.get("synergy_score", 0.0)
    for c in generated.cards
    if c.get("synergy_score") is not None and c.get("type_line") and "Land" not in c["type_line"]
]
avg_synergy = sum(synergy_scores) / len(synergy_scores) if synergy_scores else None

data=DeckGenerateResponse(
    ...existing fields...,
    synergy_weight=request.synergy_weight,
    avg_synergy_score=round(avg_synergy, 3) if avg_synergy is not None else None,
)
```

### Frontend type change

In `frontend/src/types/api.ts`, update the interfaces:

```typescript
export interface DeckGenerateParams {
  ...existing fields...
  synergy_weight?: number;
}

export interface GeneratedCard {
  ...existing fields...
  synergy_score?: number | null;
}

export interface DeckGenerateResult {
  ...existing fields...
  synergy_weight?: number | null;
  avg_synergy_score?: number | null;
}
```

These type changes are consumed by T06 and T07 in Wave 2. Adding them
here ensures the types are available when the frontend tasks start.

## Acceptance Criteria

1. `DeckBuildParams` has `synergy_weight: float = 0.7`.
2. `DeckGenerateRequest` has `synergy_weight: float` with validation `ge=0.0, le=1.0`.
3. `DeckGenerateRequest` defaults synergy_weight to 0.7 when not provided.
4. Request with `synergy_weight: 1.5` returns 422 validation error.
5. Request with `synergy_weight: -0.1` returns 422 validation error.
6. `DeckGenerateResponse` includes `synergy_weight` and `avg_synergy_score`.
7. The generate endpoint passes `synergy_weight` from the request to `DeckBuildParams`.
8. The generate endpoint computes and returns `avg_synergy_score` from the generated card dicts.
9. TypeScript interfaces updated: `DeckGenerateParams`, `GeneratedCard`, `DeckGenerateResult`.
10. Verify `npm run build` passes after TypeScript type changes.
11. Existing generate endpoint tests still pass.
