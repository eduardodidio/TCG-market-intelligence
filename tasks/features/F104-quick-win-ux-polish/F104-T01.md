# F104-T01: Batch Price Trends API Endpoint

**Wave:** 0
**Depends on:** none
**Estimated effort:** small

## User Story

As a frontend developer, I need a lightweight API endpoint that returns
mini price history (last 7 days) for multiple cards in a single request,
so that sparkline charts can be rendered in card list views without
making N individual requests.

## Dev Notes

### Endpoint

```
GET /api/cards/price-trends?card_ids=1,2,3,4,5&days=7
```

Response:
```json
{
  "trends": {
    "1": { "prices": [10.5, 11.0, 10.8, 11.2, 11.5, 11.3, 11.8], "change_pct": 12.4 },
    "3": { "prices": [5.0, 5.2, 5.1], "change_pct": 2.0 },
    "5": { "prices": [], "change_pct": null }
  }
}
```

### Implementation

- Add to `src/api/routers/cards.py` (existing router)
- Query `price_observations` table grouped by card_id, ordered by
  observed_at DESC, limited to `days` parameter (default 7, max 30)
- Extract `median_price` from each observation
- Compute `change_pct` = ((last - first) / first) * 100
- Limit `card_ids` to max 50 per request (400 if exceeded)
- Use existing `Repository` methods — no new DB queries needed beyond
  a simple SELECT with WHERE card_id IN (...) and date filter

### Files to modify

- `src/api/routers/cards.py` — add `/price-trends` endpoint
- `frontend/src/api/cards.ts` — add `fetchPriceTrends()` function

### Constraints

- Read-only endpoint, no auth required (prices are public)
- Must return in <200ms for 50 cards (use single query, not N queries)

## Testing

- Unit test: endpoint returns correct shape with mock data
- Unit test: max 50 card_ids enforced (returns 400 for 51+)
- Unit test: cards with no observations return empty prices array
- Unit test: change_pct calculation (positive, negative, zero, null)
- Frontend: `fetchPriceTrends` returns typed response
