## Dev Notes

### CLI command: `import-purchases`

Add a Click command to the CLI that processes HTML files in bulk.

```python
@cli.command("import-purchases")
@click.argument("path", type=click.Path(exists=True))
@click.option("--user-id", required=True, help="User ID to match against")
@click.option("--dry-run", is_flag=True, help="Preview without applying")
@click.option("--overwrite", is_flag=True, help="Overwrite existing prices")
@click.option("--min-confidence", type=float, default=0.85,
              help="Minimum confidence to auto-apply")
def import_purchases(path, user_id, dry_run, overwrite, min_confidence):
    """Import purchase prices from HTML files."""
```

**Behavior**:
1. If `path` is a directory, glob all `*.html` files in it.
2. If `path` is a single file, process just that file.
3. Parse all files using `parse_purchase_html()`.
4. Load user's collection.
5. Run `match_purchases()` against the collection.
6. Filter matches by `min_confidence`.
7. If `--dry-run`:
   - Print summary table (card name, set, price, date, confidence, method).
   - Print unmatched items.
   - Print "Would apply N prices. Run without --dry-run to apply."
8. If not `--dry-run`:
   - Apply all filtered matches.
   - If `--overwrite` is False, skip entries with existing price.
   - Print applied/skipped summary.

### Known limitations for V1

- Liga "Meus Pedidos" file may not have all orders expanded. The user would
  need to manually expand orders in the browser before saving the HTML, or
  save individual order pages separately.
- Sealed products are skipped (correct behavior -- they're not individual
  cards).
- If a card was purchased multiple times (e.g. in 2 orders), only the most
  recent price is applied (the user can review in preview).

## Edge Cases

- Some HTML files may contain only sealed products (no cards) -- report
  "0 cards" for that file.
- User ID doesn't exist -- fail with clear error.
- Directory has no HTML files -- fail with "No HTML files found".
- Mix of Nerdz + Liga files in same directory -- auto-detected per file.
- Very old orders (2023) -- `acquired_at` should still be set correctly.
- File encoding: some files might be saved with BOM or different encoding --
  try UTF-8-sig, then latin-1.
