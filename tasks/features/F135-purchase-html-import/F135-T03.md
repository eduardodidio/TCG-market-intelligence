## User Story

As a user, I want to upload HTML files from my purchase history, see a preview
of which cards were found and matched to my collection, and then apply the
purchase prices in bulk, so that I can populate `acquisition_price` and
`acquired_at` without manually editing each card.

## Dev Notes

### Endpoint 1: `POST /api/v1/purchases/import-preview`

Accepts one or more HTML files, parses them, matches to user's collection,
and returns a preview report.

**Request**: `multipart/form-data`
- `files`: one or more HTML files (`.html` or `.htm`)
- `overwrite_existing`: boolean query param (default `false`) -- whether to
  include matches for entries that already have `acquisition_price`

**Response** (200):
```json
{
  "total_files": 2,
  "total_orders": 5,
  "total_items_parsed": 42,
  "total_items_matched": 38,
  "total_items_unmatched": 4,
  "total_sealed_skipped": 3,
  "matches": [
    {
      "id": "match_001",
      "card_name_parsed": "Fogo do Dragao / Dragon's Fire",
      "card_name_collection": "Dragon's Fire",
      "set_code_parsed": "AFR",
      "set_code_collection": "afr",
      "collector_number": "139",
      "quantity_parsed": 3,
      "quantity_collection": 3,
      "unit_price": "0.20",
      "order_date": "2025-08-25",
      "order_number": "#9117259",
      "store_name": "Nerdz Cards",
      "confidence": 1.0,
      "match_method": "exact",
      "collection_entry_id": 456,
      "already_has_price": false,
      "current_acquisition_price": null,
      "selected": true
    }
  ],
  "unmatched": [
    {
      "card_name_parsed": "Kit Inicial - O Senhor dos Aneis",
      "set_code_parsed": null,
      "unit_price": "199.90",
      "order_number": "#5282134",
      "skip_reason": "Sealed product (no set code)"
    }
  ],
  "warnings": [
    "Order #11809236 has no expanded card data (Liga format) -- skipped"
  ]
}
```

**Implementation**:
1. Read each uploaded file as UTF-8 text.
2. Call `parse_purchase_html(content, filename)` for each file.
3. Flatten all `ParsedPurchaseItem` from all orders.
4. Load user's collection entries via repository.
5. Call `match_purchases(parsed_items, collection_entries)`.
6. If `overwrite_existing=false`, filter out matches where
   `already_has_price=True`.
7. Generate stable `id` for each match (e.g.
   `f"match_{entry_id}_{order_number}"`).
8. Return structured preview.

**Errors**:
- 400 if no files uploaded
- 400 if file is not HTML (check content-type or extension)
- 400 if HTML format is unrecognized
- 422 if parsing fails with details

### Endpoint 2: `POST /api/v1/purchases/apply`

Applies selected matches to `user_collection`.

**Request** (JSON body):
```json
{
  "matches": [
    {
      "collection_entry_id": 456,
      "acquisition_price": "0.20",
      "acquired_at": "2025-08-25",
      "overwrite": false
    },
    {
      "collection_entry_id": 789,
      "acquisition_price": "9.75",
      "acquired_at": "2026-08-16",
      "overwrite": true
    }
  ]
}
```

**Response** (200):
```json
{
  "total_applied": 35,
  "total_skipped": 3,
  "applied": [
    {
      "collection_entry_id": 456,
      "card_name": "Dragon's Fire",
      "acquisition_price": "0.20",
      "acquired_at": "2025-08-25"
    }
  ],
  "skipped": [
    {
      "collection_entry_id": 789,
      "card_name": "Terror of the Peaks",
      "reason": "Already has price and overwrite=false"
    }
  ]
}
```

**Implementation**:
1. Validate all `collection_entry_id` values belong to the current user.
2. For each match:
   - If `overwrite=false` and entry already has `acquisition_price`, skip.
   - Otherwise, update `acquisition_price` and `acquired_at` via the
     existing PATCH logic or a batch update.
3. Use a single transaction for all updates (atomic).
4. Return summary of applied vs skipped.

**Errors**:
- 400 if `matches` is empty
- 403 if any `collection_entry_id` doesn't belong to current user
- 404 if any `collection_entry_id` doesn't exist

### No credit cost

This feature does not consume credits -- it only reads local HTML files and
updates existing collection data. No Liga or MYP API calls are involved.

## Edge Cases

- User uploads the same HTML file twice -- deduplication by order_number
  should prevent double-applying
- User uploads a mix of Nerdz and Liga files in one request
- Large Liga file (11K lines, ~1MB) -- parse time should be under 2 seconds
- File encoding issues -- try UTF-8 first, fall back to latin-1
- User has no collection entries -- all matches come back as unmatched
- Concurrent requests -- the transaction ensures atomicity but two
  simultaneous apply requests could conflict (acceptable for single-user)

## Testing

### Unit tests (`tests/api/test_import_purchases.py`)

1. **Preview with Nerdz HTML**: Upload a small Nerdz HTML snippet, verify
   parsed items and matches returned.
2. **Preview with Liga HTML**: Upload a small Liga HTML snippet with expanded
   order, verify parsing.
3. **Preview with unknown format**: Upload random HTML, verify 400 error.
4. **Preview with overwrite_existing=false**: Entries with existing price
   excluded from matches.
5. **Preview with overwrite_existing=true**: Entries with existing price
   included in matches.
6. **Apply happy path**: Apply 3 matches, verify all
   `acquisition_price`/`acquired_at` updated.
7. **Apply with overwrite=false skip**: Entry already has price, not
   overwritten, appears in `skipped`.
8. **Apply with overwrite=true**: Entry already has price, overwritten.
9. **Apply with wrong user**: `collection_entry_id` belongs to another user,
   returns 403.
10. **Apply empty matches**: Returns 400.
11. **Apply atomicity**: If one update fails, none are applied (transaction
    rollback).
12. **Multiple files**: Upload 2 files (1 Nerdz + 1 Liga), all items merged
    in preview.
13. **File too large**: Upload >5MB file, verify rejection.
14. **Sealed product filtered**: Nerdz order with sealed product shows it in
    `unmatched` with appropriate skip_reason.
