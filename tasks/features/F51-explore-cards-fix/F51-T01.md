# F51-T01 — Fix CardDetail Image Fallback

**Status:** done
**Wave:** 0
**Estimate:** small

## User Story

As a user browsing explore cards, when I click on a card whose primary
Scryfall image fails to load, I want to see a fallback image (by card
name) instead of a broken/hidden image, so I can still identify the card.

## Dev Notes

### What to change

**`frontend/src/pages/CardDetail.tsx`:**
- Add the same dual-fallback image logic that `CardTile.tsx` uses:
  1. Primary: `scryfallImageUrl(set_code, collector_number, "normal")`
  2. Fallback: `scryfallImageByName(name_en, "normal")` on primary error
  3. Placeholder: generic card-back SVG or icon on fallback error
- Add state: `imgError`, `fallbackError` (mirror CardTile pattern)
- The `onError` handler currently just hides the image — change it to
  try the name-based fallback first

### Files to modify
- `frontend/src/pages/CardDetail.tsx`

### Files to reference
- `frontend/src/components/CardTile.tsx` (existing fallback pattern)
- `frontend/src/utils/scryfall.ts` (scryfallImageByName)

## Testing

- Unit test: CardDetail renders placeholder when both URLs fail
