# F47-T02: Matcher name_pt comparison

## Status: done

## User Story

As a sync pipeline, I want the matcher to compare MYP search-result names
against both the English and Portuguese card names so that cards returned
under their PT name are still recognized as matches.

## Dev Notes

### File: `src/collection/matcher.py`

**Function:** `_try_name_match()` (lines 100-162)

Currently, line 114 normalizes only `entry.name_en` and line 119 compares
each result's `_normalize(r.name)` against that single value.

Change the comparison to check against both names:

1. Build a set of normalized entry names (lines ~114-115):
   ```python
   entry_names = {_normalize(entry.name_en)}
   if entry.name_pt:
       entry_names.add(_normalize(entry.name_pt))
   ```

2. Replace the equality check on line 119:
   ```python
   if _normalize(r.name) in entry_names:
       name_matches.append(r)
   ```

No other changes needed. SKU matching (tier 1) is unaffected. The
name-set and name-only tiers automatically benefit because `name_matches`
now includes PT-name hits.

## Testing

**File:** `tests/collection/test_matcher.py`

Update the `_entry` helper to accept an optional `name_pt` parameter.

New test cases:

1. `test_name_pt_match_when_en_misses` -- entry with `name_en="Abrade"`,
   `name_pt="Abrasao"`, search result with `name="Abrasao"`. Expects
   `status="matched"`, `confidence="name_only"` (or `name_set` if set matches).

2. `test_name_en_still_preferred` -- entry has both names, search result
   matches `name_en`. Expects match via `name_en` (existing behavior).

3. `test_name_pt_none_no_change` -- entry with `name_pt=None`. Expects
   same behavior as before (no regression).

4. `test_name_pt_ambiguous` -- search results match both `name_en` and
   `name_pt` to different results, multiple candidates. Expects `ambiguous`.

5. `test_name_pt_match_name_set` -- PT name matches AND set matches.
   Expects `confidence="name_set"`.

## Acceptance Criteria

- [ ] Matcher compares result names against both `name_en` and `name_pt`.
- [ ] When `name_pt` is None, behavior is identical to current (no regression).
- [ ] PT-name matches produce the same confidence tiers (name_set, name_only).
- [ ] All existing matcher tests pass unchanged.
- [ ] New tests cover PT match, EN preference, None case, ambiguous case.
