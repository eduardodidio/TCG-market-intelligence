# F47-T03: Sync pipeline PT fallback search

## Status: done

## User Story

As a user running collection sync, I want the system to automatically retry
the MYP search using the Portuguese card name when the English name yields
zero results, so that more of my cards get matched.

## Dev Notes

### File: `src/collectors/sync_collection.py`

**Function:** `_process_single_entry()` (lines 158-281)

Currently, line 170 searches only by `entry.name_en`:

```python
search_results = await provider.search_card(entry.name_en)
```

Replace with a fallback block after line 170:

```python
# Step 1: Search MYP by English name
search_results = await provider.search_card(entry.name_en)

# Step 1b: Fallback to Portuguese name if EN search returned nothing
used_pt_fallback = False
if not search_results and entry.name_pt:
    search_results = await provider.search_card(entry.name_pt)
    used_pt_fallback = bool(search_results)
    if used_pt_fallback:
        log.info(
            "pt_fallback_used",
            name_en=entry.name_en,
            name_pt=entry.name_pt,
            results=len(search_results),
        )
```

The rest of the function (match, fetch, store) proceeds unchanged with
whatever `search_results` were obtained.

Optionally, add `used_pt_fallback` to the `log.info("card_synced", ...)`
call on line 273 for end-to-end observability.

### SyncResult enhancement (optional but recommended)

No schema change needed. The existing `match_confidence` field already
captures how the match was made. The PT fallback is a search-level
concern, not a match-level concern, so structured logging is sufficient.

## Acceptance Criteria

- [ ] When `search_card(name_en)` returns empty and `name_pt` is not None,
      the pipeline retries with `search_card(name_pt)`.
- [ ] When `name_en` search returns results, no PT fallback occurs.
- [ ] When `name_pt` is None, no PT fallback occurs.
- [ ] PT fallback usage is logged with both names and result count.
- [ ] All existing sync tests pass without modification.
- [ ] New tests cover all four scenarios (fallback triggers, skipped-EN-ok,
