# F47-T01: Add name_pt to CollectionEntry + converter

## Status: done

## User Story

As a developer, I need the `CollectionEntry` dataclass to carry the
Portuguese card name so that downstream code (matcher, sync pipeline)
can use it for search and comparison.

## Dev Notes

### 1. CollectionEntry dataclass

**File:** `src/collection/matcher.py`, lines 10-21

Add an optional `name_pt` field after `name_en`:

```
name_pt: str | None = None
```

This is a backwards-compatible change -- all existing callers that omit
`name_pt` will get `None`.

### 2. Converter

**File:** `src/collection/converter.py`, lines 9-19

In `row_to_collection_entry()`, pass `row.name_pt` to the new field:

```python
return CollectionEntry(
    set_code=row.set_code,
    collector_number=row.collector_number,
    name_en=row.name_en,
    name_pt=row.name_pt,       # <-- add this
)
```

`UserCollectionRow.name_pt` already exists in the DB model
(`src/database/models.py`, line 29).

## Testing

**File:** `tests/collection/test_converter.py`

1. Update `_make_row` helper to accept `name_pt` parameter (default `None`).
2. Update `test_happy_path_full_row` to assert `entry.name_pt`.
3. Add `test_name_pt_passed_through` -- row with `name_pt="Abrasao"` produces
   entry with `name_pt="Abrasao"`.
4. Add `test_name_pt_none` -- row without `name_pt` produces `entry.name_pt is None`.

## Acceptance Criteria

- [ ] `CollectionEntry` has `name_pt: str | None = None` field.
- [ ] `row_to_collection_entry()` maps `row.name_pt` to `entry.name_pt`.
- [ ] All existing tests pass without modification (field is optional).
- [ ] New converter tests cover `name_pt` presence and absence.
