# F47 Tech Lead Review -- 2026-08-22

## Summary

F47 adds Portuguese-name fallback to the MYP card search pipeline. When an
English name search yields zero results and a Portuguese name (`name_pt`) is
available on the collection entry, the system retries with the PT name.

## Architecture Assessment

**Rating: PASS**

### Design Decisions

1. **CollectionEntry dataclass extension** -- Adding `name_pt: str | None = None`
   is fully backwards-compatible. All existing callers that omit `name_pt`
   default to `None`, preserving existing behavior.

2. **Matcher name-set approach** -- Building a `set[str]` of normalized entry
   names (EN + PT) and using `in` membership is clean and O(1) per comparison.
   No performance concern since the set has at most 2 elements.

3. **Sync pipeline fallback** -- The fallback is correctly placed after the
   initial search and before matching. The `used_pt_fallback` flag + structured
   logging provides observability without schema changes to `SyncResult`.

### Layering

- **matcher.py** -- Pure function, no side effects. Correctly extended.
- **converter.py** -- Single source of truth for `UserCollectionRow -> CollectionEntry`.
  Maps `name_pt` alongside `name_en`.
- **sync_collection.py** -- Orchestration layer. Fallback search is a search-level
  concern, correctly placed before the match step.

### Risk Assessment

- **LOW**: No database schema changes needed (`UserCollectionRow.name_pt` already
  exists).
- **LOW**: All existing tests pass unchanged. The `name_pt` field defaults to
  `None`, so callers that do not provide it are unaffected.
- **LOW**: The fallback adds at most one additional HTTP request per unmatched card.
  Rate limiting and concurrency controls are already in place.

## Test Coverage

- **Converter tests**: 3 new tests covering `name_pt` presence, absence, and
  both-None case.
- **Matcher tests**: 6 new tests covering PT match, EN preference, None case,
  ambiguous case, name_set via PT, and only-PT-no-EN case.
- **Sync pipeline tests**: 5 new tests covering fallback trigger, EN-success skip,
  None-PT skip, fallback-still-unmatched, and both-empty cases.
- All 1663 backend tests pass.

## Verdict

Clean, minimal implementation. No overengineering. Follows established patterns.
Approved.
