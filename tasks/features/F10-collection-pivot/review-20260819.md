## 1. Architecture

The implementation respects the established layering:

- **Domain models** (`src/domain/models.py`): New `MypSearchResult`, `SyncError`, `SyncResult`, and `SyncSummary` dataclasses live in the domain layer with zero DB/framework imports. Clean separation.
- **Matcher** (`src/collection/matcher.py`): Pure functions. No DB calls, no network calls, no side effects. The 4-level priority chain (SKU exact > name+set > name only > ambiguous) is well-documented and easy to test. This is the highest-quality module in the feature.
- **Provider** (`src/providers/myp/provider.py`): `search_card()` method follows the existing pattern -- async, rate-limited, returns domain objects.
- **Parser** (`src/parsers/myp.py`): `parse_search_results()` and updated `parse_sku()` follow existing patterns. Defensive parsing with empty-list fallback on malformed input.
- **Database** (`src/database/backup.py`, `src/database/cleanup.py`, `src/database/repository.py`): Backup uses `sqlite3.backup()` correctly. Cleanup has proper safety guards (refuses empty collection, automatic backup, single transaction). New repository methods (`link_collection_entry`, `get_all_collection_entries`) are minimal and focused.
- **Orchestrators** (`src/collectors/match_report.py`, `src/collectors/sync_collection.py`): Follow the established backfill pattern -- async with semaphore concurrency, structured logging, provider cleanup in `finally`.
- **CLI** (`src/cli/main.py`): New commands (`match-report`, `db-backup`, `db-cleanup`, `sync-collection`) use lazy imports and follow the Click pattern of the existing commands.
- **API** (`src/api/routers/collection.py`): `POST /collection/sync` follows the existing `POST /collect/backfill` pattern with async job tracking and API key auth.
- **Frontend**: Dashboard, CardDetail, Cards, and MarketMovers pages updated with collection-aware logic and Scryfall images. No new framework dependencies.

**Verdict on architecture: Sound.** Layering is respected. No circular imports. No framework coupling in domain/matcher.

## 2. Findings

### IMPORTANT

#### 2.1 `_row_to_entry` duplicated across two modules

The function `_row_to_entry(row: UserCollectionRow) -> CollectionEntry` is identically defined in both:
- `src/collectors/match_report.py` (line 40)
- `src/collectors/sync_collection.py` (line 22)

Both convert a `UserCollectionRow` to a `CollectionEntry`. This should be extracted to a shared location (e.g., `src/collection/matcher.py` or a new `src/collection/utils.py`) to avoid divergence.

**Severity: IMPORTANT** -- duplication across modules that will evolve independently risks silent bugs if one copy is updated and the other is not.

#### 2.2 `collection_summary` endpoint bypasses Repository with raw SQLAlchemy

In `src/api/routers/collection.py` lines 105-133, the `collection_summary` endpoint imports `sqlalchemy` and `src.database.models` inline and opens a raw `Session` to compute total portfolio value:

```python
from sqlalchemy import select
from sqlalchemy.orm import Session
from src.database.models import UserCollectionRow

with Session(repo.engine) as session:
    linked_rows = session.execute(...)
```

This violates the layering pattern where the API layer should only talk to `Repository`, never open raw sessions. The total value calculation should be a `Repository` method (e.g., `get_collection_total_value(user_id)`) that encapsulates the query.

**Severity: IMPORTANT** -- architecture violation that sets a bad precedent. The API layer should remain a thin adapter over Repository methods.

#### 2.3 `BASE_URL` unused in `sync_collection.py`

Line 19 of `src/collectors/sync_collection.py` defines `BASE_URL = "https://mypcards.com"` but it is never referenced anywhere in the file. Dead code.

**Severity: IMPORTANT** -- dead code that could mislead future developers into thinking URL construction happens in this module rather than in the provider.

### MINOR

#### 2.4 `FAKE_USER_ID` hardcoded in API router

`src/api/routers/collection.py` defines `FAKE_USER_ID = "eduardo"` and uses it in 7 places. While the PRD explicitly states single-user support (and the ADR documents this as a known limitation), this constant should be sourced from an environment variable or config (e.g., `os.environ.get("TCG_USER_ID", "eduardo")`). This avoids hardcoding personal data in source code and makes it trivial to change if someone else clones the repo.

**Severity: MINOR** -- documented trade-off, but a one-line fix for better practice.

#### 2.5 Cleanup observation counting uses N+1 queries

In `src/database/cleanup.py` lines 132-157, the method counts observations to be deleted by iterating over `source_card_refs` one-by-one and issuing a `SELECT COUNT(*)` per source card. With hundreds of source cards, this becomes a performance concern. A single query with `IN` clause or a join would be more efficient. The same pattern appears in the actual deletion loop (lines 238-267).

**Severity: MINOR** -- acceptable for current data volumes (~548 cards), but worth noting for future scaling.

#### 2.6 `_pct` formatting has leading space on small numbers

In `src/collectors/match_report.py` line 53, `_pct` returns `" 0.0%"` (with a leading space) when `total == 0`. The `%5.1f` format spec pads to 5 characters total which is intentional for alignment in the report output, but the special case for `total == 0` returns an inconsistent format string. This is cosmetic and only affects the report's visual alignment.

**Severity: MINOR** -- cosmetic formatting inconsistency.

#### 2.7 `README.md` "Future" section contains stale entry

The "Future" section at the bottom of `README.md` (line 386) still mentions "Frontend dashboard" as a future item, even though the frontend has been shipping since F07.

**Severity: MINOR** -- stale documentation.

## Retrospective Seeds

Patterns worth propagating to `memory/agent-learnings/`:

1. **Pure matcher modules are the gold standard.** `src/collection/matcher.py` has zero dependencies on DB, network, or framework -- only domain models. This makes it trivially testable (26 tests, 100% coverage) and portable. Future features with matching/scoring logic should follow this pattern: pure functions that take domain objects in and return domain objects out.

2. **Integration tests with real DB + mocked provider catch bugs that unit tests miss.** The 9 integration tests in `test_sync_integration.py` use a real in-memory SQLite database but mock only the MYP provider. This caught the resume/dedup scenario that pure unit tests (which mock both Repository and Provider) cannot verify. For any feature with a multi-step pipeline, include at least one integration test tier that exercises real DB state.

3. **Safety guards on destructive operations prevent data loss.** Cleanup refuses to run with an empty collection, creates an automatic backup before deletion, and runs dry-run by default. This three-layer safety model (guard + backup + dry-run) should be the standard for any feature that deletes data.

4. **Avoid inline imports and raw session access in API routers.** The `collection_summary` endpoint accessed SQLAlchemy directly from the router layer, bypassing Repository. This breaks the layering pattern and is harder to test. API routers should be thin adapters that call Repository methods only.

5. **Extract shared helpers immediately when two modules copy the same function.** The duplicated `_row_to_entry` function across match_report and sync_collection was a minor oversight that introduces maintenance risk. When a helper is needed in two places, factor it out on the first copy -- do not let the second copy happen.
