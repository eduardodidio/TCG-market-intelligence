### Migration script
```python
"""One-time migration: normalize set_code to lowercase in cards and source_cards."""

import sqlite3
import sys

def normalize(db_path: str) -> None:
    conn = sqlite3.connect(db_path)
    cursor = conn.cursor()

    # cards table
    cursor.execute("UPDATE cards SET set_code = LOWER(set_code) WHERE set_code != LOWER(set_code)")
    cards_updated = cursor.rowcount

    # source_cards table
    cursor.execute("UPDATE source_cards SET set_code = LOWER(set_code) WHERE set_code != LOWER(set_code)")
    source_cards_updated = cursor.rowcount

    conn.commit()
    conn.close()

    print(f"Normalized {cards_updated} cards, {source_cards_updated} source_cards")

if __name__ == "__main__":
    db_path = sys.argv[1] if len(sys.argv) > 1 else "tcg_market.db"
    normalize(db_path)
```

- `parse_sku()` currently returns `parts[1].upper()` -- change to `parts[1].lower()`

  - MYP SKU parsing: lowercase (after this fix)
  - DB cards table: lowercase (after migration)
  - DB source_cards table: lowercase (after migration)
  - Frontend Scryfall URLs: already call `.toLowerCase()` -- no change needed
- Remove the `func.lower()` call in `importer.py` line 79 since it's no longer needed after normalization

### Edge cases
- Cards with NULL set_code -- skip in migration (already NULL)
- Unique constraint on `(game, set_code, collector_number)` in cards table -- lowercasing could create duplicates if both "DMR" and "dmr" exist. The migration must check for and handle this (currently only uppercase exists, so this is theoretical)
