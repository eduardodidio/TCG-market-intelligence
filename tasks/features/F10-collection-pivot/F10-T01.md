**Wave:** 0

## User Story
As a developer, I want a reusable function that searches MYP for a card by name so that the sync pipeline can discover MYP product pages for collection cards.

## Dev Notes

### What to implement
Add a `search_card` method to `MypCardsProvider` that calls the MYP search API and returns parsed results.

### Files to modify
- `src/providers/myp/provider.py` -- add `search_card(term: str) -> list[MypSearchResult]` method
- `src/parsers/myp.py` -- add `parse_search_results(json_text: str) -> list[MypSearchResult]`
- `src/domain/models.py` -- add `MypSearchResult` dataclass

### Key technical details
- MYP search endpoint: `GET /produto/search?marca=magic&term={query}`
- Returns a JSON array, each element has at least: `id`, `nome` (PT name), `slug`
- The response format needs to be verified empirically -- the brief says `{id, nome, slug, ...}` but there may be additional fields (set info, SKU, etc.)
- Use the existing `_fetch()` method for rate limiting and retry
- The response is JSON, not HTML -- need to handle this differently from `_fetch()` which returns HTML text. Options:
  1. Add a `_fetch_json()` method that returns `dict | list` instead of `str`
  2. Or just use `_fetch()` and parse JSON in the parser
- Prefer option 2 (parse JSON in parser) to keep provider thin and parser testable

### Edge cases
- Empty search term should return empty list (do not call API)
- Search returns no results -- return empty list
- Search returns non-JSON response (rate limited, error page) -- raise or return empty list with warning
- Card names with special characters (accents, apostrophes, hyphens) -- URL-encode the term
