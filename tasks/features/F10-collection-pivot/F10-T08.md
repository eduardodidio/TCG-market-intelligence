## User Story
As a user of the web interface, I want to trigger a collection sync via the API, so that I can sync my collection without using the terminal.

## Dev Notes

### What to implement
Add a `POST /api/v1/collection/sync` endpoint that triggers the collection sync as an async background job, following the same pattern as the existing `POST /api/v1/collect/backfill` endpoint.

### Files to modify
- `src/api/routers/collection.py` -- add `POST /sync` endpoint
- `src/api/schemas/collection.py` -- add `SyncRequest` schema (or reuse `collect.py` schemas)

### Implementation
```python
@router.post("/sync", response_model=ApiResponse[JobStatus])
async def trigger_sync(
    request: SyncRequest,
    repo: Repository = Depends(get_db),
    _auth: None = Depends(verify_api_key),
) -> ApiResponse[JobStatus]:
    """Trigger a collection sync as a background job."""
    job_id = job_tracker.start("collection_sync", {
        "limit": request.limit,
        "history_days": request.history_days,
        "force": request.force,
    })

    asyncio.create_task(_run_sync_job(
        job_id,
        limit=request.limit,
        history_days=request.history_days,
        force=request.force,
    ))

    data = JobStatus(
        job_id=job_id,
        status="started",
        message="Collection sync started",
    )
    return success_response(data=data)
```

### SyncRequest schema
```python
class SyncRequest(BaseModel):
    limit: int | None = None
    history_days: int = 365
    force: bool = False  # if True, re-sync already-linked entries
```

### Key technical details
- Uses `verify_api_key` dependency (same auth pattern as `collect/backfill`)
- Uses `job_tracker` singleton for status tracking
- The background task calls `run_sync_collection()` from the orchestrator
- Reuse `JobStatus` schema from `src/api/schemas/collect.py`
- Import `verify_api_key` from `src/api/deps` (already exists)

### Edge cases
- Sync already running -- the current job tracker allows concurrent jobs. This is fine for now; a future feature could add a lock.
- API server restarts during sync -- jobs are in-memory, they'll be lost. This is the same behavior as existing backfill/update jobs.
