## User Story
As a developer, I want end-to-end integration tests for the collection sync pipeline so that future changes don't break the critical path from collection import to price data display.

## Dev Notes

### What to implement
Integration tests that exercise the full sync pipeline with a real in-memory SQLite database and mocked MYP provider responses.

### Files to create
- `tests/collectors/test_sync_integration.py` -- end-to-end sync pipeline tests
- `tests/api/test_collection_sync_api.py` -- API endpoint integration tests
- `tests/fixtures/myp_search_responses.py` -- fixture data for MYP search results

### Test scenarios

#### 1. Full sync happy path
```
Setup:
  - In-memory SQLite DB with user_collection entries (3-5 cards)
  - Mocked provider.search_card returns matching results
  - Mocked provider.get_card_details returns card data
  - Mocked provider.get_price_history returns price data

Assert:
  - cards table has N rows matching collection
  - source_cards table has N rows linked to cards
  - price_observations has data for each card
  - user_collection entries have card_id set (not NULL)
```

#### 2. Partial match (some cards not found on MYP)
```
Setup:
  - 5 collection entries
  - Provider returns results for 3, empty for 2

Assert:
  - 3 cards synced, 2 unmatched
  - SyncSummary.matched == 3, SyncSummary.unmatched == 2
  - Unmatched entries still have card_id == NULL
```

#### 3. Resume after partial sync
```
Setup:
  - Run sync for 3 cards (limit=3)
  - Run sync again with skip_matched=True

Assert:
  - Second run only processes unlinked entries
  - No duplicate cards or observations
```

#### 4. Error recovery
```
Setup:
  - Provider raises exception for 1 card, returns data for others

Assert:
  - Sync completes (does not abort)
  - Error count in summary matches
  - Other cards are synced correctly
```

#### 5. Cleanup + sync integration
```
Setup:
  - Pre-populate DB with cards NOT in collection
  - Run cleanup
  - Run sync

Assert:
  - Non-collection cards are gone
  - Collection cards have price data
  - Dashboard stats endpoint returns collection-sized data
```

#### 6. API endpoint test
```
Setup:
  - TestClient with FastAPI app
  - Mock sync function

Assert:
  - POST /api/v1/collection/sync returns 200 with job_id
  - POST without auth returns 401 (when TCG_API_KEY is set)
```

### Key technical details
- Use `sqlite:///:memory:` for test database
- Mock `MypCardsProvider` at the method level (mock `search_card`, `get_card_details`, `get_price_history`)
- Use `pytest-asyncio` for async test functions
- Fixture data should be realistic but minimal (3-5 cards)
- Reuse fixture patterns from existing tests (see `tests/database/test_repository_api.py`)

### Edge cases to test
- Collection with duplicate entries (same card, different quality) -- should create one CardRow, both linked
- Card with no price history (empty list from provider) -- should still create CardRow and link
- Set code normalization verified in integration context (lowercase throughout)
