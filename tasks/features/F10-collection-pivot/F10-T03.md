## User Story
As a collector, I want to run a dry-run match report that shows which of my collection cards can be found on MYP, so that I can review coverage before committing to a DB cleanup and sync.

## Dev Notes

### What to implement
A CLI command `match-report` that:
1. Reads all `user_collection` entries from the DB
2. For each entry, calls `MypCardsProvider.search_card(name_en)`
3. Runs the matcher to determine match status
4. Outputs a summary report to stdout
5. Optionally writes detailed results to a JSON file

### Files to modify
- `src/cli/main.py` -- add `match-report` command

### Files to create
- `src/collectors/match_report.py` -- async orchestrator for the match report

### CLI interface
```
python -m src.cli.main match-report [OPTIONS]

Options:
  --db TEXT          Database URL [default: sqlite:///tcg_market.db]
  --limit INT       Max cards to process (for testing)
  --delay FLOAT     Seconds between requests [default: 1.0]
  --concurrency INT Max concurrent searches [default: 3]
  --output PATH     Write detailed JSON report to file
```

### Report output format
```
=== Collection Match Report ===
Total collection cards: 548
  Matched (SKU exact):  320 (58.4%)
  Matched (name+set):    85 (15.5%)
  Ambiguous:             43 ( 7.8%)
  Unmatched:            100 (18.2%)
===============================

Top unmatched sets:
  prm (28 cards) -- Promos
  tsb (12 cards) -- Time Spiral "Timeshifted"
  ...
```

### Key technical details
- Reuse `asyncio.Semaphore(concurrency)` pattern from `backfill.py`
- This is a READ-ONLY operation -- no DB writes, no mutations
- Must handle the ~548 cards with rate limiting (~2s between requests, ~18 min total)
- The `--limit` flag is essential for quick iteration during development
- Progress logging with structlog (card N of M)

### Edge cases
- Collection entries without `name_en` -- skip and count as "no name" in report
- MYP search API returns 429 or 403 -- retry logic from provider handles this
- Very slow execution (548 cards x 2s) -- the `--limit` flag allows testing with small batches
