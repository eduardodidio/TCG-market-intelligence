## 5. Saruman Conditions Verification

### Condition #1: Dry-run match report runs BEFORE any DB cleanup

**Status: SATISFIED**

Evidence:
- The `match-report` CLI command (`src/cli/main.py` line 191) and `run_match_report` orchestrator (`src/collectors/match_report.py`) perform ZERO database writes. The `test_no_db_writes` test explicitly asserts that `upsert_card`, `upsert_source_card`, `insert_price_observations`, and `insert_error` are never called.
- The wave structure enforces ordering: Wave 0 (match report) ships before Wave 1 (cleanup). The CLI provides separate commands (`match-report` vs `db-cleanup`) so the user explicitly invokes each step.
- The match report reads `user_collection` entries and searches MYP, but never mutates the database.

### Condition #2: SQLite backup before any deletion

**Status: SATISFIED**

Evidence:
- `cleanup_non_collection_data` in `src/database/cleanup.py` (line 206-208) calls `backup_database(db_path)` BEFORE entering the deletion transaction (line 212). The backup call is outside the deletion `with Session(...)` block.
- The function refuses to run if `skip_backup=False` (default) and backup fails.
- Test `TestCleanupWithBackup::test_creates_backup_before_delete` verifies `backup_database` is called before deletion occurs.
- The empty-collection safety check (line 103) prevents accidental deletion of all data.
- Three-layer safety model: (1) empty collection guard, (2) automatic backup, (3) dry-run default via CLI.

### Condition #3: Frontend gracefully handles empty data post-cleanup

**Status: SATISFIED**

Evidence:
- **Dashboard with zero collection summary**: `Dashboard.test.tsx::renders gracefully when collection summary returns zero values` -- renders collection KPIs with zeros, shows "0%" coverage. No crash.
- **Dashboard with zero market stats**: `Dashboard.test.tsx::renders gracefully when market stats returns zero` -- shows empty state message: "Import your collection and sync with MYP to see market data here." Movers section shows: "Not enough price history for movers. Run a sync and check back."
- **Dashboard with failed collection summary endpoint**: `Dashboard.test.tsx::shows collection empty state when summary endpoint fails` -- shows "Import your collection and sync with MYP to see your stats here." Market section continues to work independently.
- **CardDetail with null set_code**: `CardDetail.test.tsx::does not render image when set_code is null` -- no image rendered, no crash.
- **CardDetail 404**: `CardDetail.test.tsx::shows updated 404 message with sync hint` -- displays "Card not found. It may not have been synced yet."
