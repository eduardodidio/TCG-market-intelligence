# F10-T09 -- Dashboard Collection-Aware Stats + Cards Page Defaults

**Wave:** 4
**Status:** done
**Estimate:** M
**Depends on:** F10-T06

## User Story
As a collector, I want the Dashboard to show my collection's stats (total collection value, linked vs. unlinked cards, collection coverage) instead of generic market stats, so that the platform feels like MY personal tracker.

## Dev Notes

### What to implement
1. **Dashboard**: Replace or augment the generic "Market Overview" KPIs with collection-aware stats
2. **Cards page**: Show collection cards by default (or add a toggle between "My Cards" and "All Cards")
3. **Empty states**: All pages must gracefully handle the scenario where DB has been cleaned up and only collection-linked cards remain

### Files to modify
- `frontend/src/pages/Dashboard.tsx` -- add collection summary KPIs
- `frontend/src/pages/Cards.tsx` -- default to showing collection cards, or add filter
- `frontend/src/api/collection.ts` -- ensure summary endpoint is called on Dashboard
- `frontend/src/types/api.ts` -- add any new types if needed

### Dashboard changes
Current KPIs:
1. Total Cards (generic)
2. Total Observations (generic)
3. Average Price (generic)
4. Data Range (generic)

New KPIs (replace or add a second row):
1. **Collection Cards** -- `summary.total_unique` (from collection summary)
2. **Total Copies** -- `summary.total_cards` (quantity sum)
3. **Est. Collection Value** -- `summary.total_value` (sum of latest prices x qty)
4. **Coverage** -- `summary.linked_count / summary.total_unique * 100`% (% of collection with price data)

Keep the existing Market Overview section (movers, etc.) below the collection KPIs. The collection KPIs become the primary hero section.

### Cards page changes
Two approaches (choose the simpler one):
- **Option A (preferred)**: Add a toggle/tab at the top: "My Collection" | "All Cards". Default to "My Collection" which filters to cards where the card_id is in the user_collection table. "All Cards" shows everything in the cards table.
- **Option B**: Just keep the existing Cards page as-is, since post-cleanup the cards table only contains collection cards anyway. Add a subtitle "Showing cards from your collection" if the cards table count matches the collection linked count.

Recommend Option B for simplicity, since after cleanup the cards table IS the collection. Just update the empty state message.

### Empty state updates
- **Dashboard**: If market stats return zero cards, show a friendly message like "Import your collection and sync with MYP to see market data here."
- **Cards page**: If no cards found, show "No cards with price data yet. Run a collection sync to fetch prices."
- **Market Movers**: If no movers data, show "Not enough price history for movers. Run a sync and check back."

### Key technical details
- The Dashboard already fetches `fetchMarketStats()` -- keep this, it still works post-cleanup
- Add `fetchCollectionSummary()` call to Dashboard (already exists in `api/collection.ts`)
- The collection summary endpoint already calculates `total_value` for linked cards
- No new API endpoints needed -- reuse existing collection summary + market stats

### Edge cases
- No collection imported yet -- summary shows zeros, empty states are helpful
- Collection imported but not synced -- linked_count is 0, coverage is 0%
- All cards synced -- coverage is ~100% (some may be unmatched on MYP)
- Market stats endpoint returns no data -- graceful fallback, don't crash
