## User Story
As a collector, I want to back up my database and then remove cards/prices that are not in my collection, so that the platform only tracks and displays MY cards, not random set data.

## Dev Notes

### What to implement
1. A DB backup utility that creates a timestamped copy of the SQLite file using `sqlite3.backup()` API
2. A cleanup function that deletes rows from `cards`, `source_cards`, and `price_observations` where the card is NOT in the user's collection

### Files to create
- `src/database/backup.py` -- backup utility
- `src/database/cleanup.py` -- cleanup logic

### Files to modify
- `src/cli/main.py` -- add `db-backup` and `db-cleanup` CLI commands

### Backup implementation
```python
import sqlite3
import shutil
from pathlib import Path
from datetime import datetime

def backup_database(db_path: str, backup_dir: str = "backups") -> Path:
    """Create a timestamped backup of the SQLite database.

    Uses sqlite3.backup() for a consistent snapshot.
    Returns path to the backup file.
    """
    src = sqlite3.connect(db_path)
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    backup_path = Path(backup_dir) / f"tcg_market_{timestamp}.db"
    backup_path.parent.mkdir(parents=True, exist_ok=True)

    dst = sqlite3.connect(str(backup_path))
    src.backup(dst)
    dst.close()
    src.close()

    return backup_path
```

### Cleanup logic
1. Get all `(set_code, collector_number)` pairs from `user_collection` for this user
2. Find `cards` rows where `(LOWER(set_code), collector_number)` is NOT in that set
3. For each card to delete:
   a. Delete associated `price_observations` (via source_cards.external_id)
   b. Delete associated `source_cards` (via card_id)
   c. Delete the `cards` row
4. Also delete orphan `source_cards` and `price_observations` that have no corresponding card
5. Log counts of deleted rows for each table
6. Run `VACUUM` after cleanup to reclaim space

### CLI commands
```
python -m src.cli.main db-backup [--db-path PATH]
python -m src.cli.main db-cleanup [--db TEXT] [--dry-run] [--no-backup]
```

### Key technical details
- `db-cleanup` MUST call `db-backup` first (unless `--no-backup` is explicitly passed)
- Cleanup uses the DB URL from environment/default, not the file path
- The `--dry-run` flag on cleanup should print what WOULD be deleted without actually deleting
- Use a single transaction for the cleanup to ensure atomicity
- The backup file should be stored in `backups/` directory (gitignored)

### Edge cases
- DB file does not exist -- error with helpful message
- Backup directory already exists -- fine, append timestamped file
- No cards to delete (all DB cards are in collection) -- report "nothing to clean"
- user_collection is empty -- refuse to clean (safety check: "Cannot cleanup with empty collection")
- Set code case mismatch -- use LOWER() on both sides of comparison
