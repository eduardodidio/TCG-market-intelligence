## User Story
As a developer, I want a matching algorithm that takes a collection entry and a list of MYP search results and returns the best match, so that the sync pipeline can accurately link collection cards to MYP products.

## Dev Notes

### What to implement
Create a matching module `src/collection/matcher.py` with a pure function that scores and selects the best MYP match for a given collection entry.

### Files to create
- `src/collection/matcher.py` -- core matching logic

### Files to modify
- None (this is a new pure-function module)

### Matching algorithm
1. **Primary match** -- SKU-based: Parse each MYP result's SKU (via `parse_sku`). If `set_code` (lowercased) matches collection `set_code` AND `collector_number` matches, this is a definitive match. Return immediately.
2. **Secondary match** -- Name + set: If no SKU match, compare `name_en` (case-insensitive, stripped) against MYP result names. If exactly one result matches the name and we can confirm the set, accept it.
3. **Ambiguous** -- If multiple results match by name but none match by set_code + collector_number, mark as ambiguous.
4. **No match** -- If zero results from search, mark as unmatched.

### Match result dataclass
```python
@dataclass
class MatchResult:
    status: str  # "matched" | "ambiguous" | "unmatched"
    collection_entry: UserCollectionRow  # or a simplified dict
    myp_result: MypSearchResult | None  # best match, if any
    confidence: str  # "sku_exact" | "name_set" | "name_only" | "none"
    candidates: list[MypSearchResult]  # all results from search
```

### Key technical details
- The matcher must be a pure function (no DB, no network) for testability
- Input: collection card data (set_code, collector_number, name_en) + list of search results
- Output: MatchResult
- Set code comparison must be case-insensitive (collection has lowercase, MYP SKU parse returns uppercase -- normalize both to lowercase)
- For the SKU match, the matcher needs to call `parse_sku()` on each search result. This requires that MypSearchResult carries the SKU or that we can derive it. If the search API does not return SKU, the matcher may need to work with the card page URL + external_id instead, deferring SKU matching to the sync pipeline.

### Edge cases
- Card with multiple printings across sets (e.g., "Lightning Bolt" in 20+ sets) -- SKU match by set_code+collector_number is critical
- Split/double-faced cards where MYP uses a different name format
- Art variants (same set_code+collector_number but different art) -- should match to the same MYP product
- Collector numbers with letters (e.g., "123a", "123b") -- string comparison, not numeric
