# F139-T01 — Backend: `role` column + schema + API

**Status:** planned
**Wave:** 0
**Depends on:** —

## User Story

As the system, I need a `role` column on the `users` table so that the
frontend can distinguish admin users from guest users and apply feature
restrictions accordingly.

## Dev Notes

### 1. UserRow model (`src/database/models.py`)

Add column after `is_admin`:

```python
role: Mapped[str] = mapped_column(String(20), default="admin")
```

Default `"admin"` ensures backward compatibility — all existing users
continue to have full access.

### 2. Database migration

The project does NOT use Alembic. Add an `ALTER TABLE` in the repository
startup or use the same pattern as previous migrations (e.g., F99's
table-rebuild approach). Simplest: `ALTER TABLE users ADD COLUMN role
VARCHAR(20) DEFAULT 'admin'` — safe for both SQLite and PostgreSQL.

Add migration logic in `Repository.__init__` or a dedicated migration
helper that checks if column exists before adding.

### 3. UserProfile schema (`src/api/schemas/auth.py`)

Add field:

```python
role: str = "admin"
```

### 4. Auth endpoint (`src/api/routers/auth.py`)

The `/auth/me` endpoint already builds `UserProfile` from the user row.
Ensure the new `role` field is mapped correctly in the response.

### 5. Frontend type (`frontend/src/api/auth.ts`)

Add to `UserProfile` interface:

```typescript
role: string;  // "admin" | "guest"
```
