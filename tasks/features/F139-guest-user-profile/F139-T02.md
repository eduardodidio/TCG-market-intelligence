# F139-T02 — Backend: seed guest user in CLI

**Status:** planned
**Wave:** 1
**Depends on:** T01

## User Story

As the platform owner, I want a pre-configured guest user seeded via the
`seed-users` CLI command so that I can share a demo login with visitors
without giving them beta feature access.

## Dev Notes

### 1. Seed user entry (`src/cli/main.py` — `seed-users` command)

Add a second entry to `SEED_USERS`:

```python
SEED_USERS = [
    {
        "email": "eduardorutkoskididio@gmail.com",
        "display_name": "Eduardo Didio",
        "role": "admin",
        "is_admin": True,
    },
    {
        "email": "guest@tedhmarket.com.br",
        "display_name": "Guest",
        "role": "guest",
        "is_admin": False,
    },
]
```

### 2. Seed logic changes

- After creating the guest user, set `role="guest"` and `is_admin=0`.
- Grant initial credits (10,000) same as admin.
- Password: same `TCG_SEED_PASSWORD` env var (default `"mudar@123"`) or
  hardcode `"mudar@12345"` for the guest specifically. **User specified
  `mudar@12345`** as the guest password — use that directly.
- Idempotent: if user already exists, update `role="guest"` and
  `is_admin=0` (same pattern as admin user's `is_admin=1` update).

### 3. Do NOT reassign collection

The existing logic reassigns all collection entries to the primary seed
user. The guest user should NOT trigger this — only the first (admin)
seed user should remain the reassignment target.

### Files to modify

| File | Change |
|------|--------|
| `src/cli/main.py` | Add guest to SEED_USERS, handle role + is_admin per entry |
