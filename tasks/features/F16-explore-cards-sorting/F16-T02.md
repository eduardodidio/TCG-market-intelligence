# Task F16-T02 — API endpoint: sort and offset query params

**Feature:** F16
**Wave:** 1
**Type:** backend
**Depends on:** F16-T01
**Status:** planned

## User Story

As a frontend developer, I want the collection API to accept sort and
pagination parameters, so the UI can request sorted card lists.

## Objective

Add `sort_by`, `sort_dir`, and `offset` query parameters to the
`GET /api/v1/collection` endpoint. Wire them through to the repository.

## Dev Notes

- Relevant files:
  - `src/api/routers/collection.py` — `list_collection` endpoint (line ~50)
  - `src/api/schemas/collection.py` — response schemas (no changes needed)
  - `src/api/schemas/envelope.py` — `paginated_response` helper

- Current endpoint signature:
  ```python
  @router.get("", response_model=ApiResponse[list[CollectionCard]])
  def list_collection(
      name: str | None = None,
      set: str | None = Query(None, alias="set"),
      cursor: str | None = None,
      limit: int = Query(default=50, ge=1, le=200),
      repo: Repository = Depends(get_db),
  )
  ```

- Add new params:
  ```python
  sort_by: str = Query(default="name", regex="^(name|set|number|added)$"),
  sort_dir: str = Query(default="asc", regex="^(asc|desc)$"),
  offset: int | None = Query(default=None, ge=0),
  ```

- When `offset` is provided, use offset-based pagination. When `cursor`
  is provided (and offset is None), use cursor-based for backward compat.
  When neither is provided, start from offset=0.

- Update the response `meta` to include `offset` (the current offset value)
  alongside the existing `cursor` for backward compat.

- The `paginated_response` helper may need a small update to accept an
  `offset` kwarg. Check `src/api/schemas/envelope.py`.

- Keep the `total` count call — it already exists.

- Price sorting (`sort_by=price`) is NOT handled server-side. The API
  simply does not accept `price` as a sort_by value. The frontend will
  handle price sorting client-side.

## Implementation details

- File: `src/api/routers/collection.py`
- Function: `list_collection`
- Changes:
  1. Add `sort_by`, `sort_dir`, `offset` query params
  2. Pass them through to `repo.list_collection()`
  3. When using offset pagination, compute `next_offset = offset + limit`
     if there are more results
  4. Populate `meta.cursor` with encoded next offset (or keep None)
  5. Keep `total` count

## Acceptance criteria

- [ ] `sort_by` param accepted with values: name, set, number, added
- [ ] `sort_dir` param accepted with values: asc, desc
- [ ] `offset` param accepted (int >= 0)
- [ ] Invalid `sort_by` returns 422
- [ ] Response `meta` includes offset info
- [ ] Backward compat: `cursor` param still works
- [ ] Integration tests cover sort + pagination combos

## Test scenarios

- **Happy path:** `?sort_by=set&sort_dir=asc` returns sorted by set code
- **Happy path:** `?offset=0&limit=10` returns first 10 cards
- **Edge case:** `?sort_by=price` returns 422 (not server-side)
- **Backward compat:** `?cursor=<valid>` still paginates correctly
- **Error scenario:** `?sort_dir=invalid` returns 422
