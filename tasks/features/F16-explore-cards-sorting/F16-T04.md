# Task F16-T04 — Frontend MyCollection page: integrate sorting

**Feature:** F16
**Wave:** 2
**Type:** frontend
**Depends on:** F16-T02, F16-T03
**Status:** planned

## User Story

As a user, I want to sort my collection grid and have it update
immediately, with my sort choice preserved in the URL.

## Objective

Wire the `SortSelect` component into `MyCollection`, add sort state to
URL params, pass sort params to the API, and implement client-side price
sorting.

## Dev Notes

- Relevant files:
  - `frontend/src/pages/MyCollection.tsx` — main page (325 lines)
  - `frontend/src/api/collection.ts` — `fetchCollection` function
  - `frontend/src/types/api.ts` — `CollectionCard` type

- Current state management in MyCollection:
  - `searchTerm` / `debouncedSearch` for name filter
  - `selectedSet` for set filter
  - `cards`, `cursor`, `loading`, `loadingMore`, `error`, `summary`
  - URL params synced: `name`, `set`
  - Infinite scroll via `useInfiniteScroll` hook + sentinel

- Changes needed:
  1. Add state: `sortBy` (default "name"), `sortDir` (default "asc")
  2. Initialize from URL params `sort` and `dir`
  3. Sync to URL params alongside `name` and `set`
  4. Pass `sort_by` and `sort_dir` to `fetchCollection` params
  5. For **price sorting** (`sortBy === "price"`): do NOT pass sort params
     to the API (use default name sort). Instead, sort the `cards` array
     client-side by `latest_price`. This means price sort only works on
     already-loaded cards. Load all cards first by fetching without limit
     constraints (or just sort what's loaded and note the limitation).
  6. Replace cursor-based infinite scroll with offset-based: track
     `offset` state, increment by `limit` on load-more.
  7. On sort change: reset `cards`, `offset` to 0, re-fetch.

- Render the `SortSelect` between the search bar and the filter chips
  (or inline with the search bar on larger screens).

- Client-side price sort implementation:
  ```typescript
  const sortedCards = useMemo(() => {
    if (sortBy !== "price") return cards;
    return [...cards].sort((a, b) => {
      const pa = a.latest_price ?? (sortDir === "asc" ? Infinity : -Infinity);
      const pb = b.latest_price ?? (sortDir === "asc" ? Infinity : -Infinity);
      return sortDir === "asc" ? pa - pb : pb - pa;
    });
  }, [cards, sortBy, sortDir]);
  ```

- Pagination migration (cursor -> offset):
  - Replace `cursor` state with `offset` (number, default 0)
  - `handleLoadMore`: use `offset` param instead of `cursor`
  - `has_next`: check if response returned `limit` items
  - The API response `meta.cursor` can still be used if offset is not
    returned. But prefer reading `meta.total` to know if more exist:
    `hasMore = offset + cards.length < total`.

## Test scenarios

- **Happy path:** select "Name (Z-A)", cards re-render in reverse alpha
- **Happy path:** select "Price (High-Low)", cards sorted by price desc
- **Edge case:** price sort with cards that have null prices
- **Edge case:** change sort while loading — previous fetch is discarded
- **Boundary:** URL has `?sort=added&dir=desc` on mount, page loads sorted
