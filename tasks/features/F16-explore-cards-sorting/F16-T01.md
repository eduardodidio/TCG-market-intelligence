# Task F16-T01 — Backend repository: sorted + offset collection queries

**Feature:** F16
**Wave:** 1
**Type:** backend
**Depends on:** none
**Status:** planned

## User Story

As a developer, I want the repository layer to support sorting and offset
pagination for collection queries, so the API can expose sort controls.

## Objective

Modify `Repository.list_collection` and `Repository.count_collection` to
accept `sort_by`, `sort_dir`, and `offset` parameters, replacing the
cursor-based `after_id` approach.

## Dev Notes

- Relevant files:
  - `src/database/repository.py` — `list_collection()` (line ~569),
    `count_collection()` (line ~596)
  - `src/database/models.py` — `UserCollectionRow` (line ~89)

- Current `list_collection` signature:
  ```python
  def list_collection(self, user_id, name_search=None, set_code=None,
                       after_id=None, limit=50) -> list[UserCollectionRow]
  ```
  Orders by `UserCollectionRow.id.asc()` and uses `after_id` cursor.

- New signature:
  ```python
  def list_collection(self, user_id, name_search=None, set_code=None,
                       sort_by="name", sort_dir="asc",
                       offset=0, limit=50,
                       after_id=None) -> list[UserCollectionRow]
  ```

- Sort field mapping (sort_by string -> SQLAlchemy column):
  - `"name"` -> `UserCollectionRow.name_en`
  - `"set"` -> `UserCollectionRow.set_code`
  - `"number"` -> `UserCollectionRow.collector_number`
  - `"added"` -> `UserCollectionRow.created_at`

- When `sort_by` is provided and `after_id` is None, use `.offset(offset)`
  instead of cursor-based filtering. Keep `after_id` support for backward
  compat (if both provided, `offset` takes precedence).

- Add a secondary sort by `id ASC` for stable ordering when primary sort
  values are equal.

- Handle NULL values: `name_en` can be NULL. Use `nulls_last()` for ASC,
  `nulls_first()` for DESC (SQLite does not support NULLS FIRST/LAST
  natively, but SQLAlchemy handles it via CASE expression). Alternatively,
  use `coalesce(name_en, '')` in the ORDER BY.

- `collector_number` is a string column (e.g. "1", "10", "2"). For
  natural numeric sorting, cast to integer where possible. This can be
  done with `func.cast(UserCollectionRow.collector_number, Integer)` but
  beware of non-numeric values like "1a". Simplest: sort as string for now,
  note as a known limitation.

## Implementation details

- File: `src/database/repository.py`
- Method: `list_collection`
- Changes:
  1. Add `sort_by`, `sort_dir`, `offset` params with defaults
  2. Build a column map dict for sort_by values
  3. Apply `.order_by(column.asc() or .desc())` then `.order_by(id.asc())`
  4. When offset is provided (and after_id is None), use `.offset(offset)`
  5. Keep `.limit(limit + 1)` pattern for has_next detection
