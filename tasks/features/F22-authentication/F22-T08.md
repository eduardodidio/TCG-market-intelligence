# F22-T08: Login Page

- **Wave:** 4
- **Status:** done
- **Depends on:** F22-T05
- **Type:** frontend

## Description

Create the `/login` page with email+password form and OAuth provider
buttons. This page is the entry point for all authentication.

### `frontend/src/pages/Login.tsx`

Layout (consistent with existing dark theme):
- Centered card on dark background
- App logo/title at top
- **Email+password section**:
  - Email input (validated)
  - Password input (min 8 chars)
  - "Sign In" button
  - "Don't have an account? Register" link (toggles form to register mode)
  - Register mode adds "Display name" field and changes button to "Create Account"
- **Divider**: "or continue with"
- **OAuth buttons** (styled with provider colors/logos):
  - "Continue with Google"
  - "Continue with Microsoft"
  - "Continue with Apple"
- **Error display**: shows validation errors and API errors inline
- **Loading state**: disables form while request is in flight
- **Redirect**: after successful login, redirect to `returnTo` query
  param or `/collection`

### Route Registration

- Add `/login` route in `App.tsx` (outside `<Layout />` wrapper since
  login has its own layout, OR inside Layout -- design decision for
  developer: if inside Layout, the sidebar shows but the page fills
  the content area)

### Behavior

- If user is already authenticated, redirect to `/` (or `returnTo`)
- Email+password form validates on client before submitting
- OAuth buttons redirect to `getOAuthUrl(provider)`

## Acceptance Criteria

- [ ] Login page renders at `/login`
- [ ] Email+password form submits and logs in user
- [ ] Registration mode creates account
- [ ] OAuth buttons redirect to provider URLs
- [ ] Validation errors display inline
- [ ] API errors display inline
- [ ] Successful login redirects to returnTo or /collection
- [ ] Already-authenticated users redirected away from login
- [ ] Responsive design (mobile + desktop)
- [ ] All existing frontend tests pass
