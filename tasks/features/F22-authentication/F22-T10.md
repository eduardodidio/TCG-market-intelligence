# F22-T10: Collection Data Migration + Diagrams + Documentation

- **Wave:** 6
- **Status:** done
- **Depends on:** F22-T06, F22-T09
- **Type:** backend + docs

## Description

Handle migration of existing collection data from `FAKE_USER_ID` to real
users, create architecture diagrams, and update project documentation.

### Collection Data Migration

Add a CLI command `collector migrate-user` that:
1. Takes `--old-user-id` (default: "eduardo") and `--new-user-id` (required)
2. Calls `repo.migrate_collection_user(old, new)` (from T03)
3. Reports how many rows were updated
4. Also add auto-migration logic: when a user first logs in and the
   `user_collection` table has rows with `user_id="eduardo"` and no
   other real users exist, automatically migrate those rows to the new
   user's ID. This happens in the auth router's login/callback flow.
