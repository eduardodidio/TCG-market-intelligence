# F22-T06: Protect Backend Endpoints (Collection, Scans)

- **Wave:** 3
- **Status:** done
- **Depends on:** F22-T04
- **Type:** backend

## Description

Replace `FAKE_USER_ID` with real auth in all protected endpoints.
Public endpoints (cards, sets, market) remain untouched.

### Changes to `src/api/routers/collection.py`

- Remove `FAKE_USER_ID = "eduardo"` constant
- All endpoints that access user collection data add
  `user_id: str = Depends(get_current_user_id)` parameter
- Affected endpoints:
  - `GET /collection` -- pass `user_id` to `repo.list_collection()`
  - `GET /collection/summary` -- pass `user_id`
  - `GET /collection/sets` -- pass `user_id`
  - `GET /collection/{entry_id}` -- verify entry belongs to user
  - `POST /collection/import` -- pass `user_id`
  - `POST /collection/sync` -- keep existing `verify_api_key` AND add user auth
  - `POST /collection/snapshot-prices` -- keep existing `verify_api_key` AND add user auth

### Changes to `src/api/routers/scans.py`

- Add `user: User = Depends(get_current_user)` to scan trigger endpoint
- Scan listing can remain public or be protected (decision: protect it,
  since scans are user-initiated operations)

### Entry ownership check

- `GET /collection/{entry_id}`: after fetching the entry from DB,
  verify `entry.user_id == user_id`. If not, return 403 or 404.

### Backward Compatibility

- The existing `verify_api_key` dependency on write endpoints is kept
  as an additional guard for machine-to-machine calls (cron, CLI).
  Both `verify_api_key` and `get_current_user` are required on those
  endpoints (either auth method suffices -- use an "or" dependency).

## Acceptance Criteria

- [ ] `FAKE_USER_ID` removed from collection router

- [ ] Collection entry detail verifies ownership
- [ ] Scan endpoints require authentication
- [ ] Unauthenticated requests to protected endpoints return 401
- [ ] Public endpoints (cards, sets, market, health) remain accessible
- [ ] All existing tests updated to provide auth context
- [ ] All tests pass
