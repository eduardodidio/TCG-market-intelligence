## User Story
As the operator running banlist-sync against Neon, I want legalities written in chunked multi-row upserts, so that a full sync finishes in minutes instead of timing out after millions of round trips.

## Objective
Create `src/database/legality_writer.py` with `bulk_upsert_legalities` and `bulk_insert_legality_changes` (dialect-aware, chunked).

## Dev Notes
See `_brief/00-overview.md` (RC4) and `_brief/01-sync-fix.md` (section "legality_writer.py contract").
- Upsert helper: `src/database/compat.py::dialect_insert(engine, table)` returns the sqlite/postgresql `insert` that supports `.on_conflict_do_update`.
- Models: `CardLegalityRow` (unique `card_id, format`, cols `status, effective_date, updated_at`), `LegalityHistoryRow` (`card_id, format, old_status, new_status, changed_at, source`) in `src/database/models.py`. Do NOT edit models.py.
- Domain: `src/domain/models.py::CardLegality`, `LegalityChange` (has `source`, default `"scryfall_sync"`).
- The current per-row implementation (for reference, don't modify it): `src/database/repository.py:2878-2923`.
- Multi-row upsert pattern:
  ```python
  stmt = dialect_insert(engine, CardLegalityRow).values(rows)   # rows: list[dict]
  stmt = stmt.on_conflict_do_update(index_elements=["card_id", "format"],
      set_={"status": stmt.excluded.status, "effective_date": stmt.excluded.effective_date,
            "updated_at": stmt.excluded.updated_at})
  ```
  PostgreSQL errors with "ON CONFLICT DO UPDATE command cannot affect row a second time" if one chunk has duplicate keys, so dedupe per chunk (last wins).
- On an update, don't overwrite a non-null `effective_date` with NULL: use `func.coalesce(stmt.excluded.effective_date, CardLegalityRow.effective_date)`.
- SQLite bound-parameter limit: 500 rows × 5 cols = 2500. Safe.
- Conventions: `from __future__ import annotations`, structlog `log = structlog.get_logger()`, type hints, module docstring.

## Implementation details
- `src/database/legality_writer.py` with `CHUNK_SIZE = 500`, `bulk_upsert_legalities`, `bulk_insert_legality_changes`, and a private `_chunks(seq, n)` generator.
- One `Session(engine)` per call, commit once at the end. Return counts.
