## User Story
As a logged-in collector, I want a "Somente minha coleção" toggle and a clickable card on the ban list, so that I can focus on my affected cards and inspect their ban history in place.

## Objective
Update `BanList.tsx` + the API client + types to use the grouped endpoint, the `owned_only` filter, the status endpoint, and `BanCardDetailModal`.

## Implementation details
1. types + api client changes (small).
2. BanList: `ownedOnly` derived from `searchParams.get("owned") === "1"`; the toggle calls `setSearchParams` preserving other params; disabled when `!isAuthenticated` (and treated as false).
3. The format default: `?format=` > "commander" > "standard" > formats[0].
4. Status fetch once on mount: the subtitle `banlist.lastSynced` + the `banlist-not-synced` empty state when `legalities_count === 0`.
5. Tile → `<button type="button" data-testid="banlist-card" onClick={() => setSelected(entry)}>`; owned badge `banlist-owned-badge`; printings hint when > 1.
6. "Load more" (`banlist-load-more`) appends the next page (offset += PAGE_SIZE) while `items.length < total`; reset on a filter change.

## Test scenarios
- Happy: logged-in user toggles → fetchBanList called with `ownedOnly: true`; the URL has owned=1
- Happy: click a tile → `ban-card-modal` visible (mock the modal's fetches) → close → gone
- Edge: logged out + `?owned=1` in the URL → the toggle is disabled and the fetch uses ownedOnly false
- Edge: status legalities_count 0 → `banlist-not-synced`
- Edge: ownedOnly with empty results → the emptyOwned text
- Edge: `?format=legacy` in the URL is preselected
- Error: fetchBanList rejects → error text shown
- Boundary: total=51, page 50 → load more visible; after loading → hidden
