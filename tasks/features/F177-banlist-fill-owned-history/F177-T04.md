# F177-T04 — Grouped ban list + owned filter + status queries

- **Wave:** 1
- **Type:** backend
- **Depends on:** —
- **Status:** planned

## User Story
As a collector, I want the ban list to show each card once and tell me whether I own it, so that I can quickly see which of my cards are affected.

## Objective
Create `src/database/banlist_queries.py` with `list_banlist_grouped(...)` and `get_banlist_status(engine)`.

## Dev Notes
See `_brief/00-overview.md` (the secondary pagination bug) and `_brief/02-backend-api.md` (full contract).
- Models: `CardLegalityRow`, `LegalityHistoryRow`, `CardRow` (`name_en`, `name_pt`, `set_code`, `collector_number`), `UserCollectionRow` (`user_id`, `card_id` nullable, `name_en`, `quantity`) in `src/database/models.py`.
- Reference query to adapt: `src/database/repository.py::get_legalities_by_format` (lines ~2925-2968). Don't edit repository.py (batch hotspot); the new module receives `engine`.
- Use `sqlalchemy.orm.Session(engine)` + `select(...)`. Must work on SQLite and PostgreSQL (use `func.lower`, `ilike`, no dialect-specific SQL).
- Group key: `(name_en or "").strip().lower()`. Representative printing: owned printing first, else the lowest `card_id`. `effective_date`: the max across the group's printings (may be None). If printings in a group have different statuses (rare), take the most severe (banned > restricted).
- `owned_quantity` = sum of `UserCollectionRow.quantity` for this user over rows where `card_id ∈ group card_ids` OR `lower(name_en) == group key`. Don't double count: a collection row counts once.
- `status` validation: allowed `None | "banned" | "restricted"` → otherwise `ValueError`.

## Implementation details
- `list_banlist_grouped(engine, format, status=None, search=None, user_id=None, owned_only=False, limit=50, offset=0) -> tuple[list[dict], int]`
- `get_banlist_status(engine) -> dict` (keys: `last_synced_at, legalities_count, banned_count, restricted_count, history_count, formats`)
- Sorting: banned before restricted, then `name_en.lower()`. Pagination after grouping/filtering.

## Acceptance criteria
- [ ] 3 printings of the same banned card → 1 entry with `printings == 3`
- [ ] `status=None` returns banned + restricted, correct `total`, `offset` applied once
- [ ] `owned`/`owned_quantity` are correct for card_id matches and name-only matches (unlinked collection rows)
- [ ] `owned_only=True` without `user_id` → `([], 0)`
- [ ] `search` matches name_en or name_pt case-insensitively
- [ ] `get_banlist_status` on an empty DB → zeros and `last_synced_at=None`
- [ ] Coverage ≥ 95%; `ruff check` clean

## Test scenarios
- Happy: a format with 2 banned + 1 restricted names → order banned(a..z), restricted
- Happy: the owned printing is chosen as the representative when the user owns a non-lowest printing
- Edge: `name_en` None rows grouped under "" and not crashing
- Edge: a different user's collection doesn't mark owned
- Edge: search with no matches → `([], 0)`
- Boundary: limit=1, offset=1 → the 2nd grouped entry, total unchanged; offset ≥ total → empty list, same total
- Error: status="legal" → ValueError
- Status: history_count and formats count distinct correctly; last_synced_at = max(updated_at)
