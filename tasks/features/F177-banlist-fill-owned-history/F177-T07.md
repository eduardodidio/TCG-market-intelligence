# F177-T07 — Ban list router: grouped list, owned_only, status endpoint

- **Wave:** 2
- **Type:** backend
- **Depends on:** F177-T04
- **Status:** planned
- **Maps to AC:** AC6, AC7

## User Story
As a logged-in collector, I want `GET /banlist?owned_only=true` to return only the banned/restricted cards I own, so that the frontend toggle can filter by my collection.

## Objective
Switch `GET /api/v1/banlist` to `banlist_queries.list_banlist_grouped`, add `owned_only` with optional auth, and add `GET /api/v1/banlist/status`.

## Dev Notes
See `_brief/00-overview.md` and `_brief/02-backend-api.md` (sections "Router changes" and "Frontend contract").
- Router: `src/api/routers/banlist.py` (`list_banlist` at ~line 37). Schemas: `src/api/schemas/banlist.py` (`BanListEntry` at line 10).
- Optional auth: `from src.api.deps import get_optional_user` and `from src.domain.models import User` (check the exact User import used in `src/api/routers/market.py:12,141`, and copy it).
- Errors: `api_error(status, ErrorCode.X, msg)` from `src/api/error_codes.py`. For 401 use the existing auth code that best fits (e.g. `AUTH_TOKEN_INVALID`, or an `AUTH_REQUIRED`-like one if it exists).
- `db.engine` is available on `Repository` (the sync uses `repo.engine`).
- `status` type: `Literal["banned", "restricted"] | None = None`. FastAPI → 422 on other values.
- Route order: declare `/status` before `/card/{card_id}` (no conflict technically, but keep it tidy) and before any catch-all.
- Keep `_scryfall_image_url` for `image_url`.
- `src/api/app.py` is NOT edited (the router is already included at `/api/v1`).

## Implementation details
- `BanListEntry`: add `printings: int = 1`, `owned: bool = False`, `owned_quantity: int = 0`.
- NEW `BanlistStatusSchema(BaseModel)`: `last_synced_at: datetime | None`, `legalities_count: int`, `banned_count: int`, `restricted_count: int`, `history_count: int`, `formats: int`.
- `list_banlist(format: str, status: Literal[...] | None = None, search: str | None = None, owned_only: bool = False, limit: int = Query(50, ge=1, le=500), offset: int = Query(0, ge=0), user = Depends(get_optional_user), db = Depends(get_db))`.
- `@router.get("/status", response_model=ApiResponse[BanlistStatusSchema])`.

## Acceptance criteria
- [ ] `GET /banlist?format=commander` returns grouped entries with the new fields and `meta.total` = grouped total
- [ ] `owned_only=true` + auth → only owned; without auth → 401
- [ ] Anonymous → `owned` false for all
- [ ] `status=legal` → 422; `limit=0` or `limit=501` → 422
- [ ] `GET /banlist/status` works anonymously and returns counts
- [ ] The other banlist endpoints behave as before (`tests/banlist/test_api.py` green, with assertions adjusted only for dedup/new fields)
