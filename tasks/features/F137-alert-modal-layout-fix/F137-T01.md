# F137-T01: Debug and Fix SetAlertModal Layout Overflow

**Wave:** 0
**Parallel with:** (none -- single task)
**Files to modify:** `frontend/src/components/SetAlertModal.tsx`
**Files to create:** (none)

## User Story

As a user setting a price alert on a card, I want the alert modal to
appear centered on screen without clipping or escaping to the left, so
that I can fill in the form without layout issues.

## Problem

The SetAlertModal renders with `fixed inset-0 z-50 flex items-center
justify-center bg-black/50` as the overlay and `bg-slate-800 ... w-full
max-w-md mx-4` as the inner modal. Despite `fixed inset-0` anchoring to
the viewport, the modal content escapes to the left. This manifests on
both mobile and desktop viewports.

### Current markup structure

```
<!-- Layout.tsx root -->
<div class="flex h-screen ...">
  <aside class="fixed inset-y-0 left-0 z-30 ... md:relative md:w-64">
    ...sidebar...
  </aside>
  <div class="flex flex-1 flex-col overflow-hidden">
    <main class="flex-1 overflow-y-auto p-6">
      <!-- CardDetail.tsx renders here via <Outlet /> -->
      <!-- SetAlertModal overlay (fixed inset-0 z-50) -->
    </main>
  </div>
</div>
```

The modal is rendered inside `<main>` which has `overflow-y-auto`. Even
though `fixed` positioning should escape the parent's overflow context,
the flex centering (`justify-center`) inside the overlay can be affected
by inherited min-width constraints or the overlay itself not properly
constraining its children.

## Root Cause Analysis

Investigate these hypotheses in order:

1. **Missing overflow containment on overlay**: The overlay div has no
   `overflow-hidden`. If the inner modal's computed width (including
   `mx-4` margins and `w-full`) exceeds the overlay in edge cases, the
   content can escape. Adding `overflow-hidden` to the overlay prevents
   visual spillage.

2. **`w-full` without `min-w-0`**: The inner modal uses `w-full max-w-md
   mx-4`. In a flex context, `w-full` computes to 100% of the flex
   container, but flex children have an implicit `min-width: auto` that
   can prevent shrinking below content size. If the form inputs (which
   use `w-full pl-10 pr-3`) push the content wider than expected, the
   modal won't shrink. Adding `min-w-0` on flex children fixes this.

3. **Form input expanding beyond container**: The price input has
   `w-full pl-10 pr-3` inside a `relative` wrapper. Number inputs can
   have browser-default spinner controls that add width. Verify
   `box-sizing: border-box` is applied (should be via Tailwind's
   preflight reset, but confirm).

4. **Sidebar z-index interaction**: The sidebar is `z-30` and the modal
   overlay is `z-50`, so stacking should be correct. However, on mobile
   the sidebar overlay is `z-20` and the sidebar itself is `z-30` --
   verify the modal renders above both.

## Implementation Steps

### Step 1: Add overflow containment to overlay

```tsx
// Before:
className="fixed inset-0 z-50 flex items-center justify-center bg-black/50"

// After:
className="fixed inset-0 z-50 flex items-center justify-center bg-black/50 overflow-hidden"
```

This is the primary fix. `overflow-hidden` on the overlay ensures no
child can escape its boundaries.

### Step 2: Add min-w-0 to the inner modal container

```tsx
// Before:
className="bg-slate-800 border border-slate-600 rounded-lg shadow-xl w-full max-w-md mx-4"

// After:
className="bg-slate-800 border border-slate-600 rounded-lg shadow-xl w-full max-w-md mx-4 min-w-0"
```

`min-w-0` overrides the flex child's implicit `min-width: auto`,
allowing the modal to shrink below its content's intrinsic width if
needed.

### Step 3: Constrain form elements

Add `min-w-0` to the form element and `overflow-hidden` to the modal
body div to prevent any inner content from expanding the container:

```tsx
// Form element:
<form onSubmit={handleSubmit} data-testid="set-alert-form" className="min-w-0">

// Body wrapper:
<div className="px-6 py-4 overflow-hidden">
```

The `onClick` handler on the overlay checks `e.target === e.currentTarget`.
Adding `overflow-hidden` does not change event targets, so this should
continue to work. Confirm with existing test:
`"calls onClose when overlay clicked"`.

## Edge Cases

- Sidebar expanded (w-64) on desktop -- modal must still center relative
  to viewport, not relative to the main content area
- Sidebar collapsed (w-16) on desktop -- same centering expectation
- Mobile with sidebar closed (sidebar is `-translate-x-full`) -- modal
  must center on full viewport width
- Mobile with sidebar open (sidebar is `translate-x-0 w-64`) -- modal
  must still center on viewport (z-50 > z-30)
- Very long card names in the description text -- should wrap, not
  expand the modal
- Many existing alerts listed -- the alerts list should scroll within
  the modal if it gets long (or the modal should not exceed viewport
  height)
