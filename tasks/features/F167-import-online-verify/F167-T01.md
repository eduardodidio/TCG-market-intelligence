# F167-T01: Integration tests for import endpoints

**Status:** planned
**Wave:** 0

## User Story

As a developer, I want integration tests proving the import purchases feature works with the remote database, so we can confidently keep it in production.

## Dev Notes

### Files to create
- `tests/api/test_purchases_integration.py`

### Test scenarios

1. **`test_import_preview_with_html_file`**
   - Create a minimal Nerdz-format HTML fixture
   - Upload via `POST /api/v1/purchases/import-preview`
   - Verify response has `matches` and `unmatched` arrays
   - Verify `total_items_parsed > 0`

2. **`test_import_preview_with_liga_html`**
   - Create a minimal Liga Magic format HTML fixture
   - Upload and verify parsing works

3. **`test_apply_purchases_updates_collection`**
   - First upload for preview
   - Then call `POST /api/v1/purchases/apply` with selected matches
   - Verify `total_applied > 0`
   - Verify collection entry has `acquisition_price` set

4. **`test_apply_purchases_overwrite_protection`**
   - Set an acquisition price on a collection entry
   - Try to apply without `overwrite=true`
   - Verify entry is skipped

5. **`test_import_preview_rejects_non_html`**
   - Upload a .txt file
   - Verify 400 error

6. **`test_import_preview_rejects_oversized_file`**
   - Upload a file > 5MB
   - Verify 400 error

7. **`test_import_requires_auth`**
   - Call without token
   - Verify 401

### HTML fixtures

Create minimal HTML fixtures in `tests/fixtures/`:
- `nerdz_sample.html` — minimal Nerdz purchase history HTML
- `liga_sample.html` — minimal Liga purchase history HTML

These should contain 2-3 card purchases each, enough to test parsing.

## Testing

- Use pytest with test client (TestClient from FastAPI)
- Seed test user + collection entries in test setup
- Clean up after tests
- These tests verify the full pipeline: upload → parse → match → apply
