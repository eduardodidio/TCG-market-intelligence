# F09-T02: API key guard on collect endpoints

**Wave:** 0
**Status:** planned
**Estimate:** S

## User Story

As an operator exposing the API on a network, I want the POST collect endpoints
to require an API key, so that unauthorized users cannot trigger expensive
collection operations.

## Dev Notes

### FastAPI Dependency

Create a new dependency function in `src/api/deps.py`:

```python
def verify_api_key(x_api_key: str | None = Header(None)) -> None:
    """Verify API key for protected endpoints.

    If TCG_API_KEY env var is not set, the guard is disabled (dev mode).
    If set, the X-API-Key header must match exactly.
    """
    expected = os.environ.get("TCG_API_KEY")
    if expected is None:
        return  # No key configured — dev mode, allow all
    if x_api_key is None or x_api_key != expected:
        raise HTTPException(status_code=401, detail="Invalid or missing API key")
```

Import `Header` from `fastapi` and `HTTPException` from `fastapi`.

### Apply to Collect Routes

In `src/api/routers/collect.py`, add the dependency to the two POST endpoints:

```python
from src.api.deps import verify_api_key

@router.post("/backfill", ...)
async def trigger_backfill(
    request: BackfillRequest,
    repo: Repository = Depends(get_db),
    _auth: None = Depends(verify_api_key),  # ADD THIS
) -> ...:
```

Same for `trigger_update`.

The `GET /collect/health` endpoint (from T01) must NOT have this dependency --
it is read-only observability.

### Files to Change

- `src/api/deps.py` -- add `verify_api_key` dependency
- `src/api/routers/collect.py` -- add `Depends(verify_api_key)` to both POST routes

### Files NOT to Touch

- `src/api/app.py` -- no middleware needed, using per-route dependencies
- `src/api/schemas/` -- no schema changes
- `src/database/` -- no database changes

### Compatibility Note

When `TCG_API_KEY` is NOT set in the environment, the guard is a no-op. This
means all existing tests that call collect endpoints without a key will
continue to pass without modification. Tests for the auth behavior itself
should set the env var explicitly via `monkeypatch`.

## Acceptance Criteria

- [ ] POST `/api/v1/collect/update` returns 401 when `TCG_API_KEY` is set but
      `X-API-Key` header is missing
- [ ] POST `/api/v1/collect/update` returns 401 when `X-API-Key` header has
      wrong value
- [ ] POST `/api/v1/collect/update` returns 200 when `X-API-Key` matches
      `TCG_API_KEY`
- [ ] POST `/api/v1/collect/backfill` has the same auth behavior
- [ ] When `TCG_API_KEY` is not set, both endpoints work without any header
      (dev mode)
- [ ] GET `/api/v1/collect/health` does NOT require an API key
- [ ] All existing collect endpoint tests still pass (they run without
      `TCG_API_KEY` set)
