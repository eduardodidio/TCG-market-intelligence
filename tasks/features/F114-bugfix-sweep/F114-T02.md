# F114-T02: Scryfall DFC Image URI Fallback

**Status:** planned
**Wave:** 0

## User Story

As a user browsing the Catalog, I want all cards to show artwork including
double-faced cards, so that no cards appear with just a placeholder icon.

## Root Cause Analysis

**File:** `src/catalog/scryfall.py:217-218`
```python
image_uris = raw.get("image_uris") or {}
image_uri = image_uris.get("normal")
```

Scryfall's data structure differs for double-faced cards (DFCs):
- **Standard cards:** `image_uris.normal` exists at top level
- **DFCs (modal, transform, adventure):** NO top-level `image_uris` — images
  are under `card_faces[0].image_uris.normal`

Result: ~4,244 cards (~3.6% of catalog) have `image_uri = NULL` in the DB.

## Dev Notes

### Fix in scryfall.py `_parse_card()`

```python
image_uris = raw.get("image_uris") or {}
image_uri = image_uris.get("normal")

# Fallback for double-faced cards
if not image_uri:
    card_faces = raw.get("card_faces") or []
    if card_faces:
        face_uris = card_faces[0].get("image_uris") or {}
        image_uri = face_uris.get("normal")
```

### Re-seed affected cards

After deploying the fix, run:
```bash
python -m src.cli.main catalog seed --force
```
This will re-parse the JSONL and update image_uri for DFCs.

Alternatively, a lighter migration script could UPDATE only rows where
image_uri IS NULL by re-parsing the JSONL for those cards.

## Acceptance Criteria

1. `_parse_card()` extracts image_uri from `card_faces[0]` when top-level is absent
2. After re-seed, zero cards with NULL image_uri (except truly image-less cards)
3. Catalog page shows artwork for DFCs (e.g., "Clearwater Pathway")

## Testing

- Unit test: parse a DFC JSON blob (no top-level image_uris) — verify image_uri extracted
- Unit test: parse a standard card — verify existing behavior unchanged
- Integration: count cards with NULL image_uri before/after seed
