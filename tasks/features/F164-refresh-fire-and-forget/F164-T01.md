# F164-T01: Remove polling from CardTile, fire-and-forget UX

**Status:** completed
**Wave:** 0

## User Story

As a user, when I click refresh on a card tile, I want the button to immediately confirm the request was enqueued and release, so I can continue browsing without waiting for the price to be fetched.

## Dev Notes

### Files to modify
- `frontend/src/components/CardTile.tsx`

### Changes

1. **Remove `usePriceRequestPolling` from CardTile** — remove the import and hook call. The polling is unnecessary here since the cron processes the queue.

2. **Simplify `handleRefresh`**:
   - Call `refreshCardPrice(card.id)`
   - If response `status === "queued"`: set `enqueued = true`, show green check badge for 1.5s, then reset
   - If error: show red X badge for 3s, then reset
   - Button should only be disabled during the API call itself (`refreshing` state), NOT during the enqueued feedback period

3. **Remove states**: `queued`, `completed`, `failed`, `requestStatus`, `isPolling`, `pollingTimedOut`

4. **Replace with simpler states**: `refreshing` (during API call), `enqueued` (1.5s feedback), `refreshError` (3s feedback)

5. **Button behavior**:
   - Default: refresh icon, clickable
   - During API call: spin icon, disabled
   - After enqueue: green check icon for 1.5s, button clickable again after the 1.5s
   - On error: red X for 3s, then back to default

6. **Remove feedback text** below price (the `queued-feedback`, `completed-feedback`, `failed-feedback`, `refresh-error-feedback` spans). Replace with a single optional "Enfileirado" text that shows for 1.5s.

## Testing

- Test that clicking refresh calls `refreshCardPrice` API
- Test that after successful queue, button shows check icon briefly then resets
- Test that button is only disabled during API call, NOT during enqueued state
- Test that `usePriceRequestPolling` is NOT called in CardTile
- Test error state shows X icon and resets after timeout
