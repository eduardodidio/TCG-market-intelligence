# F45-T01: Custom MYP exceptions module

**Status: done**
**Wave: 1**

## User Story

As a developer, I want typed exception classes for MYP HTTP errors so that
callers (scan, sync) can distinguish 404, 429, and 5xx failures and react
accordingly (fast-fail, re-queue, or log).

## Dev Notes

### New file: `src/providers/myp/exceptions.py`

Define a minimal hierarchy:

```
MypError(RuntimeError)
  +-- NotFoundError(MypError)      # 404
  +-- RateLimitError(MypError)     # 429
  +-- ServerError(MypError)        # 5xx
```

Each class should store:
- `url: str` -- the URL that failed
- `status_code: int` -- the HTTP status code
- `attempts: int` -- how many attempts were made before giving up

`MypError.__init__(self, message, *, url, status_code, attempts)` stores
all three as instance attributes and passes `message` to `RuntimeError`.
Subclasses inherit without overriding `__init__`.

### Update `src/providers/myp/__init__.py`

If `__init__.py` exists, add exports for the four exception classes.
If it does not exist, create it with the exports.

## Testing

### Unit tests: `tests/unit/providers/test_exceptions.py` (new file)

1. `MypError` is a subclass of `RuntimeError`.
2. `NotFoundError`, `RateLimitError`, `ServerError` are subclasses of
   `MypError`.
3. Each exception stores `url`, `status_code`, `attempts` attributes.
4. `str()` of each exception returns the message passed to the constructor.
5. `isinstance(NotFoundError(...), RuntimeError)` is `True` (backward
   compat -- existing `except RuntimeError` blocks still catch these).
