# F45 Provider Resilience -- Tech Lead Review

**Date:** 2026-08-22
**Reviewer:** Tech Lead Agent
**Verdict:** APPROVED

## Architecture Assessment

### Exception Hierarchy (T01)
- Clean single-inheritance hierarchy: `MypError(RuntimeError)` with three subclasses.
- Backward compatible: all typed exceptions are still `RuntimeError` subclasses, so existing `except RuntimeError` blocks continue to work.
- Each exception stores `url`, `status_code`, `attempts` -- sufficient context for logging and debugging.
- Exported via `__init__.py` for clean import paths.

### Provider _fetch Refactor (T02)
- 404 fast-fail eliminates wasted retry time (saves 3-12 seconds per dead page).
- Status-specific handling is ordered correctly: 404 (immediate) > 429 (retry) > 403 (retry) > 5xx (retry) > other 4xx (immediate).
- `last_status` tracking for typed exception at loop exhaustion is clean.
- `search_card` and `fetch_current_price` updated to re-raise `NotFoundError` and `RateLimitError` before the generic catch -- essential for callers to distinguish errors.

### Scan Requeue (T03)
- `MAX_REQUEUE_ATTEMPTS = 2` prevents infinite loops.
- Single retry pass after initial gather with 3x delay multiplier is simple and effective.
- `retry_queue.clear()` before retry gather prevents stale entries.
- NotFoundError handled as immediate fail (correct -- 404 is permanent).

### Sync Requeue (T04)
- Parallel structure with scan requeue for consistency.
- New `rate_limited` and `not_found` fields on `SyncSummary` have default values (backward compatible).
- `_log_summary` updated with new fields.
- Typed statuses ("not_found", "rate_limited") in `SyncResult` give clear signal to API consumers.

## Risks

- **LOW**: The retry pass runs once, not in a loop. If a card gets rate-limited during the retry pass, it is counted as failed. This is intentional simplicity -- a second retry pass would add complexity with diminishing returns.
- **NONE**: No DB schema changes required. The new `SyncSummary` fields are Python dataclass-only.
