# F45-T02: Provider _fetch refactor -- typed exceptions + 404 fast-fail

**Status: done**
**Wave: 1**
**Depends on: T01**

## User Story

As a collector running scans, I want 404 errors to fail immediately (no
retry) so that dead product pages do not waste 3-12 seconds of backoff per
card. I also want 429 and 5xx errors to raise typed exceptions so that
upstream orchestrators can re-queue rate-limited cards.

## Dev Notes

### File: `src/providers/myp/provider.py`

**Import** (add at top, after existing imports):

```python
from src.providers.myp.exceptions import (
    MypError,
    NotFoundError,
    RateLimitError,
    ServerError,
)
```

**Refactor `_fetch` method** (lines 68-121):

Current logic (lines 79-111) handles HTTP errors in this order:
429 -> 403 -> catch-all >= 400. Replace the catch-all block with
status-specific handling:

1. **404** -- raise `NotFoundError` immediately, no retry:
   ```python
   if resp.status_code == 404:
       raise NotFoundError(
           f"HTTP 404 for {url}",
           url=url, status_code=404, attempts=attempt,
       )
   ```
   Insert this check BEFORE the existing 429 block (line 79) so it
   short-circuits on the first attempt.

2. **429** -- keep existing retry logic (lines 79-88). After the loop
   exhausts retries, change the final `raise RuntimeError(...)` on
   line 121 to check if last failure was 429 and raise `RateLimitError`.
   Simpler approach: track `last_status` variable. After loop, raise
   based on `last_status`.

3. **5xx** (500-599) -- retry with existing exponential backoff. If
   exhausted, raise `ServerError` instead of `RuntimeError`.

4. **403** -- keep existing retry logic (lines 90-99, Cloudflare recovery).
   If exhausted, raise `MypError` (generic).

5. **Other 4xx** (400, 401, 402, 405-499 except 404/429) -- raise
   `MypError` immediately, no retry.

**Implementation approach**: Add a `last_status: int | None = None`
variable before the retry loop. Set it on every non-200 response. After
the loop, use `last_status` to pick the right exception class for the
final raise on line 121.

**Key behavioral changes**:
- 404: 0 retries (was 3). Saves 3-12 seconds per dead product.
- Other 4xx (except 403): 0 retries (was 3). These are not transient.
- 429, 403, 5xx: unchanged retry count, but raise typed exception.
- Final `raise RuntimeError(...)` on line 121: replaced with typed raise.

**Do NOT change** `fetch_current_price` (lines 216-236) or `search_card`
(lines 123-142) -- they already catch `RuntimeError` which remains the
base class via `MypError(RuntimeError)`. Backward compatible.
