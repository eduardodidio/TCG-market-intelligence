# F45-T04: Sync orchestrator re-queue + 404 permanent fail

**Status: done**
**Wave: 2**
**Depends on: T02**

## User Story

As a user running collection sync, I want rate-limited cards to be retried
in a second pass so that transient 429 errors do not permanently skip
cards. I also want 404 errors to be marked as permanently failed (not
retriable) so they are clearly reported.

### Note on `_process_single_entry`

The `RateLimitError` and `NotFoundError` may be raised anywhere inside
`_process_single_entry` (lines 158-281) -- from `search_card`,
`get_card_details`, `get_price_history`, or `fetch_current_price`. Since
these all call `_fetch` internally, the typed exceptions will bubble up
naturally. The `process_entry` wrapper (the outer function) catches them.

However, `search_card` (provider.py line 138) catches `RuntimeError` and
returns `[]`. Since `MypError` inherits from `RuntimeError`, the
`RateLimitError` would be swallowed there. Two options:
- (a) Update `search_card` to re-raise `RateLimitError` before the
  generic catch. **Do this.**
- (b) Accept that search-phase 429s return empty results (less ideal).

**Update `search_card`** (provider.py lines 136-142):
