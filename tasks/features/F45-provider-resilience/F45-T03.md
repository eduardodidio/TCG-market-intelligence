# F45-T03: Scan orchestrator re-queue on RateLimitError

**Status: done**
**Wave: 2**
**Depends on: T02**

## User Story

As a user running a price scan, I want rate-limited cards to be
automatically re-queued and retried with longer delays so that transient
429 errors do not permanently skip cards in the scan run.

**Changes to `run_scan` function** (lines 27-277):

1. **Add retry queue and constants** after the `lock` declaration (line 98):
   ```python
   MAX_REQUEUE_ATTEMPTS = 2
   retry_queue: list[tuple[dict, int]] = []  # (entry, retry_count)
   cards_requeued = 0
   cards_requeue_failed = 0
   ```

2. **Update `process_entry` inner function** (lines 100-198):
   - Add a `retry_count: int = 0` parameter.
   - In the `except Exception` block (line 110), add a check BEFORE the
     generic error handling:
     ```python
     except RateLimitError:
         async with lock:
             if retry_count < MAX_REQUEUE_ATTEMPTS:
                 retry_queue.append((entry, retry_count + 1))
                 cards_requeued += 1
             else:
                 cards_failed += 1
                 cards_requeue_failed += 1
                 error_messages.append(f"{external_id}: RateLimitError after {retry_count} requeues")
         return
     except NotFoundError:
         async with lock:
             cards_failed += 1
             error_messages.append(f"{external_id}: NotFoundError (dead product page)")
         return
     except Exception as e:
         # ... existing generic error handling ...
     ```
   - Note: `RateLimitError` must be caught BEFORE `Exception` since it
     is a subclass. `NotFoundError` is caught separately so it is not
     re-queued (404 = permanently dead).

3. **Add retry pass** after the initial `asyncio.gather` (line 200):
   ```python
   # 3b. Retry pass for rate-limited entries (longer delay)
   if retry_queue:
       log.info("scan_retry_pass", requeue_count=len(retry_queue))
       # Use longer delay for retry pass
       original_delay = provider.config.delay_seconds
       provider.config.delay_seconds = max(original_delay * 3, 5.0)
       retry_tasks = [
           process_entry(entry, i, retry_count=rc)
           for i, (entry, rc) in enumerate(retry_queue, 1)
       ]
       retry_queue.clear()  # Clear before processing (new items may be added)
       await asyncio.gather(*retry_tasks)
       provider.config.delay_seconds = original_delay
   ```
   This loop runs at most MAX_REQUEUE_ATTEMPTS times (entries that get
   429 again are re-appended, but their retry_count eventually exceeds
   MAX_REQUEUE_ATTEMPTS). To keep it simple, run the retry pass once
   (not in a loop). Entries re-queued during the retry pass will be
   counted as requeue_failed.

   Actually, simpler: run retry pass in a `while retry_queue:` loop but
   the MAX_REQUEUE_ATTEMPTS guard prevents infinite loops. Each iteration
   processes only the current batch.

4. **Include retry stats in log and scan event** (line 222 area):
   Add `cards_requeued` and `cards_requeue_failed` to the
   `scan_finished` log call. These are informational only -- they do not
   change the scan_runs DB schema (no migration needed).
