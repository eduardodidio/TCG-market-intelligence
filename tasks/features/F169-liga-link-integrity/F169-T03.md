# F169-T03 — `liga-verify-links` CLI command

**Status:** planned

## User Story

As an operator, I want to audit all stored Liga URLs to find mismatches where the
stored URL points to a different card than expected, so I can fix broken links.

### New repository method: `get_all_liga_card_urls()`

**File: `src/database/repository.py`** (after `get_liga_card_url` at line 4930)

```python
def get_all_liga_card_urls(self) -> list[LigaCardUrlRow]:
    """Return all stored Liga card URLs."""
    with Session(self.engine) as session:
        rows = session.execute(select(LigaCardUrlRow)).scalars().all()
        for r in rows:
            session.expunge(r)
        return list(rows)
```

### New repository method: `get_card_by_external_id()`

**File: `src/database/repository.py`** (near `get_card_by_id`)

Need to resolve an `external_id` like `liga_123` back to a card name for
comparison. The path is: `external_id` -> `SourceCardRow` (where
`source_cards.external_id = external_id`) -> `CardRow` (via `card_id` FK).

```python
def get_card_name_by_liga_external_id(self, external_id: str) -> str | None:
    """Return the English card name for a Liga external_id, or None."""
    with Session(self.engine) as session:
        row = session.execute(
            select(CardRow.name_en)
            .join(SourceCardRow, SourceCardRow.card_id == CardRow.id)
            .where(SourceCardRow.external_id == external_id)
        ).scalar_one_or_none()
        return row
```

Note: This joins through `source_cards` because `liga_card_urls.external_id`
matches `source_cards.external_id` (both use `liga_{card_id}` format from
`liga_sweep`). However, some `liga_card_urls` entries may use external_ids that
do NOT have a matching `source_cards` row (e.g., if the source_card was deleted).
The command should handle `None` gracefully.

### CLI command design

```python
@cli.command("liga-verify-links")
@click.option("--db", default=None, callback=_resolve_db, is_eager=True, ...)
@click.option("--limit", default=50, help="Max URLs to verify")
@click.option("--dry-run", is_flag=True, help="Only show what would be verified")
def liga_verify_links(db, limit, dry_run):
    """Verify stored Liga URLs point to the expected cards via Playwright."""
```

**Algorithm:**

1. Load all `liga_card_urls` rows via `repo.get_all_liga_card_urls()`.
2. For each row (up to `--limit`):
   a. Resolve the expected card name via `repo.get_card_name_by_liga_external_id(row.external_id)`.
   b. Skip if no expected name found (orphan URL record).
   c. If `--dry-run`, just print `"Would verify: {external_id} -> {url}"`.
   d. Otherwise, open the URL in Playwright, extract the card name from the page
      (use the `<h1>` or `.card-name` selector — same technique used by
      `LigaMagicProvider`).
   e. Compare extracted name with expected name (case-insensitive, stripped).
   f. Print MATCH or MISMATCH with details.
3. Print summary: total verified, matches, mismatches, errors, orphans.

**Playwright usage**: Import `LigaMagicProvider` from `src/providers/liga/provider.py`
and use its browser context. The provider already handles Playwright setup/teardown
via `open()`/`close()`. Use `provider.page.goto(url)` and extract the card name
from the page.

Alternatively, to keep the command lightweight, use Playwright directly:
```python
from playwright.async_api import async_playwright

async with async_playwright() as p:
    browser = await p.chromium.launch(headless=True)
    page = await browser.new_page()
    ...
```

**Output format** (for T04 to consume):
```
[MATCH]    liga_123  "Sol Ring"  -> https://...
[MISMATCH] liga_456  expected="Lightning Bolt" found="Chain Lightning"  -> https://...
[ERROR]    liga_789  timeout  -> https://...
[ORPHAN]   liga_012  no card found for external_id
```

Optionally write results to a JSON file (`--output results.json`) for T04
to read programmatically.
