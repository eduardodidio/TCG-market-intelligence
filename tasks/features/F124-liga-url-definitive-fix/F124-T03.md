# F124-T03: Comprehensive Liga URL test coverage

**Status:** planned
**Wave:** 1

## User Story

As a developer, I want comprehensive test coverage verifying that every card
type produces a correct Liga URL — normal cards, split/DFC, commas,
apostrophes, accented characters — so this issue never regresses.

## Dev Notes

### What to test

1. **Unit tests for `liga_url_for_card_name`** (in `tests/unit/providers/liga/test_url.py`):
   - Normal: "Lightning Bolt" → `card=Lightning+Bolt&show=1`
   - Comma: "Thalia, Guardian of Thraben" → `card=Thalia%2C+Guardian+of+Thraben&show=1`
   - Apostrophe: "Frodo's Ring" → `card=Frodo%27s+Ring&show=1`
   - Split/DFC: "Painter's Studio // Defaced Gallery" → `card=Painter%27s+Studio&show=1`
   - DFC with comma: "Beorn, Reluctant Host // Till and Tend" → `card=Beorn%2C+Reluctant+Host&show=1`
   - Accented: "Dain, Rei dos Anoes" → properly encoded
   - Art Card suffix: "The Arkenstone // Seek the Heart (Art Card with Signature)" → `card=The+Arkenstone&show=1`
   - Whitespace: "  Lightning Bolt  " → trimmed
   - Single word: "Raze" → `card=Raze&show=1`

2. **Integration tests for CardDetail endpoint** (in `tests/api/test_card_detail_liga_url.py`):
   - Normal card → `ligamagic_url` present with `&show=1`
   - Split card → front face only in URL
   - Card with special chars → properly encoded

3. **Integration tests for collection detail endpoint** (update `tests/api/test_collection_liga_links.py`):
   - Add split card test case
   - Verify `&show=1` always present

4. **Integration tests for card_search endpoint** (update existing tests):
   - Verify `liga_url` has `&show=1`

5. **Regression test scanning all card name patterns** (in `tests/unit/providers/liga/test_url.py`):
   - Parametrized test with 20+ real card names covering all edge cases from the actual collection
