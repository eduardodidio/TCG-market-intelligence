# F124-T02: Add ligamagic_url to CardDetail API + fix CardDetail.tsx

**Status:** planned
**Wave:** 0

## User Story

As a user, when I view a card's detail page, I want the Liga Magic link to
correctly open the card on Liga — including for split/DFC cards — using a
URL built by the backend instead of the frontend.

## Dev Notes

### What to change

1. **Backend — `src/api/schemas/cards.py`**:
   - Add `ligamagic_url: str | None = None` to `CardDetail` schema

2. **Backend — `src/api/routers/cards.py`**:
   - Import `liga_url_for_card_name` from `src/providers/liga/url`
   - Build `ligamagic_url` from `card.name_en` using the utility
   - Pass it to the `CardDetail` response

3. **Frontend — `src/types/api.ts`**:
   - Add `ligamagic_url: string | null` to `CardDetail` interface

4. **Frontend — `src/pages/CardDetail.tsx`**:
   - Remove hardcoded Liga URL construction (`encodeURIComponent(card.name_en)`)
   - Use `card.ligamagic_url` from the API response instead
   - Add null check (only show link if `ligamagic_url` is present)

### Files to modify

- `src/api/schemas/cards.py`
- `src/api/routers/cards.py`
- `frontend/src/types/api.ts`
- `frontend/src/pages/CardDetail.tsx`

## Testing

- Backend: verify `/api/v1/cards/{id}` response includes `ligamagic_url`
- Backend: verify `ligamagic_url` has `&show=1` and proper encoding
- Backend: verify split card returns front-face-only URL
- Frontend: verify CardDetail uses `card.ligamagic_url` from API
- Frontend: verify no hardcoded Liga URL construction remains
