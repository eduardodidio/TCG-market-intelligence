# F166-T01 — Backend: sanity filters for outlier percentages

**Status:** planned
**Wave:** 0
**Parallel with:** T02

## User Story

As a user viewing my collection movers, I want percentages to reflect meaningful
market movements so that cards with tiny base prices (e.g. R$0.01) don't dominate
the ranking with absurd 49900% swings.

## Dev Notes

### Problem
`get_collection_movers_optimized()` in `src/database/repository.py:1219-1396`
has only one filter: `earliest.c.price_start > 0`. This allows cards with
`price_start` as low as R$0.01, causing extreme `change_pct` values that
drown out real market signals.

### Solution
Add two SQL-level filters to the main `WHERE` clause (line 1374-1377):

1. **Minimum price floor**: `earliest.c.price_start >= 0.50` — ignore cards
   with starting price below R$0.50 (penny cards cause noise)
2. **Percentage cap**: `abs(change_pct) <= 1000` — cap at +/-1000% to exclude
   extreme outliers (10x move is already significant)

Both filters go in the `.where()` clause of `stmt` (line 1374). Replace
`earliest.c.price_start > 0` with `earliest.c.price_start >= 0.50` and add
the percentage cap as a Python-side filter on the `movers` list (since
SQLAlchemy doesn't allow referencing labels in WHERE easily).

### Implementation

In `repository.py`, after line 1383 (the list comprehension building `movers`),
add a filter:

```python
movers = [m for m in movers if abs(m[8]) <= 1000.0]
```

And change line 1375 from:
```python
earliest.c.price_start > 0,
```
to:
```python
earliest.c.price_start >= 0.5,
```
