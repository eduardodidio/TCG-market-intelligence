# F166-T02 — Backend: raise max limit to 100

**Status:** planned
**Wave:** 0
**Parallel with:** T01

## User Story

As a user, I want to be able to request up to 100 movers so that the frontend
can offer "Top 10" and "Top 100" expand views without hitting API validation errors.

## Dev Notes

### Problem
The endpoint `GET /api/v1/collection/movers` in `src/api/routers/collection.py:402`
has `limit: int = 5` with `max: 20`. The frontend expand feature (T03) needs
to request up to 100 cards.

### Solution
Change the `limit` query parameter validation from `max=20` to `max=100`.

In `src/api/routers/collection.py`, find the `limit` parameter (around line 410)
and change:
```python
limit: int = Query(default=5, ge=1, le=20),
```
to:
```python
limit: int = Query(default=5, ge=1, le=100),
```

### Files
- `src/api/routers/collection.py` — change limit max from 20 to 100

## Testing

### Unit Tests (`tests/unit/test_collection_movers.py`)

1. **test_movers_limit_100_accepted** — call endpoint with `limit=100`, verify
   200 response (not 422 validation error).

2. **test_movers_limit_101_rejected** — call endpoint with `limit=101`, verify
   422 validation error.
