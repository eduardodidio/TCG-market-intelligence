# F213-T10: Admin Audit Log + DB Stats

**Wave:** 1 | **Sub-Feature:** F213g-2 (F100) | **Status:** planned

## User Story

As an admin, I want to see an audit log of actions and database statistics
so I can monitor system health.

## Dev Notes

1. Create `audit_log` table (if not exists):
   - `id`, `user_id`, `action` (string), `target` (string), `details` (JSON),
     `created_at`
   - Actions: login, scan_trigger, job_trigger, collection_import, etc.
2. Add audit logging to key operations:
   - Job triggers (from T04)
   - Collection imports
   - Banlist syncs
   - User management actions
3. Add endpoints:
   - `GET /api/v1/admin/audit-log` — paginated, filterable by action/user/date
   - `GET /api/v1/admin/db-stats` — table sizes, observation counts, collection
     counts, last sync dates, Neon connection stats
4. DB stats should be cached (5min TTL) to avoid expensive COUNT queries

## Acceptance Criteria

- [ ] Audit log records key admin actions
- [ ] Audit log endpoint returns paginated results with filters
- [ ] DB stats endpoint returns table sizes and sync dates
- [ ] Stats cached to avoid repeated expensive queries

## Testing
