# F213-T04: Admin Job Trigger Endpoints

**Wave:** 0 | **Sub-Feature:** F213g-1 (F100) | **Status:** planned

## User Story

As an admin, I want to trigger maintenance jobs (sweep, snapshot, seed, banlist
sync) from the admin panel API so I don't need CLI access.

## Dev Notes

1. Add endpoints to `src/api/routers/admin.py` (admin-only auth):
   - `POST /api/v1/admin/jobs/myp-sweep` — trigger MYP sweep (params: max_age_days, limit)
   - `POST /api/v1/admin/jobs/snapshot-portfolio` — trigger portfolio snapshot
   - `POST /api/v1/admin/jobs/catalog-seed` — trigger catalog seed
   - `POST /api/v1/admin/jobs/banlist-sync` — trigger banlist sync
   - `GET /api/v1/admin/jobs/status` — list running/recent jobs with status
2. Jobs run in background threads with status tracking
3. Use existing `BackgroundTasks` from FastAPI or simple thread pool
4. Rate limit: max 1 concurrent job of each type
5. Reuse existing CLI functions internally (don't duplicate logic)

## Acceptance Criteria

- [ ] All 4 job trigger endpoints work and return job_id
- [ ] Status endpoint shows running/completed/failed jobs
- [ ] Rate limit prevents duplicate concurrent jobs
- [ ] Admin-only auth enforced

## Testing

- Backend: Unit test each endpoint returns 200 + job_id (mock job execution)
- Backend: Unit test rate limiting (second call returns 409)
- Backend: Unit test non-admin gets 403
