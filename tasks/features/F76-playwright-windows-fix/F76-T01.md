# F76-T01 — Suppress Playwright Startup Error on Windows

**Status:** planned
**Wave:** 0
**Depends on:** —

## User Story

As a developer running on Windows, I want the app to start without noisy Playwright error tracebacks, so the console output is clean and I can focus on real errors.

## Dev Notes

### Root cause

On Windows with Python 3.14 under uvicorn, the default event loop (SelectorEventLoop in MINGW/git-bash) does not support `asyncio.create_subprocess_exec`. Playwright's `async_playwright().start()` internally creates a subprocess, which raises `NotImplementedError`.

The error IS caught by the `except Exception` block in lifespan, BUT Playwright's internal connection task logs "Task exception was never retrieved" because the task fails independently of the awaited future.

### Fix approach

**`src/providers/liga/provider.py`** — Add platform guard in `open()`:

```python
async def open(self):
    import sys
    if sys.platform == "win32":
        import structlog
        log = structlog.get_logger()
        log.info("liga_provider_skipped", reason="Windows does not support async subprocesses for Playwright")
        return
    # ... existing Playwright startup code ...
```

This prevents the subprocess from ever being created on Windows, avoiding both the `NotImplementedError` AND the "Task exception was never retrieved" warning.

### Alternative considered (rejected)
- Setting `asyncio.WindowsProactorEventLoopPolicy()` — this could break uvicorn's event loop management
- Wrapping in `asyncio.shield` or task cancellation — complex, doesn't address the root cause

### Files to modify

1. **`src/providers/liga/provider.py`** — Add `sys.platform == "win32"` guard at top of `open()` method
   - Set a flag `self._unavailable = True` so other methods know Liga isn't available
   - `close()` should be a no-op when unavailable
   - `fetch_card_price()` etc. should raise a clear error when unavailable

2. **`src/api/app.py`** — Optional: simplify the Liga startup try/except now that provider handles it internally

### Key decisions
- Guard at provider level (not lifespan) — cleaner separation of concerns
- Flag `_unavailable` instead of raising in `open()` — the provider just silently becomes a no-op
- Warning log at INFO level (not WARNING) — this is expected behavior on Windows

## Testing

- On Windows: app starts without traceback
- On Windows: Liga provider methods return appropriate errors
- On non-Windows: Liga provider starts normally
- Unit test: mock sys.platform="win32" → open() returns without starting Playwright
- Unit test: mock sys.platform="linux" → open() proceeds with Playwright startup
