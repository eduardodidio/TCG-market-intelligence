# F48-T02: Default collection sort — price descending

**Status: done**

## User Story

As a collector, I want my collection page to default to showing the most expensive cards first (price descending), so I immediately see my highest-value cards without manually changing the sort.

## Dev Notes

**File:** `frontend/src/pages/MyCollection.tsx`

### Change 1: Default sort values (lines 222-223)

**Current:**
```typescript
const [sortBy, setSortBy] = useState(searchParams.get("sort") ?? "name");
const [sortDir, setSortDir] = useState<"asc" | "desc">((searchParams.get("dir") as "asc" | "desc") ?? "asc");
```

**New:**
```typescript
const [sortBy, setSortBy] = useState(searchParams.get("sort") ?? "price");
const [sortDir, setSortDir] = useState<"asc" | "desc">((searchParams.get("dir") as "asc" | "desc") ?? "desc");
```

### Change 2: URL param sync — omit defaults (lines 363-364)

The URL sync logic omits params that match the default to keep URLs clean. These conditions must match the new defaults.

**Current (line 363-364):**
```typescript
if (sortBy !== "name") params.sort = sortBy;
if (sortDir !== "asc") params.dir = sortDir;
```

**New:**
```typescript
if (sortBy !== "price") params.sort = sortBy;
if (sortDir !== "desc") params.dir = sortDir;
```

### No backend changes

Price sorting is already client-side (see `sortedCards` useMemo at line 475). The `buildParams` function (line 378) already handles `sortBy === "price"` by skipping server-side sort params. No API changes needed.
