# F48-T01: Nav active state fix

**Status: done**

## User Story

As a user navigating the app, I want each sidebar link to highlight only when I am on that exact page, so that /market and /market/trending (and similar prefix-sharing pairs) do not both appear active at the same time.

## Dev Notes

**File:** `frontend/src/components/Layout.tsx`

**Current code (lines 128-131):**
```typescript
const isActive =
  item.to === "/"
    ? location.pathname === "/"
    : location.pathname.startsWith(item.to);
```

**Problem:** `startsWith("/market")` matches both `/market` and `/market/trending`. Same for `/banlist` vs `/banlist/history` and `/decks` vs `/decks/ranking`.

**Fix (lines 128-131):** Replace the `isActive` expression with exact-match OR exact-prefix-with-slash:
```typescript
const isActive =
  item.to === "/"
    ? location.pathname === "/"
    : location.pathname === item.to || location.pathname.startsWith(item.to + "/");
```

This ensures:
- `/market` matches `/market` but NOT `/market/trending` (because `/market/trending` does not start with `/market/`)
- `/market/trending` matches `/market/trending` exactly
- `/banlist` does not match `/banlist/history`
- `/decks` does not match `/decks/ranking`

Wait -- this is wrong. `/market/trending` DOES start with `/market/`. Let me reconsider.

The correct fix: use **exact match only** for all items. The NAV_ITEMS list already contains every route that should highlight, so `startsWith` is unnecessary:
```typescript
const isActive = location.pathname === item.to;
```

This is the simplest and most correct approach since every navigable page has its own entry in NAV_ITEMS.

**Final change (lines 128-131):** Replace the entire ternary with:
```typescript
const isActive = location.pathname === item.to;
```
