# F123-T05: Collection Sort Persistence (Price Desc Default)

**Status:** done
**Wave:** 1

## User Story

As a user navigating to my collection from any entry point (dashboard link,
set completion click, breadcrumb, direct URL), I want cards to always default
to price descending sort, so my most valuable cards appear first.

## Acceptance Criteria

1. MyCollection page defaults to `sortBy="price"` and `sortDir="desc"` when
   no sort params are in the URL.
2. When navigating from SetCompletionBar (click a set), the target URL does
   NOT override sort params (or explicitly sets `sort=price&dir=desc`).
3. When navigating from Dashboard links, sort defaults are preserved.
4. When navigating back via breadcrumb or browser back button, sort defaults
   are preserved (scroll restoration does not interfere with sort).
5. If a user explicitly changes sort (e.g., to name asc), that choice is
   respected for the session but does NOT persist across page navigations.
6. Backend sort is unchanged (already correct per F122).

## Dev Notes

### Files to check/change

1. **`frontend/src/pages/MyCollection.tsx`** (line ~276-277)
   - Current defaults: `sortBy="price"`, `sortDir="desc"` --- already correct.
   - Issue: URL searchParams may override these defaults. Check the
     `useSearchParams` or equivalent hook usage.
   - Fix: if URL has `sort` or `dir` params, use them. If not, use defaults.
     Do NOT read sort from localStorage (we want price desc as the universal
     default, not a persisted user preference).

2. **`frontend/src/components/SetCompletionBar.tsx`**
   - Check what params the "click set" navigation passes.
   - If it passes `?sort=name&dir=asc` or any sort override, remove it.
   - The navigation should pass only filtering params (e.g., `?set_code=FDN`)
     and let MyCollection use its default sort.

3. **Dashboard links** (check `frontend/src/pages/Dashboard.tsx`)
   - Verify links to `/collection` do not include sort params.

4. **Breadcrumb** (check `frontend/src/components/Breadcrumb.tsx`)
   - Verify breadcrumb back-links to `/collection` do not include sort params.

### Investigation step

The developer should first grep for all navigation links to `/collection`
across the frontend to find any that pass sort overrides:

```bash
cd frontend && grep -rn "\/collection" src/ --include="*.tsx" --include="*.ts" | grep -i "sort\|dir"
```

Fix any that override sort to something other than price desc, or remove
the sort params entirely and rely on the default.

## Testing

### Unit tests (Vitest + RTL)

- MyCollection renders with price desc sort when no URL params present.
- MyCollection respects URL sort params when explicitly provided.
- SetCompletionBar navigation link does not include sort params (or includes
  `sort=price&dir=desc`).

### Integration verification

- Navigate to `/collection` directly --- cards sorted by price desc.
- Click a set in SetCompletionBar --- collection filtered by set, sorted by
  price desc.
- Click Dashboard "View Collection" link --- sorted by price desc.
- Use breadcrumb to go back to collection --- sorted by price desc.
- Manually set `?sort=name&dir=asc` in URL --- cards sorted by name asc.
