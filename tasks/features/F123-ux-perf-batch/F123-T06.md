# F123-T06: Infinite Scroll Performance

**Status:** planned
**Wave:** 1

## User Story

As a user with a large collection (100+ cards), I want the card grid to scroll
smoothly with the next page prefetching before I reach the bottom.

## Acceptance Criteria

1. Infinite scroll prefetch triggers earlier (rootMargin increased from
   `200px` to `600px`).
2. Page size increased from 24 to 48 for fewer network round-trips.
3. No regression in initial load time.
4. Scroll performance is smooth with 200+ cards loaded in the DOM.

## Dev Notes

### Pre-existing optimizations (DO NOT redo)

- `loading="lazy"` ALREADY exists on `<img>` in CardImage.tsx (line 40).
- Skeleton loading ALREADY exists in CardImage.tsx.
- Aspect-ratio placeholders ALREADY exist (F122 CLS fix).

### Files to change

1. **`frontend/src/utils/constants.ts`**
   - Change `DEFAULT_PAGE_LIMIT` from `24` to `48`.

2. **`frontend/src/hooks/useInfiniteScroll.ts`**
   - Change default `rootMargin` from `"200px"` to `"600px"` for earlier
     trigger. This gives more time for the fetch to complete before the
     user reaches the bottom.

3. **`frontend/src/pages/MyCollection.tsx`**
   - Verify it uses `DEFAULT_PAGE_LIMIT` from constants (it does, line 551).
   - No other changes needed (sort logic is T05).

4. **`frontend/src/pages/Cards.tsx`**
   - Verify it uses the constant. No other changes expected.

5. **`frontend/src/pages/CatalogPage.tsx`**
   - Uses manual "Load More" button, not infinite scroll.
   - Just ensure page size uses the updated constant.

### What NOT to do

- Do NOT add `react-window` or `react-virtuoso`. Virtual scrolling adds
  significant complexity. The simpler optimizations (larger pages, earlier
  prefetch) should be sufficient for collections under 1000 cards.
- Do NOT change backend pagination logic.
- Do NOT re-add `loading="lazy"` (already present).
