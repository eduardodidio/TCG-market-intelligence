# F123-T02: Fix Liga Magic Card Links

**Status:** planned
**Wave:** 0

## User Story

As a user viewing my collection card details, I want the "View on Liga Magic"
link to go to the correct card page, not a different card (e.g., clicking a
link for "Dain" should not open "Arcane Signet").

## Acceptance Criteria

1. Collection card detail Liga link opens the correct card on Liga Magic.
2. Card detail page Liga link uses the correct card name.
3. Cards page search result Liga link uses the correct card name.
4. All Liga URLs are built from the card's `name_en` looked up from the
   `cards` table (authoritative source), not from stale `entry.name_en`.
5. If no `name_en` is available, fall back to `name` (Portuguese name).
6. URL encoding handles special characters (commas, apostrophes, slashes).

## Dev Notes

### Root cause

The Liga URL is built from `entry.name_en` in the collection router, but
`entry.name_en` can be wrong when the `card_id` in `user_collection` points
to a card row whose name does not match what the user originally added. This
happens because Liga sweep may have matched the wrong card, or the card_id
mapping drifted during catalog seeding.

### Files to change

**Backend:**

1. `src/api/routers/collection.py` (line ~1636-1645)
   - Currently: `liga_url = f"https://www.ligamagic.com.br/?view=cards/card&card={entry.name_en}"`
   - Fix: look up the card's `name_en` from the `cards` table via a JOIN or
     separate query. The `cards` table is the authoritative source for card
     names.
   - Pattern: `card_row = repo.session.get(CardRow, entry.card_id)` then use
     `card_row.name_en or card_row.name`.
   - Apply `urllib.parse.quote()` to the card name in the URL.

2. `src/api/routers/card_search.py` (line ~184)
   - Currently builds URL from the card name returned by search.
   - Verify the name used is from the `cards` table. If it already is, no
     change needed. If not, fix similarly.

**Frontend:**

3. `frontend/src/pages/CardDetail.tsx` (line ~350)
   - Currently hardcodes URL: `https://www.ligamagic.com.br/?view=cards/card&card=${card.name_en}`
   - Fix: use `card.ligamagic_url` from the API response if the backend now
     provides it. Otherwise, ensure `card.name_en` comes from the correct
     source (it should, since CardDetail fetches from `/api/v1/cards/{id}`
     which reads from the `cards` table directly).
   - Apply `encodeURIComponent()` to the card name.

4. `frontend/src/pages/CollectionCardDetail.tsx` (line ~624)
   - Uses `entry.ligamagic_url` from the API. No frontend change needed if
     the backend fix in step 1 is correct.

5. `frontend/src/pages/Cards.tsx` (line ~558)
   - Uses `result.liga_url` from the API. No frontend change needed if the
     backend fix in step 2 is correct.

### URL format

Liga Magic card URL pattern:
```
https://www.ligamagic.com.br/?view=cards/card&card=CARD_NAME_EN
```
The name should be URL-encoded. Liga accepts English names.
