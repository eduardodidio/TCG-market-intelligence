# F34-T05 — Tests: Backend + Frontend Comprehensive Coverage

**Wave:** 3
**Depends on:** T01, T02, T03, T04 (all prior tasks complete)
**Creates:** test files for all new code

## Objective

Write comprehensive unit and integration tests for all F34 code. Target:
maintain existing coverage levels (94%+ backend, frontend parity).

## Steps

### 1. Backend unit tests for new analytics functions

**File:** `tests/unit/analytics/test_performance_score.py`

Test `compute_performance_score()`:
- Returns None with fewer than 3 data points.
- Score 0-100 range for various price series:
  - Consistently rising prices -> "strong" (>= 70).
  - Flat prices -> "moderate" or "weak".
  - Consistently falling prices -> "declining" (< 25).
- Period filtering works (only uses last N days of data).
- Different price_field values work.
- Edge case: all same price -> score reflects ATH proximity (100) but
  flat momentum.

**File:** `tests/unit/analytics/test_period_comparison.py`

Test `compute_period_comparison()`:
- Returns None when insufficient data for either period.
- Correct delta and delta_pct for known values.
- Current period avg > previous -> positive delta.
- Current period avg < previous -> negative delta.
- Handles period longer than available data gracefully.
- Works with different price_field values.

### 2. Backend unit tests for updated orchestrator

**File:** `tests/unit/analytics/test_card_analytics_extended.py`
(or extend existing `test_indicators.py`)

Test `compute_card_analytics()` with `period_days` parameter:
- When period_days is set, volatility and momentum use that period.
- Performance and period_comparison fields populated.
- When period_days is None, new fields are None (backward compat).
- Extremes always computed over full dataset regardless of period_days.

### 3. Backend integration tests for metrics endpoint

**File:** `tests/integration/api/test_metrics_endpoint.py`

Test `GET /collection/{entry_id}/metrics`:
- 200 with valid entry, linked card, and price data.
- Response contains all expected fields (moving_averages, extremes, etc.).
- Null fields when card has < 2 price observations.
- 401 without auth token.
- 404 for non-existent entry.
- 404 for another user's entry (ownership check).
- 422 when card_id is None (not linked).
- Period parameter validation (invalid period -> 422).
- Currency conversion applied (compare BRL vs USD response).
- Different periods return different metric values.

### 4. Frontend component tests

**File:** `frontend/tests/components/MetricsPanel.test.tsx`

Test `MetricsPanel`:
- Renders all 6 metric cards with full data.
- Shows skeleton loading state.
- Shows error banner on API failure with retry button.
- Hides individual cards when their metric is null.
- Trend arrow: green for "up", red for "down", gray for "flat".
- Performance badge: correct color for each label.
- Volatility bar: correct color for low/medium/high.
- Currency values formatted correctly.
- Responds to period/currency prop changes (re-fetches).
- Has `data-testid="metrics-panel"`.

**File:** `frontend/tests/pages/CollectionCardDetail.metrics.test.tsx`

Test integration:
- MetricsPanel renders when card_id is not null.
- MetricsPanel hidden when card_id is null.
- Period change in PriceChart updates MetricsPanel.
- PriceChart backward compat: works without period prop.

### 5. API client tests

**File:** `frontend/tests/api/metrics.test.ts`

Test `fetchCardMetrics()`:
- Calls correct endpoint URL.
- Passes period and currency params.
- Includes auth header.
