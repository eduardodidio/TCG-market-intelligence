# F156-T04: Mobile back button on detail pages

**Feature:** F156d — Add visible back button to Breadcrumb on mobile
**Wave:** 0
**Status:** planned

## User Story

As a mobile user on a detail page (card, collection entry, deck), I want
a clear back button to return to the list, so I don't get stuck.

## Dev Notes

### Current State

`Breadcrumb.tsx`: renders a horizontal `<ol>` with chevron separators.
On mobile, breadcrumb items are small text — hard to tap. No dedicated
back button. Used by 20+ pages.

### Implementation

Add a mobile-only back chevron button at the start of Breadcrumb that
navigates to the parent (second-to-last breadcrumb item):

```tsx
export function Breadcrumb({ items }: BreadcrumbProps) {
  const navigate = useNavigate();
  // Parent = second-to-last item with a `to` property
  const parent = items.length >= 2 ? items[items.length - 2] : null;

  return (
    <nav aria-label="Breadcrumb" className="mb-4" data-testid="breadcrumb">
      {/* Mobile back button */}
      {parent?.to && (
        <button
          onClick={() => navigate(parent.to!)}
          className="sm:hidden flex items-center gap-1 text-sm text-slate-400 hover:text-white mb-2"
          aria-label={t("common.back")}
          data-testid="breadcrumb-back"
        >
          <svg className="h-4 w-4" fill="none" viewBox="0 0 24 24" stroke="currentColor" strokeWidth={2}>
            <path strokeLinecap="round" strokeLinejoin="round" d="M15 19l-7-7 7-7" />
          </svg>
          {parent.label}
        </button>
      )}
      {/* Desktop breadcrumb (hidden on mobile) */}
      <ol className="hidden sm:flex items-center gap-1 text-sm ...">
        ...existing breadcrumb items...
      </ol>
    </nav>
  );
}
```

Key: `sm:hidden` for back button (mobile only), `hidden sm:flex` for
full breadcrumb (desktop only). Clean separation, no behavior change
for desktop users.
