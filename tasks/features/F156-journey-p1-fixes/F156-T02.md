# F156-T02: Alert notifications clickable → card detail

**Feature:** F156b — Make alert notification items link to card
**Wave:** 0
**Status:** planned

## User Story

As a user whose price alert triggered, I want to click the notification
to go directly to the card, so I can see its current price and act.

## Dev Notes

### Current State

- `AlertBell.tsx` line 102-127: notification items are plain `<div>`s with
  card_name, old_price → new_price, and timeAgo. Not clickable.
- `AlertNotificationResponse` type has: id, alert_id, card_name, old_price,
  new_price, is_read, notified_at. **No card_id**.
- Backend `alerts.py` line 217: builds response from `AlertNotificationRow`
  which has `alert_id` FK → `PriceAlertRow` which has `card_id`.

### Implementation

**Backend** — Add `card_id` to notification response:
1. In `src/api/routers/alerts.py` line 217: join `PriceAlertRow` to get
   `card_id`, include in `AlertNotificationResponse`.
2. In `src/api/schemas/alerts.py` (or wherever the response model lives):
   add `card_id: int` to `AlertNotificationResponse`.

**Frontend** — Make notifications clickable:
1. In `frontend/src/types/alerts.ts`: add `card_id: number` to
   `AlertNotificationResponse`.
2. In `AlertBell.tsx` line 103: wrap notification item `<div>` with
   `<Link to={/cards/${n.card_id}}> ... </Link>`, add onClick to close
   dropdown (`setOpen(false)`).
3. Style: add `hover:bg-slate-700 cursor-pointer` to notification items.

### Files
- `src/api/routers/alerts.py` — join card_id into notification response
- `frontend/src/types/alerts.ts` — add card_id field
- `frontend/src/components/AlertBell.tsx` — wrap items in Link

## Testing

- Backend: notification response includes card_id
- Frontend: clicking notification navigates to `/cards/{id}`
- Frontend: dropdown closes on click

## Acceptance Criteria
