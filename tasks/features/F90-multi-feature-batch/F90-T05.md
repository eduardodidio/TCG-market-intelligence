# F90-T05: Explore Cards Web Search

**Status:** planned
**Wave:** 2

## User Story

As a collector, I want to search for cards on LigaMagic directly from
the Explore Cards page, so that I can find and price-check cards that
are not yet in my local database.

## Acceptance Criteria

1. The Explore Cards page has a "Search Web" button/mode alongside the
   existing local DB search.
2. When the user types a card name and triggers web search, the backend
   queries LigaMagic via the existing Liga provider.
3. Results display card name, set, Liga price (normal + foil), and
   Scryfall image (if card can be resolved).
4. Each result has an "Add to Collection" button that imports the card.
5. Each result has an "Add to Evaluation" button (wired up in F90-T06;
   disabled/hidden until T06 ships).
6. Web search requires authentication (costs 1 token per search).
7. Rate limiting: max 1 web search request per 3 seconds (frontend
   debounce + backend guard).
8. Error states: Liga timeout, no results found, insufficient tokens.

## Dev Notes

### Backend Changes

**New endpoint** (`src/api/routers/cards.py` or new file
`src/api/routers/card_search.py`):
- `GET /api/v1/cards/search-web?q=<name>` -- authenticated endpoint.
- Deducts 1 credit token per search call.
- Uses `LigaProvider.search_card(card_name)` to get price data.
- Parses the Liga response into a `WebSearchResult` schema:
  ```python
  class WebSearchResult(BaseModel):
      card_name: str
      set_name: str | None
      liga_url: str | None
      normal_price: float | None
      foil_price: float | None
      image_url: str | None
      scryfall_id: str | None
  ```
- If the card already exists in the local DB (match by name), include
  `local_card_id` in the response so the frontend can link to it.
- Returns a list of results (Liga may return multiple printings).

**Liga provider integration**:
- Reuse `src/providers/liga/provider.py` `search_card()` method.
- The provider uses Playwright, so the endpoint must acquire the Liga
  lock and handle the browser lifecycle. Use the existing singleton
  pattern from `src/api/deps.py`.
- Timeout: 15 seconds max for the Liga search.

**Token cost**:
- Import `CreditService` from `src/credits/service.py`.
- Deduct 1 token before calling Liga. If deduction fails, return 402
  with "Insufficient credits" detail.

### Key Decisions

- **One search = one Liga page load**: Liga does not have a search API.
  `search_card(name)` navigates Playwright to the card page. This is
  slow (~5-8s) and expensive. Hence 1 token cost + rate limiting.
- **No batch search**: single card at a time to avoid overloading Liga.
- **Playwright lifecycle**: the Liga provider singleton manages the
  browser. The endpoint just calls `search_card` through the existing
  provider instance. No new Playwright setup needed.
