# F90-T01: Schedule Save Fix

**Status:** planned
**Wave:** 0

## User Story

As an admin user, I want new schedules I create in the admin panel to
appear in the schedule list immediately after saving, so that I can
confirm the schedule was created and manage it.

## Acceptance Criteria

1. Creating a schedule via the admin panel form persists to the DB and
   the new row appears in the schedule table without a page refresh.
2. If the backend returns a validation error (422) or other error, the
   error message is displayed in the feedback area.
3. Editing an existing schedule updates it and reflects changes in the
   table immediately.
4. No regressions in schedule delete, pause/resume, or manual trigger.

## Dev Notes

### Root Cause Investigation

The API client (`frontend/src/api/client.ts`) already includes the JWT
auth header in `apiPost`. The backend endpoint
(`src/api/routers/schedules.py` POST) correctly creates the row and
returns 201 with a `ScheduleResponse` body.

The issue is likely in the response handling chain:

1. **Response envelope mismatch**: The backend returns a bare
   `ScheduleResponse` (not wrapped in `{ data: ..., meta: ...,
   errors: ... }`), but `apiPost` expects the standard `ApiResponse<T>`
   envelope. When `response.json()` returns `{ id: 1, name: "...",
   ... }` instead of `{ data: { id: 1, ... } }`, `resp.data` is
   `undefined` and the component silently does nothing.

2. **Fix approach**: Either wrap the backend response in the standard
   envelope, or adjust the frontend `handleCreate` to handle a bare
   response. The standard approach in this codebase is to wrap backend
   responses in the envelope, so the backend should return
   `{ data: <schedule>, meta: {...}, errors: [] }`.

### Files to Modify

- `src/api/routers/schedules.py` -- wrap POST/PATCH/GET/DELETE responses
  in the standard API envelope (check how other routers like
  `collection.py` or `scans.py` do it), OR
- `frontend/src/components/admin/AdminSchedulesSection.tsx` -- handle
  both envelope-wrapped and bare responses in `handleCreate`

### Preferred Approach

Check how the other routers return data. If `schedules.py` is the only
router returning bare Pydantic models (not wrapped), wrap it. If all
routers return bare models and the `apiGet`/`apiPost` helpers handle
both, then the bug is elsewhere. Debug by adding `console.error` in
`handleCreate` to log the full response.
