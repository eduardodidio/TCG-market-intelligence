# F90-T06: Evaluation List / Watchlist

**Status:** planned
**Wave:** 3

## User Story

As a collector, I want to save cards from web search to an evaluation
list, so that I can track their prices over time before deciding whether
to add them to my collection.

## Acceptance Criteria

1. A new "Evaluation List" page at `/evaluations` shows cards the user
   has saved for evaluation.
2. Each evaluation entry displays: card name, set, price at time of
   addition, current price (if available), date added, and a remove
   button.
3. Cards can be added to the evaluation list from the web search results
   (F90-T05 "Add to Evaluation" button becomes active).
4. Cards on the evaluation list are included in scheduled scans so their
   prices get updated automatically.
5. Maximum 50 cards on the evaluation list per user.
6. Users can promote an evaluation card to their collection ("Add to
   Collection" action on the eval list).
7. Removing a card from the evaluation list does not delete its price
   history.
8. Nav item "Evaluations" appears in the sidebar (under Beta Test group
   from T02).

## Dev Notes

### Backend Changes

**New DB model** (`src/database/models.py`):
```python
class EvaluationEntryRow(Base):
    __tablename__ = "evaluation_entries"
    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, ForeignKey("users.id"), nullable=False)
    card_name = Column(String, nullable=False)
    set_code = Column(String, nullable=True)
    collector_number = Column(String, nullable=True)
    liga_url = Column(String, nullable=True)
    source_data_json = Column(String, nullable=True)  # raw Liga response
    price_at_add = Column(Numeric, nullable=True)      # BRL price when added
    status = Column(String, default="watching")         # watching | promoted | removed
    card_id = Column(Integer, ForeignKey("cards.id"), nullable=True)
    created_at = Column(DateTime, default=func.now())
    updated_at = Column(DateTime, default=func.now(), onupdate=func.now())
```

**Alembic migration**: create `evaluation_entries` table. Since the
project uses SQLAlchemy with `create_all()` (no Alembic), add the table
to the models file and it will be auto-created.

**Repository** (`src/database/repository.py`):
- `create_evaluation_entry(user_id, card_name, set_code, ...)` -- insert
  with 50-per-user limit check
- `list_evaluation_entries(user_id, status="watching")` -- list active
- `delete_evaluation_entry(entry_id, user_id)` -- soft-delete (status="removed")
  or hard delete
- `count_evaluation_entries(user_id)` -- for limit enforcement
- `get_evaluation_card_ids(user_id)` -- returns card_ids for scan inclusion

**API router** (`src/api/routers/evaluations.py` -- new):
- `POST /api/v1/evaluations` -- add card to evaluation list
  - Body: `{ card_name, set_code?, liga_url?, source_data_json?, price_at_add? }`
  - Returns 201 with the created entry
  - Returns 400 if limit (50) reached
- `GET /api/v1/evaluations` -- list evaluation entries for current user
- `DELETE /api/v1/evaluations/{id}` -- remove entry
- `POST /api/v1/evaluations/{id}/promote` -- move to collection
  (creates collection entry, updates eval status to "promoted")

**Scan integration** (`src/scheduler/service.py` or
`src/collectors/scan.py`):
- When building the list of cards to scan, also include card_ids from
  the user's evaluation list (`get_evaluation_card_ids`).
- This requires the eval entries to have a `card_id` linking to the
  cards table. The card must be created (or matched) when adding to
  the eval list.

### Key Decisions

- **Card ID linking**: when a user adds a card to the eval list from web
  search, we may not have a local `card_id` yet. Options:
  (a) Create a card row immediately (preferred -- enables scan inclusion).
  (b) Store just the name/set and resolve card_id lazily on first scan.
  Go with (a) for simplicity.
- **Soft vs hard delete**: use hard delete. Eval entries are lightweight
  and the price data is on the cards/observations tables, not the eval
  table.
- **Scan inclusion**: evaluation cards should be scanned at the same
  cost (1 token per card). The token deduction already counts cards;
  we just need to include eval card_ids in the count and scan list.
