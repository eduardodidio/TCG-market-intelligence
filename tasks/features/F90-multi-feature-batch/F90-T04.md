# F90-T04: Schedule Token Cost

**Status:** planned
**Wave:** 1

## User Story

As a platform operator, I want scheduled scans to check and deduct
credit tokens before running, so that the token economy is enforced
consistently for both manual and automated scans.

## Acceptance Criteria

1. Before executing a scheduled scan, the system checks whether the
   schedule owner has enough credits (1 token per card to scan).
2. If the user has sufficient credits, tokens are deducted and the scan
   proceeds.
3. If the user has insufficient credits, the scan is skipped, the
   schedule is set to status `paused_insufficient_credits`, and a
   warning is logged.
4. The schedule status `paused_insufficient_credits` is visually
   distinct from `paused` in the frontend (amber/yellow vs grey).
5. When a user with a paused-insufficient-credits schedule gains more
   tokens (bonus claim or admin grant), they can manually resume the
   schedule.
6. Admin daily Liga scan (`admin_daily_liga` type) is exempt from token
   checks -- it uses the admin's balance which has the monthly 10k
   grant.

## Dev Notes

### Backend Changes

**ScanScheduler** (`src/scheduler/service.py`):
- In `_execute_scheduled_scan()`, before creating/running the scan:
  1. Load the schedule's `user_id` from the schedule dict.
  2. Count cards to scan: parse `filters_json` to get the scan filter,
     query the repo for matching card count
     (`repo.count_collection_entries(user_id, scan_filter)`).
  3. Instantiate `CreditService(repo)` and call
     `credit_service.check_sufficient(user_id, card_count)`.
  4. If insufficient: log warning, set schedule status to
     `paused_insufficient_credits`, return early (do not create scan
     run).
  5. If sufficient: call `credit_service.deduct(user_id, card_count,
     reason="scheduled_scan", reference_id=f"schedule_{schedule_id}")`.
- The `admin_daily_liga` scan type is exempt (skip token check for this
  type).

**Repository** (`src/database/repository.py`):
- May need a `count_collection_entries(user_id, scan_filter)` method if
  one does not exist. Check existing methods first -- `scan.py` already
  resolves the card list, so we can reuse that logic.

**Schedule status values**:
- Add `paused_insufficient_credits` as a valid status string. This is
  stored in the `status` column of `scheduled_scans` table (VARCHAR).
  No migration needed -- it is just a new string value.
