# F60-T06: Scan API + CLI provider flag

**Status:** planned
**Wave:** 1
**Depends on:** T01, T04
**Parallel with:** T04, T05

## User Story

As a user, I want to trigger Liga scans via the API and CLI (not just MYP)
so that I can use either provider for on-demand scans.

## Dev Notes

### 1. API: `POST /scans` — add `provider` field

Update `ScanRequest` schema:
```python
class ScanRequest(BaseModel):
    scan_type: str = "collection"
    provider: str = "liga"  # NEW: "liga" | "myp", default liga
    # ... existing fields
```

Update `trigger_scan()` in `src/api/routers/scans.py`:
- When `provider == "liga"`: import and use `run_liga_scan` from T04
  - Force concurrency=1, delay=5s
  - Use `ScanType.LIGA_FULL` or `LIGA_PARTIAL`
- When `provider == "myp"`: existing MYP path unchanged
- Thread launch logic stays the same (background thread with asyncio.run)

### 2. CLI: `tcg scan --provider liga`

Update existing `scan` command in `src/cli/main.py`:
- Add `--provider` option: `liga` | `myp` (default: `liga`)
- When `liga`: use `run_liga_scan()`
- When `myp`: existing `run_scan()` path

### 3. ScanRunResponse — show provider

Add `provider` field to `ScanRunResponse` schema (optional, backward compat).
Encode in `filters_json` when creating scan run.

### 4. Frontend: ScanRequest trigger

Update `frontend/src/api/scans.ts`:
- `triggerScan()` and `triggerScanAuth()` — add optional `provider` param
- Default to `"liga"`

Update `useCollectionRefresh` hook:
- Pass `provider: "liga"` to trigger

### Files to modify
- `src/api/routers/scans.py` — provider routing
- `src/api/schemas/scans.py` — ScanRequest.provider field
- `src/cli/main.py` — scan command --provider flag
- `frontend/src/api/scans.ts` — provider param
- `frontend/src/hooks/useCollectionRefresh.ts` — default provider liga
