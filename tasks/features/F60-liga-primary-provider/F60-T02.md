# F60-T02: Liga scan repo method + price priority update

**Status:** planned
**Wave:** 0
**Parallel with:** T01, T03

## User Story

As a developer, I want a repository method that returns cards eligible for
Liga scanning (by name, not MYP source_cards) and I want price priority to
favor Liga over MYP so that the platform reflects Liga prices when available.

## Dev Notes

### 1. New repo method: `get_cards_for_liga_scan()`

```python
def get_cards_for_liga_scan(self, scan_filter: ScanFilter) -> list[dict]:
    """Return collection entries for Liga scanning.

    Unlike get_cards_for_scan (MYP), this does NOT require a source_card.
    Returns entries with card_id + name_en/name_pt for Liga search.
    Optionally filters by set_code, rarity, card_ids, limit.
    """
```

- Query: `SELECT id, card_id, name_en, name_pt, set_code, collector_number
  FROM user_collection WHERE card_id IS NOT NULL`
- Returns dicts with: `entry_id`, `card_id`, `name_en`, `name_pt`, `set_code`
- Filter support: `set_codes`, `rarities`, `card_ids`, `limit`
- Does NOT need MYP source_card linkage

### 2. `get_cards_for_liga_scan()` with freshness filter

Add optional `max_age_days: int | None = None` parameter:
- When set, exclude cards that have a `source="liga"` price observation
  within the last N days
- SQL: `LEFT JOIN price_observations ON ... WHERE po.id IS NULL OR po.observed_at < date('now', '-N days')`
- This enables resume/skip behavior for `liga-sweep`

### 3. Price priority update in `get_latest_prices_batch()`

Current priority: "latest date wins, manual wins same-date ties"

New priority order (same date):
1. **manual** (user override always wins)
2. **liga** (primary source)
3. **jsonld_snapshot / myp** (fallback)

Implementation: adjust the sort key in the candidate selection:
```python
SOURCE_PRIORITY = {"manual": 0, "liga": 1, "jsonld_snapshot": 2, "myp": 3}

def _sort_key(obs):
    return (-obs.observed_at.toordinal(), SOURCE_PRIORITY.get(obs.source, 99))

candidates.sort(key=_sort_key)
winner = candidates[0]
```
