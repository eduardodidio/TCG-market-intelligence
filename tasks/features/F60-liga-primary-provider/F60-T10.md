# F60-T10: Scheduled Liga scans (APScheduler integration)

**Status:** planned
**Wave:** 3
**Depends on:** T04, T06

## User Story

As an operator, I want scheduled Liga scans (daily partial, weekly full)
so that prices stay updated without manual intervention.

## Dev Notes

### 1. Default schedules (seed on first boot)

Create two default scheduled scans if none exist:

**Liga Daily Partial** (subset of ~50 cards per day):
```python
{
    "name": "Liga Daily Partial",
    "cron_expression": "0 3 * * *",  # 3 AM daily
    "scan_type": "liga_partial",
    "filters_json": '{"limit": 50, "provider": "liga"}',
    "status": "active",
}
```

**Liga Weekly Full** (all cards):
```python
{
    "name": "Liga Weekly Full",
    "cron_expression": "0 1 * * 0",  # 1 AM Sunday
    "scan_type": "liga_full",
    "filters_json": '{"provider": "liga"}',
    "status": "active",
}
```

### 2. Scheduler integration

Update `src/scheduler/service.py`:
- When executing a scheduled scan, check `filters_json` for `"provider": "liga"`
- If liga: use `run_liga_scan()` from T04
- If myp or absent: use existing `run_scan()`
- Auto-pause on 3+ consecutive failures (existing F37 behavior)

### 3. Liga partial scan strategy

For daily partial scans (`liga_partial`):
- Use `get_cards_for_liga_scan(max_age_days=1)` — cards not scanned today
- Limit to 50 cards per run
- Order by `oldest Liga price first` (prioritize stalest data)
- Over ~7 days, all 349 cards get refreshed at least once

### 4. Scheduling page compatibility

The existing `/schedules` frontend page (F37) should work with new scan types.
Just ensure the schedule list shows Liga scan types correctly.
