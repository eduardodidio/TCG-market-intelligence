**Status:** planned
**Wave:** 1

## User Story

As a developer, I want a complete Liga scan flow that fetches prices from
LigaMagic for collection cards, saves observations, and emits SSE events
so that the frontend can show real-time progress.

## Dev Notes

### New function: `run_liga_scan()`

Create `src/collectors/liga_scan.py` — a thin wrapper around the refactored
`run_scan()` from T01 with Liga-specific defaults:

```python
async def run_liga_scan(
    db_url: str = "sqlite:///tcg_market.db",
    scan_filter: ScanFilter | None = None,
    dry_run: bool = False,
    delay: float = 5.0,
    run_id: int | None = None,
    on_complete: Callable | None = None,
    max_age_days: int | None = None,
) -> ScanRun:
```

### Key behaviors
- Uses `LigaMagicProvider` (single instance, reused across cards)
- Concurrency: **always 1** (Playwright browser, sequential)
- Delay: 5s default between cards (configurable)
- Scan type: `LIGA_FULL` or `LIGA_PARTIAL` (based on filter)
- Gets cards via `repo.get_cards_for_liga_scan()` (T02)
- Each card: `provider.search_card(name)` → extract price → save as `source="liga"`, `external_id="liga_{card_id}"`
- Emits `ScanEvent` for each card (SSE compat with existing frontend)
- Error handling:
  - `LigaNotFoundError` → skip, no retry
  - `LigaRateLimitError` → requeue with 30s delay, MAX_REQUEUE=1
  - `LigaError` → fail card
  - Other exceptions → fail card

### Browser lifecycle
- Create `LigaMagicProvider` once at scan start
- Close at scan end (in `finally` block)
- Do NOT open/close browser per card (too slow)

### SSE event format
Same as existing MYP scans — `card_scanned`, `scan_started`, `scan_complete`
events via `scan_bus`. Frontend `useScanStream` works unchanged.

### Files to create
- `src/collectors/liga_scan.py`

### Files to modify
- None (uses refactored `run_scan` from T01 or standalone)
