# F149-T01: Fix guest proxy in require_auth_or_api_key

**Feature:** F149 — Guest collection visibility fix
**Wave:** 0
**Status:** planned

## User Story

As a guest user, I want to see the admin's collection when I log in,
so that I can browse the card collection as intended by the beta access model.

## Root Cause

`require_auth_or_api_key()` in `src/auth/dependencies.py:158-168` returns
`str(user_row.id)` — the guest's own user ID. This bypasses the `_proxy_guest()`
logic that `get_current_user()` uses to swap the user ID to the primary admin's.

All collection endpoints use `require_auth_or_api_key` as their auth dependency,
so the guest user gets an empty collection (their own) instead of the admin's.

## Dev Notes

### File: `src/auth/dependencies.py`

In `require_auth_or_api_key`, after finding a valid JWT user (line ~164-166),
check if the user has `role == "guest"`. If so, resolve the admin ID:

```python
# Inside require_auth_or_api_key, JWT branch:
if user_row and user_row.is_active:
    role = getattr(user_row, "role", "admin")
    if role == "guest":
        admin_ids = repo.get_admin_user_ids()
        if admin_ids:
            return str(admin_ids[0])
    return str(user_row.id)
```

This mirrors what `_proxy_guest` does but only returns the ID string
(since `require_auth_or_api_key` returns `str`, not `User`).

### Verify other endpoints

Check that endpoints using `get_current_user` (which already calls
`_proxy_guest`) are not double-proxying. Only `require_auth_or_api_key`
needs the fix.
