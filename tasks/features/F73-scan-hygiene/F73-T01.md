# F73-T01 — Scan Reset + Stale Detection on Startup

**Status:** planned
**Wave:** 0
**Depends on:** —

## User Story

As an operator, I want stale "running" scans to be automatically marked as errors on startup, and I want to reset the current scan history to start fresh.

## Dev Notes

### Files to modify

1. **`src/database/repository.py`** — Add two methods:
   - `delete_all_scan_runs() -> int` — DELETE FROM scan_runs, returns count deleted
   - `mark_stale_scans_as_error(before: datetime) -> int` — UPDATE scan_runs SET status='error', error_summary='Auto-marked as stale: scan was still running at startup', finished_at=now WHERE status='running' AND started_at < before. Returns count updated.

2. **`src/api/app.py`** — In `lifespan()`, add stale scan cleanup BEFORE scheduler startup:
   ```python
   # Mark stale running scans as error (from previous day)
   try:
       from src.database.repository import Repository
       from datetime import datetime, timedelta
       repo = Repository(get_db_url())
       today_start = datetime.now().replace(hour=0, minute=0, second=0, microsecond=0)
       marked = repo.mark_stale_scans_as_error(before=today_start)
       if marked > 0:
           _log.info("stale_scans_marked_as_error", count=marked)
   except Exception:
       _log.warning("stale_scan_cleanup_failed", exc_info=True)
   ```

3. **One-time reset** — Add a CLI command or run directly:
   - Option A: Add `db-reset-scans` CLI command to `src/cli/main.py`
   - Option B: Just run the delete in the migration/startup once
   - Recommended: CLI command `tcg db-reset-scans` with `--confirm` flag (safer, reusable)

### Key decisions
- Stale threshold = start of current day (midnight). Any scan running from before today is stale.
- The one-time reset deletes ALL scan_runs, not just old ones
- Stale detection runs on EVERY startup (ongoing protection)
- error_summary clearly identifies auto-marked scans

## Testing

- `mark_stale_scans_as_error` correctly marks running scans from yesterday
- `mark_stale_scans_as_error` does NOT mark running scans from today
- `mark_stale_scans_as_error` does NOT mark completed/error scans
- `delete_all_scan_runs` removes all records
- CLI command works with --confirm flag
